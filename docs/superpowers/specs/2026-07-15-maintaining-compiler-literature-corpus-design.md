# 编译器文献语料库全流程维护 Skill 设计

## 目标

创建个人 Skill `maintaining-compiler-literature-corpus`，把研究方向扩展、2024–2026 文献检索、元数据核验、候选记录、分类下载、全文阅读和三个索引状态同步组成一条可中断续跑、可验证的工作流。

## 边界

- 新 Skill 负责语料库编排与一致性；不重复现有 `reading-compiler-literature` 的 14 节笔记规则。
- 检索必须围绕用户给定研究方向生成中性关键词矩阵，不能围绕某个预设框架定向搜证。
- 只纳入首次公开或正式发表年份为 2024–2026、元数据可由论文主页或正式记录核验的成果。
- 默认维护六类目录；出现无法可靠归类的新方向时，先记录为待分类，不擅自新增类别。
- 下载失败、正文不可得、重复论文和年份冲突必须保留状态与原因，不能伪装成已完成。

## Skill 结构

```text
maintaining-compiler-literature-corpus/
├── SKILL.md
├── agents/openai.yaml
├── references/corpus-contract.md
└── scripts/validate_literature_corpus.ps1
```

- `SKILL.md`：九阶段主流程、续跑规则和完成条件。
- `corpus-contract.md`：六类边界、关键词矩阵、候选字段、命名规则、状态机和索引模板。
- `validate_literature_corpus.ps1`：只读验证 PDF 签名、笔记 14 节、索引数量、C/N 编号、本地链接和候选状态。
- `openai.yaml`：个人 Skill 的显示名称、简述和默认调用提示。

## 主流程

1. 清点研究目录、现有 PDF、笔记、逐篇目录、分类索引和年份筛选清单。
2. 从研究方向生成“主题×对象×方法×证据×硬件/IR”的关键词矩阵，中英文组合检索。
3. 通过 arXiv、会议/期刊官网、ACL Anthology、ACM/IEEE/USENIX/作者主页等一手来源检索 2024–2026 文献。
4. 按规范化题名、DOI、arXiv ID 和正式版本关系去重，核验年份、作者、渠道、链接、关键词、分类和优先级。
5. 先把候选写入年份筛选清单，状态设为“已核验、待下载”。
6. 按主类别创建论文目录，下载为 `paper.pdf`，检查 `%PDF-` 签名和可解析页数，再更新状态。
7. **REQUIRED SUB-SKILL:** 使用 `reading-compiler-literature` 基于 PDF 全文生成 14 节中文阅读笔记。
8. 同一批次更新逐篇阅读目录、分类索引和年份候选状态，并重算分类、全文覆盖率与优先级统计。
9. 运行只读验证脚本；数量、链接、PDF、章节和状态全部一致后才报告完成。

## 状态模型

每篇新增文献按以下顺序推进：

`发现候选 → 元数据已核验 → 已下载 → PDF有效 → 阅读完成 → 逐篇目录已加入 → 分类索引已加入 → 年份清单已完成`

失败状态必须附原因：`重复项`、`年份不符`、`下载失败`、`非论文/正文不可得`、`待分类`。

## 中断与错误处理

- 每次开始先从三个清单和文件系统重建任务状态，不依赖聊天记录。
- 已存在有效 PDF 时不重复下载；已有合格笔记时不重写，只补缺失索引或状态。
- 正式版与预印本是同一论文时保留一个语料条目，优先正式渠道并记录首次公开年份。
- 批量处理中单篇失败不阻塞其他论文，但最终报告必须列出失败项。
- 索引更新视为同一事务：三个文件中任一状态不一致即未完成。

## 验收标准

- Skill 名称、YAML 和 `agents/openai.yaml` 通过官方 `quick_validate.py`。
- 验证脚本能在当前语料库只读运行，并对人为构造的缺失链接/缺章节样例返回失败。
- `SKILL.md` 不复制 14 节正文模板，只显式调用现有逐篇阅读 Skill。
- 新增文献数、有效 PDF 数、合格笔记数及两个索引新增行数一致。
- 年份清单不存在“尚未纳入”等与实际文件状态冲突的描述。
