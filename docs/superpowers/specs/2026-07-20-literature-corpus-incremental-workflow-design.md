# 编译器文献语料库增量维护工作流设计

## 目标

在不改变现有语料库结果、Markdown 作为唯一事实源、13 节阅读笔记和最终验证门槛的前提下，减少重复联网核验、无效 PDF 下载、全库重复扫描和失败项返工。

## 不变约束

- `00_分类索引.md`、`文献逐篇阅读/00_逐篇阅读目录.md`、`文献逐篇阅读/2024-2026_文献年份筛选清单.md` 仍是唯一状态文件。
- 只有有效 `paper.pdf`、合格 13 节笔记、三份索引同步和既有验证器通过，论文才算入库完成。
- 缓存和报告不生成、修改或推断论文事实；技术事实仍只来自 PDF 正文。
- 失败候选保留精确原因，不能被缓存静默过滤或标记完成。
- 现有 `scripts/validate_literature_corpus.ps1` 保持最终提交前的强制入口。

## 组成

### 候选缓存

新增 `文献逐篇阅读/候选处理缓存.jsonl`。每行表示一次候选处理事件，字段包括：`run_id`、`checked_at`、`title`、`normalized_title`、`doi`、`arxiv_id`、`first_public_year`、`venue`、`stable_url`、`pdf_url`、`category`、`status`、`reason` 和 `pdf_probe`。

缓存是可丢弃、可重建的辅助审计日志：它不替代年份清单，不参与索引计数，也不作为论文事实来源。JSONL 使单条追加、人工审阅和 Git diff 都保持简单。

### 增量维护脚本

新增 PowerShell 脚本，提供三个明确模式：

- `-Mode Report`：只读扫描缓存、三份 Markdown、六类目录和 PDF，报告可复用候选、三重去重命中、待下载项、缺失链接及计数差异。
- `-Mode ProbePdf -PdfUrl <URL>`：仅下载到临时文件，检查最终 URL、Content-Type、前五字节 `%PDF-` 和 `pdfinfo` 页数；不写入语料库。
- `-Mode RecordCandidate`：只向 JSONL 追加一个已核验或失败候选事件；必须传入完整字段，且不得自动更新年份清单或索引。

脚本不进行论文全文下载、不调用模型、不生成笔记、不自动提交 Git。这样可将机器确定性的预检与需要研究判断的阅读阶段分离。

### 处理状态

每轮先运行 `Report`，按 DOI、arXiv ID、规范化题名三重键将候选分为：本地已入库、缓存已失败、缓存可重试、首次待核验。只有通过元数据核验且 `ProbePdf` 返回有效 PDF 的候选才进入年份清单和全文阅读队列。

对登录页、HTML、403/429、重定向循环、网络错误分别记录精确失败类型和最终 URL。`下载失败` 默认在下一轮可重试；`重复项` 与 `年份不符` 不重试，除非候选元数据发生变化。

## 数据流

`联网检索 → 元数据核验 → RecordCandidate → Report 去重 → ProbePdf → 年份清单登记 → 完整 PDF 下载与阅读 → 三索引事务更新 → validate_literature_corpus.ps1 → 精确 Git 提交`。

在任一点中断时，下轮只重跑未完成阶段：成功 PDF 不重复下载，缓存命中的失败 URL 不重复请求，已有合格笔记不重写。

## 错误处理与安全

- 临时下载只写入系统临时目录，PDF 预检失败立即删除临时文件。
- JSONL 追加前校验必填字段、年份范围和状态枚举；不接受密码、Cookie、令牌或其他凭据字段。
- 网络请求不共享浏览器登录态；需要受限下载时，缓存记录“需要用户会话下载”，而不尝试读取账号凭据。
- 缓存文件损坏时 `Report` 报出行号并跳过该行；不修改原文件。

## 验证策略

- 为规范化题名、DOI/arXiv 去重、JSONL 校验、PDF 签名与 HTML 拒绝、报告计数建立 PowerShell Pester 测试。
- 用真实语料库运行 `Report`，确认不修改工作区且能识别 C26 一类 HTML 下载失败。
- 保留并运行既有 `scripts/validate_literature_corpus.ps1`；新脚本通过不代表语料库入库完成。

## 成功标准

- 相同候选在后续批次可由缓存命中并避免重复元数据/下载尝试。
- PDF 预检能在写入语料库前拒绝 HTML、错误页和不可解析 PDF。
- 脚本仅在 `RecordCandidate` 模式写入缓存，其他模式不改动仓库文件。
- 既有验证器对当前语料库继续返回退出码 0。
