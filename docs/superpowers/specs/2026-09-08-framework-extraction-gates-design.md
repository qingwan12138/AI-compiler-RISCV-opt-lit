# 文献框架提炼门控设计

## 目标

在创新证据层的五项 `OPP` 机会之上，增加“近邻工作碰撞”和“机制增量与可做性”两道文献门控。输出只用于判断一个机会是否有足够的独立机制与公开可核验条件；不形成具体研究方案、算法设计、预实验或最终选题。

## 范围与边界

- 不修改 taxonomy v2、PDF、逐篇笔记、既有研究方案或 `05/06` 的论文事实。
- 审计对象固定为 `07_创新机会观察区.md` 当前的五项 `OPP-01` 至 `OPP-05`。
- 近邻关系必须标注为“论文事实”或“基于任务/输出对象的分析推断”。
- 任何“可做性”仅指公开工具、数据、硬件和可证伪指标的可获得性，不评价个人能力，也不承诺研究结果。

## 新增文件

### `08_近邻工作与创新边界表.md`

每个机会建立一张审计表，至少包含：

- 最接近的 3–5 篇论文；
- 其已经覆盖的任务、输出对象、反馈与验证；
- 当前机会尚未被该近邻覆盖的具体条件；
- 重合风险（低/中/高）与理由；
- 事实/推断属性、证据位置和人工复核重点。

该文件的作用是排除“换平台、换模型、增加 Agent/RL/Alive2”等只在标签层变化的伪差异。

### `09_机制增量与可做性门控.md`

每个机会记录：

- 现有工作共同的输入、输出、反馈和约束；
- 若要成为独立框架，必须新增的信息、约束、决策对象或反馈闭环；
- 删除该增量后会退化成的最近论文；
- 可公开核验的工具/基准、可证伪指标和主要不可用资源；
- 门控结果：`保留观察`、`证据不足`、`近邻重合高`。

该文件不提出新增机制的实现方法，只说明当前文献是否足以证明它需要是一个独立机制。

## 对 `07_创新机会观察区.md` 的更新

每个 `OPP` 增加“框架审计状态”字段，链接到 `08`、`09` 的对应条目。允许状态：

- `保留观察`：近邻未覆盖条件明确，且可公开核验；
- `证据不足`：关键近邻或同任务对照尚未核验；
- `近邻重合高`：现有论文已基本覆盖，不能作为独立框架主张。

## 验收标准

1. 只新增两个 Markdown 文件并更新 `07`，不触及其他文献或研究方案文件。
2. 五项 `OPP` 都有 3–5 篇近邻工作、碰撞风险和证据来源。
3. 五项 `OPP` 都通过机制增量与可做性门控，且不含算法流程、实验方案或贡献宣称。
4. 所有 `PAPER-`、`LIM-`、`OPP-` 引用都存在；所有本地 Markdown 链接有效。
