# 08 六类编译器创新点提炼 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以 2024–2026 年逐篇阅读总结为主要证据，从零推导六类编译器研究创新点，并在 `08_六类论文创新点提炼` 中形成六份分类分析、一份总览和一份唯一主线框架。

**Architecture:** 先冻结去重后的年份—类别—总结文件清单，再按六类独立建立证据矩阵和候选机制，最后做跨类别碰撞检查。最终主线以可执行证据契约驱动的 LLM 编译优化智能体为中心，硬件响应指纹只作为辅助反馈，RISC-V 仅作为实验平台选项；旧文献仅用于否定不新颖主张，`07` 只提供文件数量和层级样式。

**Tech Stack:** Markdown、PowerShell、ripgrep、Git；证据来源为本地逐篇阅读总结和年份筛选清单。

## Global Constraints

- 主要证据限定为首次公开或正式发表于 2024–2026 年的本地逐篇阅读总结。
- 2023 年及以前的总结只用于确认已有工作和新颖性碰撞。
- 年份以 `文献逐篇阅读/2024-2026_文献年份筛选清单.md` 的校正口径为准，重复版本只计一次。
- 不读取或引用 `07_六类论文创新点提炼` 的创新内容，不读取既有实验项目作为设计依据。
- 六类必须先独立分析，再进行交叉比较；每类提出 2–4 个候选，只展开一个最推荐方向。
- 全文严格区分【论文事实】【合理推导】【候选创新】。
- 单纯换架构、换模型、加入 LLM、Agent、RAG、强化学习、形式验证工具或真实硬件本身不能作为创新；LLM Agent 只有在证据契约、反证闭环、工具裁决和记忆门控形成可分离机制时才进入主线。
- 所有 Demo、基线、消融、统计方法和可证伪条件均从本轮证据重新设计。
- 最终只推荐一条以 LLM/AI 编译器为中心的主创新，其余方向定位为支撑、独立备选、扩展或放弃；RISC-V 不作为主线限定。
- 使用简体中文；专业术语首次出现时给出英文全称和白话解释。
