# 信息价值门控框架：完整实验设计

## Material Passport

- Origin Skill: experiment-agent
- Origin Mode: plan
- Origin Date: 2026-07-19
- Verification Status: UNVERIFIED
- Version Label: voi_feedback_plan_v1

## 1. 实验目标

验证反事实决策变化与成本联合门控，是否在固定预算下比无反馈、全量反馈、随机反馈和固定阶段规则产生更多有效优化。

## 2. 实验单元

实验单元是一个“程序任务 × 反馈策略 × 随机种子”。同一个任务的所有方法使用完全相同的初始程序、测试、模型、动作空间和总预算。

## 3. 变量

### 自变量

反馈策略：

1. `NoFeedback`；
2. `AllFeedback`；
3. `RandomOne`；
4. `StageRule`；
5. `VOIGate`。

### 因变量

- Valid Improvement@Budget；
- 有效优化率；
- 首次有效优化所需轮数、Token、工具调用和秒数；
- 总 Token 和工具时间；
- 决策变化预测的 Brier score、AUROC 或 Average Precision；
- 决策变化后产生有效优化的比例；
- IR 指令和代码大小收益。

### 控制变量

模型、解码、Prompt、任务、最大轮数、候选动作、编译器、测试、反馈生成器和预算上限。

## 4. 数据集

- 预实验：20 个函数；
- 完整实验：60—120 个函数；
- 程序家族至少覆盖循环、控制流、内存、函数调用和混合模式；
- 训练/校准门控器时按程序家族切分；
- 预留一个完全未见家族测试泛化。

## 5. 反馈定义

| 反馈 | 输入 | 输出 | 主要成本 |
|---|---|---|---|
| 编译诊断 | 候选源码/IR | 首个根因、位置、类别 | 编译时间、日志 Token |
| 测试差异 | 可执行文件 | 失败输入与输出差异摘要 | 执行时间、摘要 Token |
| Optimization remark | 编译过程 | 成功/失败优化和原因 | 编译时间、remark Token |
| IR 统计 | 优化前后 IR | 指令类别变化和局部 diff | 分析时间、diff Token |

所有方法使用同一反馈生成器，避免把反馈质量差异误认为策略差异。

## 6. 反事实标注阶段

对开发集每个状态分别运行：无新增反馈、四种单反馈。记录：

- 下一动作类型是否改变；
- 修改位置是否改变；
- 候选排序是否改变；
- 改变后是否通过编译/测试；
- 是否产生静态收益；
- 反馈成本。

得到 `change`、`valid_gain` 和 `cost` 标签。首版可以用这些标签训练逻辑回归或梯度提升树；不训练 LLM。

## 7. 在线比较

每任务最多 5 轮、5 个候选，并同时设置：

- 输入 Token 上限；
- 输出 Token 上限；
- 编译次数上限；
- 测试次数上限；
- 总墙钟上限。

若某方法达到任何上限，则停止，不允许使用其他预算补偿。

## 8. 基线细节

- `NoFeedback`：单轮生成或仅采样，不看工具输出；
- `AllFeedback`：每轮返回所有当前可得反馈；
- `RandomOne`：从可用反馈中随机选择一条；
- `StageRule`：编译失败看诊断、测试失败看差异、正确无收益看 remark+IR；
- `VOIGate`：选择最高正 VOI，若均不为正则执行或停止。

`StageRule` 是最重要强基线。若它不弱于 VOI，则主线不成立。

## 9. 主要指标

```text
ValidImprovement@B = 在预算B内获得有效优化的任务数 / 任务总数
```

```text
Efficiency = 有效优化任务数 / 归一化总成本
```

归一化总成本必须分别报告原始组成，不用一个加权数字掩盖实际差异。

## 10. 决策变化质量

- `change=1`：反馈后动作类型、目标位置或候选排序发生预注册的实质变化；
- 仅改写解释措辞不算变化；
- 变化后候选必须通过正确性门控，才能计为有用变化；
- 报告 `P(change)` 的校准曲线和 Brier score；
- 报告“变化但无收益”和“不变化但有收益”两类错误。

## 11. 消融

- 去掉 `P(change)`；
- 去掉 `G`；
- 去掉 Token 成本；
- 去掉工具成本；
- 去掉墙钟成本；
- 去掉主动停止；
- 随机停止；
- 完整日志代替精确摘要；
- 只用状态阶段，不看程序和候选特征。

## 12. 统计

- Valid Improvement 使用任务级配对 bootstrap 95% 置信区间；
- 方法成败差异可用 McNemar 检验；
- 成本与收益报告中位数、四分位距和配对差值；
- 决策变化预测报告 Brier score、AUROC/AP 和可靠性图；
- 多重比较用 Holm 校正；
- 报告程序家族分层结果和最坏 10% 任务；
- 至少 3 个解码种子；成本极高时预注册一个固定种子并明确局限。

## 13. 运行时间复核

仅对正确且静态改善的 Top-1 候选计时。预热 3 次，正式至少 10 次，随机化顺序，报告中位数和置信区间。

## 14. 成功门槛

- VOI 相对 StageRule 提高 Valid Improvement@Budget；
- 平均 Token、工具调用或墙钟至少一项下降，其他项不大幅恶化；
- `P(change)` 明显优于常数预测；
- 去掉停止或成本项会降低单位成本收益；
- 结果在未见程序家族上方向一致。

## 15. 可证伪条件

StageRule 同等或更优、`P(change)` 无校准能力、节省成本以牺牲优化质量为代价、或者只在单模型上成立，均削弱或否定主张。
