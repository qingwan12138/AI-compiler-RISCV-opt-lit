# 信息价值门控框架：预实验 Demo

## 1. Demo 目标

用最小成本回答两个问题：

1. 不同反馈是否真的会让 LLM 选择不同动作？
2. 基于这种变化选择反馈，能否比固定阶段规则在相同预算下得到更多有效优化？

## 2. 规模

- 20 个 C 函数；
- 4 类反馈；
- 5 种反馈策略；
- 每任务最多 3 轮；
- 每方法每任务最多 3 个候选；
- 一个固定 LLM；
- 不训练大模型。

## 3. 第一部分：离线反事实表

从 20 个任务中采集约 40 个代表状态。每个状态分别提供：

- 无新增反馈；
- 编译诊断；
- 测试差异；
- optimization remark；
- IR 统计。

记录下一动作和候选。人工规则只判断动作是否实质改变，不评价自然语言是否更好听。

## 4. 第二部分：简单门控器

首版特征：

- 当前阶段；
- 已观察反馈类型；
- 剩余预算；
- 当前候选是否编译/测试通过；
- LLM 下一动作置信差；
- 反馈预计 Token 和工具时间。

使用简单规则或逻辑回归估计 `P(change)`。门控器只在开发状态拟合，在剩余任务上测试。

## 5. 第三部分：在线策略对比

比较：

1. 全量反馈；
2. 随机单反馈；
3. 固定阶段规则；
4. VOI 门控；
5. VOI 门控但不能停止。

所有方法使用相同 Token、最多 3 轮、最多 3 次编译和测试。

## 6. 最低记录项

- 每轮可选反馈；
- 每条反馈预计成本；
- 选择结果与原因；
- 选择前后动作；
- 是否发生实质决策变化；
- 候选是否编译、测试和静态改善；
- 剩余预算和停止原因。

## 7. 成功标准

- 至少一种反馈的决策变化率明显高于其他反馈；
- 决策变化不是纯措辞变化；
- VOI 在等预算下不弱于 StageRule，并显示更低成本趋势；
- 允许停止比禁止停止减少无效轮次；
- 有效优化不是由错误代码产生。

若 VOI 只优于全量反馈，却不优于 StageRule，则暂不扩大实验。

## 8. 预计时间

- 工具准备和任务筛选：1 天；
- 离线反事实状态采集：1—2 天；
- 简单门控和在线对比：1—2 天；
- 分析：1 天。

总计约 4—6 个工作日，主要成本是 LLM 调用而非真实性能测量。

## 9. 降级方案

- 若四类反馈生成困难：先用编译诊断、测试差异和 IR 统计三类；
- 若 LLM 无置信度：使用多个采样动作的一致率表示不确定性；
- 若工具时间差异小：仍记录 Token 和调用次数；
- 若所有反馈都不改变决策：该主线不成立，转向结构化编辑保底框架；
- 若静态指标不可靠：只作为筛选，增加少量 Top-1 计时。
