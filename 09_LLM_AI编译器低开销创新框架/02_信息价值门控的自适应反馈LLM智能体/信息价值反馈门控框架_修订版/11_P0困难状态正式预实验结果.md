# P0 困难状态正式预实验结果

## 1. 结论

困难状态独立 P0 **不满足进入 P1 的预注册门槛**。

真实反馈相对 N0 的平均效用增量为 `+0.010296`，高于 N1 的 `-0.009364` 和 MatchedPlacebo 的 `-0.041735`，说明反馈并非完全没有局部信息价值。但是，真实反馈的配对 bootstrap 95% CI 为 `[-0.040779, +0.051603]`，没有稳定为正；5 个程序族中也只有 loop、mixed 两个方向为正，低于预注册要求的至少 4 个。因此不得进入 P1。

这不是“整个创新点已被证明错误”，而是当前证据只支持一个更窄的判断：**编译错误反馈可能具有可利用的边际价值，但将多种工具反馈统一成稳定、跨任务的信息价值门控信号，目前尚未得到验证。**

## 6. 预注册门槛审计

| 门槛 | 结果 | 判定 |
|---|---|---|
| RealFeedback 均值大于 N1 与 MatchedPlacebo | +0.010296 > -0.009364、-0.041735 | 通过 |
| RealFeedback 95% CI 严格为正 | 下界 -0.040779 | **失败** |
| 完整配对子集与主分析方向一致 | 两者均为正 | 通过 |
| 至少 3/4 类反馈为正 | 3/4 | 通过 |
| 至少 4 个程序族为正 | 2/5 | **失败** |
| 各条件生成成功率至少 75% | 100%、95%、75%、95% | 通过 |
| 不由单状态或单反馈类型主导 | 最大单状态占正增量 20.3%；Compile 占 47.0% | 未触发 50% 集中度审计线，但类型集中度偏高 |

由于门槛要求全部同时满足，而第 2、5 项失败，最终判定为：**不进入 P1**。

运行目录中的 `manifest.json` 字段 `pre_registered_continue_signal=true` 来自旧版脚本的宽松继续信号，只检查总体均值等少数条件，不对应本次 7 项严格预注册门槛，不能作为进入 P1 的依据。

## 7. 对创新方向的含义

1. 继续把“四类反馈统一门控”作为主张，当前证据不足。
2. Compile 反馈呈现稳定局部增益，值得单独形成更窄的“错误诊断信息价值门控”假设。
3. Test、Remark 的均值虽为正但幅度小、区间宽；IR 为负，不宜与 Compile 合并宣称统一收益。
4. 下一步如继续，应先做 Compile-only 的独立确认实验，并扩大任务族与状态数；不能把本轮局部 Compile 结果当作原统一框架已通过。
