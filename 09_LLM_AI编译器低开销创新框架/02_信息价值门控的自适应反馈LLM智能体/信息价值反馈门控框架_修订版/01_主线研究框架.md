# 正确性门控的配对控制边际效用反馈获取：主线研究框架

## 1. 一句话解释

系统不是把所有编译日志都交给 LLM，而是估计：**在同一优化状态下，某条反馈相对于不获取它，是否会提高下一步获得正确优化的概率或收益；若预期增量不足以覆盖新增 Token、工具和时间成本，则执行当前候选、接受当前最优或停止。**

## 2. 研究对象与任务边界

### 2.1 研究对象

研究对象是 LLM 编译优化智能体的反馈获取策略，不是：

- LLM 参数规模；
- Pass 搜索空间；
- 多智能体组织形式；
- 某一硬件架构专属优化；
- 编译器反馈内容生成器本身。

### 2.2 首轮任务

首轮固定为 C/C++ 源码级局部优化：

```text
输入：基准 C/C++ 函数 + 测试驱动 + 固定编译配置
输出：结构化优化动作 + 源码补丁
目标：保持语义正确的前提下，降低 IR 指令数/代码大小；完整实验补充运行时间
```

RISC-V 可在完整实验后作为外部验证平台，检验门控策略是否仍保持方向一致，但不参与首轮门控器训练。

## 3. 四类反馈及其依赖

1. `F_compile`：首个根因、错误位置和错误类别；
2. `F_test`：失败输入、期望输出和实际输出的结构化差异；
3. `F_remark`：LLVM optimization remark，说明优化成功、失败及原因；
4. `F_ir`：优化前后 IR 指令统计、代码大小和局部差异。

反馈并非始终同时可用：

```text
候选生成
  └─ 编译
      ├─ 失败：F_compile 可用
      └─ 成功
          ├─ 测试失败：F_test 可用
          ├─ 可生成 F_remark
          └─ 可生成 F_ir
```

状态中必须维护：

```text
available_feedback_mask
feedback_prerequisite
prerequisite_cost
```

测试反馈的成本必须包含编译、执行、差异摘要和上下文 Token；不能只计算测试命令本身。

## 4. 状态、动作和输出

### 4.1 状态

```text
s = <program_summary,
     current_candidate,
     current_stage,
     observed_evidence,
     available_feedback_mask,
     action_distribution,
     best_valid_candidate,
     remaining_budget>
```

其中 `remaining_budget` 分别记录输入 Token、输出 Token、编译次数、测试次数、分析次数和墙钟时间。

### 4.2 门控动作

- 请求一种当前可用反馈；
- 生成或修改候选；
- 执行当前候选；
- 接受当前最优正确候选；
- 停止任务。

### 4.3 结构化优化动作

为避免把措辞变化误判为决策变化，LLM 必须输出结构化动作：

```json
{
  "action_type": "loop_unroll",
  "target": "function:foo/loop:L2",
  "parameters": {"unroll_factor": 4},
  "candidate_ranking": ["c2", "c1", "c3"],
  "confidence": 0.72,
  "patch": "..."
}
```

决策变化分为：

- `C1`：动作类型改变；
- `C2`：目标位置改变；
- `C3`：关键参数改变；
- `C4`：候选排序改变。

仅解释文字变化不算决策变化。

## 5. 从“决策变化”升级为“配对控制边际效用”

### 5.1 基本效用

对一个候选动作 `a`，定义任务效用：

```text
U(a) = 0                                      , 若正确性门控失败
U(a) = Gain(a)                               , 若正确且产生收益
U(a) = 0 或负惩罚                            , 若正确但无收益
```

预实验中 `Gain` 只使用一个预注册的静态目标，例如 LLVM IR 指令数下降比例。完整实验分别报告静态收益与运行时间，不用一个加权数字掩盖二者。

### 5.2 配对控制边际效用

```text
DeltaUtility(f | s)
  = E[U(a_f) | s, f] - E[U(a_0) | s]
```

- `a_f`：获得反馈 `f` 后的动作；
- `a_0`：不获取新增反馈时的动作。

该量通过同一状态、预注册解码配置和配对种子块进行估计。由于不同 Prompt 下即使使用同一 seed 也不保证生成路径严格对应，因此这里是**配对控制估计**，不是结构因果模型中的严格因果效应。完整实验至少使用 3 个配对种子块，并报告状态级配对置信区间。

### 5.3 反馈价值

```text
VOI(f | s)
  = DeltaUtility(f | s)
  - lambda_t * IncrementalTokenCost(f | s)
  - lambda_e * IncrementalToolCost(f | s)
  - lambda_w * IncrementalWallTime(f | s)
```

三类成本只记录“相对于当前状态尚未支付的新增成本”。其中：

```text
IncrementalToolCost
  = unpaid_prerequisite_calls
  + feedback_generation_calls
  + newly_required_validation_calls
```

编译已经完成时，获取 IR 反馈不得再次计入同一次编译；尚未完成的编译则记入 `unpaid_prerequisite_calls`。墙钟时间与工具次数分别作为不同预算维度报告，不能把同一前置步骤同时记入 `ExecutionCost` 和 `PrerequisiteCost`。

首版可用规则、逻辑回归或成对排序估计：

```text
DeltaUtility(f | s)
  ≈ E[U(a_f) | s,f] - E[U(a_0) | s]
```

`P(change)` 和 `P(beneficial_change)` 只作为辅助预测目标和解释变量，不再单独代表反馈价值。若正确性门控导致效用标签大量为零，优先使用“真实反馈是否优于无反馈”的成对胜负标签，不训练复杂神经门控器。

## 6. 带控制组的配对反馈标注

同一个状态至少构造以下条件：

```text
N0：无新增反馈基准，paired_seed_block = b
N1：无新增反馈复测，使用预注册的另一 seed，估计自然采样波动
P1/P2：与真实反馈匹配但来自其他任务的置换安慰剂
C ：编译反馈
T ：测试反馈
R ：optimization remark
I ：IR 统计
```

安慰剂按反馈类型分别构造 2–3 个版本，并匹配长度、格式、语气、数值密度和错误类别外观；安慰剂来自其他任务的同类反馈，经过程序名、变量名、错误位置、输入输出和优化线索泄漏检查。P0 每个状态只运行一种当前可用真实反馈及其匹配安慰剂，P1 才扩展反馈类型。

记录：

- 结构化动作是否变化；
- 候选是否通过正确性门控；
- 是否产生有效收益；
- 有益效用增量；
- 获取成本。

只有真实反馈相对于 `N0/N1/P1/P2` 显示额外有益增量，才能认为信息内容产生作用，而不是 LLM 自然随机性或增加上下文造成扰动。比较时以状态和配对种子块为单位，不把同一程序产生的多个状态当作彼此独立样本。

## 7. 在线闭环

```text
程序与当前候选
      ↓
LLM 输出结构化动作、排序和不确定性
      ↓
根据依赖关系生成“可选反馈集合”
      ↓
门控器估计各反馈 DeltaUtility 与增量成本
      ↓
选择最高正 VOI 的反馈 / 执行 / 接受 / STOP
      ↓
正确性门控 + 静态收益 + 必要的运行时间测量
      ↓
更新当前最优、状态、预算与校准记录
```

当所有可行动作的预测边际价值低于阈值 `tau` 时，在“执行当前候选、接受当前最优、停止”中选择，不强制继续请求反馈。

## 8. 研究问题

- **RQ1**：真实反馈产生的正确性门控边际效用，是否高于无反馈复测与任务置换安慰剂反馈？
- **RQ2**：减去同状态无反馈基准的边际效用目标，是否比只预测反馈后结果更适合选择反馈？
- **RQ3**：完整 VOI 门控是否优于固定阶段规则和 `DirectGain`？
- **RQ4**：VOI 是否优于等预算的额外候选采样？
- **RQ5**：依赖感知的三维预算与主动停止能否减少无效尾部轮次而不损害正确优化率？
- **RQ6**：门控器在未见程序家族、第二个 LLM 和 RISC-V 外部平台上是否保持方向一致？

## 9. 假设

- **H1**：真实反馈的配对边际效用和 beneficial-change rate 高于无反馈复测和匹配安慰剂反馈；
- **H2**：完整 `VOIGate` 的 Valid Improvement@Budget 高于 `StageRule`；
- **H3**：完整 `VOIGate` 优于 `DirectGain`，说明“反馈后结果减去无反馈基准”的边际目标提供额外信息；若仅相当，则不主张该目标优于直接结果预测；
- **H4**：完整 `VOIGate` 优于预算匹配的额外采样；
- **H5**：去掉成本项、依赖成本或主动停止后，质量—成本曲线退化；
- **H6**：结果在未见程序家族和第二平台上方向一致。

## 10. 三项创新

### 10.1 核心创新：正确性门控的配对边际效用反馈获取

将反馈价值定义为“同状态下获取反馈相对于不获取反馈带来的正确优化效用增量”，再减去尚未支付的多维增量成本。它不把“动作发生变化”直接当作价值，而要求最终候选通过正确性与收益验证。

关键对照：

- `StageRule`；
- `DirectGain`；
- 去掉无反馈基准，只预测反馈后结果；
- 去掉 `decision change` 辅助项；
- 去掉收益项；
- 去掉成本项。

### 10.2 支撑创新一：随机性复测与任务置换安慰剂控制的反馈效应标注

在同状态下加入无反馈复测和 2–3 个按类型匹配的任务置换安慰剂，区分：

- 模型自然采样波动；
- 仅因上下文变长产生的扰动；
- 真实反馈信息带来的有益变化。

### 10.3 支撑创新二：反馈依赖图与增量成本驱动的选择及停止

把反馈前置依赖和尚未支付的获取链路成本纳入决策，例如测试差异需要先成功编译。停止由剩余预算和预测边际效用共同触发，而不是固定轮数或单一 Token 阈值；其正确性由离线真实一步停止后遗憾检验。

## 11. 可证伪条件

满足任一条件，核心主张需要降级或放弃：

1. 真实反馈效应不高于无反馈复测或匹配安慰剂；
2. `StageRule` 在等预算下同等或更优；
3. `DirectGain` 与完整方法一致，说明配对无反馈基准没有额外选择价值，核心主张应降级；
4. BudgetMatchedSampling 更好，说明预算应优先用于多采样；
5. 主动停止通过牺牲正确优化率换取成本下降；
6. 收益来自更多工具执行、更长上下文或信息泄漏；
7. 结果只由少数程序或某类失败状态驱动。
