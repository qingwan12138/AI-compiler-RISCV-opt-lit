## 8. 三创新点扩展记录

### 8.1 状态、反馈和动作字段

| 字段 | 含义 | 对应创新 |
|---|---|---|
| state_id | 同一反事实状态编号 | 支撑创新一 |
| feedback_type | compile、test、remark 或 ir | 核心创新、支撑创新一 |
| action_without_feedback | 无新增反馈时的动作 | 支撑创新一 |
| action_with_feedback | 加入指定反馈后的动作 | 支撑创新一 |
| change | 动作类型、位置或排序是否变化 | 核心创新、支撑创新一 |
| beneficial_change | 变化是否产生有效优化 | 核心创新、支撑创新一 |
| predicted_change_probability | 预测决策变化概率 | 核心创新 |
| predicted_gain | 预测有效优化增益 | 核心创新 |
| token_cost | 反馈 Token 成本 | 核心创新、支撑创新二 |
| tool_cost | 编译、测试或分析调用成本 | 核心创新、支撑创新二 |
| wall_cost | 墙钟时间成本 | 核心创新、支撑创新二 |
| remaining_token | 剩余 Token 预算 | 支撑创新二 |
| remaining_tool | 剩余工具调用预算 | 支撑创新二 |
| remaining_wall | 剩余时间预算 | 支撑创新二 |
| stop | 是否主动停止 | 支撑创新二 |
| stop_reason | 低价值、预算不足、接受最优或其他预定义原因 | 支撑创新二 |
| valid | 是否满足编译、测试和收益门控 | 统一主指标 |

### 8.2 专属指标复算

- Brier Score 使用 predicted_change_probability 与 change 计算；
- AUROC 和 Average Precision 按反馈类型、失败阶段分别计算；
- Valid Improvement@Budget 由任务级 valid 与三类预算上限计算；
- 无效尾部轮数是最后一次候选改善之后仍执行的反馈轮数；
- 停止后遗憾由停止状态离线回放中最高正价值反馈与已停止结果之差计算；
- 质量—成本曲线同时以 token_cost、tool_cost 和 wall_cost 为横轴报告。

### 8.3 分创新完成检查

- [ ] 核心创新包含去决策变化、去收益和去成本三项消融；
- [ ] 支撑创新一保留自报告、启发式和反事实标签三组；
- [ ] 支撑创新二保留固定轮数、随机停止和仅 Token 预算对照；
- [ ] 四类反馈的工具结果已缓存并被各策略复用；
- [ ] 可从逐轮记录复算校准指标、Valid Improvement@Budget 和停止后遗憾。
