# 信息价值反馈门控：文献依据与创新边界

## 1. 结论

反馈有效性已有充分证据，但“反馈越多越好”并不成立。当前可研究的窄边界是：反馈是否会改变决策，以及这种变化是否值得其 Token 和工具成本。

## 2. 直接证据

| 文献 | 【论文事实】 | 对本框架的启示 |
|---|---|---|
| Compiler-generated Feedback（2024） | 多维反馈提高指令数结果，但边际收益递减，10 次以上多采样可能更优 | 直接支持预算化反馈选择问题 |
| Compiler-R1（2025） | 通过 SFT+RL 学习 thought-tool-feedback | 交互协议和 RL 已覆盖；不使用它作为创新 |
| CompilerGPT（2025） | 编译报告和测试反馈驱动多轮改写 | optimization remark 是直接基线 |
| GraphGlue（2025） | 根因分析、反馈 Agent 和错误策略拒绝 | 反馈路由和拒绝不是空白 |
| SBLLM（2025） | 多轮候选、执行反馈和模式检索 | 必须与增加采样比较 |
| Compiler-Agent Impact（2026） | 最多五轮 GCC 反馈显著提高编译率，但无正确性和性能 | 工具反馈效应应独立测量 |
| Agentic Code Optimization（2026） | 多抽象层 Agent，并分配层间计算预算 | “预算分配”主张发生碰撞 |
| AI Coding Agents Need Better Compiler Remarks（2026） | 精确结构化 remark 提高小模型能力 | 结构化反馈必须作为强基线 |
| Generative Compilation（2026） | 生成过程中在线使用编译器反馈 | 反馈时机已有新近工作 |

## 3. 已经解决的内容

- 编译错误可以帮助修复低级语法和符号错误；
- 测试和性能结果可以形成多轮闭环；
- 多 Agent 可以把分析、生成、测试和引导分开；
- 精确结构化 remark 优于含糊日志；
- 计算预算可以在多个抽象层之间分配；
- 生成期反馈可以早于完整代码生成结束。

## 4. 仍未解决的候选空白

【合理推导】现有工作大多按固定流程决定调用哪些工具，或者研究反馈内容本身；较少直接标注“如果没有这条反馈，下一决策是否仍相同”，也较少把这种反事实变化与最终有效优化和实际成本同时建模。

【候选创新】反事实决策变化反馈价值：只有能改变决策且提高有效优化概率的反馈才产生正价值。

## 5. 最近邻差异

| 方法 | 主要决策 | 本框架额外研究的问题 |
|---|---|---|
| 全量反馈 Agent | 每轮返回全部日志/指标 | 哪条反馈可以不取 |
| 阶段规则路由 | 按失败阶段固定选择工具 | 同一阶段不同反馈价值是否不同 |
| 精确 remark | 改善反馈表达 | 精确反馈是否值得当前成本 |
| 多层预算分配 | 在源码/IR/汇编层之间分配预算 | 单阶段具体反馈的决策变化价值 |
| 生成期反馈 | 在解码中加入编译信息 | 何时请求哪条反馈及何时停止 |

## 6. 不能声称的内容

- 首次使用编译器反馈；
- 首次让 Agent 选择工具；
- 首次控制 Token 或工具预算；
- 首次使用结构化 compiler remark；
- 首次做自适应停止；
- 首次在生成中调用编译器；
- 首次使用小分类器或 LLM 路由器。

## 7. 核心消融要求

- `P(change)`；
- 预期优化增益 `G`；
- Token 成本；
- 工具执行成本；
- 墙钟成本；
- 主动停止；
- 完整日志与精确结构化反馈；
- 固定阶段规则。

## 8. 证据充分程度

- 问题存在证据：高；
- 直接新颖性证据：中；
- 可实现性：高；
- 可证伪性：高；
- 与通用 Agent 路由碰撞风险：中高；
- 当前定位：唯一推荐主线，但必须继续系统检索。

## 9. 待检索关键词

- `counterfactual decision change compiler feedback`
- `value of information code agent tool routing`
- `adaptive stopping compiler optimization LLM`
- `budgeted compiler feedback selection`
- `feedback acquisition function programming agent`

## 10. 边界结论

如果实验只证明“少看日志也能保持效果”，贡献偏工程；只有证明反事实决策变化估计能预测反馈价值，并优于固定阶段规则，才有资格作为方法创新。

## 11. 三项创新的证据边界

| 创新层级 | 【论文事实】已有覆盖 | 【合理推导】研究空白 | 【候选创新】可保留主张 | 证据等级 |
|---|---|---|---|---|
| 核心创新 | Compiler-generated Feedback、Compiler-R1、CompilerGPT 等证明反馈与工具闭环可用 | 准确反馈是否值得获取没有被决策变化和成本共同刻画 | 有益决策变化减多维成本的反馈价值目标 | 中高 |
| 支撑创新一 | 模型自评、最终奖励和阶段启发式已有实现基础 | 缺少同状态逐反馈对照的可观察变化标签 | 无需训练大模型的反事实反馈标注与校准 | 中高 |
| 支撑创新二 | 固定预算、工具路由和停止规则已有近邻 | Token、工具和时间成本与边际价值缺少联合停止闭环 | 三维预算下由价值阈值触发的主动停止 | 中 |

### 11.1 不能声称的内容

- 使用 Agent、调用编译器工具、压缩日志或设置预算本身不是创新；
- 结构化反馈是否准确不是本研究的核心主张；
- 主动停止若只等价于固定阈值规则，只能算工程策略；
- 当前证据支持候选机制，但仍需持续检索 2026 年后续工作。

### 11.2 分创新证伪

1. 核心创新：StageRule 在相同预算下达到同等或更好结果；
2. 支撑创新一：反事实标签的校准和排序能力不优于自报告或阶段启发式；
3. 支撑创新二：三维主动停止节省成本但显著损害有效优化率。
