# 反事实决策变化驱动的信息价值反馈门控：主线研究框架

## 1. 一句话解释

不是把所有编译日志都交给 LLM，而是先判断哪条反馈最可能改变下一步优化决定；如果没有反馈值得花费，就直接执行当前最佳候选或停止。

## 2. 研究对象

研究对象是 LLM 编译优化智能体的**反馈选择策略**，不是 LLM 模型大小、Pass 空间或硬件平台。

可用反馈分四类：

1. `F_compile`：编译诊断；
2. `F_test`：失败输入、预期输出和实际输出差异；
3. `F_remark`：LLVM optimization remark，即编译器说明哪些优化成功或失败的报告；
4. `F_ir`：IR 指令统计、代码大小和优化前后差异。

## 3. 研究空白

【论文事实】编译反馈能改善生成，但多轮反馈存在边际收益递减；复杂 Agent 会固定执行多种工具；精确结构化 remark 已被证明有用。

【合理推导】“反馈是否准确”和“此刻是否值得获取”是两个不同问题。即使一条反馈准确，如果它不会改变下一步动作，就不值得消耗 Token 和工具时间。

【候选创新】把反馈价值定义为：获得反馈后决策改变并提高有效优化概率的预期收益，减去反馈成本。

## 4. 输入状态、处理动作和输出

### 4.1 状态

```text
s = <program_summary, candidate, stage, observed_evidence,
     remaining_budget, action_distribution>
```

- `program_summary`：程序结构摘要；
- `candidate`：当前优化动作或代码候选；
- `stage`：未编译、编译失败、测试失败、正确但无收益、已有收益；
- `observed_evidence`：已经看到的反馈；
- `remaining_budget`：剩余 Token、工具调用和时间；
- `action_distribution`：LLM 对下一步动作的偏好或不确定性。

### 4.2 门控动作

- 请求一种反馈；
- 执行当前候选；
- 生成下一候选；
- 接受当前最优候选；
- 停止任务。

### 4.3 输出

- 每轮选择的反馈或停止动作；
- 反馈价值估计；
- 修改后的候选；
- 编译、测试和静态收益；
- 全轨迹 Token、工具和时间成本。

## 5. 核心价值函数

```text
VOI(f|s) = P(change|f,s) × G(f,s) - λt·TokenCost(f)
           - λe·ExecutionCost(f) - λw·WallTime(f)
```

- `P(change|f,s)`：获得反馈 `f` 后，下一动作或候选排序改变的概率；
- `G(f,s)`：改变决策后提高有效优化概率的估计收益；
- `TokenCost`：反馈进入上下文的 Token；
- `ExecutionCost`：需要多少次编译、测试或分析；
- `WallTime`：实际耗时；
- `λt、λe、λw`：不同成本的权重。

若所有反馈的 `VOI≤τ`，系统选择执行、接受或停止。`τ` 是停止阈值。

## 6. 反事实决策变化怎样测量

预实验不需要训练门控模型。对同一个状态离线构造：

```text
原状态 → LLM 给出下一动作 A0
原状态 + 编译反馈 → A_compile
原状态 + 测试反馈 → A_test
原状态 + remark → A_remark
原状态 + IR统计 → A_ir
```

若 `A_f` 与 `A0` 在动作类型、位置或候选排序上发生实质变化，则记录 `change=1`。再检查这种变化是否产生有效优化，构成反馈价值标签。

## 7. 在线闭环

```text
初始程序与候选
      ↓
LLM 给出动作与不确定性
      ↓
门控器计算四类反馈 VOI
      ↓
选择最高价值反馈 / 执行 / 停止
      ↓
更新状态与剩余预算
      ↓
编译、测试、静态收益验收
```

## 8. 小白化例子

候选程序编译失败。完整日志有 5000 个 Token，但真正错误是“函数名未定义”。固定全量反馈会把全部日志发送给 LLM；阶段规则会发送精简编译错误；价值门控进一步判断：当前动作只涉及一个属性参数，错误与优化策略无关，局部符号反馈足够改变参数，不需要请求 IR 统计和 optimization remark。

## 9. 可检验研究问题

- RQ1：哪类反馈最常真正改变下一步决策？
- RQ2：决策变化是否提高有效优化概率？
- RQ3：VOI 门控是否优于固定阶段规则？
- RQ4：主动停止能否减少无效轮次而不降低有效优化率？
- RQ5：门控器是否能迁移到未见程序和第二个 LLM？

## 10. 假设

- H1：VOI 门控的 Valid Improvement@Budget 高于全量反馈和阶段规则。
- H2：VOI 门控的平均 Token、工具调用和首次有效优化时间更低。
- H3：`P(change)` 与真实决策变化正相关，且变化与有效优化正相关。
- H4：去掉成本项或停止动作后，单位成本收益下降。

## 11. 候选论文贡献

1. 提出面向 LLM 编译优化的反馈价值定义，将决策变化、优化收益和多种成本放在同一门控目标中；
2. 提出反事实反馈标注方法，在不训练大模型的情况下测量某条反馈是否真正改变决策；
3. 在同模型、同任务、同总预算下比较全量反馈、随机反馈、阶段规则和价值门控。

## 12. 可证伪条件

固定阶段规则达到相同结果、决策变化与有效优化无关、或门控节省成本但显著损害质量时，核心主张不成立。

## 13. 一个核心创新与两个支撑创新

三个创新构成“目标函数—标签来源—在线策略”因果链。核心创新定义反馈价值，支撑创新一提供可复现监督信号，支撑创新二将价值用于多维预算下的实际选择与停止。

### 13.1 核心创新：反事实决策变化驱动的反馈价值模型

【论文事实】编译反馈、结构化 remark、工具调用 Agent 和预算搜索均已有研究。

【合理推导】反馈准确不等于反馈值得获取；若一条反馈不会改变下一动作或候选排序，它可能只增加 Token 和工具成本。

【候选创新】把反馈价值定义为“改变决策并提高有效优化概率的预期收益”减去 Token、工具调用和墙钟时间成本。

- 输入：程序状态、当前候选、已有证据、动作分布和剩余预算；
- 处理：估计决策变化概率、有益变化收益和三类成本；
- 输出：每类反馈的价值、最高价值动作以及执行或停止决定；
- 本质变化：反馈选择目标从信息量或固定阶段规则变为单位成本的有益决策变化；
- 专属消融：去掉决策变化项、去掉收益项、去掉成本项；
- 专属指标：Valid Improvement@Budget、单位成本有效优化数、质量—成本曲线面积；
- 证伪条件：固定阶段规则同等或更好，或决策变化与有效优化无关。

### 13.2 支撑创新一：无需训练大模型的反事实反馈标注与校准

【论文事实】已有方法可让模型评价反馈或直接使用最终奖励。

【合理推导】模型自报告“有用”不是可观察标签，最终奖励也无法区分是哪一种反馈改变了决策。

【候选创新】对同一状态分别不提供反馈和加入编译诊断、测试差异、optimization remark、IR 统计，记录动作类型、修改位置或排序是否变化，再验证变化是否带来有效优化。

- 输入：同一状态及四类可缓存反馈；
- 处理：成对查询、动作归一化、变化判定、真实结果验证和概率校准；
- 输出：change 标签、beneficial_change 标签和反馈类型校准表；
- 本质变化：把抽象反馈有用性转成同状态可重复观察的反事实标签；
- 专属消融：模型自报告标签、启发式阶段标签、反事实标签；
- 专属指标：Brier Score、AUROC、Average Precision 和决策变化后有效率；
- 证伪条件：标签不能预测真实变化，或变化标签与最终收益没有关联。

### 13.3 支撑创新二：多维预算约束的反馈选择与主动停止

【论文事实】固定轮数、Token 上限和停止阈值本身均不是创新。

【合理推导】只控制 Token 会忽略编译、测试和分析工具的执行成本；固定轮数无法适应任务剩余价值。

【候选创新】联合跟踪 Token、工具调用和墙钟时间；当所有反馈的预测价值低于阈值时，在执行当前候选、接受当前最优或主动停止之间选择。

- 输入：反馈价值、三类剩余预算和当前最优候选；
- 处理：预算可行性过滤、边际价值排序和停止判定；
- 输出：反馈选择、执行、接受或 STOP 及停止原因；
- 本质变化：停止由剩余预算和预期边际收益共同触发，而不是固定轮数；
- 专属消融：固定轮数、随机停止、仅 Token 预算、三维预算主动停止；
- 专属指标：首次有效优化成本、无效尾部轮数、停止后遗憾和质量—成本曲线面积；
- 证伪条件：主动停止显著降低有效优化率，或固定轮数得到同等质量—成本表现。

### 13.4 统一数据流与假设

状态与候选 → 构造反事实反馈标签 → 校准变化概率 → 计算反馈价值 → 选择反馈或主动停止 → 编译、测试和收益验收 → 更新校准记录。

- H1：完整价值模型相对固定阶段规则提高 Valid Improvement@Budget；
- H2：反事实标签相对自报告和启发式标签具有更好的 Brier Score、AUROC 或 Average Precision；
- H3：三维预算主动停止相对固定轮数减少无效尾部轮次，同时不显著降低有效优化率；
- H4：完整系统的收益不能由更长上下文、更多工具调用或更多候选解释。
