# 正确性门控的配对边际效用反馈获取：完整实验设计

## 1. 实验目标

验证 `VOIGate` 是否能在相同任务、模型和预算下，比固定阶段规则、直接收益预测以及预算匹配的额外候选采样，获得更多正确且有效的优化。

## 2. 首轮任务定义

### 2.1 输入

- 可独立编译的 C/C++ 函数；
- 固定测试驱动；
- 输入范围和类型约束；
- 固定 Clang/LLVM 版本与编译选项；
- 未优化或可进一步优化的基准实现。

### 2.2 输出

- 结构化优化动作；
- 源码补丁；
- 候选排序；
- 模型置信度或多采样一致率。

### 2.3 首轮不包含

- LLVM IR 直接生成；
- Pass 序列搜索；
- 汇编重写；
- 多平台联合训练；
- 多智能体协同作为独立变量。

## 3. 正确性与收益定义

### 3.1 正确性门控

候选只有同时满足以下条件才记为有效：

```text
compile_ok
AND fixed_tests_ok
AND differential_tests_ok
AND sanitizer_ok
```

对 LLVM IR 扩展实验，可额外加入 Alive2 等价性验证。任何未通过正确性门控的候选，静态指标或运行速度再好也记为无效。

### 3.2 预实验主收益

预注册一个静态目标，不在结果出来后切换：

- LLVM IR 指令数下降比例，或
- 固定编译选项下的代码大小下降比例。

```text
ValidStaticImprovement
= correctness_ok AND gain >= epsilon_static
```

### 3.3 完整实验性能收益

对所有方法的最终正确 Top-1 候选进行运行时间测量，不能只测静态改善者，以避免筛选偏差。

```text
ValidRuntimeImprovement
= correctness_ok AND runtime_gain statistically positive
```

静态收益和运行时间分别报告，不合并成单一加权分数。

## 4. 实验单元与数据切分

实验单元：

```text
程序任务 × 反馈策略 × 解码种子
```

数据规模采用逐级放大：

- P0 筛选：10 个函数，20–30 个代表状态，每个状态只测试一种当前可用真实反馈；
- P1 确认：20 个函数，40–80 个代表状态，扩展到四类反馈和至少 3 个配对种子块；
- 完整实验：60–120 个函数，最终数量根据预实验效应估计调整；
- 程序家族：循环、分支、内存访问、函数调用、整数运算、混合模式；
- 按程序家族切分开发、校准、测试；
- 预留一个完全未见家族；
- 同一程序产生的不同状态不得跨训练集和测试集。

## 5. 反馈生成器与依赖图

| 反馈 | 可用条件 | 内容 | 增量成本组成 |
|---|---|---|---|
| Compile | 编译失败或警告 | 首个根因、位置、类别 | 尚未支付的编译 + 摘要 + 新增 Token |
| Test | 编译成功且测试失败 | 失败输入与输出差异 | 尚未支付的前置步骤 + 执行 + 摘要 + 新增 Token |
| Remark | 编译成功 | 成功/失败优化及原因 | 新增 remark 生成/解析 + 新增 Token |
| IR | 编译成功 | 指令类别、大小、局部 diff | 新增 IR 生成/分析 + 新增 Token |

所有方法使用同一个反馈生成器、摘要器和版本。

### 缓存公平性

反馈可以预先缓存以降低重复实验开销，但：

1. 策略仍按真实获取链路扣除 Token、工具和墙钟成本；
2. 门控器在选择前不能读取缓存反馈内容；
3. 不可用反馈不得进入候选集合；
4. 缓存结果只用于复现，不改变在线决策信息。

### 增量成本账本

每个实际工具事件只登记一次，并标记为：

- `unpaid_prerequisite`：当前状态尚未完成的前置步骤；
- `feedback_generation`：生成和解析反馈本身；
- `context_tokens`：反馈加入 Prompt 后新增的 Token；
- `new_validation`：反馈动作额外触发的验证；
- `wall_time`：上述事件的实测端到端耗时。

工具次数和墙钟是两个并列预算维度，不把 `wall_time` 再折算成工具次数；已完成或已计费的编译不得在 `prerequisite` 中重复扣费。

## 6. 配对控制标注阶段

对同一状态构造：

- `N0`：无新增反馈；
- `N1`：无新增反馈复测，使用预注册的另一 seed；
- `P1/P2/P3`：按反馈类型匹配、来自其他任务的置换安慰剂；
- `C/T/R/I`：四类真实反馈。

固定或匹配：

- 模型版本；
- Prompt；
- temperature、top_p；
- 配对种子块编号；
- 最大输出长度；
- 结构化输出格式。

记录：

- 动作类型、位置、参数和排序变化；
- correctness；
- gain；
- `DeltaUtility`；
- Token、工具和时间成本。

同一 seed 在不同 Prompt 下不被视为严格确定性配对。P0 使用预注册的固定种子方案估计是否存在信号；P1 和完整实验至少使用 3 个配对种子块，以状态为配对单位估计结果分布。安慰剂匹配长度、格式、语气、数值密度与类别外观，并进行任务线索泄漏检查。

训练首版规则、逻辑回归或成对排序器，不训练大模型。只有 P1 数据量和交叉验证稳定性足够时才使用梯度提升树；不得用复杂模型掩盖稀疏、零膨胀的效用标签。

## 7. 在线策略

### 7.1 基础基线

1. `NoFeedback`：不读取工具反馈；
2. `AllFeedback`：返回所有当前可用反馈；
3. `RandomOne`：随机选择一种可用反馈；
4. `CheapestFeedback`：选择预计总成本最低的反馈；
5. `StageRule`：按失败阶段使用固定反馈；
6. `UncertaintyOnly`：不确定性低则执行，高则请求默认阶段反馈。

### 7.2 核心对照

7. `DirectGain`：只预测 `E[U(a_f) | s,f]`，不减去同状态无反馈基准；
8. `VOIGate`：预测配对边际效用并扣除未支付增量成本；
9. `VOIGate-NoStop`：相同门控但不允许主动停止；
10. `BudgetMatchedSampling`：使用与 VOIGate 相同总预算，把节省部分用于额外候选采样；
11. `OracleFeedback`：离线选择真实单位成本收益最高的反馈，仅作上界，不参与可部署性比较。

`StageRule`、`DirectGain` 和 `BudgetMatchedSampling` 是决定论文主张能否成立的三个最重要基线。

## 8. 预算设置

每个任务分别设置：

- 输入 Token 上限；
- 输出 Token 上限；
- LLM 调用次数；
- 编译次数；
- 测试次数；
- remark/IR 分析次数；
- 总墙钟时间；
- 最大轮数和候选数。

任何方法达到任一上限即停止，不允许用其他预算补偿。

所有策略在同一状态上必须看到相同的 `available_feedback_mask`，并共享相同的缓存证据集合。反馈只在对所有策略都满足同一可用条件时进入比较，避免因反馈可用性不同造成选择偏差。

### 等预算原则

比较 `VOIGate` 与 `BudgetMatchedSampling` 时，至少报告两种匹配：

1. 相同总 Token；
2. 相同工具调用和墙钟上限。

## 9. 主要指标

### 9.1 任务级指标

```text
Valid Improvement@B
= 在预算 B 内获得至少一个有效优化的任务数 / 总任务数
```

分别报告：

- `ValidStaticImprovement@B`；
- `ValidRuntimeImprovement@B`。

### 9.2 成本指标

- 首次有效优化的输入/输出 Token；
- 首次有效优化的编译、测试和分析调用；
- 首次有效优化墙钟时间；
- 无效尾部轮数；
- 每个有效任务的原始成本。

不只报告加权成本，必须展示各组成部分。

### 9.3 门控与校准指标

- Brier Score；
- AUROC；
- Average Precision；
- reliability diagram；
- decision-change rate；
- beneficial-change rate；
- `DeltaUtility` 的排序相关；
- 各反馈类型和阶段的分层结果。

### 9.4 质量—成本曲线

分别以 Token、工具调用和墙钟时间为横轴，报告：

- Valid Improvement 曲线；
- 曲线下面积；
- Oracle gap。

## 10. 决策变化判定

结构化比较：

```text
C1 = action_type changed
C2 = target changed
C3 = key parameter changed
C4 = candidate ranking changed
```

预注册离散规则和连续 `change_score`。仅解释变化、措辞变化或格式变化不计入。

报告以下错误：

- 变化但无收益；
- 无明显变化但收益提高；
- 安慰剂引起变化；
- 无反馈复测自然变化；
- 高价值误判；
- 低价值漏判。

## 11. 消融

### 11.1 核心价值模型

- 去掉 decision-change 辅助项；
- 去掉 ExpectedGain；
- 去掉 Token 成本；
- 去掉工具执行成本；
- 去掉墙钟成本；
- 去掉未支付前置依赖成本；
- 仅使用阶段特征；
- 直接收益预测替代完整模型。

### 11.2 配对控制标签

- 无反馈复测控制；
- 去掉安慰剂控制；
- 只使用单一安慰剂；
- 模型自报告“反馈有用”；
- 阶段启发式标签；
- 普通 change 标签；
- beneficial-change / DeltaUtility 标签。

### 11.3 停止策略

- 固定轮数；
- 匹配平均轮数的随机停止；
- 仅 Token 阈值；
- 三维成本阈值；
- 完整 VOI 主动停止。

## 12. 停止后遗憾

停止后用离线回放测量一步真实遗憾：

```text
OneStepStopRegret(s)
= max_f RealizedOneStepUtility(f | s) - Utility(stop | s)
```

不得用门控器自己的预测值证明停止正确。若无法计算完整后续轨迹，应明确该指标仅是“一步遗憾”。

## 13. 统计分析

- 任务级配对 bootstrap 95% 置信区间；
- 成败差异使用 McNemar 检验；
- 连续边际效用使用状态级配对 bootstrap 或配对置换检验；
- 成本报告中位数、四分位距和配对差值；
- 多重比较使用 Holm 校正；
- 按程序家族、反馈类型和阶段分层；
- 报告最坏 10% 任务；
- P1 与完整实验至少 3 个配对种子块，并将种子作为区组而非独立任务；P0 可使用固定种子方案，但只能做信号筛选；
- 门控器使用按程序分组的交叉拟合或开发/校准/测试三分法，禁止在训练标签上报告门控性能；
- 根据预实验中 StageRule 与 VOIGate 的不一致成功比例估计完整实验样本量。

## 14. 运行时间测量

对所有策略的最终正确 Top-1 候选计时：

- 固定 CPU 频率或记录频率状态；
- 预热至少 3 次；
- 正式运行至少 10 次；
- 随机化候选执行顺序；
- 报告中位数和置信区间；
- 记录系统负载与异常值处理规则；
- 不只测静态改善候选。

RISC-V 外部验证使用同一测试和统计流程，单独报告，不与主平台数据混合训练。

## 15. 成功与放弃门槛

### 继续扩大实验

- 真实反馈的配对边际效用和 beneficial-change rate 高于控制组；
- VOIGate 不弱于 StageRule 且至少一种成本明显下降；
- VOIGate 优于 DirectGain 或显示稳定额外价值；若仅相当，则删除“边际目标优于直接预测”的主张；
- VOIGate 不被 BudgetMatchedSampling 替代；
- 主动停止降低无效尾部轮数且不明显损害有效率。

### 降级为工程结果

- 只优于 AllFeedback；
- 主要收益来自日志压缩或更短上下文；
- StageRule 基本相同；
- 配对无反馈基准没有额外选择价值。

### 放弃主线

- 安慰剂与真实反馈同样有效；
- DirectGain、StageRule 或 BudgetMatchedSampling 显著更优；
- 正确性门控后收益消失；
- 过早停止造成明显质量损失。

## 16. 复现材料

保存并版本化：

- 任务清单和切分；
- 测试驱动与随机输入生成器；
- 编译器、Sanitizer 和平台信息；
- Prompt、结构化输出 schema；
- 原始模型响应；
- 每轮状态、候选和反馈；
- 反馈缓存及其不可见性规则；
- 成本记账；
- 随机种子；
- 统计脚本和图表生成脚本。
