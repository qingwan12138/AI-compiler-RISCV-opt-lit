## 3. 配对控制表

每个 `state_id` 至少保留：

| condition | 含义 |
|---|---|
| N0 | 无新增反馈基准 |
| N1 | 无新增反馈复测，使用预注册的另一 seed 估计自然随机变化 |
| P1/P2/P3 | 按反馈类型匹配、来自其他任务的置换安慰剂 |
| C | 编译反馈 |
| T | 测试反馈 |
| R | optimization remark |
| I | IR 统计 |

控制组与真实反馈组必须记录相同的结构化动作和正确性结果。P1 和完整实验至少记录 3 个 `paired_seed_block`；种子块是区组，不是独立任务。

### 增量成本事件表

| event_id | state_id | 事件类型 | 是否此前已支付 | 工具调用增量 | Token增量 | 墙钟增量 | 被哪些策略使用 |
|---|---|---|---|---:|---:|---:|---|
| | | unpaid_prerequisite / feedback_generation / context / new_validation | | | | | |

## 7. 关键错误分析

| 类型 | 定义 | 数量 | 代表任务 | 修正方向 |
|---|---|---:|---|---|
| 自然变化误判 | N0/N1 不同但无真实反馈 | | | |
| 安慰剂扰动 | P1/P2/P3 引起变化或收益 | | | |
| 高价值误判 | 预测高 VOI 但无有益增量 | | | |
| 低价值漏判 | 预测低 VOI 但真实有益 | | | |
| 有变化无收益 | 决策变化但正确性或收益失败 | | | |

| 过早停止 | 停止后存在正的一步真实效用 | | | |

## 8. 指标复算

### Brier Score

使用预测概率与对应二元标签计算：

- `p_change` 对 `change`；
- `p_beneficial_change` 对 `beneficial_change`。

### Realized DeltaUtility

```text
realized_delta_utility
= realized_utility_with_feedback - utility_without_new_feedback
```

### Valid Improvement@B

按任务级结果计算，不把同一任务的多个候选当作独立样本。

### 无效尾部轮数

最后一次当前最优候选得到改善以后，仍继续进行且未产生改善的反馈轮数。

### 一步停止后遗憾

```text
one_step_stop_regret
= max(realized_utility_of_available_feedback)
  - utility_of_stop_action
```

### Oracle gap

```text
oracle_gap
= Oracle ValidImprovement@B - Strategy ValidImprovement@B
```

## 9. 完成检查

### 公平性

- [ ] 所有策略使用相同反馈生成器和摘要器；
- [ ] 缓存仅用于复现，选择前不可见；
- [ ] 选择反馈后按真实链路成本扣费；
- [ ] 不可用反馈未进入候选集合；
- [ ] 所有策略使用相同模型、Prompt 和预算；
- [ ] BudgetMatchedSampling 完成 Token 和工具两种预算匹配。

### 正确性

- [ ] 编译通过；
- [ ] 固定测试通过；
- [ ] 随机差分测试通过；
- [ ] Sanitizer 通过；
- [ ] IR 扩展实验使用 Alive2 时单独记录；
- [ ] 任何正确性失败未计为收益。

### 配对控制

- [ ] 同状态包含 N0 和 N1；
- [ ] 每类反馈准备 2–3 个任务置换安慰剂；
- [ ] 安慰剂长度、格式、语气和数值密度匹配；
- [ ] 安慰剂通过任务线索泄漏检查；
- [ ] seed block、temperature、Prompt 和输出 schema 可复现；
- [ ] P1 和完整实验至少包含 3 个配对种子块；
- [ ] 同一程序的状态未跨训练测试切分；
- [ ] decision change 与 beneficial change 分开记录。

### 成本审计

- [ ] 每个工具事件具有唯一 `cost_event_id`；
- [ ] 只扣除当前状态尚未支付的前置成本；
- [ ] 已完成编译未在 execution 和 prerequisite 中重复计费；
- [ ] Token、工具调用和墙钟分别报告；
- [ ] 所有策略使用相同 `available_feedback_mask` 和缓存证据集合。

### 论文主张

- [ ] StageRule 完整运行；
- [ ] DirectGain 完整运行；
- [ ] BudgetMatchedSampling 完整运行；
- [ ] Oracle 上界已计算；
- [ ] 去 decision change、收益、成本和停止消融已完成；
- [ ] 未只报告加权成本；
- [ ] 未把静态指标直接等同于运行时间；
- [ ] 未把 RISC-V 外部验证写成训练贡献。
- [ ] 未把配对控制估计写成严格因果效应。
