# 可验证结构化编辑驱动的 LLM 编译优化器：材料索引

## 1. 框架定位

本方向研究如何把 LLM 的自由代码改写收缩为带前提、目标位置、预期效果和失败定位的局部编辑契约，从而在同等生成预算下提高正确且有静态收益的候选比例。

定位：**低开销保底方向，也可作为信息价值反馈主线的安全执行器。**

## 2. 文件说明

| 文件 | 用途 |
|---|---|
| `01_主线研究框架.md` | 研究问题、核心机制、输入处理输出、假设和贡献 |
| `02_文献依据与创新边界.md` | 2024—2026 年近邻证据、碰撞和不能声称的内容 |
| `03_完整实验框架.md` | 数据、基线、预算、公平性、消融、统计和可证伪条件 |
| `04_预实验Demo.md` | 10 个函数即可启动的最小实验流程 |
| `05_数据记录与评价模板.md` | JSONL 字段、运行记录、结果表和异常记录模板 |

## 3. 推荐阅读顺序

先读 `01` 判断研究问题是否符合目标，再读 `02` 判断新颖性风险，然后按 `04` 做 Demo。只有 Demo 显示有效优化率提高，才执行 `03` 的完整实验。

## 4. 第一阶段成功标准

- 完整编辑契约的编译成功率和测试通过率高于自由改写；
- 在相同 Token 和候选数量下，有效优化率高于普通 JSON 输出；
- 去掉前提或失败定位后效果下降；
- 少量运行时间复核没有出现大面积静态收益、真实退化的情况。

## 5. 重要边界

结构化输出、RAG、编译器验证和局部 Hint 已有近邻。核心候选创新只能是：

> 将局部动作、适用前提、预期编译证据和失败后的最小修复位置绑定为一个可执行、可消融的编辑契约。
