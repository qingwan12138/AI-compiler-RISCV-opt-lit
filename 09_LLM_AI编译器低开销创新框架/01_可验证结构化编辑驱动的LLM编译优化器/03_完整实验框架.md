# 可验证结构化编辑框架：完整实验设计

## Material Passport

- Origin Skill: experiment-agent
- Origin Mode: plan
- Origin Date: 2026-07-19
- Verification Status: UNVERIFIED
- Version Label: structured_edit_plan_v1

## 1. 实验目标

检验局部编辑契约是否在固定模型和预算下提高正确且有静态收益的候选比例，并判断收益来自哪个契约字段。

## 2. 变量

### 自变量

生成协议：自由改写、普通 JSON、完整编辑契约及各项消融。

### 因变量

- 编译成功率；
- 测试通过率；
- 有效优化率；
- IR 指令数和目标代码大小变化；
- 首次有效优化 Token、轮数和时间；
- 修改行数及无关编辑比例。

### 控制变量

LLM、温度、最大 Token、提示示例、任务集合、候选数量、编译器版本、测试输入、动作集合和运行顺序。

## 3. 数据集

### 预实验

- 10 个函数；
- 循环、分支、内存访问、函数调用各至少 2 个；
- 每个函数有确定性测试输入和参考输出。

### 完整实验

- 40—100 个函数；
- 按程序家族划分训练示例、开发集和测试集；
- 同一算法的参数变化版本不能跨训练/测试泄漏。

## 4. 动作空间

首版只开放 8—15 个容易执行的局部动作，例如：

- 循环展开因子；
- 内联/禁止内联属性；
- 循环向量化或展开提示；
- 局部常量传播式重写；
- 冗余表达式替换；
- 安全的代数简化；
- 编译器已知属性的插入或删除。

动作必须由固定执行器实现，LLM 不直接修改任意文本。

## 5. 实验组

| 组 | 方法 | 作用 |
|---|---|---|
| B0 | 单轮自由源码改写 | 简单基线 |
| B1 | 自由改写 + 编译错误反馈 | 反馈基线 |
| B2 | 普通 JSON 动作 | 结构化输出强基线 |
| B3 | 受限动作 + 固定模板 | 排除 LLM 结构化能力影响 |
| M | 完整编辑契约 | 候选方法 |

## 6. 预算公平

每个任务、每个方法固定：

- 最多 5 个候选；
- 最多 2 次修复；
- 相同总输入/输出 Token 上限；
- 相同编译和测试次数；
- 相同可见静态分析信息。

若某方法提前停止，剩余预算不能转给其他任务。

## 7. 正确性和收益门控

1. Schema 通过；
2. 前提检查通过；
3. 编译通过；
4. 全部测试通过；
5. 可选 UBSan/ASan 不报错；
6. 目标静态指标改善；
7. 每种方法 Top-1 进入运行时间复核。

## 8. 评价指标

```text
CompileRate = 编译通过候选 / 全部候选
TestRate = 测试通过候选 / 编译通过候选
ValidOptimizationRate = 正确且静态改善候选 / 全部候选
```

```text
IRGain = (IR_base - IR_candidate) / IR_base
SizeGain = (Size_base - Size_candidate) / Size_base
```

同时报告首次有效优化的 Token、工具调用、轮数和秒数。

## 9. 消融实验

- `M - Preconditions`；
- `M - ExpectedEvidence`；
- `M - FailureScope`；
- `M - SchemaValidation`；
- 完整契约但随机化失败定位；
- 完整契约但允许整函数修改。

## 10. 统计分析

- 对同一任务的方法结果做配对分析；
- 二元成功指标使用 McNemar 检验或配对 bootstrap 置信区间；
- IR/大小变化报告中位数、四分位距和 bootstrap 95% 置信区间；
- 多方法比较做 Holm 校正；
- 同时报告效应量，不能只报告 `p` 值；
- 每个随机生成设置至少使用 3 个种子，或明确固定解码的局限。

## 11. 运行时间复核

- 只测每种方法每任务的 Top-1；
- 固定核心、输入和 governor；
- 预热 3 次，正式运行至少 10 次；
- 随机化方法顺序；
- 报告中位数和 bootstrap 95% 置信区间；
- 置信区间跨 1.0 的加速不记为明确收益。

## 12. 威胁与缓解

- 测试不完整：增加差分输入和 Sanitizer；
- 静态指标失真：Top-1 运行时间复核；
- 动作空间优势：B2/B3 使用相同动作集合；
- Token 长度差异：同时做等 Token 和等候选两种预算分析；
- 数据泄漏：按程序家族切分；
- 模型依赖：第二模型只做小规模趋势复核。

## 13. 成功标准

完整契约相对 B2：

- 有效优化率方向上提高，且置信区间不主要由单个任务驱动；
- 首次有效优化成本不增加；
- 至少一个核心字段消融导致明显退化；
- Top-1 运行时间复核未出现系统性负优化。

## 14. 可证伪条件

若 B2/B3 达到同等结果，或者契约只提高编译率却降低有效优化率，则核心机制不成立。

## 15. 三项创新的独立实验映射

### 15.1 核心创新：效应绑定契约

| 组别 | 方法 | 验证目的 |
|---|---|---|
| C0 | 自由改写 | 简单基线 |
| C1 | 等长度、等动作空间普通 JSON | 排除结构化和短输出解释 |
| C2 | 完整效应绑定契约 | 完整核心机制 |

主要指标：有效优化率、契约执行成功率、无关修改行数。若 C2 不优于 C1，核心创新被否定。

### 15.2 支撑创新一：双向可执行验证

| 组别 | 前提检查 | 预期证据检查 | 验证目的 |
|---|---:|---:|---|
| V0 | 否 | 否 | 仅编译测试验收 |
| V1 | 是 | 否 | 无预期证据检查，测量执行前约束贡献 |
| V2 | 否 | 是 | 无前提检查，测量执行后效应贡献 |
| V3 | 是 | 是 | 完整双向验证 |

主要指标：不适用动作率、无效动作率、预期效应命中率。V3 必须相对 V0 降低无效动作，且 V1、V2 至少各解释一种失败。

### 15.3 支撑创新二：责任定位与局部修复

| 组别 | 修复策略 | 验证目的 |
|---|---|---|
| R0 | 完整重生成 | 强反馈基线 |
| R1 | 无责任定位的局部修复 | 排除“只是改得少” |
| R2 | 带责任定位的字段级修复 | 完整支撑机制 |

主要指标：修复 Token、首次有效优化轮数、无关修改行数、错误复发率。R2 若不能降低成本或增加了无法恢复的修复失败，应降级。

### 15.4 公平性、统计和联合消融

- 固定模型、提示示例、动作空间、候选数、最大反馈轮数和 Token 预算；
- 对同一函数使用配对比较，报告中位数差、bootstrap 置信区间和失败类型分层；
- 联合消融依次移除责任定位、预期证据、前提检查，再与普通 JSON 比较；
- Top-1 运行时间使用 warm-up 后多次重复，报告中位数、方差或置信区间；
- 若收益只来自更多编译器知识、更多候选或更长上下文，不支持三项创新主张。
