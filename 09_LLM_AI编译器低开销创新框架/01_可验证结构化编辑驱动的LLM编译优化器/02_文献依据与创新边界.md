# 可验证结构化编辑框架：文献依据与创新边界

## 1. 结论

结构化生成领域已经拥挤。本框架不能声称首次使用结构化输出、规则、Hint、编译器反馈或验证器。其候选空间只剩“效应绑定 + 局部失败定位”的可执行契约。

## 2. 主要证据

| 文献 | 【论文事实】已覆盖内容 | 对本框架的边界 |
|---|---|---|
| Compiler-generated Feedback（2024） | Pass、编译和指令数反馈驱动多轮修正 | 编译反馈不是创新 |
| Code the Transforms（2024） | LLM 生成可执行变换器并用反例修正 | 生成规则或变换器不是创新 |
| Compiler-R1（2025） | LLM 输出工具调用和 Pass 序列，使用 SFT+RL | 结构化工具协议和 Agent 已覆盖 |
| CompilerGPT（2025） | 编译优化报告驱动源码改写 | 从 remark 到改写已有直接基线 |
| GraphGlue（2025） | 日志根因定位、修复和拒绝错误策略 | 失败定位本身已有近邻 |
| IntOpt（2026） | 意图形成、细化、实现、验证三阶段 | 高层意图到可执行动作已覆盖 |
| HintPilot（2026） | 文档约束、合法插入点、Hint 合成和 profiling | 安全动作空间和位置级控制已覆盖 |
| Generative Compilation（2026） | 生成过程中提供在线编译反馈 | 在线验证已出现直接近邻 |

## 3. 研究空白推导

【论文事实】上述方法分别验证结构、动作、正确性或性能，但失败常按候选或整轮处理。

【合理推导】若一个结构化动作中的一个参数错误，整轮重生成会增加 Token，并可能破坏其他正确决策。若结构化动作没有声明预期证据，也无法判断动作是否按预期产生效果。

【候选创新】把适用前提、局部动作、预期证据和失败字段绑定，并只允许修复被确定性工具指出的字段。

## 4. 最接近工作比较

| 维度 | HintPilot | IntOpt | Code the Transforms | 本框架 |
|---|---|---|---|---|
| 输出 | Hint 组合 | 高层意图和 IR 动作 | 可执行变换器 | 局部编辑契约 |
| 前提 | 文档和插入位置 | 静态分析/知识库 | 测试反例 | 显式机器字段 |
| 预期效应 | 以最终 profiling 为主 | 意图级目标 | 变换精确性 | 每个动作的证据断言 |
| 失败处理 | 迭代生成 | 返回细化或意图阶段 | 反例修正 | 定位到字段和值域 |
| 关键实验 | 加速 | 正确性与加速 | 规则精确性 | 等预算有效优化率与局部修复成本 |

## 5. 不能声称的内容

- 不能声称首次让 LLM 生成编译器动作；
- 不能声称首次使用 JSON、DSL 或语法约束；
- 不能声称首次加入前提检查或编译器反馈；
- 不能声称首次使用局部 Hint；
- 不能声称首次在线验证生成结果；
- 不能把 LLVM 或 RISC-V 目标替换当成创新。

## 6. 必须完成的消融

1. 完整契约；
2. 去掉前提字段；
3. 去掉预期证据字段；
4. 去掉失败定位，失败后整轮重生成；
5. 仅 JSON Schema，不执行语义字段；
6. 保持动作空间和输出长度相近的受限自由文本。

## 8. 当前推荐等级

- 新颖性：3/5；
- 可实现性：5/5；
- 实验可验证性：5/5；
- 时间开销：低；
- 综合定位：保底方向或主线执行器，不作为当前唯一推荐论文主线。

## 9. 三项创新的证据边界

| 创新层级 | 【论文事实】已有覆盖 | 【合理推导】研究空白 | 【候选创新】可保留主张 | 证据等级 |
|---|---|---|---|---|
| 核心创新 | Code the Transforms、HintPilot、IntOpt 已涉及结构化变换、Hint 或优化意图 | 结构化输出没有保证动作、效应与验收共同执行 | 效应绑定的局部编辑契约 | 中低 |
| 支撑创新一 | 编译、测试、验证器和 optimization remark 已用于反馈 | 前提成立和预期效应出现通常被分开处理 | 前提—预期证据双向验收 | 中 |
| 支撑创新二 | 多轮反馈和错误修复已有充分近邻 | 完整重生成难定位责任并产生无关修改 | 失败到契约字段的责任映射与受限修复 | 中 |

### 9.1 不能声称的内容

- JSON、局部 Hint、AST 修改器或 LLVM 工具本身不是创新；
- 编译成功率提高不能单独证明“效应绑定”有效；
- 字段级修复若只依赖更短输出，只能作为工程优化；
- 当前文献证据不足，需要继续查找相关研究，不能直接声称这是确定创新。

### 9.2 分创新证伪

1. 核心创新：等长度、等动作空间普通 JSON 达到同等有效优化率；
2. 支撑创新一：删除前提或预期证据检查没有带来可测退化；
3. 支撑创新二：完整重生成在相同预算下成本和质量不差于字段修复。
