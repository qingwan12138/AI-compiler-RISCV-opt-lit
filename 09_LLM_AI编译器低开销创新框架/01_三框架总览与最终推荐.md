# 三套低开销 LLM AI 编译器框架总览与最终推荐

> 分析日期：2026-07-19
>
> 证据范围：本地 2024—2026 年 LLM 编译器逐篇阅读总结；2026-07-19 针对直接近邻进行补充检索
>
> 结论状态：候选研究设计，不等同于已经证实的新颖性

## 1. 总结论

推荐的唯一主线是：

> **反事实决策变化驱动的信息价值反馈门控 LLM 编译优化智能体。**

它研究的不是“给 LLM 更多反馈”，而是：在编译诊断、测试差异、优化报告和 IR 统计之间，选择哪一条最可能改变下一步决策；若预计收益小于 Token 和工具成本，就停止当前反馈链。

另外两个方向的定位是：

- **可验证结构化编辑**：最容易实现和提高编译成功率，但 2026 年近邻工作密集，适合作为保底方向或主线的安全执行器。
- **失败边界记忆**：将失败转成带适用条件、反例条件和失效规则的负证据，适合作为独立备选或第二阶段扩展。

## 2. 为什么重新设计

【论文事实】2024—2026 年文献已经覆盖：编译器多轮反馈、强化学习工具调用、多 Agent、多抽象层协作、优化意图、结构化 Hint、历史优化模式检索、真实运行时间奖励和验证器门控。

【合理推导】继续增加 Agent 数量、反馈轮数或硬件平台，容易提高实验开销，却不能证明 LLM 的决策机制变得更好。因此本轮统一采用：

```text
固定预训练 LLM
      +
单机 Clang/LLVM 工具链
      +
有限候选/反馈预算
      ↓
比较新机制能否在同预算下提高有效优化率
```

## 3. 三套框架对比

| 框架 | 核心问题 | 新增机制 | 第一阶段主要指标 | 预计开销 | 定位 |
|---|---|---|---|---:|---|
| 可验证结构化编辑 | 自由改写容易出错和产生无关修改 | 将局部动作、前提、预期证据和失败定位绑定成可执行编辑契约 | 编译率、测试率、有效优化率 | 低 | 保底/执行器 |
| 信息价值反馈门控 | 固定多轮、全量反馈浪费 Token 和工具调用 | 预测反馈造成决策变化的概率，扣除成本后主动选择或停止 | Valid Improvement@Budget、首次有效优化成本 | 低到中 | 唯一主线 |
| 失败边界记忆 | 相似任务重复失败，普通 RAG 可能错误泛化 | 失败卡片、适用性门控、反例失效和误拦截恢复 | 重复失败率、误拦截率、固定预算有效优化率 | 中 | 独立备选/扩展 |

## 4. 统一成功定义

候选必须同时满足：

```text
Compile = 1
AND Test = 1
AND StaticGain > 0
```

其中：

- `Compile`：能否被固定版本的 Clang/LLVM 编译；
- `Test`：是否通过全部功能测试或差分测试；
- `StaticGain`：相对基线的 LLVM IR 指令数、目标代码大小或指定静态指标改善。

统一主要指标：

```text
ValidOptimizationRate = 有效优化候选数 / 全部生成候选数
```

```text
ValidImprovement@B = 在预算 B 内获得至少一个有效优化的任务数 / 总任务数
```

预算 `B` 同时报告：LLM 调用数、输入/输出 Token、工具调用数和墙钟时间。不能只控制其中一个。

## 5. 统一第一阶段实验规模

- 程序：20 个 C/C++ 函数作为预实验，扩展实验为 40—100 个；
- 数据来源：PolyBench 小函数、cBench 可独立函数、LLVM test-suite 稳定用例和人工构造的边界用例；
- 模型：固定一个主要 LLM；条件允许时使用一个较小模型复核趋势；
- 候选预算：每任务最多 5 个候选或 5 轮反馈；
- 编译器：固定 LLVM/Clang 版本、优化级别和目标 triple；
- 性能：全部候选测静态指标，仅对每种方法最终 Top-1 候选做运行时间复核；
- RISC-V：第一阶段只做交叉编译合法性抽查，不参与大规模搜索。

## 6. 三个框架分别要证明什么

### 6.1 结构化编辑框架

RQ：在相同 LLM 和生成预算下，将自由代码改写替换为可验证局部编辑契约，能否提高有效优化率？

必须排除的替代解释：收益只是因为输出更短、动作空间更小或使用了更多编译器知识。

### 6.2 信息价值反馈门控框架

RQ：在相同总预算下，以“反事实决策变化概率减去反馈成本”选择下一条反馈，能否比固定阶段反馈获得更多有效优化？

必须排除的替代解释：简单的“编译失败看日志、测试失败看差异、正确后看性能”规则已经足够。

### 6.3 失败边界记忆框架

RQ：带适用和失效条件的负证据，能否在未见程序上减少重复失败，同时不误杀本来有效的变换？

必须排除的替代解释：普通成功案例 RAG 或无条件失败黑名单已经达到相同效果。

## 7. 推荐主线的最小系统

```text
程序 + 当前候选 + 已有证据
            ↓
LLM 给出下一步动作分布和不确定性
            ↓
反馈门控器枚举可用反馈
            ↓
估计每条反馈的决策变化概率与成本
            ↓
选择一条反馈 / 直接执行 / 主动停止
            ↓
编译、测试、IR 静态评价
            ↓
记录反馈是否真的改变决策以及最终是否有效优化
```

候选价值函数：

```text
VOI(f|s) = P(change | f,s) × ExpectedGain(f,s) - λ × Cost(f)
```

- `s`：当前候选、错误阶段和已有证据组成的状态；
- `f`：可请求的反馈类型；
- `P(change | f,s)`：获得反馈后下一步动作或候选排序发生变化的概率；
- `ExpectedGain`：决策改变后获得有效优化的预期收益；
- `Cost`：Token、工具时间和日志长度的归一化成本；
- `λ`：成本权重。

第一版不训练大模型。`P(change)` 可以由规则、小型分类器或固定 LLM 评分提供，并在实验后用真实决策变化校准。

## 8. 推荐主线的基线与消融

基线：

1. 无反馈单轮生成；
2. 每轮返回全部反馈；
3. 随机选择一种反馈；
4. 固定阶段规则反馈；
5. 固定轮数的多轮反馈 Agent。

消融：

- 去掉决策变化概率，只按反馈成本选择；
- 去掉成本项，只选预计信息最多的反馈；
- 不允许主动停止；
- 把结构化摘要替换为完整原始日志；
- 使用随机停止代替价值阈值；
- 固定同一个反馈顺序。

## 9. 可证伪条件

以下任一结果都会削弱或否定推荐主线：

1. 固定阶段规则在相同预算下达到同等或更好的有效优化率；
2. 门控器节省 Token，但 Valid Improvement@Budget 明显下降；
3. 估计的决策变化概率与真实变化几乎无关；
4. 不加入成本项也得到相同结果；
5. 结果只在一个模型或少数任务上成立；
6. 真实运行时间复核显示静态收益候选大面积退化。

## 10. 推荐实施顺序

1. 先实现结构化编辑契约和统一记录格式，作为安全候选生成器；
2. 在同一候选生成器上比较五种反馈策略；
3. 证明信息价值门控优于固定阶段规则后，再扩大任务数；
4. 最后加入失败边界记忆，验证它是否进一步减少重复试错；
5. 只有前三步成立后，才考虑小模型微调、DPO 或真实 RISC-V 性能扩展。

## 11. 推荐论文题目

中文：

1. 固定预算下反事实决策变化驱动的 LLM 编译反馈选择方法
2. 面向有效优化率的成本感知 LLM 编译反馈门控
3. 低开销自适应反馈驱动的 LLM 编译优化智能体

英文：

1. Counterfactual Decision-Change Feedback Selection for Budgeted LLM Compiler Optimization
2. Cost-Aware Feedback Gating for Valid LLM-Based Compiler Optimization
3. BudgetOpt: Low-Cost Adaptive Feedback for LLM Compiler Optimization Agents

## 12. 一句话总结

这项研究不是让 LLM 看更多编译日志，而是让它只请求真正可能改变优化决策的那一条反馈，并证明在更少时间和 Token 下获得更多正确且有效的优化。
