# 09 低开销 LLM AI 编译器研究材料生成实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 基于本地 2024—2026 年 LLM 编译器逐篇阅读总结，为三个低开销研究方向生成可独立执行的研究框架、创新边界、完整实验方案、预实验 Demo 和记录模板。

**Architecture:** 09 根目录负责跨框架证据汇总、重复检查和最终推荐；三个子目录分别对应结构化编辑、信息价值反馈门控和失败边界记忆。三个框架共享统一预算与正确性门控，但研究自变量、核心机制和可证伪条件相互独立。

**Tech Stack:** Markdown、Clang/LLVM、C/C++ 小程序、固定预训练 LLM、JSON/JSONL 实验记录、可选 Python 统计分析。

## Global Constraints

- 所有新文件只能位于 `09_LLM_AI编译器低开销创新框架/`。
- 使用简体中文，术语首次出现时解释英文全称和白话含义。
- 主要证据来自本地 2024—2026 年逐篇阅读总结；未经核验的信息必须标明不确定性。
- 必须区分【论文事实】【合理推导】【候选创新】。
- 不把 LLM、Agent、RAG、强化学习、LLVM、验证器或 RISC-V 本身当作创新。
- 第一阶段不训练大模型、不修改 LLVM 后端、不开展多平台长时间搜索。
- 三个框架都以编译/测试正确性为硬门控，以有效优化质量和实验成本为联合指标。
- 三个框架使用同一 LLM、相同任务、相同候选或反馈预算，避免资源不公平。
- Git 提交信息必须以 `由Codex提交：` 开头。
