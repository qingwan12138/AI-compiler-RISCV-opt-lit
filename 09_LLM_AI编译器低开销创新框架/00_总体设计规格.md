# 09：低开销 LLM AI 编译器创新框架总体设计规格

> 设计状态：用户已于 2026-07-19 确认，材料已按规格生成
>
> 设计日期：2026-07-18
>
> 证据基础：本地 2024—2026 年 LLM 编译器逐篇阅读总结
>
> 第一阶段目标：在单机、无需训练大模型、无需多平台长时间测量的条件下，验证 LLM 编译优化机制能否提高有效优化指标

## 1. 结论

本目录将设计三个可以独立开展的低开销 LLM AI 编译器实验框架：

1. **可验证结构化编辑驱动的 LLM 编译优化器**：优先提高编译成功率、测试通过率和有效优化率，是最容易启动的保底方向。
2. **信息价值门控的自适应反馈 LLM 编译优化智能体**：在固定 Token 和工具调用预算下选择最有价值的反馈，是当前最推荐的主线。
3. **失败边界记忆驱动的反重复 LLM 编译优化器**：将失败转成带适用条件的负证据，减少跨任务重复试错，是独立备选或后续扩展。

三个框架都以 LLM 的决策机制为研究对象，不把“使用 LLM、Agent、RAG、LLVM 或 RISC-V”本身表述为创新。

## 2. 统一研究边界

### 2.1 第一阶段研究对象

- 输入：规模可控的 C/C++ 函数或小程序；
- 中间形式：源码、LLVM Intermediate Representation（LLVM IR，编译器内部使用的中间代码）和编译诊断；
- LLM 输出：结构化优化动作、反馈请求或带条件的失败约束；
- 确定性工具：Clang/LLVM、测试程序、IR 统计脚本和可选 Sanitizer；
- 输出结果：正确候选、静态优化收益、反馈成本和失败证据。

### 2.2 第一阶段不开展的内容

- 不训练超大语言模型；
- 不从零实现强化学习；
- 不修改完整 LLVM 后端；
- 不进行大规模多平台真实性能搜索；
- 不把 RISC-V 设为研究框架中心；
- 不要求第一轮实验稳定超过 `-O3` 的真实运行时间；
- 不同时实现复杂多 Agent 系统。

### 2.3 RISC-V 的位置

RISC-V 只作为后续实验平台。第一阶段可以使用 LLVM 的 RISC-V 交叉编译目标检查候选能否生成合法目标代码；只有少量代表性候选需要在真实 RISC-V 平台复核，不承担核心训练和搜索开销。

## 3. 统一评价口径

### 3.1 主要指标

所有框架至少报告以下指标：

1. **编译成功率**：能够被 Clang/LLVM 正常编译的候选比例，越高越好。
2. **测试通过率**：编译后通过功能测试或差分测试的候选比例，越高越好。
3. **有效优化率**：同时满足“能够编译、测试通过、目标静态指标改善”的候选比例，越高越好。
4. **静态优化收益**：相对基线的 LLVM IR 指令数、目标代码大小或关键指令数量变化。
5. **Valid Improvement@Budget**：在固定 Token、LLM 调用和工具调用预算内获得至少一个有效优化的任务比例，越高越好。
6. **首次有效优化成本**：获得第一个有效优化前使用的轮数、Token、工具调用和墙钟时间，越低越好。

### 3.2 次要指标

- 少量代表性程序相对 `-O3` 的真实运行时间；
- 候选多样性；
- 编译失败、测试失败和无收益候选的分类比例；
- 结果在不同 LLM 或不同随机种子下的稳定性。

### 3.3 正确性门控

任何候选只有依次通过以下门槛，才能计入性能改善：

```text
语法和编译通过
        ↓
功能测试或差分测试通过
        ↓
未触发 Sanitizer 或未定义行为检查
        ↓
静态指标改善
        ↓
少量候选进行真实运行时间复核
```

错误程序产生的“虚假加速”不得计入收益。

## 4. 框架一：可验证结构化编辑驱动的 LLM 编译优化器

### 4.1 研究问题

自由生成完整源码或 LLVM IR 容易造成语法错误、类型错误、Static Single Assignment（SSA，变量只能被赋值一次的 IR 约束）错误和大范围无关改动。能否让 LLM 输出受约束的局部编辑，并通过确定性工具执行，提高固定预算下的有效优化率？

### 4.2 一主两辅创新结构

**核心创新：效应绑定的局部编辑契约。** 每个动作必须声明：

- 修改对象和允许修改的范围；
- 前置条件；
- 参数化编辑动作；
- 预期静态效果；
- 编译与测试验收条件；
- 失败后的局部修复位置。

创新不在“结构化输出”本身，而在契约将生成范围、预期效应和失败定位绑定为同一个可执行对象。

**支撑创新一：前提—预期证据的双向可执行验证。** 执行前验证动作是否适用，执行后验证编译器是否产生预期效应，使“能编译”与“动作有效”成为两个不同验收层次。

**支撑创新二：失败责任定位与字段级局部修复。** 将编译、测试或收益失败映射到契约字段，只修改被归责字段及依赖字段，避免重新生成完整程序。

三项创新共同回答同一研究问题：如何把一次 LLM 编译优化从不可控文本生成变成可执行、可验证、可归责的局部决策闭环。

### 4.3 最小实验

- 10—30 个函数；
- 每个函数生成相同数量候选；
- 比较自由文本改写、JSON 结构化输出、完整编辑契约；
- 使用同一个 LLM、相同提示示例和相同 Token 预算；
- 主指标为编译成功率、测试通过率和有效优化率；
- 只对各方法最终最优候选做少量运行时间复核。

### 4.4 可证伪条件

若完整编辑契约在相同预算下不能提高有效优化率，或者提升完全来自减少输出长度而不是契约约束，则核心主张不成立。

## 5. 框架二：信息价值门控的自适应反馈 LLM 编译优化智能体

### 5.1 研究问题

现有智能体通常在每一轮收集固定反馈，导致无论候选处于编译失败、测试失败还是性能不足阶段，都读取大量日志和指标。能否估计下一条反馈改变当前决策的可能性，只获取最有价值的反馈，并在收益不足时主动停止？

### 5.2 一主两辅创新结构

**核心创新：反事实决策变化驱动的反馈价值模型。** 它根据当前候选状态，在以下动作间选择：

- 请求编译诊断；
- 请求失败测试差异；
- 请求 LLVM optimization remark；
- 请求 IR 指令统计；
- 执行候选；
- 停止当前轨迹并保留最优结果。

门控依据不是日志长度，而是预测该反馈是否会改变下一步优化动作或候选排序。核心评价必须在相同总预算下进行。

**支撑创新一：无需训练大模型的反事实反馈标注与校准。** 对同一状态分别隐藏或加入不同反馈，记录动作类型、位置或排序是否改变，并用真实编译、测试和收益结果判断变化是否有益。

**支撑创新二：多维预算约束的反馈选择与主动停止。** 同时跟踪 Token、工具调用和墙钟时间；当所有反馈的边际价值不足时，在执行、接受或停止之间选择。

三项创新共同回答同一研究问题：如何估计反馈是否值得获取、如何得到可复现的价值标签，以及如何在有限预算内结束低价值反馈链。

### 5.3 最小实验

- 20—40 个函数；
- 每个任务最多 3—5 轮；
- 比较无反馈、固定全量反馈、随机反馈、阶段规则反馈和信息价值门控；
- 不要求训练大模型，首版门控器可以使用规则、小型分类器或固定 LLM 评分；
- 主指标为 Valid Improvement@Budget、平均反馈轮数、首次有效优化成本和静态收益。

### 5.4 可证伪条件

若门控方法降低工具调用和 Token 后，固定预算下的有效优化率显著下降；或者规则式阶段反馈达到同等结果，则信息价值机制不能作为核心创新。

## 6. 框架三：失败边界记忆驱动的反重复 LLM 编译优化器

### 6.1 研究问题

编译优化智能体会在相似程序上重复提出已经失败的变换。普通 RAG 只检索相似文本，容易把一个程序上的失败错误推广到所有程序。能否把失败表示为带适用条件和失效条件的负证据，使智能体只在真正相似的情况下避免重复尝试？

### 6.2 一主两辅创新结构

**核心创新：带适用边界的编译优化负证据表示。** 失败边界卡片记录：

- 程序结构特征；
- 尝试的优化动作；
- 编译、测试或收益失败类型；
- 失败发生的必要条件；
- 该结论适用的编译器和目标范围；
- 需要重新尝试或使卡片失效的反例条件。

检索到卡片后，系统不是直接禁止动作，而是先检查适用条件；若条件不成立，卡片不得拦截候选。

**支撑创新一：适用条件与反例条件驱动的三态门控。** 系统输出 ALLOW、WARN_AND_MEASURE 或 BLOCK；证据不足时要求低成本补测，而不是直接允许或禁止。

**支撑创新二：误拦截审计与反例驱动的记忆失效更新。** 对少量被警告或禁止的动作进行反事实执行；若动作实际有效，则缩小卡片范围、降低置信度或使其失效。

三项创新共同回答同一研究问题：如何利用失败知识减少重复试错，同时让负记忆能够识别自身适用边界并被反例推翻。

### 6.3 最小实验

- 按程序家族组织 20—40 个函数；
- 先在训练子集收集失败轨迹，再在未见函数上使用负证据；
- 比较无记忆、普通成功案例 RAG、无边界失败记忆和失败边界记忆；
- 主指标为重复失败率、首次有效优化轮数、Valid Improvement@Budget 和错误拦截率。

### 6.4 可证伪条件

若失败边界记忆不能降低重复失败，或者错误拦截导致有效优化率下降，则该机制不成立；如果普通 RAG 达到相同效果，则带边界的负证据不能单独构成创新。

## 7. 三个框架的关系与定位

| 框架 | 主要解决的问题 | 第一阶段开销 | 预期最容易提升的指标 | 推荐定位 |
|---|---|---:|---|---|
| 可验证结构化编辑 | LLM 输出不合法、修改范围失控 | 低 | 编译成功率、测试通过率、有效优化率 | 保底主线 |
| 信息价值门控反馈 | 固定多轮反馈浪费 Token 和工具时间 | 低到中 | Valid Improvement@Budget、反馈轮数、时间成本 | 唯一推荐主线 |
| 失败边界记忆 | 相似任务重复失败、普通 RAG 误迁移 | 中 | 重复失败率、首次有效优化成本 | 独立备选/扩展 |

三者可以在后续组成完整系统，但第一阶段必须分别实验，避免把模块组合后的总体收益误认为每个机制都有效。

## 9. 文献证据使用规则

1. 主要证据来自本地 2024—2026 年逐篇阅读总结。
2. 必须明确区分【论文事实】【合理推导】【候选创新】。
3. Compiler-generated Feedback、Compiler-R1、CompilerGPT、CUDA-L1、AutoComp、IntOpt、HintPilot、PerfCoder、GraphGlue、ECO、SBLLM 等作为直接近邻基线。
4. 不能宣称首次使用编译反馈、Agent、RAG、强化学习、结构化输出、真实运行时间或验证器。
5. 具体新颖性尚未完成系统性在线检索时，统一使用“候选创新”表述。

## 10. 完成验收标准

- 三个框架各有独立研究问题和核心机制；
- 每个框架包含输入、处理、输出和反馈闭环；
- 每个框架包含简单基线、强基线和最近邻方法；
- 所有对比使用同一 LLM、相同候选数和相同预算；
- 每个框架包含消融实验、最小 Demo、风险和可证伪条件；
- 至少一个主要指标直接反映优化质量；
- 至少一个主要指标直接反映 LLM 或工具成本；
- 不依赖多平台长时间搜索即可完成第一轮实验；
- 只有少量最终候选需要真实运行时间复核；
- 最终只推荐一条主线，其余明确定位为保底或扩展。

## 11. 规格自检结果

- 未发现未完成占位符；
- 三个框架的研究问题互不重复；
- 主指标、预算口径和正确性门控在三个框架中保持一致；
- 第一阶段范围与“降低实验时间开销”的目标一致；
- LLM 是研究对象，RISC-V 只作为后续实验平台；
- 最推荐主线明确为“信息价值门控的自适应反馈 LLM 编译优化智能体”。
