## 1. 工作名称

中文工作名称：**面向真实硬件反馈的可审计编译优化智能体**。

英文工作名称：**FACT: Feedback-guided Auditable Compiler Tuning with Counterfactual Attribution and Hardware Evidence**。

名称拆解：

- **Feedback-guided**：反馈不仅包含编译错误，还包含意图落地、Pass 干预和真实硬件性能证据；
- **Auditable**：每个优化结论都能追溯到 IR、机器码、反事实变体和原始测量；
- **Compiler Tuning**：首期聚焦 LLVM Pass 序列，不泛化到所有代码生成任务。

首次名称检索未发现同名编译调优框架，但投稿前仍须再次查新。

## 2. 论文主问题

现有编译优化智能体通常以“最终是否更快”或“IR 指令数是否下降”作为主要反馈。这会混淆三个问题：

1. LLM 声称的优化意图是否真的发生；
2. Pass 序列中究竟哪一步产生收益；
3. 在一个硬件上有效的策略，换到另一硬件后为什么失效。

本方案的主研究问题是：

> 将意图落地证据、Pass 反事实归因和真实硬件性能反例联合起来，能否在固定测量预算下，提高编译优化的成功率、可解释性和跨硬件稳健性？

## 3. 三项创新如何形成一个系统

### 3.1 创新一：可执行意图契约与逐层审计

智能体提出候选 Pass 策略时，必须同步输出结构化意图，而不是优化完成后再编造解释。

最小意图契约：

```yaml
intent_id: reduce_memory_traffic
scope: function_or_loop_id
expected_ir_effect:
  loads: decrease
  stores: not_increase
expected_machine_effect:
  spill_loads: not_increase
  memory_instructions: decrease
forbidden_effects:
  - semantic_change
  - code_size_growth_over_limit
```

审计链分为：

- 语义合法性：Alive2 支持时进行翻译验证，否则使用差分测试和 sanitizer；
- IR 落地：检查指令、数据流和 optimization remarks；
- 后端落地：检查 MIR/汇编、spill、分支和机器指令类别；
- 性能收益：在真实硬件上进行重复、交错、成对测量。

输出标签：

- `valid_and_realized`：语义正确且意图落地；
- `valid_but_erased`：IR 中发生但在后端被消除；
- `valid_but_counterproductive`：意图落地但真实性能下降；
- `invalid`：语义或执行错误；
- `inconclusive`：工具覆盖不足或测量无法区分。

### 3.2 创新二：Pass 反事实归因

对通过语义检查的候选序列 `S=[p1,...,pn]`，构造三类最小干预：

- 删除：移除 `pi`；
- 替换：用同类 Pass 或 no-op 替换 `pi`；
- 邻接交换：交换 `pi` 和 `p(i+1)`。

通过 IR、机器码和运行时间的成对差异，估计 `pi` 在当前序列和当前程序上的局部贡献。这里的“因果”严格限定为受控编译实验中的干预效应，不主张普适因果规律。

归因结果用于：

- 区分必要 Pass、冗余 Pass 和破坏性 Pass；
- 识别“前一个 Pass 为后一个 Pass 创造机会”的协同边；
- 将下一轮候选预算集中到高置信组合附近；
- 为意图审计提供“哪个动作导致哪个变化”的证据。

### 3.3 创新三：硬件性能反例校准

当相同候选在 x86-64 与 RISC-V K3 上出现收益翻转时，系统保存硬件反例：

```text
程序特征 + 意图 + Pass序列 + IR变化 + 机器码变化
+ x86效应 + RISC-V效应 + 测量置信区间
```

首篇论文只要求反例能够修正候选排序或增加目标相关守卫，例如：

- 在 K3 上检测到 spill 增多时，降低高展开因子候选的优先级；
- 当向量化意图在后端未落地时，不把 IR 层改进计为成功；
- 当硬件间效应方向冲突时，将候选标记为目标相关，不学习成通用规则。

自动生成 LLVM TTI/调度模型源码补丁属于毕业论文后续扩展，不是首篇 CCF B 投稿的必要条件。

## 4. 整体架构

```text
Benchmark / LLVM IR
        |
        v
Candidate Generator
  输出：Pass序列 + 意图契约
        |
        v
Semantic Gate
  Alive2 / differential tests / sanitizer
        |
        v
Intent Auditor
  IR diff -> remarks -> MIR/assembly evidence
        |
        v
Counterfactual Engine
  删除 / 替换 / 邻接交换
        |
        v
Measurement Harness
  x86-64 主实验 + K3 RISC-V 验证
        |
        v
Attribution & Calibration Store
  局部贡献、协同边、硬件反例、置信度
        |
        v
Candidate Re-ranking / Next-round Search
```

## 5. 模块边界

| 模块 | 输入 | 输出 | 不负责什么 |
|---|---|---|---|
| Candidate Generator | IR、预算、历史证据 | Pass 序列和意图契约 | 不判断自身是否正确 |
| Semantic Gate | 原始与候选程序 | valid/invalid/inconclusive | 不判断性能 |
| Intent Auditor | 契约、IR/MIR/汇编 | 落地标签和证据 | 不把自然语言解释当证据 |
| Counterfactual Engine | 合格序列 | 最小干预变体 | 不做全空间穷举 |
| Measurement Harness | 二进制、输入、平台 | 原始测量与环境元数据 | 不用 QEMU 代替实机 |
| Attribution Store | 变体和测量 | 局部贡献、协同和置信度 | 不宣称跨程序普适因果 |
| Calibration Layer | 多硬件效应记录 | 目标相关守卫和重排序 | 首篇不修改 LLVM 源码 |

## 6. 论文贡献的建议写法

若实验成功，贡献应写成：

1. 提出一种要求优化智能体在生成时同步给出可执行意图契约，并用 IR—机器码—运行证据逐层审计的方法；
2. 提出受控 Pass 最小干预协议，为候选序列建立可复验的局部贡献与协同证据，并用于有限预算搜索；
3. 提出硬件性能反例校准方法，在 x86-64 与 RISC-V 实机之间识别收益翻转，降低目标硬件负优化；
4. 构建包含审计标签、反事实变体和跨硬件测量的评测集与可复现实验流程。

## 7. 非目标

- 不研究任意源码级算法重写；
- 不训练新的基础大模型；
- 不同时优化运行时间、能耗和代码尺寸三个主目标；
- 不声称跨任意 ISA 零样本泛化；
- 不要求所有候选均由 LLM 生成，随机或经典搜索候选同样可进入审计链；
- 不把可解释自然语言作为唯一解释质量指标；
- 不把 RISC-V 结果写成仅对 RISC-V 有效的方法。

## 8. 最小论文闭环

首篇论文必须同时证明：

1. 意图审计能发现基线反馈未发现的“虚假成功”；
2. 反事实归因能在相同测量预算下提升搜索效率或最终效果；
3. 加入 K3 性能反例后，K3 上的负优化率下降或几何平均性能提升；
4. 完整系统不降低语义正确率。

若只能证明其中一项，不能称为 FACT 完整论文，应收缩为单项方法论文。
