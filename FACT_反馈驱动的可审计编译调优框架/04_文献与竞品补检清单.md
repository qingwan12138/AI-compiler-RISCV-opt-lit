# FACT：文献与竞品补检清单

## 1. 目的

FACT 的三个组成方向均存在近邻研究。投稿前不能只依赖当前 103 篇笔记，需要围绕“组合机制是否已被做过”持续查新。本清单规定必须排查的撞题面和证据标准。

## 2. 补检原则

- 技术主张优先使用论文原文、官方文档和开源实现；
- 题目或摘要只能作为检索线索，不能替代全文方法比较；
- 对 2025–2026 年预印本至少每月更新一次；
- 每个“首次”主张必须有专项检索记录；
- 将“单模块已存在”和“三模块联合方式已存在”分开判断；
- 无法获取全文时标记为未核验，不把推测写进论文。

## 3. 方向一：意图落地审计

### 已知近邻

- IntOpt：意图表达、细化与实现；
- ACCLAIM：源码、IR、汇编多层协作；
- CompilerGPT：使用编译优化报告反馈；
- Compiler-R1：工具交互与强化学习；
- Code the Transforms：生成可执行变换器。

### 必查问题

- 是否已有工作要求模型在生成前提交结构化优化意图；
- 是否已有工作自动比较“声明意图”和 IR/机器码实际变化；
- 是否已有 compiler agent faithfulness / rationale faithfulness benchmark；
- 是否已有把后端擦除单独标为失败的评测；
- 是否已有按合法性、实现性和收益性拆分奖励的训练方法。

### 检索词

```text
compiler optimization agent intent realization
LLM compiler rationale faithfulness
optimization intent IR assembly alignment
compiler agent auditable optimization
optimization remarks LLM feedback
backend erasure compiler optimization intent
```

## 4. 方向二：Pass 反事实归因

### 已知近邻

- AutoPhase 与 CompilerGym：RL/环境基线；
- CompilerDream：Pass 状态转移世界模型；
- Priority Sampling：候选预算分配；
- ECCO：Evidence-Driven Causal Reasoning for Compiler Optimization，和“可解释因果推理 + 组合搜索”高度接近，必须全文逐项对比；
- Booster Pass Chain：可能直接涉及 Pass 助推关系，原文必须补齐；
- 传统 phase-ordering sensitivity / pass interaction 研究。

### 必查问题

- 是否已有删除单 Pass 的 marginal contribution 分析；
- 是否已有 Shapley value、causal inference 或 counterfactual explanation 用于 phase ordering；
- 是否已有 Pass 交互图直接引导搜索预算；
- 是否已有在真实硬件重复测量下验证归因稳定性；
- Booster Pass Chain 的助推关系发现方法是否与本方案重合。

### 检索词

```text
compiler phase ordering counterfactual attribution
pass interaction causal compiler optimization
Shapley value compiler pass sequence
ablation guided phase ordering
booster pass chain compiler
compiler optimization credit assignment
```

## 5. 方向三：硬件性能反例校准

### 已知近邻

- Ithemal、llvm-mca：基本块吞吐估计；
- TVM/Ansor/MetaSchedule：真实硬件测量和代价模型；
- Moses、MTL-TLP、CDMPP、MetaTune、TCL：跨设备适配；
- Closer in the Gap：RVV 真实性能盲区；
- LLVM TTI、scheduler/tune 接口。

### 必查问题

- 是否已有用收益翻转反例修正 LLM compiler agent 候选选择；
- 是否已有把跨硬件负迁移反馈到 Pass 序列搜索；
- 是否已有硬件条件 guard / abstention 用于 compiler agent；
- 是否已有从反事实微基准自动生成 LLVM cost model 更新；
- 是否已有同时记录 IR 变化、机器码变化和多硬件效应的数据集。

### 检索词

```text
hardware counterexample compiler optimization
negative transfer compiler pass tuning
cross architecture pass sequence performance
hardware conditioned compiler agent
compiler cost model counterexample calibration
target specific profitability guard
```

## 6. 组合撞题检索

这是最重要的一组检索。即使三个单项都已有工作，只要联合机制和证据链不同，仍可能形成创新；反之，如果已有系统已经完成相同闭环，必须立即调整。

```text
auditable compiler agent counterfactual hardware feedback
LLM compiler optimization intent counterfactual attribution
explainable phase ordering real hardware feedback
compiler agent rationale alignment performance measurement
counterfactual compiler optimization multi architecture
```

重点检查：CGO、CC、PACT、MICRO、ASPLOS、PLDI、LLVM Developers' Meeting，以及 arXiv 近两年 cs.PL、cs.LG、cs.AI 交叉论文。

## 7. 每篇近邻的对比记录格式

| 字段 | 内容 |
|---|---|
| 标题、作者、年份 | 记录完整书目信息 |
| 来源状态 | 全文已读 / 仅摘要 / 无法获取 |
| 研究对象 | Pass、IR rewrite、源码或 tensor schedule |
| 正确性证据 | 编译、测试、形式验证或无 |
| 性能证据 | 代理、模拟器或实机 |
| 是否有意图契约 | 是/否；如何表示 |
| 是否有反事实归因 | 是/否；干预方式 |
| 是否有跨硬件反例 | 是/否；如何使用 |
| 与 FACT 重合处 | 具体到机制 |
| FACT 仍新增什么 | 必须可验证，不能用空泛措辞 |
| 对立证据 | 是否削弱我们的假设 |
| 决策 | 保留方向 / 收窄 / 放弃 |

## 8. 投稿前查新门

提交前必须满足：

- Booster Pass Chain 原文已获取或已明确无法获取并降低相关新颖性主张；
- 对意图忠实度、Pass 因果归因和硬件反例三个交叉面完成至少两轮检索；
- 最近 90 天新增论文已补检；
- 所有“首次”字样都有检索证据，无法证明时改成更窄的贡献表述；
- 论文 Related Work 明确区分：生成候选、验证正确性、证明意图落地、归因收益和跨硬件校准。
