# 类别三：形式验证、超级优化与规则生成——候选创新点分析

> 文献数量：2024–2026 年独立条目 19；旧文献边界条目 6
> 完整阅读数量：19 份新文献总结
> 证据范围：本地逐篇阅读总结；旧文献只用于 Alive/Alive2、Souper、STOKE 等方法边界
> 分析日期：2026-07-16
> 证据充分程度：高（规则正确性与后端盈利性之间的断层在多篇近邻中重复出现）

## 1. 这一类在研究什么

结论：这类工作要自动找到比现有编译器更好的等价程序，并尽量证明变换不会改变程序含义。超级优化器在一个受限空间里搜索最优指令或表达式；翻译验证器检查一次具体变换是否保持语义；规则生成系统把成功实例泛化为可复用 rewrite。2024–2026 年的文献已将 LLM、SMT/Alive2、等式饱和、运行时双版本验证和真实性能代价组合起来。

现有成果最明显的断层是：**语义正确不等于在目标硬件上值得应用**。Alive2、LPO、LPG 等能回答“这条规则在建模范围内是否安全”，但不能回答“在 x86、RISC-V、不同 VLEN 或不同微架构上是否更快”；Minotaur、EggMind、STENSO 等虽有成本筛选，却多依赖单平台、代理成本或受限 DSL。若把正确性证书与性能结论混在一个“好规则”标签里，规则会在新硬件上产生稳定而合法的负优化。

## 3. 已有工作已经解决了什么

结论：候选生成、规则泛化、形式验证、验证反馈训练、EqSat 策略和运行时兜底都已有代表工作；剩余问题是怎样让“永远正确的规则”和“只在部分硬件盈利的规则”同时被精确表达。

1. 【论文事实】Alive/Alive2、Souper、Minotaur 已覆盖局部 IR/SIMD 变换的合成、refinement 检查和缓存复用。
2. 【论文事实】LPO 已让 LLM 在合成器支持集之外提出候选，LPG 已将规则泛化拆成符号、结构、约束和位宽四类操作。
3. 【论文事实】LLM-VeriOpt 已把 Alive2 反馈用于 GRPO，LLMLIFT 已让模型同时生成候选代码和证明；验证反馈训练本身不再新。
4. 【论文事实】CoV 已把语法、profiling、Alive2 和运行时双版本验证串成完整接纳链；简单增加“静态 + 动态验证”会撞题。
5. 【论文事实】EggMind、Foresight、E-Path 已分别探索策略 DSL、并行可组合引擎和 CFG 等式表示；EqSat + LLM 或 CFG 表示不能单独构成创新。
6. 【论文事实】Minotaur、STENSO、EggMind 都使用某种成本或测量引导，但其证据主要绑定单平台、代理模型或受限域，没有把语义有效域和硬件盈利域分别持久化。

## 4. 仍未解决的研究空白

结论：最稳健的空白是给每条自动生成规则维护两份不同性质的证书——语义证书回答“能不能做”，盈利证书回答“在哪些硬件和输入条件下值得做”。

### 空白 A：规则的语义有效域与硬件盈利域被混成一个标签

- 【论文事实】Alive2 明确只验证语义而不判断性能；LPO/LPG 的最终评价以规则发现/泛化为主，缺少跨后端全程序收益；LLM-VeriOpt 仍大量依赖指令数或代码尺寸代理。
- 【论文事实】Minotaur 的成本和 intrinsic 编码偏 x86；EggMind 缺真机向量性能；STENSO 只在 CPU 上实测。
- 【合理推导】同一 rewrite 可在所有目标上语义等价，却只在某些 ISA、微架构、VLEN、LMUL、trip count 或对齐条件下盈利。只存“已验证规则”会把安全性误当成普遍盈利性。
- 证据充分度：高。

### 空白 B：验证器 unknown 的路由缺少风险—成本联合决策

- 【论文事实】LLM-enhanced TV 使用 LLM/fuzzing处理中间情况，CoV 使用运行时双版本验证接纳 Alive2 unknown。
- 【合理推导】不同候选的潜在收益、运行时副作用和验证成本不同，应按风险和预期价值选择 fuzzing、运行时验证或直接拒绝。
- 证据充分度：中。CoV 已覆盖验证链，需要证明路由策略而非链条本身的增量。

### 空白 C：已验证规则跨 LLVM 版本的证明重放与失效管理不足

- 【论文事实】BRIDGE 的 canonical IR 依赖固定 Clang/O0；Alive2 的语义模型和 intrinsic 支持随 LLVM 演化；LPO/LPG 依赖具体工具覆盖。
- 【合理推导】规则逻辑可能不变，但解析、poison/undef 语义、属性和后端成本会变化，需要证明指纹和版本失效边界。
- 证据充分度：中低；当前语料缺少专门纵向实验，不能直接主张新颖。

## 6. 最推荐的创新点

### 6.1 创新点名称

【候选创新】**语义证书—盈利证书解耦的条件化优化规则生成**。

### 6.2 一句话解释

一条自动生成的规则只有在两道独立门都通过时才应用：第一道证明它不会改错程序，第二道证明它在当前 RISC-V/x86 硬件、向量长度和输入形状下有稳定收益；“永远正确”和“这里更快”不再共用一个标签。

### 6.3 创新点命名拆解

- **语义证书**：记录规则、前提、验证器版本、求解状态和可重放查询，回答在建模范围内是否 refinement-safe。
- **盈利证书**：记录目标硬件、输入形状、重复测量、置信区间和适用包络，回答何时有稳定性能收益。
- **解耦**：语义反例只收紧语义前提，性能反例只收紧盈利域，二者不互相冒充。
- **条件化规则**：部署时根据程序特征和硬件条件选择应用、拒绝或补测，而不是全局启用规则。

### 6.4 文献依据

- 正确性依据：Alive2、Minotaur、LPO、LPG 和 LLM-VeriOpt 证明 SMT/refinement 验证可以约束自动生成规则。
- 性能依据：STOKE、Minotaur、STENSO 证明成本必须进入搜索或筛选；CUDA-L1 等类别二文献又说明真机均值会掩盖负迁移。
- 冲突证据：LPO 明确指出少量 peephole patch 难体现全程序收益；LPG 未做完整运行时间；EggMind 使用代理成本；STENSO 的跨设备能力尚未实测。
- 不能再声称的内容：不能声称“自动生成 peephole”“首次用 LLM 泛化规则”“首次用 Alive2 验证”“首次把验证反馈用于 RL”“首次静态加运行时验证”。
- 核心候选边界：**将规则的可证明语义有效域和经真机校准的盈利域作为两个可独立更新、可独立失效的证书对象**。

### 6.5 已有工作与研究空白

传统规则库通常近似为：

```text
if semantic_precondition then rewrite
```

即使规则语义完全正确，目标后端的 instruction selection、寄存器压力、shuffle 成本、缓存和向量长度也可能使它变慢。新对象写成：

```text
if semantic_precondition
and profitability_condition(hardware, shape, compiler)
then rewrite
else keep / remeasure
```

【合理推导】研究问题不再是“能否生成更多正确规则”，而是“能否为正确规则学习可校准的硬件盈利边界，并用反例分别修正正确性与盈利性”。

### 6.6 核心机制

每条规则保存为：

```text
R = <M, Q, P_sem, Cert_sem, P_perf, Cert_perf>
```

- `M`：匹配模式；
- `Q`：替换模式；
- `P_sem`：语义前提，如位宽、无 poison、对齐、无别名；
- `Cert_sem`：Alive2/SMT 查询、结果、工具版本和规则哈希；
- `P_perf`：盈利条件，如 ISA、微架构、VLEN、LMUL、trip count、数据对齐、热点权重；
- `Cert_perf`：成对真机测量、效应分布、置信区间、样本来源和失效日期。

对规则 `r`、程序点 `x` 和硬件条件 `h`，部署门控为：

```text
Apply(r,x,h) = Valid(Cert_sem, x)
             AND LowerCI[Δperf(r,x,h)] > δ
```

其中 `Δperf = log(T_before/T_after)`，`δ` 是覆盖编译和运行风险的最小收益阈值。若语义证书通过但盈利置信区间跨零，输出“需要补测”；若盈利预测高但语义验证 inconclusive，不能应用。

两类反例分开处理：

1. **语义反例**：Alive2/SMT 给出具体输入或 poison/undef 条件，收紧 `P_sem` 或废弃规则；
2. **盈利反例**：代码正确但在某硬件/输入变慢，收紧 `P_perf`，语义证书仍保留。

对 RVV，可把 VLEN、SEW、LMUL、尾部/掩码策略和 spill 情况加入盈利特征。第一版语义验证可从固定宽度 LLVM vector IR 开始，避免假装 Alive2 已完整覆盖所有 scalable-vector intrinsic；RVV lowering 后再做差分测试和真机测量。

### 6.7 系统组成与数据流

```text
真实 IR 切片 / 已知规则实例
            ↓
LLM 或枚举器生成规则与语义前提
            ↓
Alive2/SMT 验证、反例驱动收紧 P_sem
            ↓
生成可重放 Cert_sem 与规则哈希
            ↓
x86/RISC-V 编译、反汇编、重复真机测量
            ↓
学习 hardware/shape/compiler 条件化盈利包络 P_perf
            ↓
bootstrap 置信区间与负收益反例更新 Cert_perf
            ↓
应用 / 拒绝 / 主动补测
            ↓
LLVM 版本变化时重放语义证书并重校盈利证书
```

LLM 只负责提出候选和可能前提；验证器裁决语义，真实硬件裁决盈利。规则发布时必须携带两个证书的来源和覆盖范围。

### 6.8 小白化例子

假设规则把两次标量加法合成一个向量操作。Alive2 证明两种写法在给定无溢出前提下结果相同，所以语义证书在 x86 和 RISC-V 都有效。但 x86 上 128-bit SIMD 让它快 12%，某块 RVV 板在短循环上因 `vsetvli` 和寄存器 spill 反而慢 7%。旧系统会把它作为“已验证好规则”全局启用；新系统保留同一语义证书，却把盈利证书写成“x86 有效；RVV 仅在 trip count 大于某阈值且无 spill 风险时启用”。

### 6.9 可检验的研究问题

1. 语义—盈利双证书是否比“验证通过即应用”降低目标硬件负优化率？
2. 从 x86 学到的盈利包络在少量 RISC-V 补测后能否达到接近独立调优的 Regret？
3. VLEN、LMUL、trip count、对齐和 spill 特征中，哪些决定 RVV 规则的盈利边界？
4. 性能反例只更新盈利证书，是否比直接删除整条规则保留更多跨平台可用机会？
5. LLVM 版本变化时，语义证书和盈利证书的失效率是否显著不同？

### 6.10 可验证假设

- H1：相对 semantics-only 规则库，完整方法显著降低 x86/RISC-V 上的负优化率和最坏 10% 退化。
- H2：相对每个平台从零测量，源平台盈利证书 + 主动目标补测能用更少测量达到相近 Regret@k。
- H3：移除置信区间门控后，平均收益可能接近，但错误启用率和性能尾部显著恶化。
- H4：把语义失败和性能失败混成同一负标签，会降低规则在第三个平台上的可复用覆盖率。
- H5：LLVM 版本更新后，部分语义证书仍可重放，但盈利证书需要更频繁重新校准。

### 6.11 最小可行 Demo

- **目标**：对 20–40 条局部 LLVM IR 规则证明“语义始终有效、盈利条件依硬件变化”可被自动建模。
- **规则来源**：选择 Alive/InstCombine、Souper/Minotaur 风格规则和少量 LLM 泛化候选；记录来源，避免把已有规则宣称为新发现。
- **程序**：从 TSVC、PolyBench、LLVM test-suite 抽取能触发规则的 30 个函数，并生成不同 trip count、对齐和数据分布。
- **平台**：一台 x86-64 主机和一块 RISC-V Linux/RVV 开发板；具体微架构、VLEN 和工具链需人工确认。
- **软件**：固定 LLVM 主版本、Alive2、`opt`、`llc`、`llvm-objdump`、测试/sanitizer、Linux `perf`。
- **步骤**：生成/导入规则→Alive2 验证并保存查询→在两平台编译规则前后版本→各输入重复计时→拟合简单决策树或层级回归盈利包络→双门控部署。
- **预计工作量**：1 周规则与证书格式，1 周验证重放，2 周双平台测量和模型，1 周消融与统计。
- **成功标准**：观察到一组语义证书相同但硬件盈利符号不同的规则；双证书门控在同等测量预算下降低负优化率。

### 6.12 实验设计

#### 实验平台

固定 LLVM、Alive2/Z3 版本和目标 triple；记录 CPU 型号、微码、内核、频率策略和 RVV VLEN。语义证书只对明确的 LLVM 语义和验证器覆盖负责，不把 IR 证明外推为后端实现绝对无 bug。

#### 数据集

- 规则集：已存在且可验证的标量/固定向量规则、LLM 泛化候选；
- 触发集：真实 benchmark IR 切片；
- 形状集：系统改变 trip count、对齐、位宽和向量因子；
- 外部集：不同 benchmark 家族和第三个编译器版本；
- 训练、阈值选择和最终测试按程序家族分离。

#### 对比基线

- semantics-only：Alive2 通过即全局应用；
- static-cost：Alive2 + LLVM TTI/静态指令成本；
- source-hardware：使用源平台平均收益决定所有目标是否应用；
- target-exhaustive：目标平台逐实例测量的高成本上限；
- 近邻基线：LPG/LPO 式规则生成验证后，只做单平台成本筛选；
- 完整方法：双证书、条件化盈利包络、置信区间和主动补测。

#### 消融实验

依次删除硬件条件、输入形状、置信区间、性能反例更新、主动补测和证书版本重放。另比较只用代理成本、只用运行时间、加入汇编/PMU 特征的增量。

#### 评价指标

- semantic pass/inconclusive/refuted 比例和验证时间；
- 规则触发覆盖率与已验证规则数；
- 真机 speedup 的中位数、几何平均和最坏 10%；
- negative optimization rate：正确但变慢的应用比例；
- profitability classification F1/AUROC 与 Brier/ECE；
- Regret@k 和目标平台测量次数；
- 证书重放成功率、版本失效率和重校成本；
- 编译时间与规则查询开销。

#### 统计要求

每个规则—程序—硬件组合先预热并至少重复 15 次，报告 bootstrap 95% 置信区间。性能结论使用配对统计检验和效应量；同一规则多触发点采用层级或聚类 bootstrap，避免把相关样本当独立样本。

### 6.13 与已有工作的创新边界

- 与 LPO/LPG 的区别：它们聚焦发现或泛化经 Alive2 验证的规则；本方法进一步学习规则在哪些硬件和输入条件下盈利，并持久化独立性能证书。
- 与 Minotaur 的区别：Minotaur 在 x86 SIMD cut 上做成本检查；本方法显式分离可跨平台重用的语义证书和需按硬件校准的盈利包络。
- 与 LLM-VeriOpt 的区别：LLM-VeriOpt 把验证作为训练奖励；本方法不依赖 RL，核心是规则生命周期中的双证书与双反例更新。
- 与 CoV 的区别：CoV 解决静态 unknown 的安全运行时接纳；本方法首先研究已证明安全规则的条件盈利，不复刻父子进程验证总线。
- 与 EggMind/STENSO 的区别：它们用策略或测量成本引导搜索；本方法要求最终规则带可审计、可重放、可失效的语义/盈利证书。
- 直接复用的模块：LPO/LPG 候选思想、Alive2、LLVM TTI、真机 profiler、统计分类器。
- 核心创新候选：**双证书对象 + 硬件条件化盈利包络 + 语义/性能反例的分离更新**。

### 6.14 风险与降级方案

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 近邻工作已明确实现双证书规则库 | 新颖性下降 | 收窄到 RVV VLEN/LMUL 盈利证书或 LLVM 版本双重失效；先补在线检索 |
| Alive2 不支持目标向量语义 | 规则覆盖不足 | 首版验证固定向量 LLVM IR；RVV lowering 用差分测试，明确证据等级 |
| 真机触发规则后收益太小 | 难测量 | 选热点循环并放大迭代；同时报告全程序收益，禁止只报微基准 |
| RISC-V PMU 不完整 | 盈利解释不足 | 以运行时间和反汇编为核心，PMU 为可选特征 |
| 规则交互使单条收益非加和 | 盈利证书失真 | 首版单规则/小组合；扩展时加入交互项和组合证书 |
| 规则触发次数少 | 数据不足 | 从真实切片生成语义等价形状变体；严格分离合成与真实测试结果 |
| 盈利模型过拟合两台机器 | 第三平台失效 | 输出拒绝/补测而非强制迁移；增加 leave-one-hardware-out 评测 |
| 证书存储/查询开销高 | 编译时间退化 | 离线生成、哈希索引、只在热点或 `-O3` 启用 |
| 结果表明静态 TTI 已足够 | 学术增量弱 | 转向 TTI 失效案例基准或 LLVM 版本证明重放；如实报告否定结果 |

### 6.15 可证伪条件

以下任一结果会否定或显著削弱候选创新：

1. 经验证规则在 x86/RISC-V 和不同输入形状上的盈利符号几乎总是一致；
2. LLVM TTI 或单平台平均收益已能达到与双证书相同的负优化率和 Regret；
3. 主动补测不比随机或逐实例测量节省预算；
4. 盈利证书在未见程序或第三个平台上完全失去校准；
5. 语义/性能反例分离更新不比直接删除失败规则保留更多有效覆盖；
6. 规则级收益无法在函数或全程序层复现；
7. 所有提升来自更严格阈值导致几乎不应用规则，而非正确识别盈利域。

### 6.16 综合评分

| 维度 | 1—5分 | 评分理由 |
|---|---:|---|
| 新颖性 | 4 | 与规则生成、形式验证、单平台成本均有明确差异；需补双证书近邻检索 |
| 文献证据 | 5 | LPO/LPG/Alive2 与 Minotaur/EggMind/STENSO 形成完整断层证据 |
| 可实现性 | 4 | MVP 可用几十条局部规则和两平台完成，不需训练大模型 |
| 实验可验证性 | 5 | 负优化率、Regret、校准、证书重放均可直接测量 |
| 与 RISC-V 相关性 | 5 | VLEN/LMUL/尾策略使盈利域问题具有真实后端内容 |
| 与总体主线兼容性 | 5 | 可作为跨硬件知识库中“规则级可迁移知识”的核心对象 |
| 研究风险 | 3 | Alive2 向量覆盖和规则级微小收益是主要风险 |

结论：当前适合作为**主创新候选**。它与类别一、类别二的分工清楚：类别一估计 Pass 干预的跨硬件信用；类别二审计智能体解释是否可信；本类别把最终可复用 rewrite 固化为“语义安全但盈利有边界”的双证书规则。
