# 多硬件编译：效应保持的最小架构增量知识特化

> **学术状态：候选创新，尚需针对性查新，不声称首次。** 方法简称 EPAS（Effect-Preserving Architecture Specialization）。本文不把 optimization intent、双层知识、平台 hints、Adapter、候选排序、少样本微调或 RISC-V 实测中的任一单项包装为主创新。

## 1. 候选创新点名称与独有核心

候选创新点名称为：**效应保持的最小架构增量编译知识特化**。

它研究的不是“给每个平台各找一条更好的 Pass 序列”，而是：

> 同一条通用优化知识在不同架构上可以采用不同实现，但应保持其预期的跨层优化效应；系统只学习实现该效应所必需的最小架构差异，并据此判断该知识究竟是通用、架构敏感还是架构特有。

因此，主创新由三个不可拆开的部分组成：跨层优化效应契约、效应保持的最小架构增量特化、编译知识可迁移边界发现。双层知识和排序器只是承载该原则的结构与工具。

## 3. 为什么 EPAS 不是模块缝合

普通组合式框架可以写成：

```text
通用知识 + 平台 Adapter + 排序器 → 更快候选
```

这种方案即使性能改善，也无法证明模型复用了同一条优化知识，因为平台模块可能重新学习了完整策略。EPAS 额外规定了三个可以被实验推翻的约束：

1. 每条知识必须给出可测量的效应契约，而不是只给自然语言意图；
2. 平台特化必须同时最小化效应实现误差和架构增量成本；
3. 知识类别必须由跨平台实现误差、适配成本和负迁移结果产生，而不是由研究者预先命名。

因此，EPAS 新增的是学习对象、优化目标和知识边界判据，而不是简单增加系统模块。

## 4. 主研究问题与子问题

**主研究问题**：

> 如何在保持通用优化知识预期跨层效应的前提下，仅学习目标平台所需的最小架构增量，并据此发现编译优化知识在不同硬件架构之间的可迁移边界？

**子问题**：

1. 如何把 optimization intent 转化为 IR、MIR/汇编和真实硬件上可观测的效应契约？
2. 不同平台绝对指标不可直接比较时，如何判断同一效应是否得到保持？
3. 如何约束特化过程，使其不会退化成每个平台独立训练？
4. 如何用实验证据区分架构通用、架构敏感和架构特有知识？
5. 少量目标平台测量能否在保持通用层冻结时降低效应误差和负迁移？

## 5. 跨层优化效应契约

通用优化知识单元定义为：

$$
K^m=(Pre_m,I_m,E_m^{*},Slots_m,Verify_m).
$$

| 字段 | 含义 | 示例 |
|---|---|---|
| `Pre` | 程序适用条件 | 规则循环、别名可判定、归约可识别 |
| `I` | 优化意图 | 暴露向量化、改善局部性、增加 ILP |
| `E*` | 跨层目标效应契约 | 依赖下降、并行机会增加、spill 不显著恶化 |
| `Slots` | 目标架构实现槽位 | 向量策略、展开因子、布局、Pass、intrinsic |
| `Verify` | 正确性、合法性和效应约束 | 语义等价、可编译、代码尺寸和副作用边界 |

`E_m^{*}` 只规定应保持的效应方向、优先级和禁止副作用，不规定不同平台必须使用相同 Pass、代码骨架或绝对机器指标。第一版由专家初始化 6–8 个契约，但契约权重、适用置信度和迁移类别必须由跨平台数据验证。

## 6. 平台归一化效应观测与实现误差

候选 `c` 在平台 `h` 上的真实跨层效应表示为：

$$
\Phi_h(P,c)=Normalize_h([
\Delta IR,
\Delta MIR,
\Delta Vector,
\Delta Spill,
\Delta Memory,
\Delta Branch,
\Delta CodeSize,
\Delta Runtime
]).
$$

`Normalize_h` 使用相对平台基线、方向标签或平台内标准化，解决不同 ISA 的指令数量、向量宽度和运行时间尺度不可直接比较的问题。它不把 x86 的 AVX 指令数与 RISC-V 的 RVV 指令数强行设为同值，而比较“向量利用是否增加、spill 是否恶化”等契约方向。

效应实现误差定义为：

$$
G_h(K^m,c)
=1-\cos(W_mE_m^{*},W_m\Phi_h(P,c))
+Penalty_{constraint}(K^m,c,h).
$$

`Penalty_constraint` 对语义错误、后端非法、尺寸越界和严重反向效应施加惩罚。`G_h` 是可测量的实现证据，不被表述为严格因果贡献。

## 7. 效应保持的最小架构增量特化

目标平台 `h` 的可学习特化增量为：

$$
\delta_h^m=(RuleDelta_h^m,SlotDelta_h^m,ParamDelta_h^m).
$$

候选由特化算子生成：

$$
c_h=Specialize(P,K^m,S_h,\delta_h^m).
$$

其中 `S_h` 只提供 ISA、扩展、后端能力和合法化约束，`\delta_h^m` 表示为实现当前知识新增的规则、槽位绑定和少量参数。优化目标为：

$$
\delta_h^{m*}
=\arg\min_{\delta}
[G_h(K^m,c_h)+\lambda\Omega(\delta)-\beta PerfGain_h(c_h)],
$$

满足：

$$
Correct(P,c_h)=1,\qquad Legal(c_h,h)=1.
$$

`\Omega(\delta)` 衡量特有规则数、槽位修改数、可学习参数量或校准样本数。若去掉该项后平台模块重新学习完整策略且性能不变，则“最小架构增量”主张不成立。

## 8. 编译知识可迁移边界发现

知识在平台上的迁移分数定义为：

$$
T(K^m,h)
=Realization(K^m,h)
-\alpha AdaptCost(\delta_h^m)
-\gamma NegativeTransfer(K^m,h).
$$

据此形成三类实证结论：

| 类型 | 判据 |
|---|---|
| 架构通用知识 | 零样本或极小增量即可满足效应契约 |
| 架构敏感知识 | 少量反馈和有限增量后满足效应契约 |
| 架构特有知识 | 需要大增量，或原契约在该平台不可实现 |

分类阈值必须在训练平台验证集上预先固定，不能根据留出平台测试结果调整。两平台版本只能形成初步的跨平台知识分类；至少第三类平台采用完整 **leave-one-platform-out**（整个平台不参与训练）后，才能检验分类能否推广到未见架构。

## 9. 系统闭环与支撑模块定位

```text
程序 P + 知识 K(E*)
    → 检查 Pre
    → 读取平台约束 S_h
    → 学习/检索最小增量 δ_h
    → Specialize 生成候选
    → 正确性与合法性验证
    → 提取 Φ_h，计算 G_h
    → 排序器选择 Top-k 实测
    → 更新 δ_h 与 T(K,h)
```

- LLM 用于知识抽取、候选生成或失败解释，不是主创新；
- 双层知识是 EPAS 的数据结构；
- Adapter 只是 `\delta_h` 的参数实现之一；
- `Q_shared + Q_arch` 只对通过效应验证的候选排序；
- RISC-V 是重点实验平台，不是方法边界；
- 第一版不使用完整 RL，EPAS 的成立不依赖项目名称或 Agent 数量。

## 10. 最小可行版本与数据管线

- **平台**：x86 + RISC-V，只报告跨平台效应保持与架构特化；增强版增加 ARM 或 GPU。
- **程序**：20–40 个 PolyBench、MiBench 或 LLVM test-suite 子程序。
- **知识**：6–8 个效应契约，覆盖局部性、向量化、ILP/展开、访存、控制流和代码尺寸。
- **候选**：六个现有编译配置起步，扩展到 8–12 个 Pass 宏动作。
- **观测**：IR 特征、循环/CFG、向量化报告、机器指令混合、spill/reload、代码尺寸和运行时间。
- **学习**：监督式候选排序和轻量架构增量；校准预算 `K\in\{0,5,10,20,50\}`。
- **测量**：可信基线输出、固定输入、预热、重复运行、中位数、方差或置信区间。

现有 Mini Demo 仅作为采集骨架：模拟结果、人工 `policy_order()`、非空输出检查和单次计时均不能作为论文证据。本阶段不修改 Demo 代码，也不引入世界模型、多步 rollout、完整 RL、双 LLM、LLVM 后端源码改造或创新 05。

## 11. 实验设计、指标与可证伪标准

### 基线

固定 `-O3`、每平台独立调优、共享排序器、普通平台条件模型/Adapter、QiMeng 式静态提示、只有 intent 没有效应契约、有效应契约但没有最小增量约束，以及完整 EPAS。

### 消融

去掉 `E*`、去掉部分 `\Phi_h` 维度、只使用最终 runtime、去掉 `\Omega(\delta)`、固定人工迁移类别、全参数微调、随机候选选择，以及改变校准预算和平台组合。

### 指标

真实加速比、`Speedup@K`、效应契约实现率、平均 `G_h`、架构增量大小、校准样本数、负迁移率、知识分类稳定性、Top-k Recall、Regret@k 和真实测量次数。

### 可证伪条件

若效应契约不能提高正确性、迁移性或解释能力；去掉最小增量约束后无差异；每平台独立模型在同预算下稳定更优；自动知识分类不稳定；或同一知识不能产生可追溯的不同实现，则必须降低或否定 EPAS 核心主张。

## 12. 风险、降级与代码翻译接口

| 风险 | 降级方案 |
|---|---|
| 效应契约仍依赖人工定义 | 承认首版专家初始化，只把观测、最小增量和边界发现作为验证重点 |
| `G_h` 与性能无关 | 将其降为诊断指标，不再声称效应保持带来迁移收益 |
| `\delta_h` 无法保持稀疏 | 降级为受限平台特化，并报告实际适配成本 |
| 平台数量不足 | 两平台只做跨平台分析，未加入第三平台前删除未见架构结论 |
| 范围扩大 | 限定 6–8 个契约和 8–12 个宏动作，不修改 LLVM 后端 |

代码翻译模块可接收源代码/源 ISA、语义约束、`K^m` 和目标平台 `S_h`，以最小 `\delta_h` 绑定 RVV、AVX、NEON/SVE 等实现。候选通过语义、合法性和效应契约验证后进入排序。代码翻译是第二阶段扩展，不与第一版 Pass/配置实验同时做满。

## 13. 推荐命名与综合评分

**中文候选题目**：基于效应保持与最小架构增量的多硬件编译知识特化研究  
**英文候选题目**：*EPAS: Effect-Preserving Compiler Knowledge Specialization with Minimal Architecture Deltas*  
**核心创新名称**：效应保持的最小架构增量编译知识特化

| 维度 | 评分（5 分制） | 自审判断 |
|---|---:|---|
| 创新性 | 4.6 | 比双层 schema 或 Adapter 多出独立效应目标、增量约束和边界判据，但仍需查新 |
| 可行性 | 4.1 | 可从有限效应维度和宏动作开始，跨层采集需要工程投入 |
| 硕士适配度 | 4.4 | 两平台可完成核心原型，第三平台作为增强验证 |
| 工程成本 | 3.5 | 主要成本在稳定 MIR/汇编特征、硬件测量和效应归一化 |
| 重合风险 | 2.9 | 已明确避开 IntOpt 与 QiMeng 的直接贡献，仍需检索 effect contract 与 target specialization |

综合判断：EPAS 可以成为当前框架中最有个人辨识度的主创新，但只有在 `E_m^{*}`、`\Phi_h`、`G_h`、`\delta_h` 和 `T(K,h)` 均有可复现实验，并通过无效应契约、无最小增量和平台独立模型等强基线后，才能形成较强论文贡献。
