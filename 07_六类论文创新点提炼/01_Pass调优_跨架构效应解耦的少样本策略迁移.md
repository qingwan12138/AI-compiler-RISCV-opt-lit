# 类别一：Pass 调优——反事实删减驱动的序列因果归因

> 审阅结论：建议重写为“因果归因”，不再把“少样本跨架构迁移”本身当创新。
> 文献范围：本类 15 篇逐篇阅读笔记；重点参考 AutoPhase、CompilerGym、MileStone、Priority Sampling、CompilerDream 等。
> 证据强度：中高；“Booster Pass Chain”原文尚未核验，因此只作为潜在撞题风险，不作为论据。
> 日期：2026-07-15

## 1. 先说结论

这一类最值得继续做的问题，不是“再训练一个模型搜索 Pass 序列”，也不是“把 x86 策略迁到 RISC-V”，而是：

> 找到一个好序列以后，自动判断究竟是哪一个 Pass、哪一对 Pass、在什么编译状态下带来了真实收益，并把这种可复现实验结论反过来用于下一轮搜索。

推荐创新点名称：**反事实删减驱动的 Pass 序列因果归因与搜索预算重分配**。

## 2. 已有工作做到哪里了

| 已有能力 | 代表工作 | 已经不能单独宣称为创新的内容 |
|---|---|---|
| 用 RL 搜索 Pass 序列 | AutoPhase、早期 HLS Phase Ordering | “使用 PPO/DQN 做 Pass 排序” |
| 提供标准化交互环境 | CompilerGym | “把编译器包装成 Gym 环境” |
| 同时优化时间、尺寸、能耗 | MileStone | “多目标 Pass 调优” |
| 用更好的采样提高候选质量 | Priority Sampling | “约束 LLM 输出合法 Pass 序列” |
| 用世界模型模拟多步编译 | CompilerDream | “预测执行 Pass 后的 IR 状态” |
| LLM 直接预测 Pass 序列 | Large Language Models for Compiler Optimization | “LLM 生成优化序列” |

这些工作大多回答“怎样更快找到好序列”，但没有稳定回答“为什么这个序列好”。仅看最终奖励会产生三个混淆：

1. 某个 Pass 自身有效，还是它只是为后续 Pass 创造了机会；
2. 收益来自真正的代码结构变化，还是测量噪声、编译波动；
3. 一个 Pass 在当前状态有效，是否意味着它在其他位置也有效。

## 3. 真正的研究空白

### 3.1 事实层面的空白

- 长序列只得到一个终局奖励，中间动作信用分配弱。
- 静态特征或代理指标不能可靠说明真实性能来源。
- 搜索系统通常丢弃失败序列，很少把“删除某一步后反而更快”转成可复用知识。

### 3.2 本文提出的研究判断

把 Pass 序列视为一个可干预对象：对已发现序列执行删除、替换、相邻交换等最小干预，通过成对真实测量估计局部因果贡献。这里的“因果”是受控编译实验中的干预效应，不声称得到普适的程序因果定律。

## 4. 推荐创新点

### 4.1 一句话解释

找到一个好序列后，像拆积木一样每次只拿掉或交换一块，观察性能是否变化，由此找出真正有用的 Pass 和关键协同关系，再把搜索预算集中到这些位置附近。

### 4.2 核心机制

设原序列为 `S=[p1,p2,...,pn]`，真实硬件测得代价为 `J(S)`。系统自动构造：

- 删除反事实：`S\pi`，删除第 `i` 个 Pass；
- 替换反事实：用同类 Pass 或 no-op 替换 `pi`；
- 邻接交换：交换 `pi` 与 `p(i+1)`；
- 前缀复放：比较相同前缀下不同下一步的结果。

局部贡献可写成：

`Contribution(pi | S) = median[J(S\pi) - J(S)]`

同时记录 IR 差异、优化 remark、机器指令变化和测量置信区间。只有“代码确实发生预期变化”且“成对测量差异超过噪声阈值”时，才把它记为有效贡献。

随后构造 Pass 交互图：

- 节点：Pass；
- 有向边：`pi` 为 `pj` 创造或破坏机会；
- 边属性：适用的 IR 状态、收益分布、置信度；
- 搜索用途：提高高置信边附近的采样预算，降低重复探索无效区域的预算。

### 4.3 与最近工作的差别

| 工作 | 它主要做什么 | 本方向新增什么 |
|---|---|---|
| AutoPhase / Compiler-R1 | 从终局奖励学习策略 | 对序列做最小干预，估计动作局部贡献 |
| CompilerDream | 预测 Pass 后的 IR | 用真实编译与运行校准“预测变化是否产生收益” |
| Priority Sampling | 改进候选采样 | 根据已确认的交互效应动态重分配采样预算 |
| Booster Pass Chain | 可能研究 Pass 助推链 | 原文未核验；必须补全文后比较“助推关系的发现方法与验证方式” |

因此，新意不能写成“发现 Pass 之间有交互”，而应写成：**用受控反事实编译实验给交互关系分配可复验的效应值与置信度，并直接闭环到搜索预算。**

## 5. 最小可行实验

### 5.1 范围

- 20–50 个 LLVM benchmark；
- 选 12–20 个常用中端 Pass；
- 序列长度先限制在 8–16；
- 先在一台真实 CPU 上完成，RISC-V 可作为第二阶段外部有效性验证；
- 每个候选采用随机交错、重复测量和中位数聚合。

### 5.2 对照组

1. 随机搜索；
2. PPO 或 CompilerGym 常用 RL 基线；
3. Priority Sampling / LLM 候选生成；
4. 只有终局奖励、没有反事实归因的同模型版本。

### 5.3 指标

- 达到同等最佳性能所需的真实测量次数；
- 找到的最佳运行时间与代码尺寸；
- 归因稳定性：换一次运行顺序后贡献排序是否一致；
- 归因忠实度：删除“高贡献 Pass”是否显著破坏收益；
- 知识复用率：交互图对未见程序是否减少搜索次数。

## 6. 可证伪假设

主假设：在相同真实测量预算下，反事实归因引导搜索比只看终局奖励更快找到同等或更优序列。

若出现以下结果，应降低或放弃该方向：

- 大多数 Pass 的边际贡献小于测量噪声；
- 同一序列重复归因时排序高度不稳定；
- 反事实测量开销超过其节省的搜索预算；
- 交互知识只对原程序有效，对相似程序完全不能复用。

## 7. 论文边界：可主张与不可主张

可主张：

- 提出反事实编译干预协议；
- 建立带置信度的 Pass 交互图；
- 证明归因能否提高有限预算搜索效率。

不可主张：

- 首次用 RL/LLM 做 Pass 排序；
- 首次研究 Pass 交互；
- 少样本迁移本身是创新；
- 单次运行时间差就是因果效应。

## 8. 综合判断

| 维度 | 评分（5 分） | 说明 |
|---|---:|---|
| 新颖性 | 4.0 | 重点从“搜索器”转到“可干预归因闭环” |
| 可实现性 | 4.0 | 不依赖新硬件，LLVM 工具链即可起步 |
| 实验清晰度 | 4.5 | 有直接消融和证伪条件 |
| RISC-V 相关性 | 3.5 | 可在第二阶段检验归因是否跨后端稳定 |
| 风险 | 中 | 最大风险是测量噪声和反事实成本 |

最终建议：作为类别一的主创新方向。先做单硬件、高可信归因，再决定是否扩展到跨硬件；不要一开始就把研究问题稀释成泛化的迁移学习。
