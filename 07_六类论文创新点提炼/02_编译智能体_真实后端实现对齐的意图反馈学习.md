# 编译智能体：真实后端实现对齐的意图反馈学习

> **学术状态：候选创新，尚需针对性查新。** 自然语言 intent、多 Agent 和编译反馈均已有工作；本候选点只把“可测量意图—真实后端实现误差”作为待验证的新机制。
>
> **当前定位调整（2026-07-13）**：本文不再作为 EPAS 的独立主创新，而是[创新 06](06_多硬件编译_效应保持的最小架构增量知识特化.md)的**效应观测与解释支撑**。结构化后端证据用于构造 `\Phi_h(P,c)`，意图—实现对齐用于解释 `G_h(K^m,c)` 为什么成功或失效。IntOpt 已覆盖 intent formulation/refinement/realization，因此“显式输出优化意图”本身不能再主张为本文创新。

## 1. 候选创新点名称与命名拆解

- **研究对象**：IR 优化智能体。
- **核心新机制**：将优化意图表示成可测量的后端效果预期，并与实际 MIR/汇编/硬件变化对齐。
- **目标或约束**：用实现误差指导下一轮 IR 优化，而非只依赖最终标量奖励。

候选名称：**真实后端实现对齐的优化意图反馈学习**。

## 3. 已有工作已经解决的问题

已有研究已经覆盖 LLM 生成优化、编译器工具反馈、SFT+RL、多层/多 Agent 协作和优化意图。它们说明 Agent 能提出计划并读取工具结果，但尚不能据此主张“使用 intent”或“IR Agent + Backend Agent”是创新。

## 4. 尚未解决的研究空白

IR 智能体通常只知道最终运行时间或 IR 指标，没有明确回答“我希望暴露向量化/减少访存，后端实际上是否做到了”。当结果变差时，模型难以区分：意图错误、Pass 未实现意图、后端无法利用、或硬件不适合。

## 5. 核心机制与数学表示

定义结构化意图向量：

$$
z_t=[\Delta vector,\Delta memory,\Delta branch,\Delta ILP,
\Delta spill,\Delta size],
$$

每个分量包含方向、目标幅度、容忍区间和置信度。执行 IR 动作并经过目标后端后，提取实际变化：

$$
d_t=\Phi(F^{MIR}_{t+1}-F^{MIR}_{t},F^{ASM}_{t+1}-F^{ASM}_{t},E^{HW}_t).
$$

定义加权实现误差与最终奖励：

$$
L_{align}=\sum_j w_j\rho(z_{t,j}-d_{t,j}),
$$

$$
r_t=R_{runtime}-\lambda L_{align}-\mu C_{eval}.
$$

后端智能体返回的是结构化诊断 `d_t-z_t` 及证据（spill、向量指令、分支、访存等），而不是自由文本评价。LLM 可以解释该结构，但数值证据决定训练信号。

## 6. 系统组成与数据流

```text
当前 IR 与平台状态
  → IR Agent 选择 Pass/宏动作并输出意图向量
  → LLVM 生成 MIR/汇编/二进制
  → Backend Agent 提取实际变化并决定是否实机测量
  → 计算意图实现误差
  → 返回“未实现分量 + 后端证据 + 性能”
  → IR Agent 修改动作、回退或停止
```

## 7. 可检验的研究问题与假设

- **RQ1**：实现误差反馈是否比单一 runtime reward 更快识别无效 Pass？
- **RQ2**：结构化 intent 是否能提高跨程序和跨平台泛化？
- **RQ3**：模型能否区分“IR 意图未实现”和“意图已实现但硬件无收益”？
- **H1**：加入实现误差后，在相同实机评测预算下会获得更高性能并减少无效搜索。

## 8. 最小可行 Demo

先实现 4 类意图：暴露向量化、减少访存、降低分支、控制寄存器压力；为每类定义 2–3 个 Pass 宏动作。通过 `opt`、LLVM 统计、反汇编和运行时间构造 `z_t/d_t`。第一版 IR Agent 可用规则或现成 LLM，Backend Agent 先用确定性特征提取器，不必同时训练两个 LLM。

## 9. 实验平台、基线、消融与指标

- **平台**：x86 + RISC-V；TSVC/PolyBench/MiBench/LLVM test-suite 子集。
- **基线**：Compiler-R1 风格最终奖励、无 intent 的 Agent、自然语言 intent、结构化 intent 但无对齐损失、完整方法。
- **消融**：去掉硬件事件、去掉机器码特征、去掉目标幅度只保留标签、随机诊断、只用 IR 指令数。
- **指标**：加速比、意图实现分类 F1/幅度误差、无效动作识别率、恢复成功率、评测次数、正确率、跨平台性能保持率。

## 10. 与已有工作的创新边界

边界不在“intent”一词，也不在 Agent 通信格式，而在：**意图被定义为可观测的目标后端变化；实际实现可验证；实现误差直接进入学习和决策**。必须重点查新 IntOpt、ACCLAIM、compiler feedback、goal-conditioned compiler optimization 和 intent realization。

## 11. 主要风险与降级方案

- **意图与性能非单调**：把对齐误差作为辅助信号，真实性能仍是最终目标。
- **事件不可跨平台统一**：采用通用语义维度，底层计数器通过平台映射层归一化。
- **MIR/寄存器压力难提取**：第一版使用汇编指令混合、spill/reload 和代码尺寸代理。
- **范围过大**：只做 IR 候选生成 + 后端诊断，不修改 LLVM 后端。

## 12. 与当前研究方向的关系

该候选点直接连接“代码/IR 变换—编译后端—RISC-V 实机”，并且不把 RISC-V 写死。当前它为 EPAS 提供跨层效应观测和失效解释，不单独承担主创新；它也能与跨 ISA 代码翻译结合，由翻译器给出语义/性能意图，后端提供可测量实现证据。
