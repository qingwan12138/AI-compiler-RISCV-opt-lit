# FAME-Opt 项目总览与研究定位

## 1. 项目摘要

FAME-Opt 是一个面向真实性能提升的 LLM 编译优化框架。系统要求 LLM 在优化前声明适用前提、优化动作、预期机制、可观察证据和否定条件；编译器执行后，再通过正确性、运行时间、Optimization Remarks、IR/汇编和选择性反事实判断该经验是否可信。

候选被划分为：

1. **确认成功：** 正确、稳定变快且机制被证据和反事实支持；
2. **偶然成功：** 正确且变快，但 LLM 声称的机制不成立；
3. **机制无收益：** 机制确实发生，但没有性能收益；
4. **失败：** 编译、正确性或安全检查失败。

只有确认成功经验允许作为正向可迁移知识，偶然成功和机制无收益进入负经验或警告库。

---

## 2. 主研究问题

> 在固定的编译、运行和 LLM 调用预算下，基于可证伪归因记忆的编译优化智能体，能否比随机搜索、无反馈 LLM 和普通反馈式 LLM 更快找到相对 `-O3` 的稳定高性能候选，同时减少负优化和错误经验传播？

---

## 3. 研究动机

现有 AI 编译优化普遍使用：

```text
LLM 提出优化
→ 编译
→ 测试
→ 测性能
→ 反馈
→ 再优化
```

但仍有三个断层。

### 3.1 结果成功不代表解释正确

程序变快可能来自：

- 另一个未声明 Pass；
- 常量传播或内联；
- 输入特化；
- 测量波动；
- 错误程序少做了计算。

直接保存“动作 + 加速比”会把错误机制传播到其他程序。

### 3.2 归因验证会增加成本

逐动作删除、交换、跨层分析和多输入复测会显著增加编译和运行次数，因此必须选择性验证。

### 3.3 语义正确不代表值得应用

正确变换可能因代码膨胀、寄存器压力、缓存、输入规模或目标硬件差异而变慢。语义证书不能代替性能证书。

---

## 4. 首版研究对象

| 维度 | 首版设置 |
|---|---|
| 语言 | C/C++ |
| 编译器 | Clang/LLVM |
| 优化粒度 | 编译参数、循环 Hint、受限 Pass 宏动作 |
| 平台 | 单一 x86-64 真机 |
| 程序 | 可独立验证和计时的小型 kernel |
| 性能裁决 | 真实运行时间 |
| AI | 现成 LLM |
| 训练 | 首版不训练 |
| 验证 | 差分测试、边界输入、随机输入、Sanitizer |
| 机制证据 | Remark、IR 摘要、汇编摘要、可选 PMU |

---

## 5. 首版明确不做

- 完整 LLVM Pass 排序搜索；
- 修改 LLVM 后端；
- 任意源码自由重写；
- 自动生成全新优化 Pass；
- 三平台同时测量；
- 多硬件少样本代价模型；
- 完整程序形式验证；
- 从零训练编译器大模型；
- 将 QEMU 时间写成真实硬件性能。

这些可在单平台机制成立后逐步增加。

---

## 6. 六类创新点如何收敛

| 原方向 | 吸收内容 | 本项目地位 |
|---|---|---|
| Pass 排序与 RL | 反事实删除、信用和测量预算 | 创新点二 |
| LLM 智能体与反馈 | 证据契约、反证、记忆 | 主线与创新点一 |
| 形式验证与规则生成 | 语义与盈利解耦 | 创新点三 |
| 向量化与跨 ISA | 向量化动作、跨 ISA 压力测试 | 实验场景 |
| RISC-V/RVV 后端 | RISC-V 真机验证 | 第二阶段平台 |
| 多硬件代价模型 | 硬件条件化盈利范围 | 后续候补扩展 |

本项目不把六类全部堆进首版，而是收缩为：

> AI 应学习什么样的编译优化经验，才能用有限试验获得真实、可信、可复用的性能收益？

---

## 7. 核心假设

### H1 机制可信度

FOEU 能识别普通性能日志无法区分的偶然成功。

### H2 经验质量

只使用确认成功和结构化负经验，比使用全部成功样本更能降低未见程序负优化。

### H3 测量效率

信息价值驱动的最小反事实探针，在相同预算下比固定探针获得更高归因质量。

### H4 安全部署

双证书门控降低正确但不盈利候选的接受率，并改善最坏程序性能。

### H5 最终性能

完整方法在相同候选预算下，比随机或普通反馈方法找到更优或相当的真实运行性能。

---

## 8. 项目最终输出

- 自动编译、验证、计时框架；
- 固定动作空间；
- FOEU Schema 和经验库；
- 最小反事实调度器；
- 语义与盈利证书；
- 单平台性能和泛化实验；
- RISC-V 扩展实验；
- 原始计时、失败日志、配置和复现脚本。

---

## 9. 性能提升的合理目标

不能预先承诺所有程序都超过 `-O3`。合理目标是同时证明：

- 部分程序有稳定提升；
- 几何平均不劣于强基线；
- 相同预算下搜索更高效；
- 负优化更少；
- 最坏程序损失更低；
- 错误性能解释更少进入记忆。
