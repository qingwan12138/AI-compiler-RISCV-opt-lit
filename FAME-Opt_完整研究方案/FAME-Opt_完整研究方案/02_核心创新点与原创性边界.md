# FAME-Opt 核心创新点与原创性边界

## 1. 三个创新点的逻辑

```text
FOEU：定义什么经验值得 AI 学习
          ↓
最小反事实：用尽可能少的测量确认关键动作
          ↓
双证书：决定经验能否在当前条件下部署
```

---

# 2. 创新点一：可证伪优化经验单元 FOEU

## 2.1 定位

**FOEU 是本框架的重点候选独属创新。**

普通记录通常是：

```text
程序 P + 动作 A → 加速 1.05×
```

FOEU 记录：

```text
程序与环境
+ 适用前提
+ 优化动作
+ 机制主张
+ 应出现的证据
+ 能推翻机制的条件
+ 正确性证书
+ 盈利证书
+ 反事实结果
+ 适用范围
+ 最终状态
```

## 2.2 建议结构

```json
{
  "foeu_id": "foeu_0001",
  "program": {
    "program_id": "dot_product",
    "family": "reduction",
    "source_hash": "..."
  },
  "environment": {
    "compiler": "clang",
    "compiler_version": "...",
    "target": "x86_64",
    "cpu": "...",
    "input_id": "n_1048576"
  },
  "preconditions": [
    "trip_count >= 1024",
    "contiguous_memory",
    "no_loop_carried_dependency"
  ],
  "actions": [
    {"type": "loop_unroll", "factor": 4}
  ],
  "expected_mechanism": [
    "reduce branch overhead",
    "increase instruction-level parallelism"
  ],
  "expected_evidence": [
    {"source": "remark", "predicate": "loop-unroll success"},
    {"source": "assembly", "predicate": "branch count decreases"}
  ],
  "falsifiers": [
    "unroll remark absent",
    "branch count unchanged",
    "speedup disappears on boundary input"
  ],
  "semantic_certificate_id": "sem_0001",
  "profitability_certificate_id": "profit_0001",
  "counterfactual": {
    "probe": "remove_unroll",
    "credit_log_ratio": 0.031,
    "confidence_interval": [0.012, 0.049]
  },
  "final_state": "confirmed_success",
  "applicability_scope": {
    "input_range": [1024, 16777216],
    "targets": ["x86_64"]
  }
}
```

## 2.3 四态分类

| 状态 | 正确性 | 性能 | 机制证据 | 经验权限 |
|---|---|---|---|---|
| 确认成功 | 通过 | 稳定提升 | 支持 | 正向检索、正训练样本 |
| 偶然成功 | 通过 | 稳定提升 | 不支持 | 只作解释负样本 |
| 机制无收益 | 通过 | 无提升/退化 | 支持 | 负经验、适用边界 |
| 失败 | 不通过 | 不计算 | 不审计 | 合法性/正确性负样本 |

## 2.4 重点价值

FOEU 不是普通结构化日志，它强调：

1. 事前声明否定条件；
2. 结果真实性和解释真实性分离；
3. 偶然加速不得传播错误机制；
4. 负经验拥有明确复用权限；
5. 经验可主动拒绝跨程序或跨硬件迁移；
6. 同一结构可用于 RAG、SFT、偏好学习和 RL。

## 2.5 直接实验

### E1 偶然成功识别

构造多动作候选，让程序变快但 LLM 声称机制错误。比较：

- 普通运行时间反馈；
- 自由文本解释；
- FOEU 静态证据；
- FOEU + 反事实。

指标：

- 偶然成功识别率；
- 错误解释入库比例。

### E2 未见程序记忆

比较：

- 无记忆；
- 所有成功样本；
- 自由文本经验；
- 仅确认成功 FOEU；
- FOEU + 负经验。

指标：

- 达到目标加速的候选数；
- 负优化率；
- 重复失败率；
- 最优性能。

# 3. 创新点二：信息价值驱动的最小反事实信用探针

## 3.1 问题

完整反事实成本约为：

```text
程序数 × 候选数 × 动作数 × 重复运行次数
```

因此不能对全部候选逐动作消融。

## 3.2 调度目标

候选价值可写成：

```text
ProbeValue =
  机制不确定性
  × 预期收益
  × 复用潜力
  × 改变决策的概率
  ÷ 额外测量成本
```

首版使用规则评分即可：

```text
+2：准备进入正经验库
+2：加速大于 2%
+2：包含多个动作
+2：证据冲突
+1：准备在未见程序复用
-2：运行成本过高
-2：正确性未通过
```

## 3.3 最小探针

| 动作 | 探针 |
|---|---|
| 展开 | 仅恢复默认展开因子 |
| 循环向量化 | 关闭循环向量化 |
| SLP | 单独关闭 SLP |
| 内联 | 恢复默认阈值 |
| 循环分布 | 移除分布 Hint |
| Pass 宏动作 | 删除一个关键动作 |
| 输入条件 | 改变一个边界规模 |

## 3.4 信用

```text
Credit(a) = log(T_without_a / T_with_a)
```

必须结合重复测量置信区间：

- 区间明显大于零：正贡献；
- 包含零：贡献不确定；
- 明显小于零：可能负贡献。

## 3.5 停止条件

- 信用区间已支持或否定机制；
- 候选不再达到盈利阈值；
- 再测不会改变 FOEU 状态；
- 候选不进入经验库；
- 剩余预算不足。

## 3.6 原创边界

不能声称“首次通过删除 Pass 做归因”。更稳妥的表述：

> 面向 LLM 编译优化经验入库和复用决策，联合解释不确定性、性能收益、复用价值和测量成本调度最小反事实探针。

# 4. 创新点三：语义—盈利双证书门控

## 4.1 语义证书

回答：

> 优化是否在声明的测试和验证范围内保持语义？

保存：

- 参考实现和哈希；
- 固定、边界、随机输入；
- 输出比较；
- Sanitizer；
- 浮点容差；
- 可选 Alive2；
- 验证工具版本。

## 4.2 盈利证书

回答：

> 优化在什么程序、输入、编译器和硬件条件下具有可靠收益？

保存：

- `-O3` 基线；
- 全部运行时间；
- 中位数；
- 加速比；
- 置信区间；
- 代码尺寸和可选 PMU；
- 适用输入范围；
- 编译器和平台。

## 4.3 自动接受

```text
SemanticValid = true
AND
LowerCI(Speedup) > 1 + delta
AND
NoCriticalFalsifier = true
```

`delta` 可根据噪声设为 1% 或 2%。

## 4.4 决策

| 语义 | 盈利 | 决策 |
|---|---|---|
| 通过 | 通过 | 接受并审计机制 |
| 通过 | 不确定 | 补测或回退 `-O3` |
| 通过 | 不盈利 | 拒绝部署，记录负经验 |
| 不通过 | 任意 | 立即拒绝 |

## 4.5 RISC-V 扩展

盈利证书可增加：

- ISA 扩展；
- 微架构；
- VLEN；
- SEW/LMUL；
- 尾部/掩码；
- 输入长度相对 VL；
- 编译器版本。

语义证书可能跨平台复用，但盈利证书不能未经测量直接迁移。

# 5. 最小实现与增强版

| 创新 | Demo | 正式增强 |
|---|---|---|
| FOEU | JSON + 四态 | 检索、训练、拒绝迁移 |

# 6. 新颖性表述

可以说：

- 提出候选的可证伪优化经验表示；
- 隔离偶然成功和错误机制；
- 将选择性反事实用于经验入库；
- 将语义和条件化盈利赋予不同复用权限。

暂时不能说：

- 首次使用编译器反馈；
- 首次使用反事实 Pass 删除；
- 首次将正确性和性能结合；
- 首次使用 LLM 优化 RISC-V。

falsifiable compiler optimization agent
