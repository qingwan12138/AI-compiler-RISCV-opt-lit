# FAME-Opt 正式实验与评测协议

## 1. 研究问题

### RQ1 性能

相同候选预算下，FAME-Opt 是否比 `-O3`、随机搜索和普通反馈 LLM 找到更高真实性能？

### RQ2 机制可信度

FOEU 是否能识别偶然成功、机制无收益和错误解释？

### RQ3 测量效率

最小反事实探针能否用更少测量获得接近或更好的归因结果？

### RQ4 部署安全

双证书是否降低负优化率和最坏程序损失？

### RQ5 经验泛化

确认成功和负经验是否帮助未见程序减少候选数和重复失败？

### RQ6 跨平台

加入 RISC-V 后，哪些经验语义可迁移但盈利不可迁移？盈利证书能否拒绝负迁移？

## 5. 公平预算

所有方法必须共享：

- 候选编译数；
- 正式运行次数；
- LLM 调用或等价成本；
- 最大墙钟时间；
- 动作空间；
- 输入；
- 正确性协议。


## 6. 指标

### 6.1 性能

- 几何平均加速；
- 中位加速；
- 超过 `-O3` 比例；
- 负优化率；
- 最坏 10%；
- 回退后的安全性能。

### 6.2 搜索效率

- 达到 1%/2%/5% 提升所需候选；
- best-so-far 曲线；
- 总编译；
- 总运行；
- 墙钟时间；
- token/费用；
- 每 100 次测量的确认成功数。

### 6.3 正确性

- 编译成功率；
- 测试通过率；
- Sanitizer 通过率；
- Alive2 通过/unknown；
- 错误候选被接受比例。

### 6.4 可信度

- 证据匹配；
- 偶然成功识别；
- 机制无收益识别；
- 错误解释入库率；
- 反事实信用区间。

### 6.5 泛化

- 未见程序 best speedup；
- 候选有效率；
- 负经验避免失败数；
- 经验拒绝率；
- 错误迁移率；
- RISC-V 盈利保持率。

## 7. 消融

| 消融 | 验证 |
|---|---|
| 无 FOEU，只存动作和加速 | 结构化可证伪经验价值 |
| 无事前机制声明 | 事后解释是否迎合结果 |
| 无反事实 | 归因是否可靠 |
| 全量固定反事实 | 信息价值调度是否省预算 |
| 无负经验 | 是否重复失败 |
| 无盈利证书 | 负优化是否增加 |
| 无置信区间 | 性能假阳性 |
| 无回退 | 安全性能 |
| 无经验检索 | 经验是否真正帮助 |

## 9. 正式成功标准

至少满足：

1. 相同预算下几何平均优于一个强搜索基线；
2. 未见程序不低于普通反馈 LLM；
3. 负优化率或最坏性能改善；
4. FOEU 减少错误经验入库；
5. 选择性探针减少测量或提高信息量；
6. 至少一个核心消融明显退化；
7. RISC-V 扩展能识别并拒绝部分负迁移。

不能只报告一个程序的最高加速。

## 10. RISC-V 扩展

目的：

> 验证单平台建立的语义和盈利经验在 RISC-V 上如何变化。

优先任务：

- 向量化；
- 展开；
- stride；
- reduction；
- 分支和代码尺寸。

比较：

- 直接迁移 x86 经验；
- RISC-V 重新搜索；
- 盈利证书拒绝/补测；
- 可选硬件条件。

报告：

- 语义保持；
- 盈利保持；
- 负迁移；
- 拒绝准确率；
- 输入规模性能悬崖。
