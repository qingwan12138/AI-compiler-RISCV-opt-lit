# FSCM 文献阅读总结

论文题目：**Beyond Surface-Level Pattern Trap: LLM Agents for Faster and Smarter Cross-Architecture Code Migration**

作者：Weijia Li、Ke Gao、Pengfei Chen、Jiajie Li、Xinyu Wang、Yiran Le、Yize Wu、Ling Li

发表时间：2026

发表平台：Findings of ACL 2026

关键词：跨架构迁移、ARM NEON、RISC-V RVV、代码重构、多智能体

> 本文档基于 PDF 全文整理。

## 1. 研究背景

ARM NEON 到 RVV 等低资源迁移中，LLM 容易按函数名、类型或 intrinsic 做表面映射，忽略跨函数依赖、算法语义和目标架构优化意图，导致“能编译但不正确”或机械模仿不存在的 API。

## 2. 论文要解决的问题

如何先从大型高性能库中挖掘与架构无关的功能语义，再恢复源架构的优化意图并注入 RVV 专用策略，提高迁移正确性与性能。

## 3. 核心方法概述

FSCM 全局解析仓库并重构函数依赖图；先让 Function-Aware Agent 生成通过官方测试的标量语义锚点，再继承源代码的循环/布局/快速路径意图，最后由架构优化 Agent 注入 RVV 的 VLA、寄存器分组与 intrinsic。

## 4. 实验框架与训练流程

```text
ARM 库 → 全局依赖图/功能挖掘 → 标量实现 → 官方测试
      → 源优化意图继承 → RVV 知识注入 → 编译/正确性/性能多阶段反馈
```

这是推理期多 Agent 框架，无模型训练或 RL。

## 5. 奖励函数、损失函数或关键公式

无训练损失。编译成功 CS 为后续门控；测试成功率 `TS=Npassed/Ntests`；加速比 `SR=Tscalar/Tvector`。

## 6. 实验设置

### 6.1 数据集来源

OpenCV Core/Imgproc 共 33 个算子（17+16），另以 NCNN 做补充泛化实验；源为 ARM NEON 优化实现。

### 6.2 模型与工具

Claude-Sonnet-4-20250514、Grok-4；目标硬件为进迭时空 SpacemiT X60 与阿里 T-Head C908，使用官方 OpenCV 测试。

### 6.3 对比方法

直接 Claude、Skeleton 方法、Codex Agent、Copilot Agent、编译器 `-O3` 与人工实现；消融比较直接 CoT 和依赖图引导生成。

### 6.4 评价指标

CS、TS、相对标量的 SR，以及时间/API/Token 成本。

## 7. 实验结果与结论

FSCM 在 OpenCV 上测试成功率 78%，优于最佳基线 Copilot 的 59%（论文摘要概括为最高约 22 个百分点正确性提升）。在两款 RISC-V 平台的多算子/尺寸上显著优于 `-O3`，论文总结最高获得 43.04× 加速；部分场景也超过人工实现，但个别乘法场景仍低于 1×。依赖图消融在复杂 Imgproc 上改善最明显，说明跨函数语义重构是主要贡献。

## 8. 主要创新点

### 8.1 提出“表面模式陷阱”并给出结构化解法

把跨 ISA 迁移失败归因于语义与实现细节未解耦。

### 8.2 标量语义锚点

先完成可测试的架构无关实现，再做向量性能优化，降低调试耦合。

### 8.3 优化意图继承与目标知识注入分离

保留算法级快路径，同时按 RVV VLA 特性重新实现低层代码。

## 9. 局限性

作者明确只覆盖 OpenCV/NCNN、33 个主要算子和 ARM NEON→RVV；目标仅 X60/C908。加速相对标量基线，数值容易很大，不能等同于相对成熟 ARM/RVV 实现；结果受提示和编译器版本影响，官方测试仍非形式等价证明。

## 10. 阅读后的研究方向反思

这篇论文已直接覆盖“LLM+跨架构+RISC-V”，因此再做同类多 Agent 迁移很容易撞题。可避开的方向是：把重点转到迁移结果的可证明验证、跨 VLEN 鲁棒性、编译器 IR 级语义锚点或自动定位何时不该迁移。

## 11. 可进一步尝试的研究方向

### 11.1 可证明的跨 VLEN 迁移验证

#### 研究问题

RVV 迁移代码在不同 VLEN、尾长和别名条件下是否保持语义。

#### 与原论文的区别

不重做迁移 Agent，而为 FSCM 类系统增加属性测试、符号/等价验证与反例反馈。

#### 可能的创新点

VLEN 参数化测试生成和反例最小化。

#### 实验框架

```text
迁移代码 → 多 VLEN 属性输入 → 差分/符号检查 → 反例反馈 → 修复 → K3 实测
```

#### 可行性与风险

边界输入可系统生成；完整 intrinsic 形式验证工具支持有限。

## 12. 最小可行 Demo

### 12.1 Demo 目标

审计 20 个 ARM→RVV 迁移函数的 VLEN/尾处理正确性。

### 12.2 输入数据

FSCM 开源迁移样本或 OpenCV RVV 函数。

### 12.3 执行流程

```text
生成长度/对齐/别名边界 → QEMU 多 VLEN 差分 → K3 验证 → 汇总反例
```

### 12.4 需要的工具

RISC-V GCC/Clang、QEMU、K3、OpenCV 测试、属性测试框架。

### 12.5 输出结果

| 函数 | 常规测试 | 多 VLEN 测试 | 发现反例 | 修复后加速 |
|---|---:|---:|---:|---:|

### 12.6 成功标准

发现常规测试遗漏的真实错误，并在修复后保持性能。

## 13. 与其他已读文献的关系

与 N17 AutoVecCoder 都面向 SIMD，但 FSCM 是跨文件迁移且已实测 RVV；与 N24 BRIDGE 都先恢复规范结构/语义锚点；与 N25 CoV 可组合为迁移结果的多层验证链。

## 14. 一页式总结

| 项目 | 内容 |
|---|---|
| 论文研究任务 | ARM NEON 到 RVV 高性能库迁移 |
| 核心问题 | LLM 陷入表面 intrinsic 映射 |
| 输入/输出 | ARM 库 / 正确且优化的 RVV 库代码 |
| 核心方法 | 全局重构 + 标量锚点 + 优化继承/注入 |
| 使用的模型 | Claude Sonnet 4、Grok-4 |
| 使用的编译器工具 | RISC-V 工具链与 OpenCV 测试 |
| 是否使用强化学习 | 否 |
| 是否使用形式化验证 | 否 |
| 数据集规模 | OpenCV 33 算子，另测 NCNN |
| 主要指标 | CS、TS、相对标量加速 |
| 最重要实验结果 | TS 78%；最高 43.04× |
| 核心创新 | 语义锚点与架构优化意图解耦 |
| 主要局限 | 单迁移方向、算子少、加速基线为标量 |
| 与 RISC-V 研究的相关性 | 直接相关，且是强碰撞基线 |
| 最适合作为 | 跨架构迁移对比框架 |

> 若继续做 RISC-V，应把 FSCM 当必须正面对比的强基线，创新转向验证和跨 VLEN 鲁棒性更安全。
