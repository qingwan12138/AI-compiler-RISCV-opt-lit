# SBLLM 文献阅读总结

论文题目：**Search-Based LLMs for Code Optimization**

作者：Shuzheng Gao、Cuiyun Gao、Wenchao Gu、Michael R. Lyu

发表时间：2025

发表平台：ICSE 2025

论文链接或编号：arXiv:2408.12159

关键词：代码优化、LLM、进化搜索、检索增强、执行反馈

> 本文档基于 PDF 全文整理。

## 1. 研究背景

一次性提示 LLM 生成优化代码，难以组合多种优化策略，也无法充分利用候选程序之间的性能差异。代码优化更接近一个需要反复选择、变异和评测的搜索问题。

## 2. 论文要解决的问题

如何让 LLM 在执行反馈和优化模式指导下迭代搜索，而不是只生成一次，从而提高正确且至少快 10% 的代码比例。

## 3. 核心方法概述

SBLLM 包含三部分：执行驱动的代表候选选择；根据当前代码自适应检索相似/差异优化模式；借鉴遗传算子的 GO-COT 提示，让模型分析候选优缺点并继续生成。

## 4. 实验框架与训练流程

```text
慢代码 → 多候选生成与执行
      → 按正确性/加速比/结构差异选 3 个代表
      → 检索针对性优化模式
      → GO-COT 组合、变异和修复
      → 最多 4 轮，返回最佳候选
```

这是无需微调的推理期搜索框架，不使用 RL 参数更新。

## 5. 奖励函数、损失函数或关键公式

```text
OPT(o)=1，当且仅当 A(o)=1 且 T(s)/T(o)>1.1
SP(o)=T(s)/T(o)；若错误或变慢，则记为 1.0
```

搜索适应度主要由正确性和实测加速比构成，同时用 AST 抽象后的编辑距离维持候选多样性。

## 6. 实验设置

### 6.1 数据集来源

PIE/CodeNet：Python 训练 36,857、验证 1,940、测试 986；C++ 训练 77,967、验证 2,544、测试 994；对应 3,474 道题。

### 6.2 模型与工具

CodeLlama-34B-Instruct、Gemini-Pro、GPT-3.5-Turbo-0613、GPT-4-1106-preview。Python 3.9.12；C++17、GCC 9.4.0 `-O3`。

### 6.3 对比方法

Instruction、ICL、BM25-RAG、CoT；并做候选选择、模式检索、GO-COT 消融。

### 6.4 评价指标

OPT@k 和 SP@k。每个程序执行 25 次，去掉第一次后求平均；GPT-4 因成本只抽取 10% 测试集。

## 7. 实验结果与结论

相对最强 CoT 基线，SBLLM 的 OPT@5 在 Python/C++ 上平均提升 5.11/2.87 个百分点。以 ChatGPT 为例，Python OPT@1/3/5 为 34.58%/37.32%/38.44%，SP@5 为 1.8208；C++ OPT@5 为 8.21%，SP@5 为 1.2226。去掉代表候选选择后，Python/C++ OPT@1 分别下降 10.93/2.05 个百分点；去掉 GO-COT 后，Top-1 加速率分别下降 5.08%/7.85%。3 个代表样本、约 4 轮搜索总体最好。

## 8. 主要创新点

### 8.1 将代码优化显式建模为搜索

用多轮演化代替一次性生成。

### 8.2 性能与多样性联合选种

候选既要快，也要结构上不重复，避免搜索过早收敛。

### 8.3 自适应模式检索与 GO-COT

检索内容随当前候选变化，并让模型以交叉、变异思路组合优化策略。

## 9. 局限性

多轮 LLM 调用和每轮执行 25 次的成本高；公共测试驱动搜索可能过拟合；实验仅覆盖竞赛型 Python/C++，且 GPT-4 只测试 10% 数据。执行通过也不等于对所有输入语义等价。

## 10. 阅读后的研究方向反思

SBLLM 与多数“LLM 优化器”的真正差异是搜索控制器，而不是换了提示词。后续创新应聚焦预算分配、跨硬件反馈和可证明门控，不能只再加一个 Agent 名称。

## 11. 可进一步尝试的研究方向

### 11.1 跨硬件多保真搜索

#### 研究问题

能否先用编译器代价模型/模拟器筛选，再在 x86 与 RISC-V 真机上少量验证。

#### 与原论文的区别

把单机实测适应度改为多硬件、多保真反馈，并显式控制评测预算。

#### 可能的创新点

不确定性驱动的测量升级策略和跨 ISA 鲁棒 Pareto 搜索。

#### 实验框架

```text
候选 → 静态估计 → 模拟/小输入 → 真机 → 置信度更新 → 下一轮搜索
```

#### 可行性与风险

现有 LLVM-MCA/QEMU/开发板可搭建；风险是低保真排序与真机不一致。

## 12. 最小可行 Demo

### 12.1 Demo 目标

在固定 100 次真机测量预算内比较单层与多保真搜索。

### 12.2 输入数据

50 个 PolyBench/竞赛 C 程序及多个编译候选。

### 12.3 执行流程

```text
LLM 生成 → 编译/单测 → 静态筛选 → x86/K3 测量 → 更新候选池
```

### 12.4 需要的工具

Clang/LLVM、QEMU 或 llvm-mca、x86 主机、K3 开发板、代码 LLM。

### 12.5 输出结果

| 策略 | 真机测量数 | 正确率 | 最佳加速比 | 跨机型退化率 |
|---|---:|---:|---:|---:|

### 12.6 成功标准

同预算下找到更快候选，且不增加跨硬件退化。

## 13. 与其他已读文献的关系

与 N03 StepCoder 相同点是使用反馈逐步改进，但 SBLLM 不训练策略；可用 N05 的效率判别器降低评测成本，用 N04 ECCO 的稳定执行协议补强评测可信度。
