## 1. 研究问题与动机

如何避免让 LLM 逐段重写代码带来的慢、不透明和难验证问题。

## 2. 方法与系统结构

由少量输入/输出示例合成 Python 变换器，执行后把反例和异常反馈给模型迭代修正。

## 3. 实验与主要发现

16 种变换中 7 种达到完全精确，其余多数也比直接 LLM 重写更少误变换。

## 4. 局限与批判性阅读

任务规模小，生成的变换器仍需人工审查；部分规则不够简洁或泛化不足。

## 5. 对当前研究方向的关系

与 CABLE 的结构化知识对象高度契合，可把动作保存成可执行、可验证规则。

## 6. 可提炼的研究启发

让 LLM 编写变换规则比直接改写每个程序更可审计、复用和低成本。

## 7. 一句话总结

让 LLM 编写变换规则比直接改写每个程序更可审计、复用和低成本。
