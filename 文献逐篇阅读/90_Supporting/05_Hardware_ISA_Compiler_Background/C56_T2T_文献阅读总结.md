# C56 From Threads to Tiles: T2T, a Compiler for CUDA-to-NPU Translation via 2D Vectorization 文献阅读总结

论文题目：**From Threads to Tiles: T2T, a Compiler for CUDA-to-NPU Translation via 2D Vectorization**  
作者：Shuaijiang Li、Jiacheng Zhao、Ying Liu、Shuoming Zhang、Lei Chen、Yijin Li、Yangyu Zhang、Zhicheng Li、Runyu Zhou、Xiyu Shi、Chunwei Xia、Yuan Wen、Xiaobing Feng、Huimin Cui。  
发表：CGO 2026 主会，pp. 362–374，DOI [10.1109/CGO68049.2026.11395190](https://doi.org/10.1109/CGO68049.2026.11395190)。来源：[CGO 官方论文页](https://2026.cgo.org/details/cgo-2026-papers/32/From-Threads-to-Tiles-T2T-a-Compiler-for-CUDA-to-NPU-Translation-via-2D-Vectorizati)、[White Rose Accepted Version](https://eprints.whiterose.ac.uk/id/eprint/244124/)。阅读本地 PDF 14 页。

## 1. 研究背景

CUDA 以标量线程和 SIMT 表达并行，而 Ascend、Cambricon 等 NPU 使用显式二维 tile 指令、片上 scratchpad 和不同的同步语义。直接把 CUDA 线程映射到 NPU 会丢失跨线程/跨 block 的规则性，产生掩码、非合并访存和低硬件利用率。T2T 将这个差距形式化为从 threads 到 tiles 的 lifting 问题。

## 2. 论文要解决的问题

如何在保持 CUDA 内存、同步和 warp-level 语义的前提下，自动发现可组合的二维并行区域，将多个 block/warp/thread 循环映射到 NPU 的二维 tile 指令，并对不同 NPU 后端保持可重用的中间表示和代码生成接口。

## 3. 核心方法概述

前端用 Polygeist 将 CUDA 转为 MLIR；Unified Parallelism Abstraction（UPA）把 grid、block、warp 和 thread 关系显式化；控制流向量化和 loop fission 将同步点转换为可独立处理的区域；二维 vectorization pass 选择最多七个候选循环中的组合，检查 stride、segment stride、repeat 和对齐约束，生成 NPU tile 计划；随后通过 mask simplification、in-place computation、warp-level function vectorization 和 NPU 特定 lowering 生成 Ascend CCE 或 Cambricon BangC。

## 4. 实验框架与训练流程

没有机器学习训练。T2T 是基于规则和 IR 分析的编译器。其搜索对象是每个 UPA unit 内的 loop/vectorization plan，按硬件合法性和利用率选择方案。论文开源实现地址为 [github.com/onlyoh/T2T](https://github.com/onlyoh/T2T)。

## 5. 奖励函数、损失函数或关键公式

没有奖励或损失函数。核心约束是 NPU 二维指令的 stride、segment stride、repeat 和 bank/alignment 限制。实验性能定义为 NPU 程序吞吐率与理论峰值之比，再除以 NVIDIA A100 CUDA 对应比值；因此报告的 0.8 表示达到 CUDA 基线归一化利用率的 80%。

## 6. 实验设置

目标硬件为 Huawei Ascend 910B 和 Cambricon MLU370，NVIDIA A100 用作正确性与性能参照。基准包括 Rodinia 中 28 个可运行 CUDA kernel，以及 AI CUDA Engineer suite 的 65 个 kernel；每个 kernel 在物理设备上执行，时间平均 1000 次。比较对象是仅做一维向量化的自实现 baseline，并单独报告 control-flow optimization 与二维向量化的增量。

## 7. 实验结果与结论

T2T 在两类 NPU 上成功执行全部 65 个 AI CUDA Engineer kernel 和 28 个 Rodinia kernel。AI suite 上，Ascend 910B 达到最高 74%、平均 41% 的 CUDA 归一化性能，MLU370 达到最高 52%、平均 25%；Rodinia 上分别为 73%/27% 与 48%/18%。在 Ascend 上，控制流优化相对一维 baseline 提升 42%，再叠加二维向量化提升 141%；MLU370 的对应增量为 50% 和 178%。复杂 shfl 或非规则访存会回退到标量/低效路径，个别 kernel 只有约 0.03×。

## 8. 主要创新点

1. 将 CUDA 到 NPU 翻译明确建模为从隐式标量线程到显式二维 tile 的 lifting。
2. 用 UPA 统一表达多级 CUDA 并行层次，使跨 block/warp/thread 的二维组合可分析。
3. 将语义保持的控制流、同步、mask 和 warp-level 优化接入可移植的 NPU IR 流程。

## 9. 局限性

1. 性能高度依赖访存规律、stride 是否静态可知和目标 NPU 的专用库；不规则 pooling 等算子收益很低。
2. 论文覆盖 Ascend 910B 与 MLU370，未证明对 TPU、AMD XDNA 等后端的实测效果。
3. 某些复杂 warp shuffle 只能标量模拟，二维向量化计划搜索仍可能产生较大编译复杂度。
4. 归一化 CUDA baseline 与 NPU 峰值的比较不能直接替代端到端应用吞吐或能耗评估。

## 10. 阅读后的研究方向反思

T2T 说明“跨 ISA 迁移”关键不是逐条指令翻译，而是把源端隐式并行关系恢复成目标端可合法组合的 tile 结构。对 RISC-V 向量/矩阵扩展，可以复用 UPA 思路，把 RVV 的向量长度、LMUL、mask 和内存段约束纳入统一的计划生成器。

## 11. 可进一步尝试的研究方向

1. 增加 RVV/RVV-1.0 和 RISC-V 矩阵扩展后端，比较 1D/2D/分块向量化计划。
2. 用运行时 shape、访存采样和硬件计数器补足静态 stride 不可知的 kernel。
3. 对二维向量化计划建立 cost model，联合考虑寄存器、scratchpad、bank conflict 和同步代价。
4. 在真实 CUDA 应用和端到端模型上评估编译时间、正确性、性能与能耗。

## 12. 与当前批次文献的关系

T2T 与 C20/C47 的共同点是从高层 IR 生成面向硬件的后端代码；T2T 面向 CUDA/NPU，C20/C47 面向 RISC-V 指令选择和指令融合。与 PolyUFC（C55）相比，T2T 的核心代价是向量化合法性和硬件利用率，C55 的核心代价是频率、带宽和 EDP；二者都展示了 MLIR 在跨硬件编译中的中间层作用。

## 13. 一页式总结

T2T 通过 UPA、控制流处理和二维 tile vectorization，将 CUDA 的标量线程并行映射到 Ascend 910B 与 Cambricon MLU370 的二维 NPU 指令。14 页 CGO 论文在 65 个 AI CUDA Engineer 和 28 个 Rodinia kernel 上验证了完整翻译，并相对一维 baseline 报告最高 6.9× 的案例提升和最高约 74% 的 CUDA 归一化峰值性能。贡献是语义保持、可扩展的 CUDA-to-NPU 编译管线；主要边界是非规则访存、复杂 shuffle 和后端专用接口。
