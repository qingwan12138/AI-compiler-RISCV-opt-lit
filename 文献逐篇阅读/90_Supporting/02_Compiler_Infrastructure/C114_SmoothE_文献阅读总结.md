## 1. 研究背景

本文研究等价图（e-graph）抽取。编译器中的项重写通常按固定顺序依次执行，重写顺序会影响最终性能，即“阶段排序问题”（phase ordering problem）。等价饱和（equality saturation）把多个语义等价表达式放入 e-graph：e-class 表示等价类，e-node 表示其中的操作或值，重写规则可以累积加入候选，最后再从同一个图中抽取代价最低的表达式。

论文指出，现有抽取方法有两类困难。第一，整数线性规划（ILP）可以表达较强的全局优化，但对大图扩展性差；贪心或迭代启发式方法速度快，却可能错过公共子表达式复用，得到次优结果。第二，很多方法假设总成本是 e-node 成本的线性加和，难以表达操作之间的相互作用，也难以直接接入学习型代价模型。论文的目标是把抽取过程改写成可微、可并行、能使用复杂代价函数的优化问题，并利用 GPU 加速。

## 2. 论文要解决的问题

### 2.1 扩展性与解质量的权衡

一般 e-graph 抽取在考虑公共子表达式时是 NP-hard。ILP 求解器可能在大图上超时，启发式方法则不保证接近最优。论文要研究如何在较短时间内获得接近 ILP 质量的可行抽取结果（第 1、2 节）。

### 2.2 线性代价模型的限制

现有方法主要优化 `Y^T W` 形式的线性代价，无法自然表示非线性操作交互或基于机器学习的代价预测。论文要研究如何在保留抽取约束的同时优化任意可微的连续代价函数（第 1、2 节）。

### 2.3 GPU 上的不规则图计算

e-graph 具有稀疏、依赖不规则的特点，直接把图算法搬到 GPU 会遇到内存访问和并行化问题。论文还要研究如何通过稀疏张量、向量化、seed batching 和强连通分量分解提高执行效率（第 4 节）。

> 本文主要研究：如何把带完整性和无环约束的 e-graph 抽取转化为连续可微优化，并在 GPU 上以较好的速度处理线性及非线性代价模型。

## 3. 核心方法概述

SmoothE 将每个 e-node 的离散选择变量放松为选择概率，用 softmax 产生同一 e-class 内的条件概率，再通过概率传播得到 e-node 的边际选择概率；随后以梯度下降最小化代价和无环惩罚，最后按条件概率逐层采样出一个离散、满足完整性约束的抽取结果。

```text
输入：经等价饱和得到的 e-graph、代价模型
        ↓
每个 e-node 的二值选择变量 W 放松为概率 S
        ↓
对每个 e-class 使用 softmax 得到条件概率 P_S
        ↓
概率传播 e(P_S) 得到边际概率 S，并计算代价
        ↓
加入 NOTEARS 矩阵指数无环惩罚
        ↓
GPU 上梯度下降；多个随机 seed 并行优化
        ↓
按根 e-class 和最大条件概率逐层采样
        ↓
输出满足完整性约束的离散 e-graph 抽取结果 W
```

方法的关键组件如下：

1. `P_S` 是“给定所属 e-class 已被选择时，某 e-node 被选择”的条件概率；同一 e-class 中所有 e-node 的条件概率由 softmax 归一化。
2. `e(P_S)` 根据父 e-node 的依赖传播选择概率。论文讨论父节点独立、完全正相关和二者平均的混合假设，默认使用混合假设。
3. 无环约束使用 NOTEARS 的矩阵指数判据连续化：对依赖转移矩阵 `B`，用 `tr(exp(B)) - c` 作为周期检测项，其中 `c` 是 e-class 数量。
4. 采样从根 e-class 开始，在每个已选 e-class 中选择条件概率最大的 e-node，并继续选择其子 e-class；这直接满足根选择和子图完整性约束。无环性主要依靠优化阶段的惩罚保证。
5. 实现使用 PyTorch、稀疏张量和 GPU 向量化；seed batching 把多个随机初始化作为一个 batch 并行运行，取其中代价最低的离散结果。

## 4. 实验框架与训练流程

本文不涉及模型训练、SFT、提示词推理、强化学习、PPO、GRPO 或工具调用型智能体。它是一个静态的组合优化/搜索系统；“学习”主要指可微代价模型实验和梯度下降优化选择概率。

### 4.1 e-graph 抽取流程

输入 e-graph 后，系统把二值 e-node 变量转换为连续概率变量，使用 softmax 参数化条件概率，并通过概率传播计算边际概率。损失由目标代价和 NOTEARS 无环惩罚组成。每次优化迭代后都可以采样一个离散结果，并在耐心参数达到或超时后停止（第 3.5 节）。

### 4.2 GPU 执行流程

e-node、e-class、父子关系用稀疏表示；概率传播使用稀疏矩阵—向量乘。多个 seed 共享 batch 维度并行优化。无环项的矩阵指数计算先按强连通分量（SCC）拆分，再用 batched approximation 减少矩阵指数开销（第 4 节）。

### 4.3 非线性代价实验流程

论文没有训练一个通用的性能预测器，而是为每个 e-graph 构造一个四层 MLP 代价模型：输入维度为 e-node 数量，隐藏层宽度为 64 和 8，使用 ReLU，输出一个标量成本。训练样本是随机生成的离散有效解，目标值是表示节省量的随机负数。该 MLP 用来测试 SmoothE 对可微非线性目标的支持。

## 5. 奖励函数、损失函数或关键公式

本文没有强化学习奖励函数。核心是连续优化损失。

### 5.1 选择概率

把二值变量 `W` 放松成 `S`：

```text
S_i = Pr(N_i is chosen),  S_i ∈ [0, 1]
```

`N_i` 是第 `i` 个 e-node。每个 e-class 内的条件概率 `P_S` 由 softmax 产生并满足和为 1。

### 5.2 连续代价

线性代价可写为：

```text
X(S) = Y^T S
```

其中 `Y_i` 是 e-node 的代价。相比原始二值输入 `W`，连续 `S` 使代价可以对优化参数求梯度。论文还允许把 `X` 换成任意可微的非线性代价函数。

### 5.3 无环惩罚

论文使用 NOTEARS 判据：

```text
h(B) = tr(exp(B)) - c
L = X(S) + λ · h(B)
```

`B` 是按条件概率构造的 e-class 依赖转移矩阵，`c` 是节点数，`λ` 控制无环项权重。对非负矩阵，`h(B)=0` 对应没有任意长度的有向环；论文说明当 `λ` 足够大时，含环解的概率可以被压到零。实际实现采用强连通分量分解并近似批量矩阵指数。

### 5.4 优化与采样

自由参数 `l` 经 softmax 得到 `P_S`，通过 `e(P_S)` 得到 `S`，再反向传播 `L` 更新 `l`。采样阶段从根 e-class 开始选择最大条件概率 e-node，并递归展开子 e-class。采样确保完整性约束，但不单独证明采样结果无环；无环性依靠前述惩罚项。

## 6. 实验设置

### 6.1 数据集来源

论文使用五类真实 e-graph 数据集和两类从 NP-hard 问题转换得到的对抗数据集。表 1 给出的规模如下：

| 数据集 | 任务 | e-graph 数量 | 最大 e-node 数 | 最大 e-class 数 | 代表工作负载 |
| --- | --- | ---: | ---: | ---: | --- |
| diospyros | DSP 向量化 | 12 | 218,933 | 9,584 | 线性代数 kernel |
| `\$exc` | CGRA 映射 | 14 | 19,830 | 4,892 | Bzip2、FFmpeg |
| impress | FPGA HLS | 3 | 102,030 | 90,312 | 大整数乘法 |
| rover | datapath 综合 | 9 | 16,960 | 2,852 | DSP/图形 kernel |
| tensat | 张量图优化 | 5 | 57,800 | 34,800 | ResNet-50、BERT |
| set | 最小集合覆盖转换 | 4 | 996,738 | 104,632 | NP-hard 对抗集 |
| maxsat | 最大可满足性转换 | 6 | 3,851 | 3,781 | NP-hard 对抗集 |

三类真实数据集来自 e-graph extraction gym；impress 数据由论文作者从其代码库构建。set 数据来自 Frequent Itemset Mining Dataset Repository，maxsat 数据来自 MaxSAT Evaluations，均按先前工作转换为 e-graph。论文没有报告传统意义上的训练/验证/测试划分，因为主实验不是训练模型。

### 6.2 模型与工具

- 硬件：Linux 服务器，2 张 NVIDIA A100 80 GB GPU，2 个 AMD EPYC 9124 CPU（2×16 核、3.7 GHz），1.5 TB RAM；跨 GPU 实验还使用 NVIDIA GeForce RTX 2080 Ti 11 GB。
- 软件：PyTorch 2.0.1、CUDA 11.7、`torch_sparse` 0.6.17；ILP 基线包括 CBC、SCIP、CPLEX，CPLEX 线程数为 32。
- SmoothE 后端：PyTorch 自动微分、稀疏矩阵运算、GPU batch；启发式基线使用原 Rust 实现。
- Artifact：论文提供公开代码、数据和 conda 环境；复现 SmoothE 约需 1 小时，全部 baseline 约需额外 4 天；artifact 推荐 A100 80 GB 以上。

### 6.3 对比方法

1. CPLEX ILP：商业整数规划求解器，并用 10 小时运行结果作线性代价 oracle。
2. SCIP ILP：开源 ILP 求解器。
3. CBC ILP：开源 ILP 求解器。
4. egg 默认启发式抽取。
5. extraction gym 的改进启发式 `heuristic+`。
6. 非线性代价实验另加入遗传算法，以及忽略非线性项的近似线性 `ILP*`。

### 6.4 评价指标

| 指标 | 含义 | 趋势 |
| --- | --- | --- |
| normalized cost increase | 相对 CPLEX 10 小时 oracle 的成本增加百分比 | 越小越好 |
| extraction time | 得到抽取结果的墙钟时间 | 越小越好 |
| valid solution / fails | 是否在时间限制内得到有效解 | 有效解越多越好 |
| worst / avg. | 每个数据集最差 e-graph 与可行解几何平均统计 | 成本与时间越小越好 |
| speedup | 相对 CPU 或 ILP 的时间加速 | 越大越好 |

线性 ILP 方法统一设置 15 分钟硬时间限制；SmoothE 的最大差异按 3 次运行统计。论文没有把这些抽取成本直接等同于真实硬件端到端运行时间，而是使用任务相关代价，如 tensat 的 GPU 执行时间代理、impress 的 FPGA 资源使用代价。

## 7. 实验结果与结论

### 7.1 主要结果

在五类真实数据集上，SmoothE 都能产生高质量解。表 2 报告的 SmoothE 时间和相对 oracle 成本增加为：diospyros `8.4±0.7 s`、`0.1±0.0%`（最差/平均均约 0.1%）；`\$exc` `19.3±1.7 s`、`0.7±0.0% / 0.2±0.0%`；impress `4.6±0.0 s`、`0.0±0.0% / 0.0±0.0%`；rover `20.6±1.3 s`、`4.4±1.2% / 0.2±0.1%`；tensat `24.4±2.5 s`、`17.0±0.0% / 4.6±0.1%`。这些数字是相对 CPLEX 10 小时 oracle 的标准化成本增加，不是相对原程序的真实加速比。

### 7.2 与传统方法的比较

相对 ILP，SmoothE 在除 `\$exc` 外的数据集上达到相近或更好的质量，并报告约 8×–37× 的执行加速；相对 egg 和 `heuristic+`，SmoothE 在五类真实数据集上都得到更好的抽取质量，同时比 ILP 快得多。CPLEX 在 `\$exc`、impress、rover 上更容易得到高质量解；SCIP/CBC 在多项大图上可能失败或达到时间上限。

### 7.3 对抗数据集与具体案例

在 set 和 maxsat 转换数据集上，ILP 求解器可在约一分钟内找到最优解，因为这些图更适合 ILP；启发式方法因公共子表达式较多而质量较差。SmoothE 明显优于启发式，但不如 ILP：表 4 中 SmoothE 相对 oracle 的最差/平均成本增加分别为 set `50.0±0.0% / 21.9±0.5%`、maxsat `31.1±0.4% / 22.9±0.2%`。

### 7.4 非线性代价

论文用每个 e-graph 的四层 MLP 构造非线性代价，并与遗传算法和忽略非线性项的 `ILP*` 比较。图 5 显示 SmoothE 在五类数据集上都抽取得到最低成本；遗传算法在 tensat 上表现较好，但在其他数据集上更容易陷入局部最优；`ILP*` 因忽略节点交互而持续劣于 SmoothE。非线性代价下，SmoothE 的单次迭代更新时间大致不变，图中每个 e-graph 都在 1 分钟内完成抽取。

### 7.5 消融、seed batching 与可移植性

- 图 6：GPU 执行优化和矩阵指数优化分别带来约 10× 加速；矩阵指数优化同时显著降低内存使用，否则大 e-graph 会触发 GPU OOM。
- 图 7：增加 seed 数量会降低平均成本和方差；seed 少于 64 时延迟增长低于线性，使用 256 个 seed 时该案例成本收敛且方差为零。
- 图 8：采样占总运行时间约 4.8%–21.8%，优化阶段占主要部分；大多数数据集上损失计算最耗时，`\$exc` 上梯度下降更耗时。
- 表 5：RTX 2080 Ti 的显存约为 A100 的八分之一，因此 batch size 约缩小 8×。除单个 e-graph 显存不足的 4 个失败案例外，SmoothE 在较低端 GPU 上仍能运行，但大型图的显存是限制因素。
- 图 9：采样损失与连续优化损失在四个 tensat/rover e-graph 上保持接近，说明其采样过程通常能得到接近松弛解的离散结果；这不是形式化正确性证明。

## 8. 主要创新点

### 8.1 创新点一：可微的 e-graph 抽取表述

论文首次把 e-node 离散选择转为连续概率，并以概率图模型方式处理 e-class 完整性约束。该设计使梯度下降可用于全局抽取搜索，并能接入非线性可微代价。其价值由线性和 MLP 代价实验共同支持；“首次”是论文作者的贡献表述，本文不额外声称其覆盖所有 e-graph 抽取工作。

### 8.2 创新点二：面向 GPU 的稀疏和多 seed 实现

论文不是简单调用 GPU，而是将父子关系表示为稀疏张量，采用向量化概率传播，并以 seed batching 解决图依赖导致的设备间通信问题。消融结果显示 GPU 执行和矩阵指数优化各有约 10× 贡献。

### 8.3 创新点三：把复杂代价模型纳入同一优化流

现有 ILP 和启发式基线对非线性代价支持有限。SmoothE 只要求连续可微目标，因此可把 MLP 等学习型代价放入同一梯度优化流程。实验说明在作者构造的非线性代价上可得到比遗传算法和近似线性 oracle 更低的成本，但这不等于已经证明真实硬件代价模型普遍有效。

### 8.4 创新点四：连续无环惩罚的工程化处理

论文将 NOTEARS 的矩阵指数无环项用于 e-class 依赖图，并通过 SCC 分解与批量近似降低成本。这是把组合约束纳入可微优化的关键工程模块，而不是独立的形式化验证器。

## 9. 局限性

### 9.1 论文明确承认或直接显示的局限

- 论文结论把更真实的非线性代价模型和更先进的概率图模型列为未来工作；当前非线性实验使用的是作者构造的 MLP，不是来自真实编译器或硬件测量的学习模型。
- GPU 显存限制会让大 e-graph 或较低端 GPU 出现失败；A100 80 GB 是推荐环境。
- SmoothE 在 set/maxsat 对抗图上不如 ILP，说明可微方法并不支配所有图结构。
- 无环惩罚依赖超参数 `λ`、概率传播假设和矩阵指数近似；采样本身只直接保证完整性约束。
- 全部 baseline 复现成本很高，论文 artifact 估计约需 4 天；这影响独立复现实验的门槛。

### 9.2 阅读后发现的潜在局限

- 论文优化的是抽取代价，不是从源代码到目标机器代码的端到端性能；代价与真实后端行为之间的偏差没有在本文中系统量化。
- e-graph 的等价关系来自给定重写规则。SmoothE 优化的是已有候选空间，不能自动发现未被规则加入的变换，也不能替代重写规则设计。
- 独立、完全相关和混合父节点假设会影响概率传播；对含复杂共享和循环结构的 e-graph，LBP/并行迭代的收敛质量需要进一步验证。
- MLP 训练目标使用随机有效解和随机负数节省量，适合验证“可接入非线性目标”的机制，但不能直接代表真实性能预测器的泛化能力。
- 论文没有研究 LLVM IR、MLIR dialect、RISC-V 后端或真实异构设备上的端到端部署，因此不能把结果直接推广到这些平台。

## 10. 阅读后的研究方向反思

SmoothE 最值得借鉴的是“把候选空间、约束和代价统一成可优化对象”的思路：在 LLVM/MLIR 中，可以把候选 rewrite、schedule 或 lowering 配置显式表示，再用可微或混合搜索选择候选。但论文核心贡献已经是 e-graph 抽取的连续化和 GPU 实现；仅把目标平台替换为 RISC-V、把 PyTorch 换成 MLIR，不能构成充分的新颖性。

对 RISC-V/异构硬件研究的相关性为中等偏低。论文的 e-graph 和代价模型可作为后端指令组合、RVV idiom 或多设备 lowering 的搜索模块；然而当前实验任务来自 DSP、CGRA、FPGA、datapath 和张量图，而不是 RISC-V 实机。若要形成新的研究问题，必须加入目标 ISA 合法性、寄存器/向量长度约束、真实硬件性能反馈或跨设备通信代价，而不是只改标签。

按 Taxonomy v2 的角色建议，本文更适合作为 `SUPPORTING / B4_Traditional_ML_Compiler_Optimization`：它提供传统编译器优化与可微搜索基础设施，不属于 LLM 的 Selector、Translator 或 Generator。若维护者采用更偏“评测/抽取器”的组织口径，也应保留该分类建议的人工复核状态；本 staging 不分配正式 Paper_ID。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RISC-V RVV 的语义约束 e-graph 抽取

#### 研究问题

如何在 RVV 的向量长度、LMUL、尾部/掩码语义和寄存器压力约束下，从 LLVM IR 或 MLIR vector dialect 的等价候选中抽取真实硬件成本更低的程序。

#### 与原论文的区别

不仅替换目标架构，而是把 RVV 合法性、寄存器分配和真实执行反馈加入候选约束与代价模型。

#### 可能的创新点

设计 RISC-V 后端可验证的 e-node 表示；用编译器合法性检查过滤候选；研究静态代价与板卡/模拟器测量的联合目标。

#### 实验框架

```text
LLVM/MLIR 输入 → RVV 候选重写与合法性检查 → e-graph
→ SmoothE/混合抽取 → LLVM RISC-V lowering → Spike/真实 RVV 测量
→ 更新代价模型并比较 greedy、ILP、SmoothE
```

#### 可行性

需要 LLVM RISC-V/RVV 后端、MLIR vector/linalg、Spike 或真实 RVV 板卡、可复现 kernel 集和少量性能采样。

#### 主要风险

后端指令选择和寄存器分配可能使抽取代价与实际性能脱钩；硬件测量噪声和不同 VLEN 会导致代价模型迁移困难。

### 11.2 可微与形式化等价检查结合的 MLIR rewrite 搜索

#### 研究问题

如何让可微代价搜索产生高质量候选，同时用 MLIR verifier、Alive2 或 SMT 检查确保每次 rewrite 保持目标语义。

#### 与原论文的区别

SmoothE 依赖 e-graph 的等价候选和抽取约束；该方向把候选生成、语义检查和抽取结合成编译器闭环。

#### 可能的创新点

把验证失败作为硬过滤或可学习的 penalty；研究“可微搜索提出候选、符号工具做最终判定”的分层接口，并测量验证开销。

#### 实验框架

```text
MLIR/LLVM IR → rewrite 候选 → verifier/SMT 过滤 → e-graph
→ 可微抽取 → 编译/运行测试 → 正确性与代价联合评估
```

#### 可行性

需要选定有限 dialect/LLVM pass 范围、可靠的等价检查工具和小规模可控的 benchmark。

#### 主要风险

验证器可能无法处理复杂内存、浮点或未定义行为；若把验证失败简单转成数值惩罚，仍可能产生不可接受的错误候选。

### 11.3 面向异构内存/加速器的通信感知抽取

#### 研究问题

如何在 CPU、GPU、NPU 或 PIM 之间的候选分解、数据放置、同步和通信代价共同存在时，从多级 MLIR e-graph 中选择全局方案。

#### 与原论文的区别

把单图操作成本扩展为跨设备执行图、通信边和同步约束，并使用真实设备或校准模拟器反馈，而不只使用节点成本。

#### 可能的创新点

设计包含设备与通信信息的 e-class 语义；研究分层抽取或分解式 NOTEARS 惩罚；分析 GPU 并行搜索对跨设备代价模型的影响。

#### 实验框架

```text
高层张量/MLIR → 设备与数据放置候选 → 异构 e-graph
→ 通信/能耗/延迟联合代价 → 并行抽取 → 多设备 runtime 执行
```

#### 可行性

需要 MLIR 多级 lowering、至少两类可测设备或可信模拟器，以及可分解的张量/图计算基准。

#### 主要风险

多设备同步和动态负载使代价函数可能不可微；搜索空间和测量成本也会远高于单设备 e-graph。

## 12. 与其他已读文献的关系

本 slot 当前只完成 SmoothE 一篇论文，因此没有同批次内可进行事实级横向比较的其他论文。就仓库现有主题而言，SmoothE 与已收录的传统 MLIR/张量优化工作在“候选表示—代价模型—搜索/抽取”主线上相近，但本文的核心对象是等价饱和后的 e-graph 抽取，不是 MLIR lowering、LLVM pass 排序、LLM 代码生成或 RISC-V 后端。

它可作为：

- 传统编译优化中的可微抽取/搜索 baseline；
- MLIR/LLVM 多级优化研究中的候选选择工具模块；
- 非线性或学习型代价模型的实验参考。

它不能直接替代：

- 语义验证器，因为本文没有独立形式化验证流程；
- 真实硬件性能评测，因为论文主要优化抽取成本；
- LLM 编译器方法，因为本文没有语言模型参与最终系统角色。

## 13. 一页式总结

| 项目 | 内容 |
| --- | --- |
| 论文研究任务 | 从等价饱和 e-graph 中快速抽取低成本表达式 |
| 核心问题 | ILP 扩展性差、启发式质量不稳、线性代价模型表达能力有限 |
| 输入 | 含 e-node/e-class 依赖关系的 e-graph 与代价模型 |
| 输出 | 满足完整性约束、尽量无环且代价较低的离散抽取结果 |
| 核心方法 | 概率化 e-node 选择、可微代价、NOTEARS 无环惩罚、GPU seed batching |
| 使用的模型 | PyTorch；非线性实验使用四层 MLP 代价模型 |
| 使用的编译器工具 | e-graph 数据集/抽取器、egg 启发式、CBC、SCIP、CPLEX、PyTorch |
| 是否使用强化学习 | 否 |
| 是否使用形式化验证 | 否；使用的是等价图约束和连续无环判据，不是独立语义验证器 |
| 数据集规模 | 5 类真实数据集共 43 个 e-graph，另有 set 4 个、maxsat 6 个对抗 e-graph |
| 主要指标 | normalized cost increase、抽取时间、有效解/失败数、speedup |
| 最重要实验结果 | A100 上五类真实数据集约 4.6–24.4 秒完成；相对 10 小时 CPLEX oracle 的平均成本增加约 0.0%–4.6%，但 tensat 最差增加 17.0% |
| 核心创新 | 首个可微 e-graph 抽取流程，并把复杂可微代价与 GPU 并行实现结合 |
| 主要局限 | 对抗图上不如 ILP；依赖超参数、概率假设和显存；非线性代价主要是合成 MLP |
| 与 RISC-V 研究的相关性 | 中等偏低：可借鉴抽取与代价建模，但未做 RISC-V/RVV 实验 |
| 最适合作为 | 传统编译优化 baseline、可微抽取方法参考、搜索工具模块 |

> 这篇论文最值得学习的是把“候选等价空间、编译约束和复杂代价”统一到可微搜索框架中；最主要的局限是它优化的是 e-graph 抽取成本，不能直接等同于真实后端性能或形式化正确性。如果用于后续研究，最合理的使用方式是把它作为 LLVM/MLIR/RISC-V 后端搜索模块，再接入真实目标代码生成、语义验证和硬件反馈，而不是简单替换为另一种架构。
