# Poseidon 文献阅读总结

论文题目：**Thinking Fast and Correct: Automated Rewriting of Numerical Code through Compiler Augmentation**

作者：Siyuan Brant Qian、Vimarsh Sathia、Ivan R. Ivanov、Jan Hückelheim、Paul Hovland、William S. Moses

发表时间：2026

发表平台：CGO 2026，Distinguished Paper Award

论文链接或编号：DOI `10.1109/CGO68049.2026.11395228`

关键词：浮点优化、编译器增强、上下文感知重写、混合精度、LLVM、动态规划

> 本文档用于文献阅读、组会汇报和后续研究分析。论文事实与阅读后的研究思考需要分开描述。

## 1. 研究背景

浮点数用有限位数近似实数。论文第 1、2 节说明，改变精度、重排表达式或使用近似数学函数，可能同时影响运行时间和数值误差；但浮点运算不满足实数运算中的结合律和分配律，简单重写可能使结果变差。现有工具通常只支持精度调节、直线表达式或受限 DSL，并且需要人工提供表达式和数值上下文。

## 2. 论文要解决的问题

### 2.1 自动获得足够的数值上下文

论文研究小规模替代输入（surrogate profile）是否足以估计指令值域、执行频率和误差敏感度，从而指导大程序中的浮点重写。

### 2.2 在性能与精度之间自动取舍

论文希望在生产编译器中统一处理精度变化和代数重写，并自动选择满足误差约束的低成本方案。

> 本文主要研究：如何利用编译器内的数值 profiling、候选重写评估和动态规划，在真实规模程序上自动寻找浮点性能/精度折中。

## 3. 核心方法概述

Poseidon 是构建在 Enzyme、LLVM 和 MLIR 生态之上的两阶段编译框架。第一阶段对预优化 IR 插桩，收集执行次数、操作数范围和反向自动微分得到的梯度敏感度；第二阶段识别浮点子图、生成精度变化和代数重写候选，估计每个候选的代价与误差，再用动态规划求全局方案。

```text
输入 C/C++ 或 LLVM/MLIR 程序
        ↓
标准预优化，暴露较大的浮点子图
        ↓
插桩编译 + 小规模替代输入执行
        ↓
收集值域、执行次数、梯度和敏感度
        ↓
提取浮点子图并生成精度/代数重写候选
        ↓
临时物化候选，估计运行代价与数值误差
        ↓
动态规划求性能/精度 Pareto 前沿
        ↓
物化重写并执行后续 LLVM 优化
```

## 4. 实验框架与训练流程

本文不涉及模型训练、SFT 或强化学习，主要采用编译期分析、外部重写器、数值评估和动态规划搜索。

### 4.1 第一阶段：预优化与 profiling

Poseidon 在 LLVM IR 上运行 mem2reg、SROA、控制流简化等标准优化，使跨基本块的浮点计算更容易被识别。Enzyme 生成反向自动微分代码，插入值和梯度记录调用；替代输入执行后得到 profile。

### 4.2 第二阶段：候选生成与评估

候选包括子图精度变化和代数重写。精度候选按 ADAPT 风格敏感度排序，减少指数级配置空间；代数候选由已注册的外部工具生成。候选会先临时物化并重新运行标准优化，以估计可删除指令和实际代价。

### 4.3 求解与输出

动态规划维护“总代价到最小误差”和“总代价到重写集合”的映射，按用户误差容限选择最快方案，也可选择前沿上的其他点。输出是带有选定浮点重写的本地编译程序。

## 5. 奖励函数、损失函数或关键公式

本文没有使用强化学习，因此不存在强化学习奖励函数。核心是误差和代价模型。

对浮点子图 φ，论文用各输出指令的局部误差与 profile 梯度估计误差贡献：

```text
ERROR(φ) = Σ LOCAL_ERROR(o) × GRADIENT(o)
ΔERROR(T) = ERROR(Tφ) - ERROR(φ)
```

其中 `T` 是候选重写，`Tφ` 是替换后的子图。局部误差通过在 profile 输入超矩形中采样，并与 MPFR 高精度结果比较得到。代价模型包括基于 LLVM TargetTransformInfo 的加权指令数，以及即时编译浮点微基准并测时的 Instruction-JIT 模型。动态规划的时间复杂度为 `O(NT)`，`N` 是每个子图候选数，`T` 是总代价上界。

## 6. 实验设置

### 6.1 数据集来源

实验包含 84 个 FPCore 微基准、`logexp`、四元数求导程序 `dquat`、3×3 对称矩阵特征值求解器和 DOE LULESH 水动力学代理应用。`dquat` 用 1,000 个输入矩阵生成 profile，再用 1,000,000 个矩阵评估；特征值实验用 10 个矩阵 profile、100,000 个互斥测试矩阵评估；LULESH 用 problem size 30 的 100 次迭代生成替代 profile，再评估 problem size 50。

### 6.2 模型与工具

框架使用 Enzyme 的反向自动微分、LLVM、MLIR、Herbie 和 MPFR。主实验使用 LLVM 21.0.0 与 Herbie 2.3；对 STOKE 的比较使用 LLVM 15.0.7 与 Herbie 2.2。论文还报告用 LLVM、Enzyme、Python、Racket 和 Docker 复现实验。

### 6.3 对比方法

主要对比包括手写 FP64/FP32、MPFR、LLVM TargetTransformInfo 代价模型、STOKE、Herbie 以及仅做精度调节或仅做代数重写的 Poseidon 变体。

### 6.4 评价指标

| 指标 | 含义 | 方向 |
|---|---|---|
| Speedup | 相对基线的运行时间比 | 越大越好 |
| Geomean relative error | 多测试输入的几何平均相对误差 | 越小越好 |
| Worst-case relative error | 测试输入中的最大相对误差 | 越小越好 |
| ULP error | 与高精度参考结果的最后一位差异 | 越小越好 |

## 7. 实验结果与结论

### 7.1 主要结果

在 84 个微基准中，Poseidon 在 58% 的程序上改善精度，几何平均相对误差最多改善 1.38×，最高加速比为 1.82×。在 `dquat` 上，精度调节与代数重写联合搜索得到最高 1.46× speedup，且相对误差约为 `10^-7`。

### 7.2 大程序结果

特征值求解器实验显示，Poseidon 可通过选择性降低精度获得接近手写 FP32 的速度，也能通过上下文感知重结合改善第一特征对的误差。LULESH 的 FP64 基线在 1662 次迭代后相对 MPFR 参考值出现 12 ULP 偏差；Poseidon 用 100 次小规模 profile 指导 9 个精度/表达式重写和 2 个简化重写，使结果达到 FP64 可表达的 0 ULP 误差，且没有显著增加运行时间。MPFR 实现至少比原生 FP64 慢 500×，FP80 基线慢 6.79×且仍有 2 ULP 误差。

### 7.3 消融实验

Instruction-JIT 代价模型比 TTI 能发现更宽的性能/精度前沿，因为 TTI 对不同浮点精度的代价区分有限。过度放大或缩小 profile 值域会减少有效候选，但在约 `0.1–10` 的范围缩放内，`dquat` 仍能得到较丰富的折中方案。将大型浮点子图拆分可缩短求解时间，却会丢失跨子图数值上下文和部分精度收益。

## 8. 主要创新点

### 8.1 生产编译器内的上下文感知浮点重写

论文把 profiling、候选生成、误差/代价评估和 IR 重写放入同一编译流程，避免源代码级工具需要人工构造 DSL 输入。这一贡献由全应用实验支持。

### 8.2 联合搜索精度变化与代数重写

动态规划在同一全局框架中组合两类候选，能够得到单独技术无法覆盖的性能/精度折中。

### 8.3 小替代 profile 驱动大程序优化

论文提出并通过多组实验支持“结构化关键值”假设：数值敏感性在许多程序中具有结构稳定性，因此不必完整运行所有真实输入。

## 9. 局限性

### 9.1 论文明确或实验暴露的限制

外部重写工具和完整动态规划在大型程序上开销较高；论文报告某些全流程约需 4 小时，虽然之后的 fine-tuning 编译平均约 0.3 秒。超大型子图会产生很长的符号表达式，拆分又会损失上下文。方法依赖 Enzyme、LLVM 和 MPFR 等工具链。

### 9.2 阅读后的潜在限制

profile 是替代输入而非完整输入分布，结构化关键值假设在分布漂移、异常输入或分支覆盖不足时可能失效。误差模型使用采样和一阶梯度近似，不能等同于形式化数值正确性证明。论文实验主要面向 CPU/LLVM 生产编译流程，跨 RISC-V 后端的真实硬件收益在当前 PDF 中未被验证。

## 10. 阅读后的研究方向反思

Poseidon 最值得借鉴的是将编译器 IR、运行反馈和可解释的代价/误差模型结合起来。它更适合作为反馈驱动优化的工具模块或 baseline，而不是直接作为 RISC-V 论文的完整方案。仅替换目标架构不足以形成创新；真正可研究的是把 RISC-V/RVV PMU、真实后端代码生成和输入分布漂移纳入可验证的误差—性能闭环。Poseidon 的核心贡献是上下文感知浮点重写和 DP 求解，不能把这些机制简单改名为新的 LLM 或强化学习方法。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RVV 的反馈驱动数值重写

#### 研究问题

如何把 RVV 向量长度、尾部处理和真实硬件计数器加入浮点精度/表达式重写的联合选择。

#### 与原论文的区别

加入真实 RVV 后端和硬件反馈，而不是只迁移 LLVM 目标。

#### 可能的创新点

建立向量化代价与数值误差的联合模型，并处理不同 VLEN 的可移植性。

#### 实验框架

```text
LLVM/RVV IR → profile 与 PMU → 候选重写/向量化 → 真实板卡验证 → Pareto 选择
```

#### 可行性

需要 LLVM RVV、可访问的 RISC-V 向量平台、MPFR 和数值基准。

#### 主要风险

硬件计时噪声、输入分布漂移和向量尾部语义可能使代价模型不稳定。

### 11.2 可审计的数值重写验证闭环

#### 研究问题

如何对候选浮点重写提供区间、抽样证据和编译器变换记录的可审计证明。

#### 与原论文的区别

把采样误差估计扩展为证据分层，而非只输出预测误差。

#### 可能的创新点

结合局部形式化检查、反例生成和 profile 覆盖率报告。

#### 实验框架

```text
候选重写 → 静态合法性检查 → 数值抽样/反例 → 证据汇总 → 选择并记录
```

#### 可行性

可复用 LLVM、MPFR、Alive2 类工具和现有浮点基准。

#### 主要风险

形式化范围可能不足以覆盖数学库函数和复杂控制流。

## 12. 与其他已读文献的关系

本批次的 NEURA 研究 CGRA 的控制流—数据流统一表示和跨执行模型编译，Poseidon 研究浮点数值上下文与重写选择，二者都把优化决策放入编译器 IR，但输入反馈和目标硬件不同。Poseidon 可作为反馈驱动数值优化 baseline；NEURA 更适合作为多硬件 IR 基础设施参考。当前 PDF 不支持声称二者存在直接方法重复。
