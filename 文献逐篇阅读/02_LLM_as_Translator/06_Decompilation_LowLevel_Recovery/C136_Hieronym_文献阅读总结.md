## 1. 研究背景

本文研究剥离符号（stripped）的二进制函数命名恢复。剥离符号会去掉函数名、变量名和部分结构信息，使逆向工程师难以进行漏洞分析、恶意软件分析和安全审计。IDA Pro、Ghidra 等工具通常只能给出 `FUN_...` 一类地址占位名，自动恢复有意义的函数名因此具有实际价值（第 1 节）。

已有方法大致分为两类：一类是基于特征、图或编码器的传统机器学习模型，通常把函数命名视为从封闭词表中分类或多标签预测；另一类是近期的生成式 LLM 方法。前者难以生成未见过的自然语言名称，也容易受架构和优化级别影响；后者虽然能生成开放词表名称，但仍面临评价指标不稳、剥离二进制语义稀疏、通用 LLM 与二进制语义之间存在知识缺口等问题（第 2.2 节）。

论文特别指出，单函数输入并不总是足够：调用者、被调用者、程序域信息和目标函数自身共同决定函数语义；另一方面，过度依赖调用关系又可能受内联等优化影响。作者因此引入层次化摘要和多源上下文，让 LLM 处理更稳定的语义抽象。

## 2. 论文要解决的问题

### 2.1 评价问题

仅使用 token-level Precision、Recall、F1 评价函数名，会把分词策略造成的差异误当作模型能力差异。例如，论文指出 `c_isascii_string` 在不同分词策略下会产生明显不同的 F1。因此需要同时评价词元级匹配和整个函数名的语义一致性（第 2.2、3 节）。

### 2.2 语义稀疏与跨条件泛化问题

剥离二进制缺少源代码中的命名和类型信息，单个函数往往不足以推断项目特定语义。不同 ISA、编译器和优化级别还会改变指令及控制流表现，导致仅依赖局部表示的方法泛化不稳（第 2.2 节）。

### 2.3 LLM 二进制领域适配问题

通用 LLM 的预训练语料中二进制代码比例有限，直接使用会产生源代码语义与二进制语义之间的鸿沟。论文研究如何用函数级和语句级摘要构造领域适配监督，再用全局二进制上下文、局部调用上下文和目标函数完成命名生成。

> 本文主要研究：如何让生成式 LLM 在多架构、多优化级别和未见项目的 stripped binary 上生成更可靠、更具语义一致性的函数名，并建立不依赖单一分词结果的双层评价方法。

## 3. 核心方法概述

Hieronym 是一个直接生成函数名的 LLM 变换器，最终输出不是 pass、配置或候选动作，而是低层二进制对应的自然语言函数名，因此按 Taxonomy v2 属于 TRANSLATOR/T6。系统包括三部分：层次化领域适配、多源信息融合、函数命名微调（第 4.1 节）。

```text
带符号表的二进制/反编译代码
        ↓
Tree-sitter 抽取函数与控制流语句
        ↓
Qwen3-Coder 生成函数级、语句级摘要并做自一致性筛选
        ↓
按地址及结构/语义相似度对齐到 stripped binary
        ↓
全局二进制摘要 + 局部调用上下文 + 目标函数（函数名遮蔽）
        ↓
Code Llama + LoRA 生成函数名
        ↓
混合分词/语义对齐的 token-level 评价
        ↓
GPT-4o 判断 + Qwen3-Embedding 阈值过滤的 name-level 评价
```

全局上下文由字符串字面量、文件类型元数据和动态链接依赖构成，提示 LLM 生成 100–150 词的程序域摘要（附录 A）。局部上下文由内部函数摘要和外部函数名组成；目标函数使用 stripped binary 的反编译代码，但将地址型函数名替换为 `[MASK]`（第 4.3 节）。

层次化摘要使用函数级摘要表达总体意图、语句级摘要表达具体实现逻辑。语句从带符号二进制的 AST 中抽取，少于 5 行的片段会合并，行数差小于 8 的重叠片段也会合并。随后用 Tree-sitter 的 AST 路径 Jaccard 相似度与 CodeBERT 余弦相似度完成 stripped/未 stripped 语句对齐（第 4.2 节）。

## 4. 实验框架与训练流程

### 4.1 领域适配数据准备

作者先从带符号表的二进制反编译代码构造训练材料，因为这类代码比 stripped binary 保留更多结构信息。Qwen3-Coder 生成函数级和语句级摘要，多次生成后以自一致性筛选摘要。再使用 DWARF 和函数起止地址做函数级对齐；语句级则结合 AST 结构和语义相似度，对齐摘要与 stripped 输入（第 4.2 节）。领域适配数据只使用训练集构造（第 5.2 节）。

### 4.2 函数命名微调

模型基于 Code Llama，采用 LoRA（Low-Rank Adaptation，低秩适配）而不是全参数微调。原始 attention 权重被冻结，仅训练两个低秩矩阵。输入由三项组成：全局上下文 `B`、调用上下文 `C={C+, C-}` 和目标函数 `T`；输出是开发者定义的函数名 token 序列。监督信号来自保留符号表二进制中的原始函数名（第 4.4 节）。

### 4.3 推理与评价

推理时，模型根据输入上下文自回归生成函数名。评价分为 token-level 和 name-level。token-level 使用规则与 LLM 辅助的混合分词，并对词根、缩写、拼写变体和同义词做语义对齐。name-level 对每个架构—优化级别组合随机抽取 200 个函数，共 3,200 个函数，由 GPT-4o 做语义判断，并要求 Qwen3-Embedding 余弦相似度达到 0.7，两个条件均满足才算正确（第 3 节）。

### 4.4 训练/工具边界

本文采用监督微调和 LoRA，不涉及 PPO、GRPO 或其他强化学习。Qwen3-Coder 用于生成领域适配摘要；GPT-4o 和 Qwen3-Embedding 用于评价，不是最终函数名生成模型。Ghidra 11.2.1 用于反编译，论文没有把 Ghidra 作为 LLM 的决策选择器。

## 5. 奖励函数、损失函数或关键公式

本文没有使用强化学习奖励函数。关键训练目标是自回归条件似然最大化：

```text
max_theta log P_theta(W) = sum_t log P_theta(w_t | I ; w_1:t-1)
```

其中 `I={B,C,T}` 是全局二进制上下文、局部调用上下文和目标函数，`W` 是真实函数名 token 序列，`theta` 是可训练参数。每个 token 的条件概率由隐藏状态与词嵌入的点积经 softmax 得到；LoRA 使更新从 `d×d` 降为 `2×r×d`，其中 `r << d`（第 4.4 节）。

评价公式为：

```text
P = TP / (TP + FP)
R = TP / (TP + FN)
F1 = 2 × P × R / (P + R)
```

其中 TP、FP、FN 分别是语义对齐后正确预测、错误预测和遗漏的 token 数。name-level 是满足 GPT-4o 判断和 embedding 相似度阈值的预测比例，不是形式化语义等价证明。论文明确使用 0.7 embedding 阈值；没有将该阈值声称为数学正确性保证。

## 6. 实验设置

### 6.1 数据集来源

主数据集沿用 SymGen 数据集，包含 33 个开源项目，使用 GCC 9.4.0 编译，覆盖 x86、x64、ARM、MIPS 四种架构及 O0–O3 四个优化级别。清洗后共有 9,842 个唯一二进制和 2,237,915 个二进制函数；训练、验证、测试按 8:1:1 划分。按源文件划分，避免同一源文件不同优化级别跨集合泄漏；还去除同名、相同函数体、同源仅地址相关差异的函数，以及空函数、无意义名称和 Ghidra 自动生成名称（第 5.2 节）。

额外评测包括：去除训练项目后的跨项目测试；使用 Clang 14.0.0 的跨编译器测试；IDA Pro 9.0 的跨反编译器测试；来自六个 GNU 项目的 363 个混淆二进制；SPEC CPU2017 的 Xalan C++；四个 AndroZooOpen Java 项目（超过 4,400 个函数）；以及 VirusShare 的 x64 ELF 恶意软件外部测试集。恶意软件测试保留含符号表样本以获得真实名称，再在评测前剥离符号（第 5.6、6.2 节）。

### 6.2 模型与工具

最终命名模型的基础模型是 Code Llama；领域摘要由 Qwen3-Coder 生成。评价使用 GPT-4o 与 Qwen3-Embedding。硬件为 48 核 Intel Xeon Platinum 8558P、2 TB RAM 和 8 张 NVIDIA H100，Ubuntu 22.04、Python 3.10。工具包括 Ghidra 11.2.1、ANTLR 4、PyTorch、Hugging Face Transformers、LlamaFactory、NLTK 和 python-Levenshtein（第 5.1 节）。

### 6.3 对比方法

主要 baseline 为 SymGen、SymLM、XFL 和 BLens。XFL 与 BLens 只在 x64 上比较；NERO、NFRE、Epitome 因已有研究中性能低于所选方法而未纳入；llasm 因源码不可得且作者联系后仍无法复现而被排除（第 5.1 节）。

### 6.4 评价指标

| 指标 | 含义 | 方向 |
| --- | --- | --- |
| Token Precision/Recall/F1 | 预测名称与真实名称的语义对齐 token 重合 | 越大越好 |
| Name-level accuracy | GPT-4o 与 embedding 双重判定为语义一致的名称比例 | 越大越好 |
| Weighted macro F1 | 跨架构/优化条件汇总的 F1 | 越大越好 |
| 推理吞吐率 | 大二进制上每秒处理函数数 | 越大越好 |
| 每函数 token/延迟 | 生成成本与端到端时间 | 越小越好 |

## 7. 实验结果与结论

### 7.1 主要结果

在四架构、四优化级别的主测试上，Hieronym 的加权宏平均 token Precision、Recall、F1 分别为 0.4487、0.4223、0.4339。按架构看，x64 的 F1 为 0.5256，x86 为 0.4832，ARM 为 0.4239，MIPS 为 0.3031。name-level accuracy 最高为 x64 的 0.4254，ARM 为 0.3455，x86 为 0.3220，MIPS 为 0.1709（第 5.3 节）。

与同配置的 SymGen 相比，跨全部架构和优化级别，Hieronym 的 token Precision、Recall、F1 分别提升 50.12%、41.75%、45.10%；name-level accuracy 平均提升 79.94%。在 SymGen 的评价指标下，F1 仍提升 47.96%（第 5.4 节）。

### 7.2 与传统方法及 LLM baseline 的比较

传统方法在未见二进制上明显退化。论文报告 SymLM 在自身数据集上平均 F1 约 0.73，但在该严格去重测试上降到 0.0515；作者将其与历史设置中的数据泄漏风险联系起来。Hieronym 的跨优化级别 F1 变化约 7.48%，小于 SymLM、XFL、BLens 的变化，说明摘要和多源上下文有助于减轻优化级别敏感性。

相对于 LLM baseline SymGen，Hieronym 的优势来自全局上下文、调用上下文和层次化领域适配，而不是单纯扩大生成模型。相对不同架构，MIPS 仍明显弱于 x64，说明低层恢复任务尚未被完全解决。

### 7.3 消融与泛化

层次化函数摘要使 F1 提升 18.83%；加入全局二进制上下文和局部调用上下文分别带来 27.63% 和 13.81% 的增益。调用上下文的单独比较中，Precision、Recall、F1 平均提升 10.52%、17.22%、13.81%，但在 O2/O3 因函数内联等优化使调用关系减少，增益变小（第 5.5 节）。

跨编译器时，使用 Clang 14.0.0 重新编译的测试中，Hieronym 加权宏平均 F1 为 0.4587，SymGen 为 0.3173。跨反编译器时，IDA Pro 9.0 重新反编译后，Hieronym F1 为 0.4633，SymGen 为 0.3853。跨项目去重测试中，Hieronym F1 为 0.4661，SymGen 为 0.3377。对 363 个混淆二进制，三种混淆条件下 Hieronym F1 为 0.3866、0.3759、0.3030，均高于 SymGen（第 5.6 节）。

### 7.4 跨语言与真实案例

在 SPEC CPU2017 Xalan C++ 二进制上，Hieronym F1 为 0.4093，SymGen 为 0.3696；在四个 Java 项目超过 4,400 个函数上，Hieronym F1 为 0.3779，SymGen 为 0.2977。对 2,478 个恶意软件函数，不再微调直接推理，Hieronym 的 Precision、Recall、F1 为 0.4855、0.4897、0.4876（第 6.2 节）。

### 7.5 效率

Hieronym 平均每函数生成 20.69 tokens、0.0333 秒；SymGen 为 14.86 tokens、0.0245 秒。大二进制（2,284 个函数）上，Hieronym 吞吐率为 3.27 函数/秒，端到端延迟为每函数 0.3056 秒；全局摘要和调用摘要阶段可并行（第 7 节局限与成本讨论）。

## 8. 主要创新点

### 8.1 双层函数名评价

论文把 token-level 与 name-level 结合，并以混合分词、词元语义对齐、GPT-4o 判断和 embedding 阈值缓解单一分词评价的偏差。其价值是把“词面不同但语义相同”和“分词错误”分开；但 name-level 仍是 LLM 判定，不是形式化证明。

### 8.2 层次化二进制领域适配

相较仅生成函数摘要，论文同时用函数级摘要表达总体意图、语句级摘要表达实现细节，并对齐到 stripped 输入。消融结果支持该设计有效；真正贡献是把摘要层次与剥离二进制对齐过程结合起来，而不是单独使用摘要或 LLM。

### 8.3 全局、局部、目标三源融合

全局域信息、调用图邻域和 masked 目标函数各自提供互补语义。该组合使模型能够恢复项目特定词并提升跨架构/优化级别泛化，但也引入额外摘要生成成本和上下文偏置。

### 8.4 参数高效训练与严格去重

LoRA 将大模型适配成本限制在 attention 层低秩更新；按源文件和函数内容严格去重，则让跨项目和跨条件结果更接近真实泛化，而不是记忆训练样本。

## 9. 局限性

### 9.1 论文明确承认的局限

作者指出基础模型仍沿用 Code Llama，未来可换用更强模型；语句抽取依赖启发式规则，缺少客观质量指标；Ghidra 反编译误差和不同反编译器差异会造成数据偏差；真实函数名可能本身含糊或无描述性；Qwen3-Coder 生成的摘要有质量和风格波动；GPT 评价器选择可能引入偏差；推理成本高于 SymGen（第 7 节）。

### 9.2 阅读后发现的潜在局限

第一，name-level 评价同时依赖 GPT-4o 和 Qwen3-Embedding，虽然比纯 token 匹配稳健，但仍不是人工标注或程序语义验证，阈值选择也可能影响结论。第二，主数据集主要来自开源 GNU 项目和 GCC 9.4.0，跨架构覆盖虽广，却没有 RISC-V，不能直接推出 RISC-V 适用性。第三，函数命名是低层恢复中的一个子任务，不等价于恢复可重编译源码、LLVM IR 或完整控制流。第四，论文声称 ACM CCS 2026，但当前材料中的正式会议信息仍是模板占位符，正式出版状态需后续核验。

## 10. 阅读后的研究方向反思

### 10.1 对 LLM 编译器研究的启发

可借鉴“稳定语义摘要 + 原始低层表示”的双视图输入：对 LLVM IR、RISC-V 汇编或机器码优化，摘要可以帮助模型聚焦意图，原始 IR/汇编则保留可验证细节。多源上下文也提示低层优化不应只看局部指令窗口，还可显式提供调用关系、目标架构元数据和编译器诊断。

### 10.2 不能直接照搬的核心贡献

Hieronym 的核心是函数命名和二进制语义摘要，不是 IR/汇编等价变换。将其名称生成模块直接改成“RISC-V”并不足以构成新的编译器优化贡献；若用于优化，必须增加语义等价验证、可执行测试和真实性能反馈。

### 10.3 与 RISC-V 的关系

相关性为中等偏低：方法处理四种非 RISC-V 架构，提供跨 ISA 语义建模和严格去重的范式，但没有 RISC-V 实验、RVV 指令、RISC-V 后端或硬件性能测量。最合理的用法是作为低层语义恢复和数据构造参考，不应作为 RISC-V 优化结果的直接证据。

## 11. 可进一步尝试的研究方向

### 11.1 RISC-V stripped binary 函数命名迁移

#### 研究问题

层次摘要与调用上下文是否能在 RISC-V、RV64GC 和 RVV 下保持稳定的函数语义。

#### 与原论文的区别

需要建立 RISC-V 编译矩阵并处理 ABI、寄存器约定和向量指令，而不是只替换测试架构名称。

#### 可能的创新点

加入 RVV intrinsic/指令语义摘要、ABI 感知上下文和跨编译器去重。

#### 实验框架

```text
C/C++ 源码 → GCC/Clang RV64/RVV 编译 → stripped binary
→ Ghidra/其他 lifter → 分层摘要 + LLM 命名 → 人工/语义/跨项目评价
```

#### 可行性

需要 RISC-V GCC/LLVM、QEMU 或真实开发板、可追踪符号表和去重脚本；可从 Code Llama/Qwen 类模型的 LoRA 开始。

#### 主要风险

RISC-V 数据规模和跨项目多样性不足，且函数名本身未必能由低层语义唯一恢复。

### 11.2 面向 LLVM IR 的语义摘要辅助优化

#### 研究问题

函数级意图摘要是否能帮助 LLM 在生成 LLVM IR peephole 变换时减少无关候选并提高可验证率。

#### 与原论文的区别

输出从函数名变为 LLVM IR，必须对每个变换执行 Alive2 或等价测试，评价从名称相似度变为正确性与性能。

#### 可能的创新点

将摘要作为候选生成条件，将 verifier 反馈作为拒绝/修复信号，比较无摘要、局部摘要和多源摘要。

#### 实验框架

```text
LLVM IR → LLM 生成摘要与候选变换 → Alive2/LLVM 验证
→ 编译运行与性能测量 → 记录正确候选并反馈模型
```

#### 可行性

可使用现有 LLVM/Alive2 基础设施和 T2 论文的 IR 基准。

#### 主要风险

摘要可能诱导模型进行不受约束的语义猜测；有限 benchmark 通过不等于普遍正确。

### 11.3 低层恢复与可重编译性联合评价

#### 研究问题

函数命名、结构恢复和重编译成功率之间是否存在可测的关联。

#### 与原论文的区别

原论文只输出名称；新方向要求恢复结构化 IR 或 C，并验证重新编译后的行为。

#### 可能的创新点

构建“名称语义—控制流结构—重编译行为”三级评价，避免用单一 BLEU/F1 代表恢复质量。

#### 实验框架

```text
二进制 → 名称/结构候选 → LLVM IR/C → 编译与测试
→ 语义一致性检查 → 分层报告
```

#### 可行性

可复用本文的严格源文件去重和跨反编译器测试策略。

#### 主要风险

反编译器错误会把上游模型和下游验证混在一起，必须做工具隔离实验。

## 12. 与其他已读文献的关系

本轮 staging 只有 Hieronym 一篇合格论文，因此没有可在当前批次内建立的横向实验比较，也不能虚构与其他已读文献的数字关系。与全库已有的 LLM4Decompile、DecLLM、SLaDe、Forklift 和 BRIDGE 属于相邻的 T6 低层恢复方向，但本笔记不把它们当作“本轮已读”论文，也不复述其结果。

从任务边界看，Hieronym 输出函数名；LLM4Decompile、DecLLM 等输出更完整的源代码或可重编译结果；BRIDGE 输出 canonical LLVM IR。Hieronym 更适合作为二进制语义摘要/命名模块或数据预处理参考，而不是直接作为 IR 优化 baseline。它与 T2 的验证引导优化工作可在系统层组合，但两者的输出和评价指标不同，不能合并结论。

| 论文研究任务 | stripped binary 函数名恢复 |

这篇论文最值得学习的是把“可解释的层次语义摘要”和“可生成的 LLM 命名”结合，并用跨项目、跨编译器和跨反编译器测试检验泛化；最主要的局限是输出仍是函数名而非可验证的程序变换，且没有 RISC-V 或形式化语义验证。如果用于后续研究，最合理的使用方式是作为低层语义表示和评价设计参考，再把输出接到 IR/汇编生成与验证闭环，而不是简单地把测试架构名称替换为 RISC-V。
