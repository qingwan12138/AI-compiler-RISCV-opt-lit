# Nova 文献阅读总结

论文题目：**Nova: Generative Language Models for Assembly Code with Hierarchical Attention and Contrastive Learning**

作者：Nan Jiang、Chengxiao Wang、Kevin Liu、Xiangzhe Xu、Lin Tan、Xiangyu Zhang、Petr Babkin

发表时间：2025（ICLR 2025 正式会议论文；arXiv 首次公开版本为 2023 年）

发表平台：International Conference on Learning Representations 2025（ICLR 2025）

论文链接或编号：[ICLR 官方论文页](https://proceedings.iclr.cc/paper_files/paper/2025/hash/ef283d62b4bce30854a8d4827f331229-Abstract-Conference.html)；[官方 PDF](https://proceedings.iclr.cc/paper_files/paper/2025/file/ef283d62b4bce30854a8d4827f331229-Paper-Conference.pdf)；arXiv:2311.13721

关键词：汇编语言模型、二进制反编译、层次化注意力、对比学习、二进制代码相似性

> 本文档只依据已核验的 ICLR 2025 正式 PDF 正文；论文事实、阅读分析和后续建议分开描述。

## 1. 研究背景

本文研究二进制程序分析。安全分析、恶意软件检测、漏洞检测、二进制恢复和遗留软件维护经常只能获得汇编代码，而不是源代码。源代码大语言模型（Large Language Model，LLM；这里指能生成代码的语言模型）直接迁移到汇编存在困难：单条指令携带的信息少，完整语义分散在长指令序列中；同一源函数经不同编译优化级别后会形成差异很大的汇编。

论文第 1 节指出，已有二进制模型多为编码器模型，不能直接受益于生成式 LLM 的代码生成能力；已有生成式反编译方法的单元测试通过率也较低。因此作者希望构造专门面向 x86-64 汇编、同时支持生成和表示学习的基础模型。论文没有把该方法宣称为已支持所有 ISA 的方案。

## 2. 论文要解决的问题

### 2.1 汇编的低信息密度与长依赖

源代码中的一个语义片段常对应多条汇编指令，操作码、寄存器、内存访问及控制流依赖共同决定功能。普通 token 级注意力难以稳定学习跨较长指令序列的语义。

### 2.2 不同优化级别造成的语法多样性

同一 C 函数分别以 O0、O1、O2、O3 编译时，指令集合和组织方式可能显著变化。模型需要学习“功能相同但表面形式不同”的汇编，同时理解优化级别之间的差异。

### 2.3 生成与理解任务的统一

论文以二进制代码反编译（Binary Code Decompilation，BCD；汇编到高层源代码）和二进制代码相似性检测（Binary Code Similarity Detection，BCSD；判断不同优化版本是否来自同一函数）作为下游任务。

> 本文主要研究：如何在生成式代码 LLM 中加入面向汇编指令结构和编译优化差异的建模机制，以改善二进制反编译和二进制相似性表示。

## 3. 核心方法概述

Nova 建立在 DeepSeek-Coder 源代码模型上，使用从 C 源函数编译、剥离和反汇编得到的 x86-64 汇编语料继续预训练。系统核心是三层层次化自注意力（hierarchical self-attention）与两个对比学习目标：功能对比学习使同一函数的源代码和不同优化版本汇编靠近；优化对比学习按优化级别组织表示。

```text
C 函数（The-Stack、AnghaBench）
        ↓ gcc O0/O1/O2/O3 编译、strip、objdump 反汇编
规范化的 x86-64 汇编函数 + 源代码函数
        ↓ 语言建模 + 功能对比学习 + 优化对比学习
Nova 汇编基础 LLM
        ├─ 汇编 → C 源函数：BCD 生成
        └─ 汇编 → [INST] 表示 → 相似度排序：BCSD
```

LLM 在 BCD 中直接生成源代码，因此按 taxonomy v2 的角色建议为 `TRANSLATOR`；若按受控二级类，最贴近 `T6_Decompilation_LowLevel_Recovery`，并可在研究分区 T2 中作为 ASM/低层恢复论文。

## 4. 实验框架与训练流程

### 4.1 数据构建与汇编继续预训练

作者从 The-Stack 和 AnghaBench 的 C 函数构建数据：用 gcc 的 O0、O1、O2、O3 编译为可执行文件，去除调试信息，再用 objdump 反汇编；每个函数作为一个数据点。规范化包括删除 `%` 和注释、在若干标点周围加空格、把十六进制数转为十进制、把指令地址替换为 `[INST-n]` 标签。

作者从 DeepSeek-Coder 开始训练；层次化注意力应用于一半注意力头，以保留标准注意力头的既有能力。先进行一轮语言建模，再进行一轮对比学习。

### 4.2 BCD 微调与推理

输入提示形如“这是经过某优化级别的汇编代码：{asm}，源代码是什么？”，目标是生成对应 C 函数。作者从预训练语料抽取 216 万个汇编—源代码对（约 0.338B tokens）进行 BCD 微调；测试使用未参与训练的 HumanEval-Decompile。

每个汇编函数采样 20 个输出，temperature 为 0.2、top-p 为 0.95，再用测试用例执行生成的 C 代码，报告 Pass@1 和 Pass@10。

### 4.3 BCSD 微调与检索式评估

BCSD 使用 BinaryCorp-3M 的 O0/O3 汇编对微调。测试时将 O0 查询函数与 K 个 O3 候选函数编码，选相似度最高者；K 取 50、100、200、500，在 Binutils、Curl、ImageMagick、SQLite、OpenSSL、Putty 上报告 Recall@1。

本文不涉及 PPO、GRPO 或其他强化学习，也没有工具调用式在线修复循环；编译器和测试执行主要用于生成数据、反编译结果的功能验证及构造评测样本。

## 5. 奖励函数、损失函数或关键公式

本文没有使用强化学习奖励函数。关键训练目标为语言建模损失、功能对比学习损失和优化对比学习损失：

```text
L = L_lm + λ (L_fcl + L_ocl), 其中 λ = 0.1
```

`L_lm` 是代码语言建模的负对数似然。`L_fcl` 使用同一函数的源代码、O0/O1/O2/O3 汇编表示，按函数批次计算距离矩阵，使同一函数不同表示的嵌入距离更小、不同函数距离更大；批大小为 64 个不同函数。汇编函数嵌入是所有 `[INST]` 标签隐藏状态的平均，源函数嵌入是源代码 token 隐藏状态的平均。

`L_ocl` 对同一函数施加排序约束：优化级别越高，源代码与优化汇编嵌入的距离应越大，即模型学习 O0 到 O3 的优化顺序。BCD 微调另用 `L_bcd = -log P(src|p)`；BCSD 使用候选排序的对比式损失。论文的目标是学习功能一致性、优化差异和生成概率，并非通过奖励信号搜索代码。

## 6. 实验设置

### 6.1 数据集来源

预训练来源是 The-Stack 和 AnghaBench。表 1 报告的函数数量为：AnghaBench 原始 C 函数约 757.1K，O0–O3 汇编合计约 3.7M；The-Stack 原始 C 函数约 138.8K，O0–O3 汇编合计约 609.3K。结论部分将两者概括为约 430 万个汇编函数。论文未给出传统意义上的独立预训练/验证集规模。

BCD 测试集 HumanEval-Decompile 含 164 个 C 函数，每个函数分别形成 O0–O3 汇编；论文说明该测试集未用于训练。BCSD 微调集 BinaryCorp-3M 含 224,606 个函数的 O0/O3 汇编；测试项目为 Binutils、Curl、ImageMagick、SQLite、OpenSSL 和 Putty，论文说明这些项目不在训练数据中。作者没有详细量化数据泄漏风险。

### 6.2 模型与工具

基础模型为 DeepSeek-Coder；发布 Nova-1.3B 和 Nova-6.7B。数据生成工具是 gcc、strip 和 objdump。BCD 通过测试用例执行生成的 C 代码验证功能正确性；正文没有声称使用形式化验证器或 Alive2。硬件训练平台、gcc 的具体版本和推理硬件配置在正文中未明确说明，具体超参数主要放在附录。

### 6.3 对比方法

BCD 对比 CodeLlama-7B、StarCoder2-7B、DeepSeekCoder-7B、Qwen-2.5-Coder-7B、LLMCompiler-7B、GPT-3.5-Turbo、GPT-4o、LLM4Decompile-1.3B/6.7B。另做 Granite-3B-Code-128K 与 LongCoder 注意力设计比较。BCSD 对比 jTrans、DiEmph 和 CodeArt。

### 6.4 评价指标

| 指标 | 含义 | 趋势 |
| --- | --- | --- |
| Pass@1 | 每个反编译任务的一次采样中至少一个正确结果的估计通过率 | 越大越好 |
| Pass@10 | 十次采样中至少一个通过测试用例的估计通过率 | 越大越好 |
| Recall@1 | 候选池中同源函数被排在第一位的查询比例 | 越大越好 |

Pass@1/10 依据生成 C 程序在测试用例上的执行结果；这不是形式化语义等价证明。Recall@1 是相似度排序指标，也不是执行等价性证明。

## 7. 实验结果与结论

### 7.1 主要 BCD 结果

表 2 在 HumanEval-Decompile 的 O0–O3 和平均值上报告结果。Nova-1.3B 的平均 Pass@1 为 25.17%，Pass@10 为 38.30%；Nova-6.7B 分别为 34.36% 和 46.91%。同规模比较中，Nova-1.3B 相对 LLM4Decompile-1.3B 的平均 Pass@1 提高 14.84 个百分点、Pass@10 提高 21.58 个百分点；Nova-6.7B 相对对应规模模型提高 12.41 和 15.53 个百分点。Nova-1.3B 还高于 GPT-4o，平均 Pass@1/Pass@10 分别高 8.38 和 13.80 个百分点。上述数值都是 164 个函数、四个优化级别分组后取平均的绝对百分点差。

### 7.2 BCSD 结果

表 6–9 显示，Nova-6.7B 在 K=50、100、200、500 的六项目平均 Recall@1 分别为 0.86、0.79、0.75、0.67。Nova-1.3B 分别为 0.84、0.78、0.73、0.64；与 CodeArt 相比，作者概括其在四种候选池设置下分别多正确排序约 3%、1%、2%，在 K=500 时并列最高。Nova-6.7B 相对 CodeArt 的平均优势约为 5%、2%、4%、3%。

### 7.3 消融实验

表 5 中，去掉对比学习和层次化注意力的 `Nova−CL−HA` 平均 Pass@1/Pass@10 为 15.78%/27.41%；加入对比学习但去掉层次化注意力的 `Nova−HA` 为 21.86%/35.25%；完整 Nova 为 25.17%/38.30%。这表明在该实验条件下，对比学习和层次化注意力都带来增益，后者把平均 Pass@1 从 21.86% 提高到 25.17%。表 3 还显示在 Granite-3B-Code-128K 上加入 Nova 方法后平均 Pass@1 从标准微调的 13.97% 提高到 18.49%。

### 7.4 案例与表示分析

附录案例展示 Nova-1.3B 能从优化后的 x86-64 汇编恢复函数参数和嵌套循环，而 GPT-4 与 LLM4Decompile 的输出遗漏参数或循环。t-SNE/PCA 分析显示完整 Nova 的嵌入按功能区分更清晰；附录注意力分析观察到标准头中宽注意力最多约占 30%，层次化头中每个指令片段的注意力不超过 5%，但这些是作者对注意力分布的分析，不等于语义正确率证明。

## 8. 主要创新点

### 8.1 面向汇编的三层层次化注意力

Nova 将注意力分为指令内、前一指令和指令间三层，并在每条指令末尾加入 `[INST]` 摘要标签。其价值在于让模型先压缩单条指令语义，再建模邻近上下文和长距离指令依赖。表 4 与消融表 5 支持该设计在本文 x86-64 BCD 条件下有效；“通用适用于所有汇编语言”仍是作者提出的未来方向，不是本文实验证明的结论。

### 8.2 功能对比学习与优化对比学习的组合

功能对比学习把同源的源代码和多种优化汇编拉近，优化对比学习则把不同优化级别按顺序组织。该组合直接针对汇编语法差异，而不是把普通源代码 LLM 简单提示为反编译器。

### 8.3 生成与理解任务共享的汇编基础模型

Nova 同一基础模型经过不同任务微调，既可生成 C 代码，也可产生用于 BCSD 的函数表示。论文的真正贡献是汇编专用表示与生成训练设计的结合；使用 gcc、objdump、LLM 或测试用例本身不是独立创新。

## 9. 局限性

### 9.1 论文明确承认的局限

论文附录 A.9 明确指出 Nova 只用 x86 汇编语料预训练，因此是 x86-specific；原因包括 x86 二进制任务较多和计算资源限制。作者还只训练了 1.3B 与 6.7B 两种规模，更大模型留作未来工作。论文认为机制本身可能迁移到 ARM、MIPS 等汇编，但没有提供跨 ISA 实验。

### 9.2 阅读后发现的潜在局限

BCD 正确性由测试用例执行判定，有限测试不能替代形式化语义等价验证；反编译可读性与真实源代码恢复程度也未由单一 Pass@K 完整刻画。训练数据主要是由 C 编译得到的函数，复杂跨函数语义、手写汇编、异常处理和未覆盖 ISA 的表现无法从本文确认。BCSD 的 O0 查询/O3 候选设置对真实多编译器、多平台场景仍较窄。模型训练成本、具体硬件和版本信息在正文中不完整，复现实验需要依赖作者发布的模型和代码资源。

## 10. 阅读后的研究方向反思

值得借鉴的是“先建立指令级摘要，再组织长距离依赖”的建模思想，以及将同一源函数在不同优化级别下的编译产物用于功能不变性学习。对 RISC-V/RVV 研究而言，不能只把 x86 token 替换为 RISC-V token 就宣称创新；需要证明 RVV 的向量长度、掩码、尾部策略和别名语义如何进入表示与验证。

本文更适合作为汇编 Translator 的基础模型和 baseline，也可作为跨 ISA 迁移的预训练机制参考。它的核心贡献是汇编层次注意力与对比学习，后续工作应在新 ISA、真实硬件反馈或更强等价验证上形成差异，而不是直接复刻其数据生成流程。

## 11. 可进一步尝试的研究方向

### 11.1 RVV-aware 跨 ISA 汇编恢复

#### 研究问题

研究能否将 ARM NEON 或 x86 SIMD 汇编恢复/翻译到带显式向量长度和掩码语义的 RISC-V RVV 汇编或 LLVM IR。

#### 与原论文的区别

不只替换 ISA，而是把 VL、vtype、mask、tail policy 等状态作为结构化上下文，并评估跨 ISA 语义保持。

#### 可能的创新点

设计 RVV 指令摘要、跨 ISA 功能对比目标和编译/执行一致性反馈。

#### 实验框架

```text
多 ISA 源函数与汇编对
        ↓ 结构化指令摘要 + Nova 式对比预训练
目标 RVV 汇编/IR 生成
        ↓ LLVM 编译、仿真器或硬件测试
语义与性能反馈
```

#### 可行性

需要 LLVM/RVV、QEMU 或真实 RVV 平台、跨 ISA 平行语料和可执行测试。

#### 主要风险

不同 ISA 的 ABI、向量状态和未定义行为难以对齐，有限测试可能掩盖语义错误。

### 11.2 形式化验证增强的汇编 Translator

#### 研究问题

研究生成的低层代码能否通过 SMT/翻译验证器筛选并迭代修复。

#### 与原论文的区别

Nova 使用测试用例评估 BCD；该方向将有限测试扩展为受边界约束的语义验证，并把失败原因反馈给模型。

#### 可能的创新点

让 `[INST]` 摘要同时携带寄存器、内存和控制流约束，形成验证感知的生成目标。

#### 实验框架

```text
汇编输入 → Nova 生成候选 → 编译/验证器
                         ├─ 通过：保留
                         └─ 失败：提取反例/错误 → 再生成
```

#### 可行性

需要 LLVM IR 或可建模汇编、SMT/翻译验证工具和可控的函数级基准。

#### 主要风险

验证器覆盖范围、内存模型和循环边界会限制可验证程序规模；验证通过也可能只是在有界条件下成立。

### 11.3 面向编译优化轨迹的多级表示学习

#### 研究问题

研究从 O0 到 O3 的单一顺序是否足以表示不同编译器、不同 pass 顺序和不同硬件目标的优化轨迹。

#### 与原论文的区别

将论文的线性优化级别扩展为带编译器、目标 ISA、pass 图和性能标签的多维轨迹。

#### 可能的创新点

构造优化偏序或图结构对比学习，而非假定所有优化都能由 O0<O1<O2<O3 表示。

#### 实验框架

```text
源函数 × 编译器 × ISA × pass 轨迹
        ↓ 结构化汇编摘要与多维对比目标
统一低层代码表示
        ↓ 反编译、相似性、性能预测三类评测
```

#### 可行性

需要可重复的 LLVM/GCC 编译矩阵、多个 ISA 目标和足够的计算资源。

#### 主要风险

数据量和编译矩阵迅速膨胀；不同优化轨迹的“距离”未必有唯一合理定义。

## 12. 与其他已读文献的关系

本文正文明确将 LLM4Decompile、SLaDe、Meta LLMCompiler 等作为相关工作或 baseline；本轮去重检查确认 LLM4Decompile、SLaDe、Forklift、DecLLM、PtxDec、BRIDGE、Hieronym、SK²Decompile 已在正式语料中，Nova 本身未发现正式条目。Nova 与这些工作的共同点是直接处理低层代码或反编译；区别在于 Nova 的核心是通用汇编基础模型、层次化注意力和两种对比学习，而 SK²Decompile 是结构恢复到标识符命名的两阶段方案，BRIDGE 强调结构感知检索与迭代验证。

在当前批次只有 Nova 一篇已完成全文笔记，因此没有其他本批次论文可供建立事实级横向比较。按角色建议，Nova 适合作为 `TRANSLATOR` 的汇编/反编译 baseline；其 BCSD 分支可作为低层表示学习工具模块，但不应因此改分类为 SELECTOR 或 GENERATOR。

| 输入 | C 源函数编译得到的规范化 x86-64 汇编；BCSD 为 O0/O3 汇编 |
| 输出 | BCD 的 C 源函数；BCSD 的函数嵌入和相似度排序 |
| 核心方法 | 三层层次化注意力 + 功能/优化对比学习 |
| 使用的模型 | DeepSeek-Coder 起始模型；Nova-1.3B、Nova-6.7B |
| 使用的编译器工具 | gcc、strip、objdump；测试用例执行 |
| 是否使用强化学习 | 否 |
| 是否使用形式化验证 | 否；使用有限测试执行验证功能正确性 |
| 数据集规模 | 预训练约 4.3M 汇编函数；BCD 微调 2.16M 对；HumanEval-Decompile 164 函数；BCSD BinaryCorp-3M 224,606 函数 |
| 主要指标 | BCD Pass@1/Pass@10；BCSD Recall@1 |
| 最重要实验结果 | Nova-1.3B 平均 Pass@1/10 为 25.17%/38.30%；相对同规模 LLM4Decompile 提高 14.84/21.58 个百分点 |
| 核心创新 | 指令摘要驱动的层次化注意力，以及功能和优化对比学习组合 |
| 主要局限 | 仅 x86 语料；仅 1.3B/6.7B；测试正确性不等于形式化等价 |
| 与 RISC-V 研究的相关性 | 中：机制可启发 RVV 汇编建模，但论文没有 RISC-V 实验 |
| 最适合作为 | 汇编 Translator baseline、跨 ISA 表示学习方法参考 |

> 这篇论文最值得学习的是把汇编的指令级局部语义和跨指令长依赖显式分层，并用同源函数的多优化版本做对比学习；最主要的局限是只验证了 x86-64 和有限测试执行；如果用于后续研究，最合理的使用方式是作为低层 Translator baseline，再加入 RVV 语义建模或验证反馈，而不是简单替换目标 ISA。
