# AwareCompiler 文献阅读总结

论文题目：**AwareCompiler: Agentic Context-Aware Compiler Optimization via a Synergistic Knowledge-Data Driven Framework**

作者：Hongyu Lin、Haolin Pan、Haoran Luo、Yuchen Li、Kaichun Yao、Libo Zhang、Mingjie Xing、Yanjun Wu

发表时间：2025

发表平台：arXiv:2510.11759（预印本）

关键词：LLM Agent、LLVM phase ordering、知识库、SFT、强化学习、代码尺寸

> 本文档基于 16 页 PDF 全文整理。

## 1. 研究背景

直接让通用 LLM 从抽象程序特征生成 LLVM pass 序列，容易出现语义错位、无效 pass 和长决策链上的稀疏反馈。传统 ML 又依赖大量 profiling 数据，跨程序扩展性有限（第1节）。

## 2. 论文要解决的问题

如何让小型 LLM 编译器智能体理解程序特征与 pass 作用之间的关系，通过知识检索和编译环境交互生成合法、有效的代码尺寸优化序列，并利用训练数据与反馈共同提升策略。

## 3. 核心方法概述

AwareCompiler 包含三部分：一是由经验知识、符号依赖/冲突和负面序列组成的知识库；二是用 AutoPhase 特征表示程序、检索相关知识并自适应生成 pass 序列；三是先 SFT 学习推理格式与有效序列，再用 RL 和编译工具反馈优化。训练样本由程序特征、推理过程、最优序列和优化效果组成（第3节）。

## 4. 实验框架与训练流程

```text
程序 → AutoPhase 特征
→ 检索经验/符号/负面知识
→ LLM 推理并生成 pass 序列
→ LLVM 编译与 instruction count 工具
→ 格式/合法性/性能反馈
→ SFT 初始化 + RL 强化
```

推理时智能体可在通用策略失败后查询知识库并重试（第4.6节案例）。

## 5. 奖励函数、损失函数或关键公式

SFT 最小化代码尺寸任务上的监督损失；RL 最大化折扣累计回报（式10–11）。组合奖励包括：

- Format Reward：正确输出 `<think>`、`<tool call>`、`<answer>`；
- Answer Reward：序列 schema、工具协议和编译测试有效；
- Performance Reward：`ΔIC=(IC_before-IC_after)/IC_before`。

论文未明确给出具体 RL 算法、各奖励权重及完整训练超参数。

## 6. 实验设置

### 6.1 数据与模型

Qwen2.5-Instruct 1.5B/3B/7B；SFT 样本 2,000+，RL 样本 15,000+。基准为 BLAS、cBench、CHStone、MiBench、NPB、OpenCV、TensorFlow（第4.1节）。

### 6.2 编译环境

LLVM 10.0.0，固定 124 个 pass；代码尺寸用 LLVM IR instruction count 表示。训练/实验硬件为 Xeon Gold 6430、4×H100 80GB、1TB RAM。

### 6.3 基线与指标

`-O1/-O2/-O3/-Oz` 及 GPT-5、Gemini-2.5-Pro、DeepSeek-V3、Claude-Opus-4 等通用 LLM。主要指标为相对初始 IR 的 instruction reduction 和合法 pass 成功率。

## 7. 实验结果与结论

AwareCompiler-1.5B 在七套基准上的平均 IR 指令减少为 30.03%，略高于 `-Oz` 的 29.98%，高于 DeepSeek-V3 的 26.52% 和 GPT-5 的 12.91%（表1）。3B/7B 平均为 27.86%/29.47%，说明更大模型不必然更好。1.5B 去知识、去 RL 数据、两者都去掉后分别为 27.24%、29.37%、16.98%（表2）。完整奖励达到 30.03%，去掉任一奖励后为 8.02%–18.10%（图5）。

## 8. 主要创新点

### 8.1 三类编译知识统一检索

同时保存有效经验、pass 依赖/冲突和已知退化序列。

### 8.2 上下文感知的 Agent 工作流

从静态特征出发，允许工具验证、知识检索与多轮修正，而非一次性预测。

### 8.3 知识与数据的两阶段训练

SFT 负责稳定格式和基本策略，RL 用真实编译效果强化有效行为。

## 9. 局限性

论文是预印本，实验以 LLVM IR 指令数代理代码尺寸和性能，未报告最终二进制尺寸、运行时间、能耗或真实后端结果。比较中排除了其他 ML 方法，理由是数据未公开，因而缺少与 CompilerGym/AutoPhase 等强基线的同条件比较。论文没有明确 RL 算法、知识库规模/更新规则、正确性测试覆盖和多次重复的方差，复现细节不足；LLVM 10 与当前工具链也有版本差距。

## 10. 阅读后的研究方向反思

AwareCompiler 已覆盖“知识库+Agent+SFT/RL+复合奖励”这条宽泛组合，后续不能只换模型或增加一种知识。更稳妥的创新应围绕可审计证据、跨架构真实性能、知识冲突处理或验证覆盖，并用成熟搜索/编译基线公平比较。

## 11. 可进一步尝试的研究方向

### 11.1 可审计的跨架构负面知识门控

#### 研究问题

如何区分“普遍无效的 pass 组合”和“只在某架构退化的组合”，并给出可复核证据。

#### 与原论文的区别

原文的负面知识是静态集合；扩展工作绑定编译统计、硬件计数器、架构和置信度。

#### 可能的创新点

证据溯源、架构条件负面记忆、不确定性拒绝机制。

#### 实验框架

```text
LLM 提议 → 依赖检查 → x86/K3 编译实测
→ 归因 pass statistics/PMU → 写入带条件的负面知识
```

#### 可行性与风险

无需大规模微调即可先做检索增强；性能归因容易混淆，需要消融验证。

## 12. 最小可行 Demo

### 12.1 Demo 目标

构建一个不训练或只轻量微调的小型 Agent，为 20 个程序生成 LLVM pass 序列并维护证据化失败记忆。

### 12.2 输入数据

cBench/PolyBench 小程序及 x86、K3 测量记录。

### 12.3 执行流程

```text
特征提取 → 检索历史证据 → 生成序列 → 编译/测试/计时 → 更新记忆
```

### 12.4 需要的工具

LLVM、代码 LLM、向量/结构化数据库、perf、K3。

### 12.5 输出结果

| 方法 | 合法率 | 正确率 | x86/K3 加速 | 重复失败率 |
|---|---:|---:|---:|---:|

### 12.6 成功标准

相对无记忆 Agent 降低重复无效尝试，且不因跨架构负迁移明显降低最终性能。

## 13. 与其他已读文献的关系

与 Compiler-R1 同属 RL 编译智能体；与 CITROEN 不同，AwareCompiler 用知识与 LLM 生成序列，CITROEN 用真实 statistics 训练在线 GP；与 ECCO 的证据因果蒸馏高度相邻，ECCO 进一步把 LLM 意图与 GA 分工。设计新总线时应避免重复这三者的已有组合。

## 14. 一页式总结

| 项目 | 内容 |
|---|---|
| 论文研究任务 | 知识与数据协同的 LLM phase-ordering Agent |
| 核心问题 | 语义错位、交互低效、奖励稀疏 |
| 输入/输出 | AutoPhase 特征 / LLVM pass 序列 |
| 核心方法 | 三类知识库、检索、SFT、RL、工具反馈 |
| 使用模型 | Qwen2.5-Instruct 1.5B/3B/7B |
| 是否使用强化学习 | 是，但算法细节未明确 |
| 是否使用形式化验证 | 否 |
| 最重要结果 | 1.5B 平均指令减少 30.03% |
| 核心创新 | 知识检索与数据训练协同的上下文 Agent |
| 主要局限 | 指标代理性强、复现与公平对比不足 |
| 与 RISC-V 相关性 | 中，可通过真实后端扩展 |
| 最适合作为 | 竞品与负面知识设计参考 |

> 需要谨慎看待“平均减少 30.03%”：它是 LLVM IR 指令数，不等同于程序运行加速。
