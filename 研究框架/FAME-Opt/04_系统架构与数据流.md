# FAME-Opt 系统架构与数据流

## 1. 总体架构

```text
Program & Environment Manager
            ↓
Baseline Profiler
            ↓
Experience Retriever
            ↓
LLM Optimization Planner
            ↓
Action Validator & Executor
            ↓
Semantic Gate
            ↓
Evidence & Performance Collector
            ↓
Probe Scheduler
      ┌─────┴─────┐
      ↓           ↓
  不追加探针   最小反事实
      └─────┬─────┘
            ↓
Certificate Builder
            ↓
FOEU Auditor & Memory
            ↓
下一轮候选
```

---

## 2. Program & Environment Manager

必须保存：

```text
program_id
program_family
source_hash
input_id
input_generator_version
compiler_path
compiler_version
target_triple
cpu_model
os
kernel_version
environment_variables
random_seed
```

所有实验结果都绑定环境，避免不同版本混淆。

---

## 3. Baseline Profiler

步骤：

1. 编译参考实现；
2. 编译 `-O3` 基线；
3. 固定输入校验；
4. 预热；
5. 重复计时；
6. 计算中位数和置信区间；
7. 保存 Remark；
8. 保存 IR 和汇编摘要。

输出：

```json
{
  "program_id": "dot_product",
  "input_id": "n_1048576",
  "flags": ["-O3", "-march=native"],
  "runs_ns": [100100, 99800, 100050],
  "median_ns": 100000,
  "remark_summary": {
    "vectorized_loops": 1,
    "unrolled_loops": 0
  },
  "assembly_summary": {
    "vector_instruction_count": 32,
    "conditional_branch_count": 4
  }
}
```

---

## 4. Experience Retriever

检索顺序：

1. 高匹配负经验；
2. 高匹配确认成功；
3. 同类程序机制无收益；
4. 偶然成功只用于警告。

首版无需向量数据库，可按：

- 程序族；
- 动作类型；
- 循环/访存/分支标签；
- 输入规模桶；
- 平台；

做简单加权匹配。

---

## 5. LLM Optimization Planner

输入：

- 源码或 IR 摘要；
- 基线性能；
- Remark；
- 汇编摘要；
- 正负经验；
- 剩余预算。

输出固定 JSON：

```text
preconditions
actions
expected_mechanism
expected_evidence
semantic_oracle
performance_claim
falsifiers
experience_usage_reason
```

每轮只生成 2–3 个候选。

LLM 禁止：

- 修改测试；
- 删除计算；
- 任意拼接命令；
- 使用动作白名单之外的参数；
- 改变计时区域。

---

## 6. Action Validator & Executor

职责：

- Schema 校验；
- 白名单校验；
- 参数范围；
- 动作冲突；
- 生成命令；
- 设置超时；
- 保存日志。

冲突示例：

- 同时启用和关闭向量化；
- 展开因子越界；
- 使用当前编译器不支持的 flag；
- 使用与目标架构不兼容的 `-march`。

---

## 7. Semantic Gate

### 层 1：编译和链接

失败立即终止。

### 层 2：固定、边界、随机输入

所有输入预先固定。

### 层 3：Sanitizer

准备入库候选至少执行 ASan/UBSan 中适用部分。

### 层 4：Alive2 可选

只对适合的局部 IR 使用，不作为首版所有候选前置条件。

---

## 8. Evidence & Performance Collector

### 编译证据

- Optimization Remarks；
- IR 指令类别；
- 基本块；
- 向量类型；
- 内联状态；
- 代码尺寸；
- 汇编指令类别。

### 性能证据

- 真实运行时间；
- 可选 cycles、instructions、branches、cache-misses。

运行时间是最终裁决，PMU 只作机制辅助。

---

## 9. Probe Scheduler

输出：

```json
{
  "probe_required": true,
  "selected_probe": "remove_unroll",
  "probe_reason": "best candidate with conflicting evidence"
}
```

首版规则：

```text
正确性失败 → 不探针
性能不达标 → 通常不探针
最佳候选 → 探针
多动作且证据冲突 → 探针
准备入库 → 探针
仅当前程序临时候选 → 可不探针
```

反事实必须计入总测量预算。

---

## 10. Certificate Builder

生成独立文件：

```text
semantic_certificate.json
profitability_certificate.json
```

语义通过并不意味着盈利通过。

---

## 11. FOEU Auditor

分类：

```text
if semantic_invalid:
    failed
elif profitable and mechanism_supported and counterfactual_supported:
    confirmed_success
elif profitable and not mechanism_supported:
    accidental_success
elif not profitable and mechanism_supported:
    mechanism_without_profit
else:
    uncertain
```

经验权限：

| 状态 | 正向检索 | 负向提醒 | 训练 |
|---|---:|---:|---|
| 确认成功 | 是 | 否 | 正样本 |
| 偶然成功 | 否 | 是 | 解释负样本 |
| 机制无收益 | 否 | 是 | 性能负样本 |
| 失败 | 否 | 是 | 合法性/正确性负样本 |

---

## 12. 单候选生命周期

```text
提出候选
→ Schema
→ 编译
→ 正确性
→ 性能
→ 机制证据
→ 是否探针
→ 双证书
→ FOEU 分类
→ 记忆更新
```

---

## 13. 搜索轮次

### Round 0

建立 `-O3` 基线。

### Round 1

生成 2–3 个差异明显候选。

### Round 2

根据反馈只调整一个关键决策。

### Round 3

达到阈值后优先审计，不继续无止境搜索。

停止条件：

- 达到候选预算；
- 找到置信区间达标候选；
- 连续两轮无新动作；
- 重复候选；
- 正确性失败率过高；
- 最优候选已完成审计。

---

## 14. RISC-V 扩展字段

预留：

```text
target_triple
march
mabi
vector_length
sew
lmul
mask_policy
tail_policy
hardware_id
```

第二阶段优先复测 x86 上三类经验：

- 确认成功；
- 偶然成功；
- 机制无收益。

观察语义状态和盈利状态如何变化。
