# 配对控制边际效用反馈获取：文献依据与创新边界

## 1. 使用说明

本文件用于约束论文表述，不替代正式系统综述。表中的 2026 年工作和预印本必须在投稿前核验：

- 精确题目；
- 作者；
- 发表或预印本版本；
- 实验任务；
- 是否真的覆盖“同状态反馈边际效用”；
- 是否已有相同的主动获取与停止机制。

未经核验的条目在论文中不得写成确定事实。

## 2. 已有研究大致覆盖的能力

已有工作通常已经覆盖以下一种或多种能力：

- 使用编译错误、测试结果或性能结果进行多轮代码修改；
- 让 Agent 调用编译器、测试器、分析器和搜索工具；
- 使用结构化 compiler remark 改善反馈质量；
- 使用 SFT 或 RL 学习 thought-tool-feedback 交互；
- 在固定轮数、Token 或计算预算下搜索；
- 在源码、IR 或汇编等多个抽象层之间分配计算；
- 在生成过程中提前引入编译反馈。

因此，本研究不能把“调用工具”“反馈闭环”“预算控制”或“停止”本身当作首创。

## 3. 证据、推导与候选创新

【论文事实】近期工作已经覆盖：利用掩蔽反馈反事实衡量反馈对后续动作分布的影响、在显式工具预算下动态规划和提前停止、利用结构化编译器提示改善代码优化，以及通过编译器—LLM协作分配优化预算。

【合理推导】因此，“反馈改变动作分布”“预算感知工具调用”“结构化编译器反馈”和“主动停止”都不能单独作为本研究的新颖性主张。仍可检验的窄空白是：在编译优化任务中，是否能用正确性门控的同状态配对结果估计反馈的**边际效用**，并在反馈依赖和未支付增量成本约束下优于直接结果预测及等预算多采样。

【候选创新】正确性门控的配对边际效用反馈获取，以及为其服务的随机性复测、任务置换安慰剂和依赖成本选择机制。当前证据支持把它作为候选主线，但不能声称已证明“首次”或严格因果效应。

## 5. 候选研究空白

本研究只保留一个狭窄主张：

> 现有方法已经研究反馈对动作分布的影响、反馈结构、工具预算和停止；本研究进一步测量在同一编译优化状态下，获取某条反馈相对于不获取它，是否产生通过正确性门控的正向效用增量，并把该增量与尚未支付的获取成本联合建模。

这个空白是否真实存在，必须通过持续检索和最近邻复现确认。

## 6. 与最近邻方法的区分

| 最近邻方向 | 其主要问题 | 本框架额外回答的问题 |
|---|---|---|
| 全量反馈 Agent | 每轮向模型返回所有日志或指标 | 哪些反馈不值得获取，删除后是否影响正确优化 |
| 固定阶段路由 | 按编译失败、测试失败、无收益选择固定工具 | 同一阶段不同程序、候选和剩余预算下，反馈价值是否不同 |
| 结构化 compiler remark | 怎样让反馈更精确、可读 | 即使反馈精确，此刻是否值得付出获取和上下文成本 |
| 不确定性门控 | 模型不确定时请求帮助 | 请求哪一类反馈，以及反馈能否产生正向配对边际效用 |
| 直接收益预测 | 预测得到反馈后的有效优化结果 | 减去同状态无反馈基准后的边际效用是否更适合反馈选择 |
| 多层预算分配 | 在源码、IR、汇编等层级分配计算 | 在固定优化层级内选择具体反馈并考虑其依赖成本 |
| 固定轮数/阈值停止 | 达到阈值或轮数后停止 | 停止是否由剩余边际效用与完整获取成本共同触发 |
| 多采样搜索 | 用预算生成更多候选 | 同等预算用于反馈还是候选采样，哪种收益更高 |

- 首次让 Agent 选择工具；
- 首次控制 Token、工具调用或时间预算；

- 首次使用 LLM 路由器、小分类器或置信度；

## 8. 可保留的候选贡献表述

### 6.1 核心方法

提出面向 LLM 编译优化的**正确性门控配对边际效用获取函数**：在同状态下比较获取反馈与不获取反馈的正确优化结果，并扣除尚未支付的 Token、工具执行和墙钟增量成本。

### 6.2 标注方法

提出带“无反馈复测”和“按类型匹配的任务置换安慰剂”的配对标注流程，用于分离：

- LLM 自然随机性；
- 上下文扰动；
- 真实反馈信息产生的有益变化。

### 6.3 在线策略

提出反馈依赖图与增量成本驱动的选择及停止策略，在反馈不可用、尚未支付的前置成本过高或边际效用为负时，选择执行、接受当前最优或停止。

## 9. 必须设置的最近邻基线

- `StageRule`：固定阶段规则；
- `UncertaintyOnly`：只按不确定性决定是否请求默认反馈；
- `DirectGain`：只预测反馈后的有效优化结果，不减去同状态无反馈基准；
- `CheapestFeedback`：始终选择最低成本的可用反馈；
- `BudgetMatchedSampling`：把节省预算用于额外候选采样；
- `OracleFeedback`：离线上界，仅用于估计可提升空间。

没有 `DirectGain`，无法证明同状态无反馈基准和边际目标有必要；没有 `BudgetMatchedSampling`，无法证明预算应投入反馈选择而不是多采样。

## 11. 创新成立所需证据

| 创新 | 必需证据 | 否定证据 |
|---|---|---|
| 配对边际效用获取 | 相比 StageRule 和 DirectGain 提升等预算正确优化 | DirectGain 或 StageRule 同等/更优 |
| 控制型配对标注 | 真实反馈效应高于无反馈复测和匹配安慰剂 | 三者无差异或安慰剂同样有效 |
| 依赖感知停止 | 成本下降且正确优化率不显著降低，停止后遗憾低 | 过早停止明显损害质量 |

## 12. 论文表述建议

建议写成：

> 我们不主张首次使用编译器反馈、反事实动作变化或预算化工具调用。我们研究的是在同一优化状态下，某条反馈相对于不获取它所产生的正确性门控配对边际效用，并将该效用与未支付增量成本用于在线反馈选择和停止。

不建议写成：

> 本文的核心创新是让 Agent 自动选择编译反馈。

后者范围过大，容易与既有工具路由、预算 Agent 和结构化反馈工作发生直接碰撞。
