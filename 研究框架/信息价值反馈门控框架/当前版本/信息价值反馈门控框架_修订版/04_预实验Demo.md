# 正确性门控的配对边际效用反馈获取：预实验 Demo

## 1. Demo 目标

预实验不追求一次完成论文，而是用最低成本依次回答四个“继续或停止”问题：

1. 真实反馈相对于无反馈复测和匹配安慰剂，是否产生额外的正确优化效用？
2. 减去同状态无反馈基准的边际目标，是否比只预测反馈后结果更适合选择反馈？
3. `VOIGate` 能否在等预算下至少不弱于 `StageRule`？
4. 节省的预算用于额外候选采样时，是否会轻易替代反馈获取？

“反事实”在本 Demo 中只表示同状态配对控制比较，不表示已经完成严格因果识别。

## 2. 两阶段规模

### 2.1 P0：信号筛选

- 10 个 C 函数；
- 5 类程序模式：循环、分支、内存、函数调用、混合；
- 20–30 个代表状态；
- 每个状态只选择一种当前可用的真实反馈；
- 条件为 `N0`、`N1`、一个随机抽取的匹配安慰剂和一种真实反馈；
- 每任务最多 2 轮；
- 一个固定 LLM；
- 使用预注册固定种子方案；
- 不训练复杂模型，仅使用规则和描述性配对统计。

P0 约需 80–120 个条件运行。它只判断“是否值得继续”，不能用于声称方法已显著优于全部基线。

### 2.2 P1：机制确认

只有 P0 出现有效信号才执行：

- 扩展到 20 个函数和 40–80 个状态；
- 覆盖 Compile、Test、Remark、IR 四类反馈；
- 每类反馈使用 2–3 个匹配安慰剂；
- 至少 3 个配对种子块；
- 每任务最多 3 轮；
- 训练规则、逻辑回归或成对排序器；
- 完整比较 `StageRule`、`DirectGain`、`VOIGate` 和 `BudgetMatchedSampling`。

## 3. 环境固定

记录：

- Clang/LLVM 精确版本；
- 编译选项；
- CPU、操作系统；
- LLM 精确模型 ID；
- temperature、top_p、seed block；
- Prompt 和输出 schema 哈希；
- 测试和随机输入生成器版本。

预实验不同时更换模型、编译器或平台。RISC-V 不进入 P0/P1，只在完整实验后用于外部验证。

## 4. 任务与状态准备

每个函数必须具备：

- 原始正确实现；
- 固定单元测试；
- 随机输入差分测试；
- Sanitizer 可执行配置；
- 可复现的 IR 指令数或代码大小测量；
- 至少一种理论上可优化的结构。

首轮主目标固定为 LLVM IR 指令数下降，阈值 `epsilon_static` 在运行前预注册。状态分为：

- 编译失败：Compile 可用；
- 编译成功但测试失败：Test 可用；
- 编译与测试通过但收益不足：Remark 或 IR 可用。

P0 在每个状态只测试一种真实反馈，按上述状态规则预注册，不根据事后结果挑选反馈。

## 5. 配对控制条件

```text
N0：无新增反馈基准
N1：无新增反馈复测，使用预注册的另一 seed
P1/P2/P3：同类型、跨任务置换的匹配安慰剂
C/T/R/I：当前状态下预注册的一种真实反馈
```

### 5.1 配对种子规则

- 相同 seed 在不同 Prompt 下不保证严格确定性，因此只作为配对区组编号；
- P0 使用固定种子方案筛选信号，并把随机性局限写入结论；
- P1 至少使用 3 个配对种子块；
- 每个条件使用相同 temperature、top_p、最大输出长度和结构化输出格式；
- 统计时以任务/状态为单位，种子作为区组，不把多次生成当作独立任务。

### 5.2 安慰剂构造规则

每类真实反馈准备 2–3 个置换安慰剂：

- 来自另一任务的同类反馈；
- 匹配 Token 长度、字段结构、语气和数值密度；
- 编译/测试安慰剂还应匹配错误类别外观；
- 替换程序名、变量名、错误位置、输入输出和优化线索；
- 通过人工或规则泄漏检查，确认不能推断当前任务答案；
- P0 对每个状态随机抽取一个安慰剂，P1 轮换全部安慰剂。

## 6. 记录与效用

记录：

- action type、target、parameters、ranking；
- correctness；
- static gain；
- decision change；
- beneficial change；
- `DeltaUtility`；
- 新增 Token、未支付前置工具、反馈生成、额外验证和墙钟成本。

```text
U(a) = 0，若正确性门控失败
U(a) = static_gain，若正确且达到预注册改善阈值

DeltaUtility(f | s)
  = U(a_f) - U(a_0)
```

同一工具事件只计费一次。已完成编译不得同时记入反馈执行成本和前置成本。

## 7. P0 执行与停止门槛

### 7.1 执行步骤

1. 冻结任务、状态、目标、Prompt、种子方案和反馈映射；
2. 对每个状态运行 `N0`、`N1`、一个匹配安慰剂和一种真实反馈；
3. 对所有候选执行编译、固定测试、差分测试和 Sanitizer；
4. 计算状态级配对 `DeltaUtility` 和 beneficial-change；
5. 用配对 bootstrap 置信区间或配对置换检验描述方向，不以单个 p 值作为继续依据；
6. 分程序家族和状态类型检查结果是否由少数案例主导。

### 7.2 继续到 P1

同时满足：

- 至少一种真实反馈的配对边际效用高于 `N1` 和匹配安慰剂；
- 有益结果不只来自一个函数或一个状态类别；
- 正确性门控后信号仍存在；
- 安慰剂没有达到与真实反馈相同的效果；
- 数据和成本记录无泄漏、重复计费或反馈可用性错误。

### 7.3 直接停止

满足任一条件即不进入 P1：

- 真实反馈与安慰剂无可区分的方向；
- 正确性门控后收益消失；
- 结果由单个任务主导；
- 反馈生成或验证成本已经超过可接受预算；
- 需要复杂模型才能在训练数据上勉强出现信号。

## 8. P1 简单预测器

### 8.1 特征

- 当前阶段和程序结构摘要；
- 当前动作类型与置信度；
- 已观察反馈和可用反馈 mask；
- 剩余多维预算；
- 预计新增 Token、工具次数和墙钟；
- 未支付前置依赖；
- 多采样动作一致率。

### 8.2 模型与切分

优先顺序：

1. 手工规则；
2. 逻辑回归；
3. 成对排序器；
4. 数据量和分组交叉验证稳定时才使用梯度提升树。

同一程序产生的全部状态只能出现在一个数据分区。使用按程序分组的开发、校准和测试切分，或者交叉拟合；禁止在训练标签上报告门控效果。

### 8.3 预测目标

- 自报告反馈有用性；
- 阶段启发式；
- `P(change)`；
- `P(beneficial_change)`；
- `DirectGain = E[U(a_f) | s,f]`；
- `DeltaUtility = E[U(a_f)|s,f] - E[U(a_0)|s]`。

若效用大量为零，使用“真实反馈是否优于 N0”的成对胜负标签，不升级复杂模型。

## 9. P1 在线策略比较

最低比较：

1. `StageRule`；
2. `DirectGain`；
3. `VOIGate`；
4. `VOIGate-NoStop`；
5. `BudgetMatchedSampling`。

`AllFeedback`、`RandomOne`、`CheapestFeedback` 和 `UncertaintyOnly` 作为补充基线；Oracle 只离线计算上界。

### 等预算

- 相同输入/输出 Token 上限；
- 相同 LLM 调用上限；
- 相同编译、测试和分析调用上限；
- 相同墙钟上限；
- 相同 `available_feedback_mask` 和缓存证据；
- 达到任一上限立即停止；
- `BudgetMatchedSampling` 分别匹配 Token 预算和工具/墙钟预算。

## 11. 扩大到完整实验的门槛

同时满足：

1. 真实反馈的配对边际效用高于控制组；
2. `VOIGate` 至少不弱于 `StageRule`，并至少降低一种原始成本；
3. `VOIGate` 优于 `DirectGain`，或能明确说明两者相当时核心主张如何降级；
4. `BudgetMatchedSampling` 没有显著更优；
5. 主动停止减少无效尾部轮数，且有效优化率未明显下降；
6. 结果在至少 4 个程序家族中方向一致；
7. P1 的组外测试结果与校准结果方向一致。

若只优于 `AllFeedback`，不扩大实验。

## 12. 降级方案

- 测试反馈生成困难：先做 Compile、Remark 和 IR，并明确适用阶段；
- LLM 不提供置信度：使用多次采样动作一致率；
- 运行时间噪声大：预实验只使用预注册静态目标；
- 分类器数据不足：使用规则门控并报告 Oracle gap；
- `DirectGain` 与 `VOIGate` 相当：删除“边际目标优于直接结果预测”的主张，保留成本审计结果；
- `StageRule` 接近 Oracle：将结果定位为“简单规则足够”，不包装复杂方法；
- `BudgetMatchedSampling` 更优：反馈门控主线停止，转向搜索预算分配问题。
