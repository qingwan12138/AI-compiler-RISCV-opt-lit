# P0 困难状态独立复现实验预注册

## 1. 独立性

本实验是 `p0-deepseek-formal-v2-20260720-001` 之后的新 P0，不替换、不合并、不选择性重算上一轮负结果。新运行使用独立编号、Prompt 哈希、状态清单和结果目录。

## 2. 研究问题

当优化状态包含无法仅靠表面源码稳定推断的问题时，真实编译器反馈相对无反馈复测和跨任务匹配安慰剂，能否带来额外的正确优化效用？

## 3. 固定设置

- 模型：`deepseek-v4-pro`
- temperature：0.2
- top_p：0.95
- max_tokens：2048
- 编译器：Ubuntu 24.04 中的 Clang 18.1.3
- 正确性：编译、固定测试、随机差分测试、ASan、UBSan
- 目标：目标函数在 `clang -O0 -S -emit-llvm` 下的指令数
- 任务：10 个 C 函数、20 个状态、每状态 4 个条件，共 80 次生成

## 4. 状态与反馈

20 个状态按预先固定的全局顺序轮换四类反馈，每类 5 个状态：

1. Compile：当前状态不能编译，真实反馈为该状态的 Clang stderr；
2. Test：当前状态可编译但固定/差分测试失败，真实反馈为真实反例的 expected/got；
3. Remark：当前状态正确但优化受阻，真实反馈为 Clang loop-vectorize remark；
4. IR：当前状态正确但静态收益不足，真实反馈为当前目标函数的 LLVM IR 片段。

每类 MatchedPlacebo 使用同类反馈的下一个任务状态，保持字段外观和工具类型，但与当前任务不对应。N0 与 RealFeedback 使用同一配对块编号；N1 使用预注册的另一块编号。块编号不宣称 API 严格确定性。

## 5. 效用与分析

正确性门控失败或生成截断时 `U=0`。正确候选相对该状态最近的正确未优化实现，目标函数 IR 指令数下降至少 1% 时：

```text
U(a) = (IR_baseline - IR_candidate) / IR_baseline
DeltaUtility(condition | state) = U(condition) - U(N0)
```

主分析为全部 20 状态的意向处理；同时报告四条件均成功的完整配对子集，不用后者替换主分析。

## 6. 进入 P1 的固定门槛

必须同时满足：

1. RealFeedback 平均 DeltaUtility 大于 N1 和 MatchedPlacebo；
2. RealFeedback 配对 bootstrap 95% CI 方向为正；
3. 完整配对子集与主分析方向一致；
4. Compile、Test、Remark、IR 至少 3 类反馈为正；
5. 至少 4 个程序族方向为正；
6. 每个条件成功生成率至少 75%；
7. 正向结果不由一个状态或一种反馈类型主导。

任一条件不满足则不进入 P1。正式运行开始后不调整 Prompt、max_tokens、状态、反馈文本或阈值；Token 上限消融只能作为后续独立实验。
