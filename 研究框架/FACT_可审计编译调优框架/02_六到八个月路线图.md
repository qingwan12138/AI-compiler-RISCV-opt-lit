# FACT：六到八个月路线图

## 1. 总体原则

- 以一篇 CCF B 类会议论文的完整证据链为主，不追求一次做完毕业论文所有扩展；
- 前两个月必须得到可运行基线，不能长期停留在框架设计；
- 每个阶段设置停止条件，避免后期才发现研究问题不成立；
- x86-64 和 K3 均需从第一阶段纳入环境设计，不能最后才移植 RISC-V；
- 正式测试集在方法冻结前保持封存。

## 2. 月度计划

### 第 1 月：环境冻结与最小基线

任务：

- 冻结 x86-64 与 K3 的操作系统、LLVM、链接器、target flags 和 CPU 配置；
- 从 LLVM test-suite、PolyBench/C、cBench 中筛选首批 10–15 个程序；
- 建立统一编译、执行、超时和结果采集接口；
- 复现 `-O0/-O2/-O3`；
- 实现最小 Random Pass Search；
- 确定 12–20 个可跨两端稳定运行的 Pass。

交付物：

- 环境冻结清单；
- benchmark 可运行名单和排除名单；
- x86/K3 基线数据；
- 单程序重复测量稳定性报告。

阶段门 G1：

- 至少 10 个程序可在两端正确运行；
- 主要程序的重复测量噪声足以区分 3%–5% 的性能差异；
- 如果 K3 工具链无法执行自定义 Pass 序列，优先改成交叉编译后部署，不更换研究问题。

### 第 2 月：意图契约与审计原型

任务：

- 固定四类意图：访存、冗余计算、控制流、向量化；
- 定义 JSON/YAML 意图契约；
- 实现 IR diff、optimization remarks 和汇编静态证据抽取；
- 人工标注 100–200 个候选，建立审计金标准；
- 完成只读 remarks、只读 IR、完整审计三种版本比较。

交付物：

- 意图契约 schema；
- 审计器原型；
- 标注说明与双人复核规则；
- E1 初步结果。

阶段门 G2：

- 四类意图中至少三类的自动审计 F1 达到 0.80；
- 若某类长期低于 0.70，将其从首篇论文移除，不用 LLM 主观判断补足。

### 第 3 月：反事实引擎与归因忠实度

任务：

- 实现删除、替换、邻接交换三类变体；
- 建立变体去重和编译缓存；
- 设计局部贡献和协同边计算；
- 在 10–20 个程序上完成归因稳定性实验；
- 比较高贡献与低贡献 Pass 的删除效应。

交付物：

- Counterfactual manifest；
- E3 归因忠实度结果；
- 典型必要、冗余和协同 Pass 案例。

阶段门 G3：

- 高贡献 Pass 的删除在多数案例中造成可重复收益损失；
- 不同重复运行下的贡献排序具有中等以上一致性；
- 若归因不稳定，先收缩序列长度和 Pass 集，不立即引入更复杂模型。

### 第 4 月：归因引导搜索与完整 x86 实验

任务：

- 将归因结果用于候选重排序和预算分配；
- 实现 LLM + compile/test 基线与 LLM + audit 基线；
- 在 x86 上扩展到 30–50 个程序；
- 完成 E2、E4 和主要消融；
- 冻结正式测试集、候选预算和统计协议。

交付物：

- x86 主结果表；
- 测量预算—性能曲线；
- B3–B6 消融结果；
- 方法冻结版本 v1。

阶段门 G4：

- 意图审计或归因引导至少一项达到预设主阈值；
- 如果两项均未达到，应停止全系统扩展，转为单项问题复盘。

### 第 5 月：K3 跨架构反例与校准

任务：

- 将 x86 top-k 候选部署到 K3；
- 标注正迁移、无显著变化和收益翻转；
- 提取 K3 汇编、spill、分支和可用 PMU 证据；
- 建立硬件反例库；
- 实现目标相关守卫或候选重排序；
- 完成 B7 与 B8 比较。

交付物：

- E5 收益翻转数据集；
- E6 K3 校准实验；
- 至少 3 个可解释的硬件反例案例。

阶段门 G5：

- K3 上必须观察到足够的候选排序差异；
- 校准后负优化率或几何平均运行时间达到一个预设阈值；
- 如果几乎没有收益翻转，创新三降级为“硬件条件验证”，论文主线改为 01+02。

### 第 6 月：端到端实验与论文初稿

任务：

- 完成封存测试集上的 E7；
- 运行 5 个随机种子；
- 完成置信区间、效应量和多重比较校正；
- 整理失败案例和 inconclusive 结果；
- 撰写论文方法、实验和威胁章节；
- 做一次内部审稿人模拟。

交付物：

- 完整结果表和图；
- 可复现性清单；
- 论文初稿 v1；
- 6 个月投稿可行性决定。

### 第 7 月：增强实验与论文重写

优先级从高到低：

1. 补强最薄弱的主张；
2. 增加一个强搜索基线；
3. 增加第二款 RISC-V 板卡；
4. 增加 LLVM 版本迁移；
5. 将一个硬件反例人工转成 LLVM TTI/调度修补案例。

不得为了表格数量增加与主问题无关的数据集。

### 第 8 月：投稿材料冻结

任务：

- 完成匿名化、artifact 说明和复现实验；
- 锁定所有表格与原始数据哈希；
- 做引用完整性和最近工作补检；
- 完成第二轮内部审稿与修改；
- 根据实际截止日期提交。

## 3. 最小投稿线

满足以下条件才进入投稿：

- x86 与 K3 的完整结果均存在；
- 正确性、意图落地、搜索效率和硬件校准四类证据均有独立指标；
- H1、H2、H3 分别达到其对应的至少一个备选成功阈值，且其他指标不出现严重回归；
- 关键消融完整；
- 有失败案例与局限性分析；
- 结果可从环境清单和原始记录复现。

## 4. 毕业论文增强项

不阻塞首篇投稿：

- 自动将硬件反例转为 LLVM TTI/调度模型候选补丁；
- 扩展到第二种主要优化目标；
- 扩展到更多 ISA 或更多 RISC-V 微架构；
- 研究归因知识跨程序复用；
- 将反例数据用于轻量训练或 adapter 更新。
