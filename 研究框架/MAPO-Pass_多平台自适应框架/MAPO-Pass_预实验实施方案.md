# MAPO-Pass 预实验实施方案

> **文档定位：** 本文是“面向多硬件平台的自适应编译优化框架（MAPO / MAPO-Pass）”的启动实验方案。它的目标不是立即证明完整系统优于所有编译器优化，而是依次检验核心机制成立所必需的前提，并为后续正式实验建立可复现数据与控制流程。
>
> **核心主张边界：** MAPO-Pass 的唯一核心机制是“由真实性能响应指纹条件化的共享—残差 Pass 收益建模”。反事实 Pass 信用只作为辅助监督和解释证据；风险感知目标只作为训练约束。LLM 如被采用，只能是受约束的候选生成器，不构成预实验的核心变量。

---

## 1. 预实验要回答的三个问题

### H0：多平台适配是否确有必要？

对同一程序和同一组候选 Pass 序列，不同硬件平台的候选排序、最优候选和收益方向是否存在稳定差异？

若答案是否定的，那么“平台条件化”没有足够的研究动机；应先调整程序、Pass 空间或平台组合，而不是增加模型复杂度。

### H1：真实性能响应指纹是否比平台标签更有信息？

在相同训练样本和相同目标平台测量预算下，使用真实微基准响应构成的平台指纹，能否比硬件 ID、ISA 标签或静态规格更准确地为程序候选排序？

### H2：共享—残差模型能否以少量校准适配未见平台？

将一个真实平台完全留出训练后，MAPO-Pass 能否在固定且与基线相等的校准测量预算内，选择到比公共策略和普通共享模型更合适的候选，同时避免严重负优化？

---

## 2. 总体原则与不做的事情

### 2.1 真实性能的定义

只有在目标真实设备上、完成正确性检查、预热和重复测量后获得的运行时间，才能称为“真实性能”。QEMU 的运行时间反映模拟器和宿主机，不得当作目标 ISA 的真实性能。gem5 等体系结构模拟器的结果只代表其配置的模拟微架构，不得直接写成真实芯片性能结论。

### 2.2 公平性原则

- 所有方法面对同一训练、验证和测试程序划分；程序同族样本不得跨集合泄漏。
- 所有方法从相同的候选池中选择候选；不得让 MAPO-Pass 额外搜索更多序列。
- 未见平台比较中，所有方法消耗相同的**目标平台真实性能测量总预算**；微基准测量也计入 MAPO-Pass 的预算。
- 所有候选都经过相同的编译、正确性、超时和计时流程。

### 2.3 第一版明确不做

- 不从零搜索完整 LLVM Pass 空间；
- 不修改 LLVM 后端；
- 不以强化学习、LLM、Agent、RISC-V 本身作为创新点；
- 不将模拟器运行时间混入真实硬件结论；
- 不在预实验阶段穷举所有 Pass 删除和交换反事实。

---

## 3. 分阶段路线

| 阶段 | 是否需要真实设备 | 目标 | 可输出的结论 |
|---|---|---|---|
| P0：无设备管线 | 否 | 交叉编译、候选生成、正确性和数据格式跑通 | 系统能生成并验证跨目标候选，不能声称性能收益 |
| P1：模拟机制筛选 | 否，可选 | 在明确模拟配置中观察候选排序差异 | 机制在模拟微架构上可行，不能声称真实硬件收益 |
| P2：真实平台差异 | 是 | 证明相同候选在真实平台上存在不同偏好 | 多平台问题是否真实存在 |
| P3：留一平台少样本适配 | 是 | 在固定预算下比较 MAPO-Pass 与基线 | 核心模型是否具备未见平台适配价值 |
| P4：反事实辅助证据 | 是 | 检查关键 Pass 的跨平台边际效应 | 信用监督是否有解释与排序增益 |

P0 可以立即在 Windows + WSL2 或现有 Windows 工具链中开始；P2、P3 和 P4 的性能主张必须等待真实设备。

---

## 4. P0：无真实设备的最小可行管线

### 4.1 目标

在不依赖真实 ARM 或 RISC-V 设备的条件下，先证明候选 Pass 序列能被稳定生成、编译、运行并记录。P0 不训练性能模型，也不报告跨平台运行时间比较。

### 4.2 初始配置

- 目标三元组：`x86_64`、`aarch64`、`riscv64`；
- 程序：6–8 个小型且可确定性校验的内核，覆盖计算、访存、分支和循环/向量化；
- Pass 动作：15–20 个稳定 Pass；
- 候选：每个程序 16–32 条从 `-O3` 基础流水线进行局部删除、交换或有限重排得到的序列；
- 功能执行：本机直接运行或用 QEMU 仅验证目标二进制输出。

### 4.3 每条记录必须保存

```text
program_id, program_family, input_id, target_triple, compiler_version,
candidate_id, pass_sequence, compile_command, binary_hash,
correctness_status, timeout_status, stdout_hash, stderr, ir_features,
assembly_features, timestamp
```

### 4.4 P0 验收条件

1. 同一程序的至少 5 个边界输入和 20 个预先固定随机种子输入下，所有被接受候选均与参考输出一致；
2. 失败候选保留编译错误或超时原因，不被静默删除；
3. 每条候选可由 `candidate_id`、Pass 序列和环境信息复现；
4. 不产生任何标注为“目标平台性能”的 QEMU 或模拟器时间。

整数程序的参考输出来自独立的 `-O0` 参考二进制或已验证的校验和值；浮点程序必须预先记录绝对/相对误差阈值及比较规则。随机输入的种子清单在生成候选前固定，不能根据候选结果补选。

---

## 5. P1：模拟阶段（可选）

### 5.1 用途

若暂时没有多台真实设备，可使用 gem5 等模拟器配置三组明确的“模拟平台”，检查候选排序在不同缓存、执行宽度或向量配置下是否变化。此阶段的作用是调试数据流、候选池和模型接口，而非代替真实实验。

### 5.2 报告约束

所有图表标题都应写为“模拟配置”或“模拟微架构”；不得出现“x86/ARM/RISC-V 真实加速比”。模拟结果只用于决定后续真实测量优先测哪些程序与候选。

---

## 6. P2：真实性能平台差异实验

### 6.1 平台与程序

优先选择三个真实平台：x86-64、ARM、RISC-V。资源受限时可先采用“两台不同微架构的 x86 + 一台 RISC-V”，以同时覆盖同 ISA 差异与跨 ISA 差异。

初始实验使用：

- 8 个程序；
- 每个程序 32 条相同候选序列；
- 每个候选在每个平台预热后重复计时 7 次；
- 每次计时使用相同输入、超时阈值和运行线程数。

候选执行顺序应在每个平台内随机化，避免温度、缓存状态或后台任务与特定候选系统性相关。

### 6.2 环境控制

每个平台记录 LLVM/Clang 版本、操作系统/内核、目标三元组、链接库、CPU 型号、核心绑定、线程数、频率策略、运行输入、预热次数、重复次数和超时。

Windows 主机应记录电源计划、进程亲和性和后台负载；若在 WSL2 中执行，必须额外记录 WSL2 版本与宿主机信息。不能控制的项应标为“未控制”，不能假装已经固定。

### 6.3 主要分析

对每个程序计算：

- 平台间候选排序的 Spearman 相关系数；
- Top-1 与 Top-5 候选重合率；
- 平台 A 的最佳候选迁移到平台 B 后的 regret（与 B 的最佳候选相比的性能损失）；
- 公共候选与平台专属最佳候选的差距；
- 同一候选相对 `-O3` 的收益是否在不同平台出现正负翻转。

### 6.4 P2 的继续条件

在运行前固定以下判据。满足其中至少两项才继续 P3：

1. 跨平台候选排序的程序级 Spearman 中位数不高于 0.80，且按程序族重采样的 95% 置信区间上界低于 0.90；
2. Top-5 重合率的程序级中位数不高于 60%；
3. 源平台最优候选迁移到目标平台的 regret 中位数超过 1%，且其 95% 置信区间下界大于 0；
4. 至少 4 个程序出现相对 `-O3` 收益方向相反的候选；
5. 平台专属最优相对固定公共候选的宏几何平均收益超过 1%，且 95% 置信区间下界大于 0。

若条件不满足，优先增加平台敏感程序或动作（循环展开、内联、向量化和访存相关变换），而不是立刻引入更大模型。

## 7. P3：留一真实平台与固定校准预算

### 7.1 协议

对每个平台轮流执行 leave-one-platform-out（留一平台）：将目标平台 $h^*$ 的全部测试程序从训练中移除，仅用其余平台训练共享部分。$h^*$ 只可使用固定预算完成校准，随后必须在未参与校准的测试程序上选择候选。

### 7.2 预算单位

一个“目标平台真实性能测量单元”定义为：**一个指定工作负载与一个候选二进制的完整重复测量汇总**，即包含预热和 7 次计时后得到的中位数。总预算初始设为 $B=80$ 个单元。任何失败、超时或不正确的测量也计入预算，不得替换为新的样本。

MAPO-Pass 的 80 个单元建议分配为：

- 16 个微基准响应单元：在预先版本化的 `fingerprint_manifest` 中固定任务、输入规模、编译选项和重复规则。它包含整数吞吐/依赖链、浮点吞吐/依赖链、连续/stride 访存、两档缓存工作集、分支、循环展开和向量响应等 16 项；
- 64 个程序—候选校准单元：从 4 个校准程序（不同程序族）各取 16 个候选。程序、候选 ID 和运行顺序由训练平台以外的固定随机种子一次性生成，不能根据目标平台结果自适应选择。

每项微基准以同平台参考循环归一化：$r_k=\log(T_k/T_{\mathrm{ref},k})$；再用**仅由源平台训练数据**计算的均值和标准差标准化，形成 $\phi(h)$。这样指纹表达相对响应形状，而不是直接编码主频或整机快慢。

不使用响应指纹的基线可把完整 80 个单元分配给程序—候选校准：它们使用与 MAPO-Pass 的 **64 个程序—候选校准对**相同的预注册校准对，再获得 16 个预注册的保留校准对。该方案在总预算相同的条件下给予基线更多程序候选观测，因而是对 MAPO-Pass 更强的比较。所有方法均必须报告总单元数、重复次数与实际失败/超时数。

### 7.3 MAPO-Pass 最小模型

输入包括程序—候选特征 $x(p,s)$、目标平台响应指纹 $\phi(h)$ 以及少量校准观测。预测相对 `-O3` 的对数收益：

$$
\widehat{\Delta}(p,s,h)=g_{\mathrm{shared}}(x(p,s))+g_{\mathrm{residual}}(x(p,s),\phi(h)).
$$

第一版可使用容量匹配的梯度提升树或小型 MLP；不必先用强化学习。共享项学习跨平台通用收益，残差项只学习由响应指纹条件化的平台特异修正。

适配步骤必须固定如下：先仅用源平台训练 $g_{\mathrm{shared}}$ 与由指纹初始化的残差先验；留出平台时冻结共享项和所有特征提取器，只用 64 个预注册校准单元拟合一个带 Ridge 正则的目标平台残差 Adapter $u_{h^*}$。Ridge 系数、模型容量和训练轮数只能在源平台的嵌套留一验证中确定，不能利用 $h^*$ 的测试程序或测试性能调节。测试阶段 Adapter 只推理，不再更新。

风险约束作为训练与选择的一部分，而不是事后描述：模型同时预测负优化概率 $r(p,s,h)=P(\Delta<-0.02)$，训练损失为收益预测损失加上负优化标签的二元交叉熵；系数由源平台验证固定。选择时只在 $r\le0.25$ 的候选中最大化预测收益；无候选满足时回退到 `-O3`。必须报告“去除风险头/约束”的消融。

### 7.4 必需基线

| 基线 | 目的 |
|---|---|
| `-O3` | 编译器强默认基线 |
| 固定公共候选 | 检验“一条序列服务所有平台” |
| 普通共享模型 | 多平台混合训练，但没有硬件输入 |
| 静态规格模型 | 输入 ISA、缓存、核心数等静态信息 |
| 平台独立校准模型 | 只用目标平台 80 单元训练或拟合 |
| 共享主干 + 平台 ID/嵌入 | 检验仅记住已见平台是否足够 |
| 共享 + 响应指纹（无残差） | 分离响应指纹本身的作用 |
| 共享—残差 + 静态规格 | 分离残差结构与真实响应指纹的作用 |
| MAPO-Pass 去风险约束 | 检验负优化控制是否由风险机制带来 |
| MAPO-Pass | 响应指纹条件化共享—残差模型 |

对于未见平台，平台 ID 基线必须显式使用 `unknown` 表示，不能偷偷赋予其额外的真实平台标签。

### 7.5 主要指标

- 相对 `-O3` 的几何平均加速比和中位数加速比；
- Top-1 选择 regret；
- 负优化比例与最差 10% 程序表现；
- Spearman、Pairwise Accuracy、NDCG、Top-5 Recall；
- 每平台宏平均（不能由样本多的平台主导）；
- 总测量单元数、编译次数、运行次数和推理耗时。

### 7.6 统计控制

- 每个工作负载使用中位数运行时间；原始重复值也保留；
- 报告以测试程序族为重采样单位的配对 bootstrap 95% 置信区间；7 次重复仅用于形成单个测量单元的中位数，不能当作独立样本；
- 对同一测试程序上的方法比较使用配对检验，并对多重比较做 Holm 校正；
- 同时报效应量（如对数加速比的中位数差），不只报告 p 值；
- 报告异常值规则。若基线或候选的 MAD/中位数超过预设阈值，应复查环境或标记为不稳定，而不是选择性删除；
- 训练、校准和测试按程序家族分组划分，避免同源程序泄漏。

### 7.7 预注册的 H1/H2 判定

H1（响应指纹优于静态规格）成立的最低条件是：在三次留一平台结果的宏平均中，MAPO-Pass 相对“共享—残差 + 静态规格”在相对 `-O3` 的几何平均加速比上至少高 1%，且以测试程序族为单位的配对 bootstrap 95% 置信区间下界大于 0。Top-1 regret 的降低作为共同报告的次要指标；若主指标不满足，必须将结论收缩为“响应指纹可行，但尚未证明优于静态规格”。

H2（少量校准的未见平台适配）成立的最低条件是：MAPO-Pass 相对普通共享模型达到同样的 1% 宏几何平均收益门槛及正的 95% 置信区间下界，并且不触发第 11 节的负优化风险失败条件。所有阈值在首次真实平台测试前固定，不得事后调整。

## 8. P4：反事实 Pass 信用（辅助实验）

P3 的信用辅助损失**只可使用源平台训练数据**，不得使用留出目标平台的校准或测试数据。目标平台的 P4 在 P3 主结果冻结后才可执行，只用于解释；它不更新模型、不改变候选选择，也不参与 P3 比较。建议从源平台训练程序中选择少量关键 Pass，而不是对所有序列全穷举；每个平台抽取 3 个程序、每程序 3 个关键 Pass，执行：

1. 删除该 Pass；
2. 与相邻 Pass 交换；
3. 在所有真实平台重新测量；
4. 保存 IR diff、汇编变化、正确性和运行时间。

定义删除 Pass 后的边际效应：

$$
C_i(p,h)=\log\frac{T(S^{-i},p,h)}{T(S,p,h)}.
$$

这里 $S$ 是原序列，$S^{-i}$ 是删除第 $i$ 个 Pass 的序列。信用标签可作为辅助损失，但其权重必须只在源平台验证集上固定；同时报告“不使用信用辅助损失”的模型。P4 的目标平台反事实测量属于主结果之后、单独声明的解释性附加成本，绝不能计入或改变 P3 的 80 单元主比较。若第一版没有稳定的排序增益，信用只保留为解释材料，不能单独构成新的主创新。

---

## 9. 正确性与失败处理

每个候选先完成以下检查，任何一项失败都不得进入性能比较：

1. 编译成功；
2. 在 5 个边界输入和 20 个固定种子随机输入上与独立参考输出一致，优先使用校验和或逐字节比较；
3. 不超时、不崩溃；
4. 所需的运行时间和环境元数据完整。

编译失败、输出不一致、崩溃和超时都要作为结构化结果保留。它们不能被计为“慢”，也不能在汇总时悄悄丢弃。

## 10. 结果目录与最小交付物

每次实验建立唯一 `run_id`，至少输出：

```text
runs/<run_id>/manifest.json       # 环境、Git 提交、随机种子、参数
runs/<run_id>/candidates.jsonl    # 每个候选的编译、正确性与原始测量
runs/<run_id>/summary.csv         # 用于复核的汇总表
runs/<run_id>/rank_matrix.csv     # 平台 × 程序 × 候选排名
runs/<run_id>/calibration.json    # 留一平台预算消耗明细
runs/<run_id>/figures/            # 迁移矩阵、收益分布、信用热力图
```

预实验至少应形成四张可审阅图表：候选排名相关性图、跨平台迁移 regret 矩阵、等预算未见平台对比图、负优化与最坏程序表现图。

## 11. 可证伪条件与降级决策

| 观察结果 | 含义 | 下一步 |
|---|---|---|
| 平台候选排序几乎一致 | 多平台差异证据不足 | 调整 Pass 与基准覆盖，不扩大模型 |
| MAPO-Pass 相对“共享—残差 + 静态规格”的宏几何平均收益不足 1%，或 95% 置信区间下界不大于 0 | H1 未被支持 | 收缩为响应指纹可行性结果，重构计算、访存、控制流子指纹 |
| MAPO-Pass 相对普通共享模型的宏几何平均收益不足 1%，或 95% 置信区间下界不大于 0 | 共享—残差机制未被支持 | 检查数据量、校准划分与残差容量；缩小主张 |
| 只靠更多校准样本才有效 | 机制没有测量效率优势 | 如实报告为数据驱动适配，不主张少样本能力 |
| 相对普通共享模型的负优化比例增加超过 5 个百分点，或任一留出平台超过 25% | 风险约束无效 | 提高退化惩罚、使用保守候选或放弃该策略 |
| 反事实信用无排序增益 | 信用只保留为解释材料 | 不将其作为训练贡献 |

只有当 P2 证明存在平台差异，且 P3 在等预算下显示 MAPO-Pass 对至少部分未见平台具有可复核优势时，才进入更大规模正式实验。LLM 候选生成应排在这些结论之后。

---

## 12. 推荐执行顺序

1. 完成 P0：候选、交叉编译、正确性和记录格式；
2. 获得至少两台真实平台后完成 P2；
3. 建立最小共享—残差排序模型，执行 P3 留一平台实验；
4. 对有代表性的正、负和不稳定候选执行 P4；
5. 根据可证伪条件决定扩大规模、收缩主张或停止该方向。

这条顺序的目的，是先证明“为什么需要 MAPO-Pass”和“核心机制是否有效”，再考虑强化学习、LLM 或更大的搜索空间。
