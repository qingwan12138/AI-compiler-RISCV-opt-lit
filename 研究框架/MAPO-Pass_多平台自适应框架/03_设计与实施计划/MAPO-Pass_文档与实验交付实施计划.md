# MAPO-Pass 文档与实验交付实施计划

## Global Constraints

- 主线唯一：真实性能响应指纹条件化的共享—残差 Pass 收益建模；
- P0/QEMU 不构成真实性能数据；
- 所有性能主张以真实设备、正确性、预热、重复和原始记录为前提；
- 候选、程序划分、预算与阈值必须在主测量前冻结；
- 反事实信用和 LLM 只能是辅助模块，不能改变主结论边界。

## Task 1：冻结研究边界

核对标题、摘要和贡献表述均围绕 H0/H1/H2；删除或降级将 LLM、RL、QEMU、RISC-V 名称、Pass 信用单独包装为核心创新的说法。交付物是本目录的核心研究框架文档。

## Task 2：建立 P0 工件

创建基准 manifest、输入 seed manifest、候选 manifest 和 run writer；实现 `x86_64`、`aarch64`、`riscv64` 的候选编译、参考比对、超时和错误记录。交付物是一个可重跑的 P0 `run_id` 与 P0 数据规格列出的文件。

## Task 3：P0 审查与复现

用新的 run ID 重跑一部分程序与候选；检查候选哈希、二进制哈希、输出哈希、失败日志和环境版本。任何结果若依赖未记录环境变量或手工修复，应回到 Task 2。

## Task 4：准备 P2 真实测量

登记真实设备清单、访问方式、CPU/OS/内核/频率策略、线程绑定、运行负载和计时工具。冻结 P2 候选池、程序族划分、执行顺序和统计脚本，随后才开始真实计时。

## Task 5：P2 决策

计算排名相关性、Top-k 重合、迁移 regret 与收益方向翻转；按路线图的预注册门决定是否进入 P3。若未达标，记录否定结果并调整基准/候选，而不是直接训练更复杂模型。

## Task 6：P3/P4 与论文证据包

执行三次留一真实平台、固定 80 单元预算、强基线和程序族 bootstrap；冻结主结果后才做 P4 反事实。交付物包括原始 run、汇总表、图、统计脚本、环境 manifest 与结论边界说明。

## 验收

文档交付通过的条件是：任何一项核心主张都能定位到其定义、数据来源、比较基线、预算、统计规则和否定条件；任何实验结果都能定位到版本化 run 工件；任何 QEMU 或模拟数据都不会被误读为真实硬件性能。
