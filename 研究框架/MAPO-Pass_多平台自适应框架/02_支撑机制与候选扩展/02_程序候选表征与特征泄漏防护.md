# 程序—候选表征与特征泄漏防护

> 定位：共享收益模型的输入规范与可复核接口，不是独立创新点。

## 1. 表征目标

特征 $x(p,s)$ 应描述“什么程序遇到什么候选”，而不应偷看“目标平台上该候选跑得多快”。它既服务收益预测，也服务错误排查、消融和复现。

## 2. 最小特征组

| 组别 | 示例 | 获取时点 |
|---|---|---|
| 程序元数据 | program_id、family、input_id、规模、数值类型 | 编译前 |
| IR 结构 | 基本块、循环深度、调用、load/store、算术和控制流比例 | 候选编译后 |
| 候选描述 | Pass token、相对基线的编辑、长度、参数 | 候选注册时 |
| 静态后果 | IR/汇编尺寸、优化 remark、向量/分支近似 | 编译后、运行前 |
| 合法性状态 | 编译成功、链接成功、目标特性掩码 | 编译后 |

所有特征都应带版本、提取命令和缺失掩码。不同目标的汇编特征不能假定同维可比；应优先记录方向性比例、规范化统计或显式目标标签。

## 3. 禁止的泄漏

以下内容不得作为 $x(p,s)$ 的训练特征：目标平台测试运行时间、目标平台的候选排名、测试程序集上的错误/超时结果、事后选出的 Pass 信用、根据目标结果生成的候选标识，或会间接编码这些信息的缓存文件。

程序划分以程序家族为单位。一个家族的变体、同一算法不同规模和自动生成的同源内核不得跨越训练、校准与测试集合。

## 4. 特征版本与审计

每个 run 的 `manifest.json` 记录：特征 schema 版本、提取器二进制哈希、LLVM 版本、候选 manifest 哈希、程序划分和随机种子。`candidates.jsonl` 保存原始特征或其可逆索引，使后续模型重训不依赖隐含状态。

## 5. 消融

必须比较：仅候选 token、程序 + 候选静态特征、加入汇编/remark 特征，以及完整特征。若复杂特征未提升排序或降低风险，应优先采用更简单、可解释的版本。
