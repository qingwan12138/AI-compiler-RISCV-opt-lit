# MAPO-Pass 研究总览

> 文档状态：当前研究主线设计稿。  
> 核心命题：以真实性能响应指纹为条件，学习跨平台共享的 Pass 收益与平台特有残差；在固定目标平台测量预算内，为未见平台选择低风险候选。  
> 学术边界：以下均为待检验的研究假设和方法设计，不声称“首次提出”。

完整背景见[研究材料](../多平台自适应编译优化框架研究材料.md)，可执行预实验协议见[MAPO-Pass 预实验实施方案](../MAPO-Pass_预实验实施方案.md)。本目录将它们重组为与 EPAS `01–03` 相同的“主线—支撑—实施”结构。

## 1. 当前唯一主线

MAPO-Pass 不将“多平台”“RISC-V”“强化学习”“LLM”或“共享模型 + 平台头”本身视作核心创新。唯一需要被实证支持的主张是：

> **真实微基准响应构成的平台指纹，能够在相同目标平台测量预算下，比平台 ID 或静态规格更有效地条件化共享—残差 Pass 收益模型，从而在未见平台上作出更低 regret、风险受控的候选选择。**

对程序 $p$、候选 Pass 序列 $s$、平台 $h$，模型预测相对 `-O3` 的对数收益：

$$
\widehat{\Delta}(p,s,h)=g_{shared}(x(p,s))+g_{residual}(x(p,s),\phi(h),u_h).
$$

- $x(p,s)$：程序—候选特征；
- $\phi(h)$：由预注册微基准测量得到的真实性能响应指纹；
- $u_h$：目标平台在固定校准预算内拟合的受正则约束残差 Adapter；
- $g_{shared}$：从源平台学习的通用收益规律；
- $g_{residual}$：仅解释响应形状所支持的平台特异偏移。

模型同时给出负优化风险 $r(p,s,h)=P(\Delta<-0.02)$。选择器只在 $r\le0.25$ 的候选中取最高预测收益；无合格候选时回退 `-O3`。

## 2. 核心研究问题与假设

### 主研究问题

> 在真实平台测量预算受限且目标平台未参与训练时，如何利用平台的真实性能响应而不是名称或 ISA 标签，预测不同 LLVM Pass 候选对程序性能的差异，并控制负优化？

### 可验证假设

- **H0（必要性）**：相同候选在不同真实平台上存在可重复的排序、最优项或收益方向差异；否则没有充分理由引入平台条件化。
- **H1（信息性）**：响应指纹条件化模型在等预算留一平台实验中优于“共享—残差 + 静态规格”。
- **H2（适配性）**：共享—残差模型在冻结共享部分后，仅用预注册少量校准单元即可优于普通共享模型，且不增加不可接受的负优化。
- **H3（安全性）**：显式风险约束降低负优化比例或最差程序损失，代价不超过预先声明的平均收益损失。

H1/H2 的正式阈值、基线、预算和否定条件以预实验实施方案为准；P0 和 QEMU 只能验证管线，不能支持 H0–H3 的真实性能结论。

## 3. 研究对象、边界与非目标

第一版研究 LLVM Pass 宏动作和有限候选序列，而不是从零搜索完整 Pass 空间。候选来源为 `-O3` 基础流水线的局部删除、交换、有限重排或等价的稳定编译开关；所有方法从同一候选池选择。

第一版明确不做：

- 修改 LLVM 后端或将后端实现本身当作贡献；
- 用 QEMU/gem5 时间宣称目标 ISA 的真实性能；
- 以 LLM、Agent、RL 或 RISC-V 平台名称作为创新点；
- 让 MAPO-Pass 比基线额外枚举候选或使用更多目标平台测量；
- 用目标平台测试程序调整超参数或补选校准样本。

反事实 Pass 信用是解释和辅助监督，风险头是训练/选择约束；两者均不替代主模型。LLM 若使用，仅能产生受候选空间约束的候选。

## 4. 方法链与数据流

```text
版本化程序、输入和候选池
        ↓
所有平台采用同一编译、正确性和超时协议
        ↓
源平台真实测量 → 程序—候选收益数据 + 特征 x(p,s)
        ↓
预注册微基准真实测量 → 平台响应指纹 φ(h)
        ↓
训练共享收益项 g_shared 与指纹条件化残差先验
        ↓
留出平台：仅消耗固定校准预算拟合 u_h
        ↓
风险约束候选排序 / 回退 -O3
        ↓
未参与校准的程序测试 → 收益、regret、负优化、置信区间
```

这条链将“平台信息”限定为可复核的响应曲线，而非不可解释的平台标签；将“少样本适配”限定为冻结共享部分后的残差拟合，而非对目标平台重新训练完整模型。

## 5. 证据标准

| 主张 | 必需证据 | 不能作为证据 |
|---|---|---|
| 需要多平台适配 | 至少两个真实平台上的候选排序、Top-k、regret 与收益方向差异 | QEMU 时间或单一平台结果 |
| 响应指纹有信息 | 等预算、留一平台下优于静态规格的预注册比较 | 使用目标平台标签的事后拟合 |
| 少样本适配有效 | 冻结共享项后，在未校准测试程序上的收益和风险优势 | 把所有目标平台程序用于训练 |
| 风险控制有效 | 负优化比例、最差 10% 程序与风险消融比较 | 只报告平均加速比 |
| Pass 信用有价值 | 主结果冻结后的反事实边际效应与解释一致性 | 用目标平台反事实结果反哺主模型 |

## 6. 第一版最小可行范围

- 平台：P0 为 `x86_64`、`aarch64`、`riscv64` 交叉编译与正确性；P2/P3 需要至少两台真实设备，三类真实平台才可主张完整未见平台适配。
- 程序：P0 选择 6–8 个确定性小型内核，覆盖计算、访存、分支和循环/向量化；正式阶段扩展到按程序家族划分的基准集。
- 候选：P0 每程序 16–32 条版本化候选；正式比较中候选池和随机执行顺序预先固定。
- 测量：真实平台预热后重复 7 次，以中位数形成一个测量单元；原始值、环境与失败均保留。
- 模型：容量匹配的梯度提升树或小型 MLP；先验证机制，不以模型规模取胜。

## 7. 可证伪与降级

若 H0 不成立，应调整程序覆盖、Pass 动作或平台组合，而不是扩大模型。若 H1 不成立，结论只能是“响应指纹可行但未证明优于静态规格”。若 H2 不成立，不能声称少样本未见平台适配；可保留多平台候选数据集和平台差异分析。若风险约束恶化负优化，应采用更保守的回退策略或放弃该模块。

## 8. 推荐表述

中文题目候选：

> **基于真实性能响应指纹的多平台自适应编译优化方法研究**

英文题目候选：

> **MAPO-Pass: Multi-platform Adaptive Pass Optimization via Performance-Response Fingerprints**

一句话总结：

> **MAPO-Pass 不把平台名称塞进候选排序器，而是用平台在一组固定工作负载上的真实响应形状来约束共享收益与平台残差的分工，并在等预算下检验这种分工能否减少未见平台的选优损失。**
