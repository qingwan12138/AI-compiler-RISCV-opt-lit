# Pass 调优：跨架构效应解耦的少样本策略迁移

> **学术状态：候选创新，尚需针对性查新。** 本文依据当前 44 个文献条目的组内证据提出，不声称“首次”。
>
> **当前定位调整（2026-07-13）**：本文保留为第一类文献组的候选提炼记录，并已并入[创新 06：效应保持的最小架构增量编译知识特化](06_多硬件编译_效应保持的最小架构增量知识特化.md)，不再作为独立主创新。共享—平台残差模型只承担 EPAS 实例化候选的排序与测量节省；Pass/Pass 宏动作是知识单元 `K^m` 的一种应用载体，RL/策略迁移仅作为后续扩展。

## 1. 候选创新点名称与命名拆解

- **研究对象**：LLVM Pass/Pass 宏动作调优。
- **核心新机制**：把一次优化的收益解耦为跨架构共享效应与平台残差。
- **目标或约束**：只用少量新平台实测样本完成策略迁移。

候选名称：**跨架构效应解耦的 Pass 少样本策略迁移**。

| 证据 | 已提供的基础 |

## 3. 已有工作已经解决的问题

当前工作已经证明：Pass 顺序具有非交换性；IR 特征、历史动作和 RL/搜索能够优于固定优化级别；编译器可被封装成稳定环境；真实性能可作为奖励。因而“用 RL 搜索 Pass”或“在 RISC-V 上测运行时间”本身不是本方案的创新。

## 4. 尚未解决的研究空白

现有组内工作较少回答：同一 Pass 在 x86、ARM、RISC-V 上的收益中，哪些来自程序结构的通用规律，哪些来自平台、工具链和后端的条件效应。若每个平台独立训练，会浪费共享经验；若完全共享策略，又会混合相互冲突的收益。

## 5. 核心机制与数学表示

对程序状态 `x`、Pass 动作 `a` 和平台表示 `e_h`，将真实收益建模为：

$$
\Delta R(x,a,h)=g_{shared}(x,a)+g_{arch}(x,a,e_h)+\epsilon.
$$

其中 `g_shared` 学习跨平台稳定效应，`g_arch` 学习平台残差。训练使用同一程序/动作的跨平台配对数据，并约束训练平台上的残差均值接近零，降低共享项与残差项的不可辨识性：

$$
\mathcal L=\mathcal L_{rank}+\lambda_1\mathcal L_{value}
+\lambda_2\left\|\mathbb E_h[g_{arch}]\right\|^2.
$$

新平台只更新小型残差头或平台嵌入：

$$
\phi_{new}^{*}=Adapt(\phi_{new}^{0},\mathcal D_{new}^{K}),\quad
\theta_{shared}\text{ 冻结}.
$$

这里称“效应解耦”而非严格因果分解；除非实验执行受控干预，否则不作因果主张。

## 6. 系统组成与数据流

```text
同一源码与输入
  → 生成统一初始 IR
  → 应用相同 Pass/宏动作
  → 在 x86、RISC-V（可选 ARM）编译运行
  → 形成跨平台配对收益
  → 训练共享效应头 + 平台残差头
  → 新平台少量校准
  → Pass 候选排序与在线搜索
```

## 7. 可检验的研究问题与假设

- **RQ1**：显式解耦是否比单一平台条件模型具有更高的跨平台候选排序准确率？
- **RQ2**：在 `K∈{0,5,10,20,50}` 次校准下，是否获得更高的 `Speedup@K`？
- **RQ3**：共享项能否识别稳定优化，残差项能否识别循环展开、内联等平台冲突动作？
- **H1**：配对训练与残差约束会降低未见平台上的负迁移率。

## 8. 最小可行 Demo

选择 20–40 个小程序、8–12 个 Pass 宏动作、x86 主机和一台 RISC-V 设备。每个程序对每个宏动作测量相对 `-O3` 的运行时间变化，构造约 500–1000 条配对记录。先用小型 MLP/GNN 做候选排序，不必训练 LLM；证明解耦模型有效后，再接入 LLM Agent 生成候选。

## 9. 实验平台、基线、消融与指标

- **平台**：至少 x86 + RISC-V；可增加 ARM 或第二款同 ISA 设备。
- **基线**：`-O2/-O3/-Oz`、AutoPhase 风格策略、每平台独立模型、共享模型无平台输入、共享模型+平台 ID/Adapter、完整解耦模型。
- **消融**：去掉配对数据、去掉零均值约束、去掉平台残差、全参数适应替代轻量适应。
- **指标**：真实加速比、候选排序 Kendall/Spearman、Top-k 最优召回、负迁移率、`Speedup@K`、实机运行次数。

## 10. 与已有工作的创新边界

本候选记录的边界不在 phase ordering、RL 或 Adapter，而在“对编译动作收益进行可检验的跨架构共享—残差解耦”。在当前主线中，该机制只用于验证与选择由 EPAS 知识单元实例化的 Pass 候选，不再单独承担“可迁移编译知识”的定义。仍需针对 cross-architecture phase ordering、multi-task compiler autotuning、hardware-conditioned policy 等关键词查新。

## 11. 主要风险与降级方案

- **分解不可辨识**：采用同程序同动作配对、残差正则和独立平台留出测试。
- **硬件噪声**：固定频率、预热、多次运行取中位数并记录方差。
- **数据规模不足**：先做候选排序而非端到端 RL。
- **平台过少**：至少加入同 ISA 两设备，用微架构差异验证“架构标签”不足。

## 12. 与当前研究方向的关系

该点位于“AI 编译器 + 多架构真实后端”交叉处，RISC-V 是关键实验平台但不是方法边界。当前不把它独立列为主创新；其 Pass 效应数据、候选空间和少样本排序方法服务于创新 06 的效应观测、实例化候选筛选与验证闭环。只有未来重新聚焦端到端 Pass 策略迁移时，才考虑独立发展。
