# 失败边界记忆驱动的反重复 LLM 编译优化器：主线研究框架

## 1. 一句话解释

智能体不仅记住“这个优化失败过”，还记住它在什么程序条件下失败、什么反例会推翻该结论；只有当前程序满足这些条件时，失败记忆才限制 LLM。

## 2. 研究问题

LLM 编译优化会出现三种重复：

- 同一任务的多轮中重复同类失败；
- 相似程序间重复尝试已知无效动作；
- 检索到一个失败案例后过度泛化，错误禁止本来有效的动作。

研究问题：

> 带适用和失效条件的负证据，能否在未见程序上减少重复失败，同时不降低有效优化率？

## 3. 失败边界卡片

```json
{
  "card_id": "neg-001",
  "program_signature": {
    "pattern": "loop_reduction",
    "dependence": "loop_carried",
    "trip_count_bucket": "small"
  },
  "action": {"type": "unroll", "value": 8},
  "failure": {
    "stage": "test",
    "category": "semantic_mismatch",
    "evidence": "output_diff_hash"
  },
  "applicability": [
    "same_action_type",
    "loop_carried_dependency",
    "trip_count_small"
  ],
  "falsifiers": [
    "dependency_proven_absent",
    "trip_count_large",
    "action_value_le_2"
  ],
  "scope": {"compiler": "llvm-major", "target": "target-family"},
  "confidence": 0.8,
  "status": "active"
}
```

## 4. 输入、处理和输出

### 输入

- 当前程序结构签名；
- LLM 候选动作；
- 历史失败卡片；
- 编译、测试和收益证据；
- 当前编译器与目标信息。

### 处理

1. 检索相似失败卡片；
2. 检查适用条件；
3. 检查反例和失效条件；
4. 输出允许、警告、要求补测或禁止；
5. LLM 在负约束下生成下一候选；
6. 新结果更新卡片置信度；
7. 误拦截或反例使卡片降权/失效。

### 输出

- 最终候选；
- 命中的失败卡片和门控决定；
- 重复失败、误拦截和恢复记录；
- 有效优化与成本指标。

## 5. 关键机制

### 5.1 三态门控

- `ALLOW`：卡片不适用或存在反例；
- `WARN_AND_MEASURE`：部分条件成立，需要低成本验证；
- `BLOCK`：关键适用条件全部成立且卡片置信度超过阈值。

### 5.2 卡片更新

```text
confidence_new = confidence_old + α·confirmed - β·falsified - γ·false_block
```

- `confirmed`：相似条件下动作再次同类失败；
- `falsified`：动作在满足声明条件时成功；
- `false_block`：被卡片禁止的动作经反事实执行后实际有效。

## 6. 为什么不是普通 RAG

普通 Retrieval-Augmented Generation（RAG，检索增强生成）把相似案例放入 Prompt；它通常不检查失败结论何时适用，也不记录何时应该撤销。失败边界记忆必须由工具检查条件，并通过反事实抽样测量误拦截。

## 7. 数据流

```text
当前程序 + LLM 候选
        ↓
检索失败边界卡片
        ↓
适用条件与反例检查
        ↓
ALLOW / WARN_AND_MEASURE / BLOCK
        ↓
生成或执行候选
        ↓
编译、测试、静态收益
        ↓
确认、降权或失效卡片
```

## 8. 小白化例子

历史上“对小循环展开 8 次”导致代码大小增加且没有收益。无条件黑名单会禁止所有循环展开；普通 RAG 可能让 LLM照搬“不要展开”。失败边界卡片只在循环小、动作因子为 8、目标条件相似时发出警告。如果新程序循环次数大，或只展开 2 次，卡片自动不适用。

## 9. 研究问题

- RQ1：失败边界记忆能否降低重复失败率？
- RQ2：它是否比无条件失败黑名单具有更低误拦截率？
- RQ3：跨程序家族时，失败边界是否仍能迁移？
- RQ4：反例失效机制是否能恢复被错误阻止的有效动作？
- RQ5：负证据是否提高固定预算下的有效优化率？

## 10. 假设

- H1：失败边界记忆的重复失败率低于无记忆和成功案例 RAG。
- H2：误拦截率低于无边界失败记忆。
- H3：固定预算下首次有效优化轮数减少。
- H4：去掉反例失效后，有效优化率下降。

## 11. 候选贡献

1. 提出带程序前提、作用范围和反例条件的编译优化失败卡片；
2. 提出 ALLOW/WARN/BLOCK 门控和反例驱动的置信度更新；
3. 用重复失败率、误拦截率和反事实恢复实验验证负记忆是否真的有用。

## 12. 可证伪条件

若普通 RAG 达到同等效果、失败卡片大量误拦截、或反例失效无贡献，则该方向不能作为独立创新。

## 13. 一个核心创新与两个支撑创新

三个创新构成“负证据表示—条件化使用—自我纠错”因果链。核心创新定义失败知识，支撑创新一决定当前候选如何受约束，支撑创新二主动寻找反例并撤销错误记忆。

### 13.1 核心创新：带适用边界的编译优化负证据表示

【论文事实】成功案例检索、历史模式复用、普通 RAG 和失败日志存储已有充分近邻。

【合理推导】文本相似度不能说明失败结论在什么程序结构、动作参数、编译器版本或目标范围内成立。

【候选创新】失败卡片必须联合表示程序签名、动作、失败类别、适用条件、反例条件、工具链范围、置信度和状态。

- 输入：失败轨迹、程序结构特征、动作和工具链信息；
- 处理：失败归类、条件抽取、范围绑定和卡片规范化；
- 输出：可由工具检查的条件化负证据；
- 本质变化：失败案例从相似文本变为带条件语义的可执行约束；
- 专属消融：无记忆、成功案例 RAG、无条件失败记忆、完整失败边界卡片；
- 专属指标：重复失败率、跨程序复用率、固定预算有效优化率；
- 证伪条件：成功案例 RAG 或无条件失败记忆达到同等结果。

### 13.2 支撑创新一：适用条件与反例条件驱动的三态门控

【论文事实】黑名单、规则门控和二元允许/禁止容易实现，但它们本身不是创新。

【合理推导】条件只满足一部分或存在潜在反例时，直接禁止会误杀有效动作，直接允许又会重复失败。

【候选创新】根据适用条件、反例条件和置信度输出 ALLOW、WARN_AND_MEASURE 或 BLOCK；证据不足的候选进入低成本补测。

- 输入：当前程序签名、候选动作和匹配失败卡片；
- 处理：适用条件检查、反例检查、置信度判断和补测选择；
- 输出：三态门控决定及可解释原因；
- 本质变化：不确定候选从二元决策转入可观测的测量状态；
- 专属消融：二元黑名单、无反例检查三态门控、完整三态门控；
- 专属指标：误拦截率、补测收益率、禁止准确率；
- 证伪条件：三态门控不能降低误拦截，或补测成本超过避免重复失败的收益。

### 13.3 支撑创新二：误拦截审计与反例驱动的记忆失效更新

【论文事实】在线计数或置信度更新是常见方法，不能单独作为创新。

【合理推导】被禁止的动作通常不会被执行，系统因而缺少能够证明禁止错误的结果，负记忆可能永久保留偏差。

【候选创新】对少量 WARN_AND_MEASURE 或 BLOCK 动作进行反事实抽样执行；若动作实际有效，则记录 false_block，降低置信度、缩小适用范围或使卡片失效。

- 输入：被警告或禁止的动作、卡片置信度和审计预算；
- 处理：分层抽样、反事实执行、误拦截判定和卡片更新；
- 输出：confirmed、falsified 或 false_block 事件及新卡片状态；
- 本质变化：记忆不仅累积失败，还主动寻找能够推翻自身的反例；
- 专属消融：不更新、仅成功失败计数更新、误拦截审计更新；
- 专属指标：误拦截恢复率、错误记忆存活时间、长期有效优化率和审计成本；
- 证伪条件：审计不能恢复有效动作，或额外执行成本抵消全部收益。

### 13.4 统一数据流与假设

失败轨迹 → 条件化负证据卡片 → 适用与反例检查 → ALLOW/WARN_AND_MEASURE/BLOCK → 执行或补测 → 误拦截审计 → 确认、降权或失效。

- H1：失败边界卡片相对普通检索和无条件失败记忆降低重复失败率；
- H2：完整三态门控相对二元黑名单降低误拦截率；
- H3：误拦截审计相对计数更新提高恢复率并缩短错误记忆存活时间；
- H4：三项创新联合使用时的收益不能由更长检索上下文或更多额外执行解释。
