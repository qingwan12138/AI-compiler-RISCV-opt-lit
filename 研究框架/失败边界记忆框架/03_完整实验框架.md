# 失败边界记忆框架：完整实验设计

## Material Passport

- Origin Skill: experiment-agent
- Origin Mode: plan
- Origin Date: 2026-07-19
- Verification Status: UNVERIFIED
- Version Label: failure_boundary_memory_plan_v1

## 1. 实验目标

验证带适用和失效条件的失败记忆，能否跨程序减少重复失败，并比无条件黑名单产生更少误拦截。

## 2. 数据构造

### 程序规模

- 预实验：20 个函数；
- 完整实验：60—120 个函数；
- 至少 5 个程序家族；
- 每个家族包含相似结构和关键差异，便于检验边界。

### 切分

- 记忆构建集：收集失败卡片；
- 开发集：确定匹配阈值；
- 同家族测试集：测近分布迁移；
- 未见家族测试集：测过度泛化。

## 3. 实验组

| 组 | 记忆方式 | 作用 |
|---|---|---|
| B0 | 无记忆 | 简单基线 |
| B1 | 只检索成功案例 | 普通 RAG 强基线 |
| B2 | 保存失败文本并直接加入 Prompt | 无结构负记忆基线 |
| B3 | 无条件失败黑名单 | 排除单纯禁止动作效果 |
| M | 失败边界卡片 + 适用/失效门控 | 完整方法 |

## 4. 控制变量

所有方法固定：LLM、Prompt 主体、程序、候选数、轮数、Token、动作空间、编译/测试次数和静态收益评价。记忆文本长度应控制或作为协变量报告。

## 5. 失败定义

- 编译失败；
- 测试或差分失败；
- Sanitizer 失败；
- 正确但静态指标未改善；
- 重复动作且没有新增证据；
- Top-1 运行时间复核明显退化。

不同失败类型不能混成一个“失败”标签。

## 6. 主要指标

```text
RepeatFailureRate = 与已有卡片同动作、同条件、同失败类型的次数 / 全部失败次数
```

```text
FalseBlockRate = 被BLOCK但反事实执行后有效的动作数 / 被抽查BLOCK动作数
```

```text
RecoveryRate = 反例出现后成功解除错误限制的卡片数 / 已确认错误卡片数
```

同时报告 Valid Improvement@Budget、首次有效优化轮数、Token 和工具调用。

## 7. 反事实误拦截审计

从每种方法被阻止的动作中按失败类型分层抽样执行。执行预算预先固定，不能只检查可疑案例。若被阻止动作实际正确且有收益，计为 false block，并更新卡片。

## 8. 消融

- 去掉程序结构条件；
- 去掉动作参数条件；
- 去掉编译器/目标作用域；
- 去掉 falsifier；
- 去掉 false-block 降权；
- 二态 ALLOW/BLOCK，去掉 WARN_AND_MEASURE；
- 随机卡片检索；
- 只按文本相似度匹配。

## 9. 卡片质量评价

- Applicability precision：卡片命中后同类失败的比例；
- Applicability recall：已知重复失败中被卡片发现的比例；
- FalseBlockRate；
- 失效延迟：反例出现到卡片失效需要多少次证据；
- 卡片覆盖率和平均长度；
- 不同失败类别的质量分布。

## 10. 统计分析

- 重复失败和有效优化使用任务级配对 bootstrap；
- FalseBlockRate 使用 Wilson 或 bootstrap 区间；
- 首次有效优化轮数可用配对生存曲线或中位数差；
- 多方法比较用 Holm 校正；
- 同家族和未见家族分开报告；
- 报告最坏程序家族，避免只报总体平均。

## 11. 成功标准

- M 的重复失败率低于 B0/B1；
- M 的 FalseBlockRate 低于 B3；
- M 的 Valid Improvement@Budget 不低于 B1，并优于 B2/B3；
- falsifier 和降权消融导致误拦截上升；
- 未见家族中没有大面积负迁移。

## 12. 风险与降级

- 失败卡片太少：先人为设计边界程序对；
- 程序签名难提取：使用编译器静态统计和人工可核字段；
- 误拦截审计成本高：固定抽样比例，不全量执行；
- 卡片文本过长：用结构字段而非完整日志；
- 普通 RAG 最好：方向降级为错误分析工具；
- 记忆跨模型不稳定：固定一个模型建立和使用卡片。

## 13. 可证伪条件

普通成功案例 RAG 同等或更优、FalseBlockRate 不可接受、或反例失效机制无贡献时，核心创新不成立。

## 14. 三项创新的独立实验映射

### 14.1 核心创新：条件化负证据表示

| 组别 | 记忆方法 | 目的 |
|---|---|---|
| M0 | 无记忆 | 简单基线 |
| M1 | 成功案例 RAG | 正经验检索强基线 |
| M2 | 无条件失败记忆 | 排除“记住失败即可” |
| M3 | 完整失败边界卡片 | 核心机制 |

主要指标：重复失败率、跨程序复用率、固定预算有效优化率。M3 必须优于 M1 和 M2，且不能依赖更长检索上下文。

### 14.2 支撑创新一：三态门控

| 组别 | 门控方法 | 目的 |
|---|---|---|
| G0 | 二元允许或禁止 | 黑名单基线 |
| G1 | 无反例检查的三态门控 | 测量反例条件贡献 |
| G2 | 适用与反例条件完整三态门控 | 完整支撑机制 |

主要指标：FalseBlockRate、补测收益率、禁止准确率和额外测量成本。G2 必须相对 G0 降低误拦截，并证明 WARN_AND_MEASURE 的收益超过成本。

### 14.3 支撑创新二：误拦截审计更新

| 组别 | 更新方法 | 目的 |
|---|---|---|
| U0 | 不更新 | 静态记忆基线 |
| U1 | 仅成功/失败计数更新 | 常规在线更新强基线 |
| U2 | 带误拦截反事实审计的失效更新 | 完整支撑机制 |

主要指标：误拦截恢复率、错误记忆存活时间、长期有效优化率和审计成本。U2 若不能恢复有效动作或额外成本抵消收益，应降级。

### 14.4 数据划分、公平性和统计

- 失败卡片只从检索池构造，测试池按程序家族隔离，避免数据泄漏；
- 所有方法使用相同 LLM、候选预算、记忆条目上限和上下文 Token 上限；
- 对 WARN_AND_MEASURE 和 BLOCK 分层抽样审计，预先固定审计比例；
- 报告任务级配对差异、bootstrap 置信区间、同家族与未见家族分层结果；
- 联合消融按“去审计更新→去反例检查→去适用边界”逐层退化；
- 若收益来自更多额外执行而不是更准确的负约束，不能支持三项创新。
