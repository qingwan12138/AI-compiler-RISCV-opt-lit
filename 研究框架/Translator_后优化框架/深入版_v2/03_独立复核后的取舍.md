# 独立复核后的取舍：先复用、再测量、最后决定复杂模块

日期：2026-09-08。两项限定范围的调查由 Luna 子代理完成，主线程核验影响决策的一手来源并修改方案。没有要求子代理重读全库，也没有生成逐篇阅读笔记。

## 1. 决策摘要

**批准做低成本问题验证，不把完整机制视为已成立的论文创新。**

- 保留：Translator、LLVM IR 直接重写、整函数验证、收益与正确性同时成立的指标。
- 评价口径：根据后续用户确认，改为统一 Oz 后的 IR 指令数，O3 仅作补充对照；简单清理只用于诊断。此前为了对齐 LPO 而固定 O3 的决定不再适用。
- 暂缓：复杂符号组合搜索、大规模模型训练、多 Agent、GPU/跨架构扩展。
- 先复用：LPO artifact 的流程和已有记录。先证明真实数据需要新的修复决策，才实现联合关系契约和成本前沿。

## 2. 找到了可以直接节省工程量的入口

[LPO 官方 artifact](https://github.com/uw-pluverse/lpo-artifact) 提供抽取器、运行脚本、原始结果目录及结果汇总脚本；运行参数可保存非等价候选。它仍要求构建工具依赖，不能理解为下载即可免安装运行。

最省成本的第一步是读取已有 `rq1_results_lpo` 中少量记录，核对“输入—候选—错误—重试”的可恢复程度。**目录存在不等于公开了完整失败轨迹**：缺少的原始模型响应、反例或时间信息要先盘点，不能补造。

| 可复用部分 | 不必重造什么 | 不能直接继承什么 |
|---|---|---|
| 原始结果与汇总 | 输出格式认识、少量工具夹具 | 原论文结果不算我们的复现实验 |
| IR 抽取器 | 基本块依赖序列包装 | 包装函数不是原生完整函数，须单独标记 |
| 模型/工具调用脚本 | 基础调用流程、保存输出 | 现有接口兼容性、预算语义、当前模型版本仍需验收 |
| 本地旧预实验工具 | 日志/hash/子进程包装的部分思路 | 旧源码测试不等于 Alive2 细化；旧 regex 计数和普通 bootstrap 不直接作正式评价 |

当前 artifact 页面未展示明确许可文件入口，复用代码/再发布前检查具体许可；先只读研究，不默认有权原样搬入并发布。

本地已查看旧 `preexperiment/p0_runner.py` 的 hash、进程包装、指令计数和 bootstrap 函数。说明并非所有外围工作从零开始，但还没有迁移代码或跑旧实验。旧 README 使用其他机器路径，不能据此认定当前机器工具齐备。

## 3. 数据入口需要纠正

[LLVM Opt Benchmark](https://github.com/dtcxzyw/llvm-opt-benchmark) 已归档并指向 [nightly 仓库](https://github.com/dtcxzyw/llvm-opt-benchmark-nightly)。其文件可按需读取，不要求 clone 全库。

正式实验选择一份固定快照，不在一轮实验中混用不同 nightly。模块中先选符合限制的原生完整函数；抽取指令序列的路线单独报告，尤其要区分“片段得到验证”和“原应用整体被优化”。

第一批可用 archived 快照保证稳定性；较新 nightly 作为后续保留集候选。论文年份新旧与 benchmark 快照新旧是两个不同问题。

## 4. 新颖性核查的决定

补充的[Compiler generated feedback for Large Language Models](https://arxiv.org/abs/2403.14714)已研究编译器反馈迭代优化，并报告充分采样可能优于反馈。因此不能只在很小调用预算上挑一个有利点。

子代理没有提供足以确认“本方案被完整覆盖”的新证据，但这也不证明不存在竞争工作。此前确认的 Angelix、Qlose、MENTOR 和 CUDABeaver 仍然是主要创新边界，不因为换一个模块名称就消失。

最重要的实证比较是：

> 相同模型、起点、语义契约和预算下，**按实际优化目标选择联动重写范围**，是否比普通最小范围修复多获得经 Oz 清理后仍有 IR 简化收益的正确程序？

本问题暂不要求运行加速。若论文进一步主张代码尺寸收益，必须测量固定后端的机器码字节数；仅有 IR 简化不够。换成 Oz 本身不是创新，也不改变 Translator、联合修复和整函数验证机制。

不是“整套系统是否胜过随机生成”。没有前一句的证据，就不能把范围决策作为主创新。

## 5. 主线程发现的一个待验证弱点

把某区域恢复原状后得到的较低指令数，未必对应合法程序；错误程序可以异常地短。因此成本探针只是启发式特征，不能叫“已保留优化收益”。

P0/P1 必须按 verified / refuted / unknown 区分探针，再测探针排序与最终有效收益的关系。若无预测力，直接删除前沿模块；不以增加复杂模型修补一个尚无证据的特征。

## 6. 下一步真正实施的最小包

1. **零模型费用盘点：**只读官方 artifact 的最多 10 条记录，确认它们是否包含完整 source/candidate、错误种类与后续结果；这只能生成工具夹具和字段清单。
2. **工具烟雾：**锁定 LLVM/Alive2，复跑已知正确、错误和未知状态，确认统一 Oz 与计数，另配置 O3 对照。
3. **小样本天然失败：**先 20 个新开发函数、每个 4 次候选，共最多 80 次初始生成，检查格式、对齐率和费用；通过后才扩到协议中的 120。
4. **只跑三项：**普通反例重写、简单候选组合枚举、原程序回退。先估算复杂方法可能增加多少空间。
5. 有空间才加入局部契约，再加成本前沿；每加一项都与上一层配对比较。

80 次只是烟雾投入上限，不足以宣布方法有效。无需一开始就花数万次请求跑完整论文矩阵。

## 7. Token 使用约定

- 检索/元数据/可复用工具盘点：小上下文 Luna，单次明确范围与返回长度。
- 框架取舍、相近工作边界、实验因果设计：主线程负责。
- 不让两名代理搜索同一个题目，不让每个代理重读全部历史。
- 不反复生成长篇新方案；优先在当前四份深入版文件中更新决策。
- 本轮没有可审计的实际 Token 节约统计，不虚报节省比例。

**当前定位：一个边界更清楚、能止损的研究候选，而不是已经确定能发表的研究成果。**
