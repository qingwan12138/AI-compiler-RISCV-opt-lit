# 三套实验框架“三创新点”同步改写规格

> 规格日期：2026-07-19
>
> 规格状态：已通过用户复核
>
> 改写范围：`09_LLM_AI编译器低开销创新框架`
>
> 组织原则：每套框架采用“一个核心创新 + 两个支撑创新”，三个创新共同回答一个研究问题

## 1. 改写目标

当前三套实验框架已经形成独立研究问题，但创新点主要以一个核心机制呈现，另外两项方法贡献散落在系统流程、候选贡献和消融实验中。此次改写将三项方法贡献显式化，并确保：

1. 三个创新点属于同一个因果链，而不是三个热门模块的拼接；
2. 每个创新点都改变输入信息、执行约束、学习目标或反馈闭环中的至少一项；
3. 每个创新点都有独立消融实验和可证伪条件；
4. 实验平台、评价指标、数据记录和预实验 Demo 与三个创新点一一对应；
5. 不把使用 LLM、Agent、RAG、JSON、LLVM、RISC-V 或增加实验指标本身称为创新。

## 2. 统一创新结构

每套框架统一采用以下结构：

```text
统一研究问题
    ↓
核心创新：改变主要决策机制
    ↓
支撑创新一：为核心决策提供可验证信息或约束
    ↓
支撑创新二：形成修复、停止、更新或失效闭环
    ↓
三个独立消融 + 联合消融
    ↓
统一主要指标 + 各创新专属指标
```

“核心创新”承担论文的主要新颖性主张；“支撑创新”必须具有独立研究假设，但不与核心创新争夺主线定位。

## 3. 框架一：可验证结构化编辑驱动的 LLM 编译优化器

### 3.1 统一研究问题

在固定模型、Token 和候选数量下，能否通过可执行、可验证、可定位失败的局部编辑表示，提高 LLM 编译优化的有效优化率，并减少无关重写和重复修复？

### 3.2 核心创新：效应绑定的局部编辑契约

- 研究空白：自由代码改写和普通结构化建议没有把动作与预期编译效应绑定为同一个可执行对象。
- 新机制：将修改位置、参数化动作、适用前提、预期证据、验收条件和失败范围组成编辑契约。
- 本质变化：最小决策单元从“整段代码”或“文本建议”变为“可执行且可验收的效应绑定动作”。
- 专属消融：使用普通 JSON 动作替换完整契约，并控制输出长度和动作空间。
- 专属指标：有效优化率、无关修改行数、契约执行成功率。
- 证伪条件：普通 JSON 在相同预算和动作空间下达到同等效果。

### 3.3 支撑创新一：前提—预期证据的双向可执行验证

- 研究空白：现有结构化输出通常只约束输出格式，不能证明动作在当前程序上适用，也不能确认编译器是否实现了预期效应。
- 新机制：执行前检查动作前提，执行后检查预期优化证据；两类检查共同决定接受、拒绝或进入修复。
- 本质变化：验证从“代码能否编译”扩展为“动作是否适用且预期效应是否出现”。
- 专属消融：分别删除前提检查、预期证据检查和两者之间的绑定。
- 专属指标：不适用动作率、无效动作率、预期效应命中率。
- 证伪条件：删除任一检查不影响正确性、有效优化率或无效动作率。

### 3.4 支撑创新二：失败责任定位与字段级局部修复

- 研究空白：反馈驱动方法在失败后经常重新生成完整程序，难以判断哪个决策字段造成失败。
- 新机制：把编译、测试和收益失败映射到契约字段，只允许修改被归责字段及其依赖字段。
- 本质变化：修复单元从完整候选变为具有责任边界的局部字段。
- 专属消融：完整重生成、无责任定位的局部修复、带责任定位的局部修复三组比较。
- 专属指标：首次有效优化轮数、修复 Token、无关改动、错误复发率。
- 证伪条件：责任定位不能减少修复成本，或严格局部修复阻止必要的跨字段修改。

## 4. 框架二：信息价值门控的自适应反馈 LLM 智能体

### 4.1 统一研究问题

在固定总预算下，能否只获取真正可能改变优化决策并提高成功概率的反馈，从而以更少 Token、工具调用和时间获得更多有效优化？

### 4.2 核心创新：反事实决策变化驱动的反馈价值模型

- 研究空白：反馈准确不等于反馈值得获取，固定多轮或全量反馈没有衡量反馈是否改变下一步决策。
- 新机制：将决策变化概率、变化后的有效优化收益和反馈成本统一到反馈价值函数中。
- 本质变化：反馈选择目标从“获得更多信息”变为“获得能改变有效决策的信息”。
- 专属消融：删除决策变化项、收益项或成本项，并与固定阶段规则比较。
- 专属指标：Valid Improvement@Budget、单位成本有效优化数。
- 证伪条件：固定阶段规则达到同等结果，或决策变化与有效优化无关。

### 4.3 支撑创新一：无需训练大模型的反事实反馈标注与校准

- 研究空白：缺少能够判断某类编译反馈是否真正改变 LLM 决策的可复现实验标签。
- 新机制：对同一状态分别隐藏或加入不同反馈，记录动作类型、修改位置和候选排序的变化，再用真实验证结果标注该变化是否有益。
- 本质变化：把抽象的“反馈有用性”转成可观察、可校准的决策变化标签。
- 专属消融：自报告有用性、启发式标签和反事实标签三组比较。
- 专属指标：Brier Score、AUROC、Average Precision、决策变化后有效率。
- 证伪条件：反事实标签不能预测真实变化或最终有效优化。

### 4.4 支撑创新二：多维预算约束的反馈选择与主动停止

- 研究空白：只控制轮数或 Token 会忽略编译、测试和分析工具的时间成本，也难以判断何时停止无效循环。
- 新机制：联合跟踪 Token、工具调用和墙钟时间；当所有反馈价值低于阈值时，在执行、接受和停止之间选择。
- 本质变化：停止不再由固定轮数触发，而由剩余预算和预期边际收益共同触发。
- 专属消融：固定轮数停止、随机停止、仅 Token 预算和三维预算主动停止。
- 专属指标：首次有效优化成本、无效尾部轮数、质量—成本曲线面积。
- 证伪条件：主动停止虽然节省成本，却显著降低有效优化率，或固定轮数达到同等质量—成本表现。

## 5. 框架三：失败边界记忆驱动的反重复 LLM 编译优化器

### 5.1 统一研究问题

带适用条件和失效条件的负证据，能否在未见程序上减少重复失败，同时避免错误禁止本来有效的编译优化动作？

### 5.2 核心创新：带适用边界的编译优化负证据表示

- 研究空白：普通 RAG 或失败黑名单记录“发生过什么”，但没有明确失败结论在什么条件下成立。
- 新机制：失败卡片统一记录程序签名、动作、失败类别、适用条件、反例条件、工具链范围和置信度。
- 本质变化：失败案例从相似文本变为带条件语义的可执行负约束。
- 专属消融：成功案例 RAG、无条件失败记忆和失败边界卡片三组比较。
- 专属指标：重复失败率、跨程序复用率、固定预算有效优化率。
- 证伪条件：普通检索或无条件黑名单达到同等效果。

### 5.3 支撑创新一：适用条件与反例条件驱动的三态门控

- 研究空白：二元允许/禁止无法处理条件只满足一部分或证据不足的候选。
- 新机制：根据适用条件、反例条件和置信度输出 ALLOW、WARN_AND_MEASURE 或 BLOCK。
- 本质变化：不确定候选不会被直接禁止，而是转入低成本测量以补充证据。
- 专属消融：二元黑名单、无反例检查的三态门控和完整三态门控。
- 专属指标：误拦截率、补测收益率、禁止准确率。
- 证伪条件：三态门控不能降低误拦截，或补测成本超过避免重复失败的收益。

### 5.4 支撑创新二：误拦截审计与反例驱动的记忆失效更新

- 研究空白：负记忆一旦写入容易长期保留错误结论，普通在线更新又可能只看到被允许执行的动作。
- 新机制：对部分被警告或禁止的动作进行反事实抽样执行；若实际有效，则记录误拦截并降低置信度、缩小适用范围或使卡片失效。
- 本质变化：记忆不仅累积失败，还主动寻找能够推翻自身的反例。
- 专属消融：不更新、仅成功/失败计数更新和带误拦截审计的失效更新。
- 专属指标：错误记忆存活时间、误拦截恢复率、长期有效优化率。
- 证伪条件：审计无法恢复有效动作，或额外执行成本抵消全部收益。

## 6. 文件同步范围

每个实验子文件夹的六份材料全部同步：

1. `00_材料索引与使用说明.md`：增加三创新点导航和建议阅读顺序；
2. `01_主线研究框架.md`：明确核心创新、两个支撑创新及统一因果链；
3. `02_文献依据与创新边界.md`：分别给出三项创新的论文事实、合理推导、近邻边界和证据强弱；
4. `03_完整实验框架.md`：为每项创新设置独立基线、消融、指标、统计分析和证伪判据；
5. `04_预实验Demo.md`：增加三个阶段或三组实验，分别验证三项创新；
6. `05_数据记录与评价模板.md`：增加能够计算每项创新专属指标的记录字段。

根目录同步更新：

- `00_总体设计规格.md`：更新统一组织原则；
- `01_三框架总览与最终推荐.md`：把每套框架拆成一主两辅；
- `02_文献证据矩阵与创新碰撞检查.md`：逐项检查九个创新的近邻碰撞；
- `03_完成报告与下一步.md`：更新完成情况和推荐顺序；
- `99_材料生成实施计划.md`：记录本轮增量改写任务和验收条件。

本轮不新建实验代码，不运行真实 LLM API，也不扩大 RISC-V 实验范围。

## 7. 验收标准

改写完成后必须满足：

1. 三个子框架均明确出现“核心创新”“支撑创新一”“支撑创新二”；
2. 九个创新点均包含研究空白、新机制、本质变化、专属消融、专属指标和证伪条件；
3. 每套框架的三个创新能够组成单一数据流和统一研究问题；
4. 每项支撑创新至少改变一项输入、约束、学习目标或反馈闭环；
5. 三份预实验 Demo 均能分别验证三项创新，而不是只验证完整系统；
6. 三份记录模板均有对应字段，能够复算主要指标；
7. 文献边界继续区分【论文事实】【合理推导】【候选创新】；
8. 结构化编辑框架维持保底/执行器定位，信息价值门控维持唯一推荐主线，失败边界记忆维持独立备选/扩展定位；
9. 全部 Markdown 无空文件、乱码、未完成占位符和重复内容；
10. Git 提交只包含 `09_LLM_AI编译器低开销创新框架`，提交信息以 `由Codex提交：` 开头。

## 8. 预期结果

改写后，每套框架都可以用同一套论文贡献表达：

1. 提出一个解决主要研究空白的核心机制；
2. 提出一个为核心机制提供可验证信息或约束的支撑机制；
3. 提出一个形成修复、停止或失效更新闭环的支撑机制；
4. 通过独立消融证明三项机制的贡献不是由更大模型、更多数据或更多搜索预算造成。

其中，信息价值门控框架仍是最推荐的 CCF-B 投稿候选；另外两套框架不会因为增加创新点数量而自动升级为同等推荐等级。
