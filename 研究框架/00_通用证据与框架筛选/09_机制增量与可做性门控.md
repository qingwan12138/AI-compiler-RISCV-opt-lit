# 机制增量与可做性门控

> 生成日期：2026-09-08  
> 依据：[`08_近邻工作与创新边界表.md`](08_近邻工作与创新边界表.md)、[`05_创新证据矩阵.md`](05_创新证据矩阵.md) 与 [`06_局限与反例证据表.md`](06_局限与反例证据表.md)。  
> 解释：这里的“可做性”仅指现有公共工具、数据、硬件或指标能否核验一个文献观察；不评估个人能力、资源承诺，也不构成研究方案或算法设计。

## 使用规则

- 只有信息、约束、决策对象或反馈闭环的可识别差异，才可能构成最低独立机制；模型名称、Agent、RL、Alive2、平台或更多搜索轮数本身不是机制差异。
- “可证伪指标”是使观察可被否定的公开衡量条件，不是承诺实施的预实验。
- `保留观察` 不代表创新成立；`证据不足` 与 `近邻重合高` 都要求先补充或人工复核证据。

## OPP-01：静态优化代理与目标机效应之间的可比较证据缺口——机制增量与可做性门控

### 共同输入与输出

共同输入是程序/IR、候选变换或策略、静态代理与目标平台；共同输出是候选排序或性能判断。PAPER-C25、PAPER-C35 已以 Runtime 参与选择，PAPER-C09 已提供静态微架构估计。

### 最低独立机制判据

同一可追溯记录必须把静态代理、目标平台、真实 Runtime 与排序误差共同关联，并使该关联影响候选比较；若只额外测量 Runtime 或只更换代理，则不满足独立机制判据。

### 退化为的最近工作

缺少“同一记录单位的代理—Runtime 关系”时，退化为 PAPER-C25/PAPER-C35 的真实测量选择，或 PAPER-C09 的静态估计使用。

### 公开核验条件

LLVM 优化管线、公开基准与可访问目标机/性能计数工具、`llvm-mca` 或同类静态代理，均足以核验是否存在被记录的对应关系；不要求新增私有设施。

### 可证伪指标

若在明确平台、程序集和测量协议下，所记录的代理关系不能区分 Runtime 排序错误，或与不记录该关系的比较没有任何可观察差异，则“可比较证据”这一机制主张不成立。

### 门控结果
证据不足

现有库证明代理与 Runtime 都被使用，但尚未完成 2024–2026 年专门相关性/校准工作审计，不能确认该最低机制未被近邻覆盖。

## OPP-02：验证结论、未判定结果与最终可用输出之间的证据分层——机制增量与可做性门控

### 共同输入与输出

共同输入是生成的 IR、代码或规则及其验证结果；共同输出是接受、拒绝、修复或未判定的生成结果。PAPER-12、PAPER-13、PAPER-C34 已使用多层验证/反馈，PAPER-14 描述验证器边界。

### 最低独立机制判据

必须在同一成功率口径中保存编译、测试、形式验证、超时/未判定和后端可执行状态，且该分层改变最终接受或报告的判定；若只是再调用一个验证器，不满足独立机制判据。

### 退化为的最近工作

缺少统一分层口径时，退化为 PAPER-12 的验证反馈、PAPER-13 的测试/Alive2 验证，或 PAPER-C34 的多验证器链。

### 公开核验条件

LLVM/Clang、Alive2、公开测试基准及可复用生成样本可核验验证状态是否被完整记录；PAPER-14 所述 unsupported/inconclusive 情形提供边界检查依据。

### 可证伪指标

若统一状态记录与既有多阶段流程在成功率分母、拒绝/未判定归属和可执行输出比例上没有可观察差异，则该分层只是重复报告而非独立机制。

### 门控结果
近邻重合高

验证反馈、分层验证和未判定边界已有强近邻；在未证明统一状态口径改变决策前，不应把“验证分层”作为独立框架候选。

## OPP-03：真实性能反馈的预算与稳定性可审计比较——机制增量与可做性门控

### 共同输入与输出

共同输入是候选程序/策略、编译与运行资源、真实或替代反馈；共同输出是性能排序、接受候选或搜索结果。PAPER-C25、PAPER-C35、PAPER-N07、PAPER-C37 都记录其中一部分成本或重复测量。

### 最低独立机制判据

反馈闭环必须把候选数量、编译次数、执行次数、重复测量、LLM/墙钟成本和性能方差作为同一预算约束下的决策输入；仅限制轮数、缓存结果或增加搜索不满足判据。

### 退化为的最近工作

缺少统一预算账本时，退化为 PAPER-C25 的混合反馈、PAPER-C35 的轮数比较、PAPER-N07 的重复执行，或 PAPER-C37 的宏基准成本处理。

### 公开核验条件

公开编译器、基准、计时工具和可重复执行脚本足以记录上述成本字段；可在同一工具链下复核预算与方差，但这不表示已有结论一定可跨论文比较。

### 可证伪指标

若在固定预算下，完整成本账本不能区分不同反馈来源的候选质量或稳定性，或缺失字段不影响任何比较结论，则“可审计比较”不是可识别机制。

### 门控结果
证据不足

现有笔记显示成本字段分散，但未完成同任务、同预算的近年文献核查；不能据此宣称存在未覆盖的反馈机制。

## OPP-04：跨平台适用边界的可比报告缺口——机制增量与可做性门控

### 共同输入与输出

共同输入是同一程序、优化对象、平台与测量协议；共同输出是平台相关决策及其性能结果。PAPER-C35、PAPER-C25、PAPER-64 已展示不同范围的平台比较。

### 最低独立机制判据

必须把平台作为影响“决策是否改变”的条件变量，并在相同程序、验证状态与测量协议下报告改变/不改变的后果；只在多个平台各跑一次实验不满足判据。

### 退化为的最近工作

缺少平台条件与决策变化的关联时，退化为 PAPER-C35 的双 CPU Pass 评测、PAPER-C25 的 CPU 迁移测试或 PAPER-64 的多加速器结果。

### 公开核验条件

LLVM/Clang 的多目标后端、公开基准以及至少两类可访问目标环境或可信执行/测量设置，可核验平台、变换和结果是否在同一记录口径下关联。

### 可证伪指标

若平台标签不能解释任何决策改变或性能排序改变，或不同平台使用了不可比的程序/验证/测量协议，则“跨平台边界”机制不能成立。

### 门控结果
证据不足

跨平台实验已有近邻，但本库尚未审计平台条件模型、跨 ISA 与 LLVM 后端近年工作，不能判断该条件变量是否已被充分机制化。

## OPP-05：从局部规则/Pass 成功到完整编译流水线收益的证据闭环——机制增量与可做性门控

### 共同输入与输出

共同输入是规则、Pass 或启发式及其匹配程序；共同输出包括局部变换、验证结论、后端产物与整程序性能。PAPER-44、PAPER-C36、PAPER-C37、PAPER-17 和 PAPER-14 分别覆盖其中若干环节。

### 最低独立机制判据

同一可追溯单位必须连接：(1) 规则/Pass 的适用前提，(2) 语义验证状态，(3) 后端利润或损失，(4) 整程序 Runtime 归因；缺少任何一层时，不能把局部成功解释为完整流水线收益。

### 退化为的最近工作

缺少四层连接时，退化为 PAPER-44 的规则生成与筛选、PAPER-C36 的 Pass 生成、PAPER-C37 的启发式搜索，或 PAPER-17/PAPER-14 的局部优化与等价验证。

### 公开核验条件

LLVM、Alive2、公开编译器基准、生成规则/Pass 的应用日志、二进制分析与 Runtime 测量工具可分别核验四层连接是否存在；当前不假定这些证据已经被某一工作统一实现。

### 可证伪指标

若规则/Pass 的局部收益无法在应用日志、验证状态、后端产物和程序级 Runtime 之间建立可追溯链，或完整链条与仅局部筛选没有可区分结论，则该闭环不能被视为独立机制。

### 门控结果
保留观察

现有近邻覆盖了各个局部环节，但当前证据尚未显示四层归因被同一记录单位连通。仍需补查 rule mining、e-graph、MLIR transform 与 pass synthesis 文献，不能将此状态解释为创新结论。
