# 2024—2026 年编译器文献六类创新点总览

> 生成日期：2026-07-16
>
> 证据范围：本地语料库中 2024—2026 年的 112 条去重总结；2024 年 38 条、2025 年 45 条、2026 年 29 条。
>
> 方向约束：研究主线以 LLM/AI 编译优化为中心。RISC-V/RVV 只作为实验平台选项，不作为主线标题、理论对象或唯一应用场景。
>
> 结论性质：下列内容均为【候选创新】或【合理推导】，不是已经通过完整在线查新和实验验证的原创性断言。

## 1. 证据构成

| 类别 | 2024—2026 年总结数 | 本轮重点 |
|---|---:|---|
| 编译阶段排序与强化学习调优 | 16 | Pass 级信用、因果证据、不确定性和跨硬件反馈 |
| LLM 编译优化智能体与反馈驱动 | 55 | 可执行反馈、反证、正确性与机制证据、长期记忆 |
| 形式验证、超级优化与规则生成 | 19 | 语义正确性、盈利条件、规则部署与反例收缩 |
| 向量化与跨 ISA 代码迁移 | 5 | VLEN、尾部/掩码、迁移正确性和性能悬崖 |
| RISC-V/RVV 编译器与真实后端 | 8 | `vl/vtype` 状态、寄存器压力、后端联合决策 |
| 多硬件编译、代价模型与 IR 基础设施 | 9 | 硬件表征、低样本代价模型、选择性迁移 |
| **合计** | **112** | — |

清单中 108 条具有完整的标准化总结，4 条因源材料受限而降级使用。类别二文献最多，类别四文献最少；数量不直接等于创新强度。

## 2. 六个推荐候选创新

| 类别 | 推荐候选创新 | 核心未解问题 | 最小可行验证 |
|---|---|---|---|
| 1 | **反事实置信区间驱动的跨硬件 Pass 信用分配** | 整条 Pass 序列变快，不能说明每个 Pass 都有贡献，更不能说明其贡献可迁移 | 对短序列执行删除/交换反事实，在多个平台估计 Pass 贡献和置信区间 |
| 2 | **可执行证据契约驱动的反证式编译优化智能体** | Agent 的优化解释可能与 IR、汇编或真实性能不一致，偶然加速还可能污染记忆 | Agent 先声明前提、动作、预期证据和否定条件，再由工具逐项验收 |
| 3 | **语义证书—盈利证书解耦的条件化优化规则生成** | “语义正确”和“在当前条件下值得应用”是两个不同命题 | 为规则分别生成可重放语义证书和硬件条件化盈利证书 |
| 4 | **VLEN 参数化反例驱动的 RVV 迁移验证与性能悬崖定位** | 单板卡、单 VLEN 测试不能暴露尾部、掩码和有效 `vl` 缺陷 | 改变 VLEN/SEW/LMUL/长度/对齐/掩码，缩减正确性反例并定位性能悬崖 |
| 5 | **配置状态显式化的 RVV 多层后端** | `vsetvli` 状态与寄存器压力被局部分阶段处理，导致全局次优 | 在受限 MLIR/机器 IR 原型中显式表达配置状态并对比局部插入 |
| 6 | **硬件响应指纹—变换效应因子化的可拒绝低样本跨硬件调优** | 规格相近不等于优化响应相近，强制迁移会负迁移 | 用小型响应指纹选择/拒绝经验，以有限目标测量校准动作 |

## 3. 横向创新碰撞审查

| 交叉点 | 容易发生的概念撞车 | 本轮划界 |
|---|---|---|
| 类别 1 与类别 2 | 都可能让学习器选择 Pass 或 Transform | 类别 1 研究 Pass 级因果归因；类别 2 研究 Agent 的证据契约和反证闭环 |
| 类别 2 与类别 3 | 都要求正确性和性能证据 | 类别 2 约束 Agent 的行为与记忆；类别 3 约束可部署规则的两类证书 |
| 类别 2 与类别 6 | 都可能跨硬件反馈 | 类别 2 是 LLM Agent 主线；类别 6 的指纹/拒绝机制降为 Agent 的硬件反馈组件 |
| 类别 3 与类别 4 | 都使用反例 | 类别 3 收紧规则前提；类别 4 覆盖 VLEN、尾部和掩码配置空间 |
| 类别 4 与类别 5 | 都围绕 RVV 配置语义 | 类别 4 是实验压力测试；类别 5 是可选的后端扩展 |

### 3.1 与近年文献的碰撞风险

- 类别二不能只写成“让 LLM 通过编译器反馈反复修改代码”，因为编译反馈、执行反馈、反思和多智能体工作已经很多；真正需要验证的是**机器可解析的证据契约、主动反证、失败诊断和记忆门控**。
- 类别三不能只写成等价验证或规则数据库；必须保持语义证书和盈利证书的独立生命周期。
- 类别六不能重新夺走主线；它只作为 Agent 的硬件观察与迁移拒绝组件，且必须与 Agent 的候选生成和证据验收闭环连接。
- 类别四、五主要是实验平台或可选扩展，不应把论文标题收窄为 RISC-V 编译器论文。

| 4 | VLEN 参数化反例驱动的 RVV 迁移验证与性能悬崖定位 | 4 | 4 | 5 | 5 | 2 | 3 | 5 | **28** |

## 5. 最终主线选择

【候选主线】**可执行证据契约驱动的硬件感知 LLM 编译优化智能体**。

主线要回答的问题是：

> LLM Agent 能否在受限编译和性能测量预算下，提出结构化编译变换，主动寻找能推翻自身解释的证据，并只把“机制与收益同时成立”的优化经验迁移到新的程序和硬件？

主线保留四个核心机制：

1. **结构化候选生成**：Agent 输出受限的 MLIR Transform、Pass 序列或编译参数，而不是任意自然语言改代码。
2. **可执行证据契约**：每个候选都带有前提、动作、预期 IR/汇编证据、性能目标、正确性条件和否定条件。
3. **反证式工具反馈**：确定性工具主动执行对照、编译报告、汇编检查、正确性测试和真实性能测量；失败原因驱动下一轮搜索。
4. **硬件感知记忆门控**：硬件响应指纹用于判断经验是否可迁移、需要补测还是必须拒绝，但不改变主线的通用 LLM Agent 定位。

## 6. 主线的最小边界

- **只选一种动作空间**：建议首版使用 MLIR Transform 脚本参数或受限 LLVM Pass 序列，不同时覆盖任意源代码重写。
- **只选一类程序**：20—30 个向量/内存密集型 kernel，固定输入族并保留未见测试集。
- **平台是实验变量，不是理论限定**：可选择 x86、ARM、GPU 和 RISC-V/RVV 中的 2—3 个平台；RISC-V 最多作为其中一个平台。
- **严格限制 Agent 工具预算**：例如每个任务 20、50、100 次候选编译/运行，报告搜索成本。
- **正确性先于性能**：编译、运行、差分测试和数值容差全部通过后才计算性能收益。
- **允许失败结论**：如果 Agent 不能从证据中学到可迁移机制，应报告失败诊断和适用边界，而不是只保留成功案例。

## 7. 六类候选在主线中的位置

| 类别 | 在主线中的角色 | 是否为 MVP 必需 |
|---|---|---|
| 1 Pass 信用分配 | 作为更细粒度的因果归因器，帮助 Agent 判断哪一步真正有效 | 否，第二阶段扩展 |
| 2 反证式智能体 | 主线核心：候选生成、证据契约、反证和记忆门控 | **是** |
| 3 双证书规则 | 作为规则部署前的语义/盈利审计层 | 可选增强 |
| 4 VLEN 反例验证 | 作为跨平台实验中的边界压力测试 | 可选平台增强 |
| 5 RVV 状态化后端 | 作为未来特定后端动作空间 | 否 |
| 6 指纹与效应因子化 | 作为硬件反馈、教师路由和负迁移拒绝组件 | 建议加入，但不单独占据主线 |
