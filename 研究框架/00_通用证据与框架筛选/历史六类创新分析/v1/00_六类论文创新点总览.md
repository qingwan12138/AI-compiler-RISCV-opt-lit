# 六类论文创新点总览——基于 103 篇逐篇阅读笔记的独立重审

> 审阅原则：DeepSeek 改写的逐篇笔记用于提取事实和检索线索，不继承其创新结论；每类先独立寻找研究空白，再做横向比较。
> 覆盖范围：01–06 六类共 103 篇阅读笔记。
> 分析日期：2026-07-15。
> 当前状态：候选研究方向，不等同于已完成全球查新或已被实验证明的创新。

## 1. 总结先行

六类最终不应被写成六个相似的“跨架构迁移模块”。独立重审后，六个方向分别回答六个不同问题：

| 类别 | 推荐主创新 | 它真正回答的问题 | 当前推荐级别 |
|---|---|---|---|
| 01 Pass 调优 | 反事实删减驱动的序列因果归因 | 一个好 Pass 序列究竟为什么好？ | A- |
| 02 编译智能体 | 优化意图的逐层落地审计 | LLM 声称的优化是否真的在 IR、机器码和运行层发生？ | A |
| 03 规则生成 | 性能反例驱动的规则适用域细化 | 语义正确的规则在什么条件下才值得应用？ | A- |
| 04 跨 ISA 向量迁移 | 固定宽度 SIMD 到 VLA 的语义契约恢复 | 固定 lane 程序如何在不同 VLEN 下仍正确？ | A |
| 05 RVV 后端 | 反事实微基准到代价模型补丁闭环 | 如何把 RVV 负优化变成可审查的 LLVM 修补？ | A+ |
| 06 多硬件代价模型 | 可拒绝的硬件条件代价模型 | 什么时候跨硬件预测不可信，系统应停止自动决定？ | B+ / 高风险 |

最值得优先投入的是 05。它的问题具体、真实硬件证据明确、输出能落到 LLVM TTI/调度模型和回归测试，最容易形成“问题—方法—补丁—真实收益”的完整论文链。

02 和 04 是第二梯队：02 适用面广，能纠正 LLM 编译研究把“说到”误当“做到”的评估缺陷；04 直接切中 RVV 的 VLA 本质，研究辨识度高。

06 不是不能做，而是近邻工作最多。只有把核心改成负迁移检测、校准不确定性和拒绝决策，才有继续查新的价值。

## 2. 本次重审纠正的关键问题

### 2.1 不能再把跨硬件少样本迁移本身当空白

Moses、MTL-TLP、CDMPP、MetaTune 以及 2026 年的 TCL 已经直接研究跨设备迁移、少量目标数据和持续适配。类别 06 因此改成“可拒绝迁移”，重点从平均迁移效果转到最坏错误和负迁移风险。

主要近邻：

- [Moses](https://arxiv.org/abs/2201.05752)
- [MTL-TLP](https://arxiv.org/abs/2211.03578)
- [CDMPP](https://arxiv.org/abs/2311.09690)
- [MetaTune](https://arxiv.org/abs/2102.04199)
- [TCL](https://arxiv.org/abs/2604.12891)

### 2.2 不能再把平台无关向量 IR 当新想法

[MLIR Vector dialect](https://mlir.llvm.org/docs/Dialects/Vector/)已经提供机器无关、可重定向且支持 scalable vector 的抽象；[LLVM RVV](https://llvm.org/docs/RISCV/RISCVVectorExtension.html)也使用 scalable vector 类型。因此类别 04 改为“固定宽度 SIMD 中隐含的 VLA 语义契约如何恢复和验证”。

### 2.3 不能再把“形式证明 + 收益检查”当首次组合

Alive/Souper/Minotaur 已逐步连接合成、验证和成本；[LPG](https://arxiv.org/abs/2603.18477)更直接组合语法检查、语义验证和 profitability checking。因此类别 03 的创新只能落在“性能反例如何自动收紧规则适用条件”。

### 2.4 不能把 QEMU 当真实性能标尺

[QEMU 官方文档](https://www.qemu.org/docs/master/system/invocation.html)说明其不是 cycle-accurate 仿真器，指令计数通常也不能代表真实运行性能。因此 QEMU 仅用于功能、兼容性、多配置覆盖和静态信息；类别 04、05、06 的真实性能结论必须来自实机或经严格验证的专用性能模拟器。

### 2.5 不能笼统写“现有 LLM 编译器都只在 x86”

[Meta LLM Compiler](https://arxiv.org/abs/2407.02524)覆盖 x86-64 和 ARM。更准确的空白不是“从未跨 ISA”，而是意图、IR 变化、后端实现和实际收益之间缺少可审计的一致性证据。

### 2.6 Ithemal 不是跨 ISA 证据

[Ithemal](https://proceedings.mlr.press/v97/mendis19a.html)研究的是 x86-64 基本块在不同 x86 微架构上的吞吐预测，不能写成 x86、ARM、RISC-V 之间的跨 ISA 性能模型。

## 3. 六类方向的独立判断

### 3.1 类别一：反事实 Pass 归因

核心不是再发明一个搜索器，而是在已发现序列上做删除、替换和交换干预，为每一步建立带测量置信度的边际贡献，并据此调整下一轮搜索预算。

最小论文贡献：

- 反事实编译干预协议；
- Pass 交互图与归因稳定性指标；
- 在相同真实测量预算下减少搜索次数。

主要风险：反事实成本可能过高，Pass 贡献可能被噪声淹没；Booster Pass Chain 原文需补齐以排除撞题。

### 3.2 类别二：意图逐层落地审计

把一次 LLM 优化拆成三类成功：语义合法、意图实现、性能获益。要求 LLM 先输出结构化意图契约，再用 IR diff、optimization remarks、MIR/汇编和真实测量逐层核对。

最小论文贡献：

- 可执行的意图契约；
- `valid_and_realized / valid_but_erased / valid_but_counterproductive` 等落地标签；
- 审计反馈减少无效重试并提高自述忠实度。

主要风险：部分高层意图难以用确定性分析自动判定。

### 3.3 类别三：规则效益适用域

形式证明只说明“能做”，不能说明“值得做”。对语义正确但性能变差的反例做最小化，学习带目标和上下文条件的 profitability guard，并允许系统在未知条件下拒绝应用规则。

最小论文贡献：

- 规则语义契约与性能证据分层；
- 性能反例最小化；
- 守卫条件自动细化；
- 降低负优化率但不过度牺牲正优化召回。

主要风险：收益翻转可能依赖难以观察的微架构状态。

### 3.4 类别四：VLA 语义契约恢复

使用现有 MLIR/LLVM 向量抽象作为底座，从 NEON/SSE/AVX 代码恢复 lane、mask、tail、VL、reduction 和 memory contract，在多个 VLEN 下差分验证，并把最小失败样本反馈到具体契约字段。

最小论文贡献：

- 固定宽度到 VLA 的契约模式；
- 多 VLEN 隐蔽错误 benchmark；
- 契约级反例定位和修正；
- 相比直接 LLM/规则翻译提高未见 VLEN 正确率。

主要风险：shuffle 和浮点 reduction 的精确语义复杂，形式验证覆盖有限。

### 3.5 类别五：RVV 代价模型修补闭环

从一个 RVV 负优化出发，自动生成只改变一项后端决策的 A/B 微基准，在真实硬件测量后定位成本排序错误，生成带适用范围、置信区间和回归测试的 TTI/调度参数修补。

最小论文贡献：

- 单因素反事实微基准生成；
- 从硬件反例到 LLVM cost model patch 的自动链路；
- 在未见应用上减少负优化；
- 补丁跨 CPU 回归边界。

主要风险：没有真实 RVV 硬件就无法完成核心结论；微基准与完整程序效应可能不一致。

### 3.6 类别六：可拒绝跨硬件代价模型

模型同时输出排序、校准不确定性和负迁移风险。对低风险样本自动决定，对高风险样本拒绝并主动选择少量目标硬件测量。

最小论文贡献：

- 负迁移检测；
- selective prediction / abstention；
- 面向 top-k regret 而非平均回归误差的评测；
- 在同等测量预算下降低最坏负优化。

主要风险：相关研究更新快，必须专项查新；拒绝过多会让系统失去实用性。

## 5. 推荐推进顺序

### 第一优先：05 RVV 代价模型修补闭环

先确认真实 RVV 硬件、编译器版本、可用性能计数器和三类目标盲区。它最接近一个能被 LLVM 社区复核的成果。

### 第二优先：02 意图落地审计

可以先在现有 x86 环境完成，不被 RVV 硬件阻塞。若效果成立，再把 RVV lowering 当作高价值案例。

### 第三优先：04 VLA 语义契约

先扩展 VecIntrinBench 的多 VLEN 和 tail/mask/shuffle 测试，再实现契约恢复。不要先造新 IR。

### 第四优先：03 或 01

- 若更偏编译器规则和形式方法，选 03；
- 若更偏强化学习、搜索与分析，选 01。

### 暂缓大规模实现：06

先检索 selective prediction、abstention、negative transfer、OOD detection 与 compiler cost model 的交叉工作，确认空白后再做多硬件数据采集。

## 6. 六类共同的实验纪律

1. **正确性与性能分开。** 编译成功不等于语义正确，语义正确不等于性能更好。
2. **代理指标与真实指标分开。** IR 指令数、代码尺寸、QEMU 指令计数只能作为筛选或辅助证据。
3. **真实硬件重复测量。** 采用随机交错、热身、环境固定、置信区间，并公开异常值处理方式。
4. **明确验证覆盖。** Alive2 的 `inconclusive` 不等于错误，bounded verification 也不等于所有输入上的完整证明。
5. **报告负结果。** 负优化、拒绝、超时、无法验证都应单列，而不是从成功率分母中删除。
6. **版本可复现。** 记录 LLVM/GCC、目标特性、CPU、VLEN、编译选项、频率与运行环境。
7. **设置证伪条件。** 每个方向都已经在对应文件中给出停止或降级标准。

## 8. 下一轮工作建议

1. 为 05 建立真实 RVV 硬件与 LLVM 版本清单，选择 predication、stride、LMUL 三个起始问题；
2. 为 02 定义 4 类可被确定性工具检测的意图及标注协议；
3. 为 04 扩展多 VLEN 隐蔽错误用例；
