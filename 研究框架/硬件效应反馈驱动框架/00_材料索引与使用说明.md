# 硬件效应反馈驱动的可验证 LLM 编译优化智能体

## 1. 文件夹定位

这是独立于此前材料的研究文件夹，主线名称为：

**硬件效应反馈驱动的可验证 LLM 编译优化智能体**

核心问题不是“把 LLM 换到某个 ISA”，而是研究硬件反馈如何改变 LLM Agent 的候选生成、证据判断和知识迁移。RISC-V/RVV 只作为实验平台之一。

## 2. 材料清单

| 文件 | 用途 |

| 02_LLM智能体与证据契约材料.md | 2024—2026 年 LLM 编译优化文献证据 |
| 03_硬件效应反馈与选择性迁移材料.md | 硬件响应摘要、低样本迁移和拒绝机制 |

## 3. 推荐执行顺序

1. 先读 01_硬件感知LLM智能体主线框架.md。
2. 再读 02 和 03 材料，明确 LLM 机制与硬件反馈的分工。
3. 按 06_硬件感知预实验Demo.md 先在本机 GCC 上运行弱替代实验。
4. 有真实第二平台后，重新执行同一契约和测量流程。
5. RISC-V/RVV 可以作为一个实验平台，但不能成为论文标题或唯一实验依据。

## 4. 核心边界

- 单纯增加硬件 ID、-march 参数或一个硬件 embedding 不是创新。
- 硬件反馈必须改变候选路由、补测或拒绝决策，并能通过消融验证。
- 单机的 -march=x86-64 与 -march=native 只能验证“硬件条件输入”的流程，不能冒充真实跨硬件泛化。
- 任何性能收益都必须通过正确性、编译证据和重复测量门控。
