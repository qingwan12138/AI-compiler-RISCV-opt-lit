# 硬件效应反馈驱动的可验证 LLM 编译优化智能体

## 1. 最终定位

【候选主线】**硬件效应反馈驱动的可验证 LLM 编译优化智能体**。

它让 LLM Agent 不只看程序的中间表示（Intermediate Representation，编译器内部的程序表示）来猜优化，而是同时读取硬件响应和后端证据，提出带硬件条件的优化候选，并决定经验应该迁移、补测还是拒绝。

RISC-V/RVV 不是研究对象限定，只是可选实验平台。主线应能在 x86、ARM、GPU 和 RISC-V/RVV 中至少两个平台上复现同一协议。

## 2. 单一研究问题

> 在有限编译和性能测量预算下，硬件效应反馈能否让 LLM Agent 生成更少错误、更少负迁移、证据更一致的编译优化候选？

这里的“硬件效应”不是硬件型号或规格表，而是对向量、缓存、stride、分支、访存和 predication 等模式的实测响应摘要。

## 3. 现有问题与研究空白

现有 LLM 编译优化工作已经能够：

1. 根据 IR、编译器反馈或运行结果提出代码修改；
2. 通过多轮搜索修复编译错误；
3. 在部分 kernel 或平台上得到性能提升；
4. 使用多智能体、强化学习或执行反馈扩大候选搜索。

但仍然容易出现：

1. Agent 解释的优化意图没有在 IR 或机器指令中实现；
2. 同一个优化在不同硬件上收益方向相反；
3. 性能偶然变好但机制证据不成立；
4. Agent 只知道成功或失败，不知道失败的具体原因；
5. 没有明确决定何时迁移历史经验，何时补测，何时拒绝。

【候选研究空白】是把硬件效应反馈直接接入 Agent 的证据契约和记忆门控，使硬件信息改变候选决策，而不是只作为 prompt 中的一段背景文字。

## 4. 核心创新机制

### 4.1 硬件响应摘要

对平台 h 的一组 microbenchmark 记录归一化响应：

<code>phi(h) = Normalize([vector, cache, stride, branch, predication, reduction])</code>

它不是静态硬件 ID，而是“这块硬件对不同优化模式真实怎么反应”的可测摘要。

### 4.2 硬件条件化证据契约

Agent 的每个候选都必须包含：

| 字段 | 作用 |
|---|---|
| 程序前提 | 循环依赖、输入形状、别名、对齐 |
| 硬件前提 | 向量宽度、缓存/stride 模式、目标编译配置 |
| 动作 | Transform、Pass 或参数 |
| 预期 IR 证据 | 预期循环、向量和内存操作变化 |
| 预期后端证据 | 汇编类别、编译报告或指令计数变化 |
| 性能假设 | 哪个瓶颈应该改善 |
| 否定条件 | 哪个反例会推翻该候选 |
| 决策 | 迁移、补测、拒绝或接受 |

### 4.3 迁移、补测和拒绝

对源平台 s 的历史候选转移到目标平台 t 时，系统计算：

<code>score = similarity(phi(s), phi(t)) - uncertainty - negative_transfer_risk</code>

- score 高：允许迁移候选；
- score 中等：在目标平台主动补测；
- score 低：拒绝迁移，改为目标平台搜索。

这个分数只是一个最小路由器，不应被包装成完整的微架构理论。

### 4.4 反证式反馈

工具链返回的不只是一个 reward：

- 编译失败：返回失败阶段和 IR 位置；
- 预期 IR 或汇编没有出现：标记“意图未实现”；
- 正确性失败：缩减输入并返回反例；
- 性能不稳定：要求重复测量；
- 性能变好但证据不匹配：禁止写入已验证记忆；
- 硬件响应不相似：触发补测或拒绝。

### 4.5 记忆门控

只有满足以下条件，候选才进入可迁移记忆：

1. 编译成功；
2. 参考实现差分通过；
3. 关键 IR/后端证据出现；
4. 多次性能测量稳定；
5. 硬件条件和适用程序被记录；
6. 没有被预注册的否定条件推翻。

## 5. 系统数据流

~~~text
程序/IR + 硬件响应摘要
          ↓
LLM Agent 生成结构化候选
          ↓
生成硬件条件化证据契约
          ↓
编译器、汇编、正确性、性能工具执行
          ↓
证据裁决器：接受 / 修订 / 迁移 / 补测 / 拒绝
          ↓
失败诊断返回 Agent；通过候选写入门控记忆
~~~

## 6. 最小可行范围

| 项目 | 首版范围 |
|---|---|
| Agent 输出 | 受限 MLIR Transform、LLVM Pass 序列或编译参数 |
| 程序 | 20—30 个向量/内存密集 kernel |
| 平台 | 2—3 个平台；RISC-V 可作为其中一个 |
| 硬件摘要 | 30—100 个短 microbenchmark 响应 |
| Agent 预算 | 每任务 20、50、100 次候选编译/运行 |
| 输出 | 候选、契约、后端证据、决策、失败原因和记忆状态 |

首版不同时做任意 C/C++ 仓库重写、多智能体辩论、新 RVV 后端和完整强化学习。

## 7. 研究问题与假设

### RQ1：硬件效应反馈是否改变候选质量？

H1：加入硬件响应摘要后，目标平台上的候选排序 regret 和负迁移率低于无硬件反馈版本。

### RQ2：硬件条件化契约是否提高证据一致性？

H2：完整 Agent 在“预期 IR/后端证据实际出现”的比例上高于不含硬件条件字段的 Agent。

### RQ3：迁移/补测/拒绝是否优于强制迁移？

H3：选择性路由在相同目标测量预算下减少负迁移，并保持不低于 target-only 的中位性能。

### RQ4：反证和记忆门控是否减少无效搜索？

H4：完整闭环达到固定性能阈值所需的 Agent 调用数和编译测量数更少。

## 8. 基线与消融

### 基线

1. 编译器默认优化；
2. 无 Agent 的随机或贝叶斯调优；
3. Direct-LLM：无契约直接生成代码；
4. Contract-LLM：有契约但无硬件反馈；
5. 硬件感知 Agent：有硬件反馈但强制迁移；
6. 高预算 target-only 搜索；
7. 最近邻的编译器反馈式 Agent 方法。

### 消融

| 消融 | 检验内容 |
|---|---|
| 去掉硬件响应摘要 | 硬件反馈是否真正有用 |
| 用硬件 ID 替换响应摘要 | 实测效应是否优于标签 |
| 去掉硬件前提字段 | 条件化契约是否有作用 |
| 去掉迁移/补测/拒绝 | 选择性路由是否减少负迁移 |
| 去掉反证字段 | 失败诊断是否改变下一轮动作 |
| 去掉记忆门控 | 偶然成功是否污染后续搜索 |
| 缩小目标测量预算 | 方法是否保留低样本价值 |

## 9. 评价指标

- 编译成功率：衡量候选能否被工具链接受；
- 正确性通过率：衡量是否保持程序语义；
- 证据一致性：预期 IR/后端证据实际出现的比例；
- 负迁移率：迁移后比目标默认配置更慢的比例；
- route accuracy：迁移、补测、拒绝与 oracle 决策的一致程度；
- speedup 和 regret：衡量真实性能和距离高预算上界的差距；
- Agent 调用数和编译测量数：衡量搜索成本；
- 记忆污染率：错误解释或不稳定结果进入记忆的比例；
- 跨平台中位收益：检查是否依赖单一平台。

所有运行时间都要预热、多次重复、报告中位数、离散程度和置信区间。

## 10. 实验平台边界

第一阶段可在 GCC/x86 上完成工具闭环；第二阶段加入真实的第二平台。RISC-V/RVV 可以承担：

- 一个真实后端平台；
- VLEN、尾部和掩码压力测试；
- 迁移拒绝和负迁移案例。

但论文主问题应保持为跨平台的硬件感知 LLM Agent，不写成 RVV 专用方法。

单机的 <code>-march=x86-64</code> 与 <code>-march=native</code> 只能模拟不同编译目标配置，不能等价替代真实多硬件泛化。

## 11. 风险与降级

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 硬件摘要不能预测收益 | 硬件模块贡献不足 | 回退到目标实测，主线保留证据契约 Agent |
| Agent 只是增加搜索次数 | 创新被认为是工程组合 | 固定调用预算，报告每次调用和测量成本 |
| 契约字段难以自动检查 | 机制不可复现 | 首版只保留 IR、正确性、性能三类硬门 |
| 真实第二平台不可用 | 无法证明跨平台 | 明确写成单平台闭环，后续再补平台 |
| 迁移拒绝过于保守 | 退化为 target-only | 报告 coverage-risk 曲线，按变换族局部迁移 |
| 近邻工作已覆盖完整机制 | 新颖性下降 | 收窄到硬件效应字段、拒绝策略或特定动作空间 |

## 12. 可证伪条件

以下结果会直接削弱主线：

1. 去掉硬件反馈后结果完全相同；
2. 强制迁移与选择性路由的负迁移率没有差异；
3. 证据契约不改变 Agent 的搜索效率或证据一致性；
4. 结果只在一个 kernel、一个模型或一个平台成立；
5. 加入硬件摘要的采集成本超过节省的测量成本；
6. 正确性过滤后性能优势消失。

## 13. 预期贡献边界

候选贡献不是“用了 LLM + 硬件信息”，而是：

1. 一种可解析的硬件条件化证据契约；
2. 一种根据硬件效应和反证反馈进行迁移、补测或拒绝的 Agent 路由；
3. 一套在相同 Agent/测量预算下验证证据一致性、负迁移和搜索成本的实验协议。

语义证书、RVV 压力测试和后端状态化属于支撑或后续扩展，不进入首版核心贡献。
