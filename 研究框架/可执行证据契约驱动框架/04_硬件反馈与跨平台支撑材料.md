# 类别六：多硬件编译、代价模型与 IR 基础设施——候选创新点分析

> 文献数量：2024–2026 年独立条目 9
> 完整阅读数量：9 份新文献总结；旧文献边界条目 6
> 证据范围：本地逐篇阅读总结；旧文献用于 TVM/Ansor、学习型代价模型、Ithemal、ProGraML、MLIR 边界
> 分析日期：2026-07-16
> 证据充分程度：高（TCL 是直接碰撞基线，也清楚暴露数据规模、教师选择和负迁移空白）

## 1. 这一类在研究什么

结论：这类研究解决同一程序如何在 CPU、GPU、NPU、x86、ARM 和 RISC-V 等不同硬件上选择不同的布局、tile、融合、并行、特化和 kernel。IR 基础设施提供可组合动作，代价模型减少昂贵真机测量，跨硬件学习尝试复用旧平台经验。

2024–2026 年的工作已经覆盖 Transform Dialect、upstream MLIR 高性能流水、全局 kernel orchestration、LLM 自动并行化、Triton 生成评测、向量化/多线程/DMA 组合、运行时不变量特化，以及 TCL 的跨硬件持续学习。尤其 TCL 已经把主动采样、轻量 Mamba 代价模型、教师蒸馏和 EWC 组合起来，因此“持续学习 + 跨硬件代价模型”不能再直接作为创新。

剩余关键问题是：TCL 每个硬件仍从约 844–865 万记录中选约 10%，数据量巨大；同厂商硬件更容易迁移，教师选错会负迁移，CPU↔GPU 等跨类型迁移不足。现有方法通常用硬件 ID、静态规格或模型参数间接表达平台差异，缺少一份低成本、可复现、直接测得的“硬件响应指纹”来决定哪些历史知识值得迁移、哪些必须拒绝。

旧边界中，TVM 建立语义—调度分离和学习型成本；Learning to Optimize Tensor Programs 已使用迁移学习与不确定性探索；Ansor 已自动生成搜索空间并分配预算；Ithemal 已做基本块吞吐预测和微架构微调；ProGraML 已建立结构化程序图；MLIR 已提供多层 dialect 基础设施。因此，搜索、迁移学习、图表示、多层 IR 或不确定性采样都不能单独作为创新。

【论文事实】上述事实来自本地总结。TCL 是 2026 预印本，其具体数字仍应在论文写作前复现；本文件把它作为当前语料中的最强碰撞，而非已被独立验证的绝对上界。

## 3. 已有工作已经解决了什么

结论：动作表达、候选搜索、单硬件成本学习、全局组合和跨硬件持续适配都有成熟近邻；新的主张必须解释“为什么这个源硬件可迁移”，并在证据不足时拒绝迁移。

1. 【论文事实】Transform Dialect 已把可组合优化计划建模为受 handle 和契约约束的 IR，适合作为统一动作空间。
2. 【论文事实】TVM/Ansor、Korch 和 RVV MetaSchedule 已分别覆盖单 kernel schedule、全局 kernel 编排和真机搜索。
3. 【论文事实】TCL 已通过主动采样、Mamba 和持续蒸馏跨硬件迁移代价模型；“再换一个模型”难形成研究增量。
4. 【论文事实】RIFS 已将运行时剖析、可回退变换和 LightGBM 收益门控串联，证明动态证据可以安全进入 LLVM 优化。
5. 【论文事实】MLIR Latency Hiding 说明组合优化的收益高度依赖计算/传输/线程条件，必须逐层消融。
6. 【论文事实】TritonBench、OMPar 等再次证明编译通过、功能正确与性能提升必须分开评价。

## 4. 仍未解决的研究空白

结论：最强空白是用少量可移植微基准测出平台的响应指纹，并让跨硬件代价迁移具有“选择教师—拒绝教师—主动补测”的可校准决策。

### 空白 A：硬件相似性缺少实测响应定义

- 【论文事实】TCL 发现同厂商硬件更容易正迁移，源硬件选择错误会负迁移；论文主要用历史模型/数据完成持续适配。
- 【论文事实】Closer in the Gap 强调 RVV PMU 需先校准，predication/stride/LMUL 的真实性能与静态假设偏离；RIFS 也未验证其所谓可移植特征跨 ISA 有效。
- 【合理推导】型号、ISA、核心数或缓存容量相近，不等于对某类编译变换的性能响应相近。应以一组受控 microbenchmark 的归一化响应定义任务相关相似性。
- 证据充分度：高。

### 空白 B：代价模型没有显式分解“共享变换效应”和“硬件交互效应”

- 【论文事实】TCL 的代价模型预测候选排序，CKD/EWC 保存旧知识；Ithemal/ProGraML 等旧工作也多直接从程序表示预测成本。
- 【合理推导】直接预测绝对延迟容易把程序规模、平台速度和变换收益混在一起；预测相对基线的变换效应，并显式加入硬件响应交互，更适合跨硬件迁移和解释。
- 证据充分度：中高。

### 空白 C：跨硬件迁移缺少可审计拒绝和目标域回退

- 【论文事实】TCL 明确存在错误源硬件造成负迁移；RIFS 用守卫保留原函数路径，但不是跨硬件教师拒绝。
- 【合理推导】迁移系统应输出“使用哪个教师、为什么、置信度多大”；不满足校准阈值时自动退回目标域主动搜索。
- 证据充分度：高。

## 6. 最推荐的创新点

### 6.1 创新点名称

【候选创新】**硬件响应指纹—变换效应因子化的可拒绝低样本跨硬件调优**。

### 6.2 一句话解释

先用几十到几百个可复现微基准测出每块硬件“对向量、缓存、分支、stride、predication 等模式的真实反应”，再迁移相似硬件上的优化经验；如果指纹和少量目标测量表明不相似，系统明确拒绝教师并回到目标板主动搜索。

### 6.3 创新点命名拆解

- **硬件响应指纹**：不是厂商规格表，而是标准 microbenchmark 在该硬件上的归一化时间/吞吐/可用 PMU 响应。
- **变换效应因子化**：预测“某个优化相对基线带来多少变化”，并拆成跨硬件共享项与硬件交互项。
- **可拒绝**：迁移不是必选动作；教师不相似、模型不校准或置信区间跨零时可以拒绝。
- **低样本**：目标是数百至数千次目标测量，而不是 TCL 每硬件数十万条选中记录。
- **跨硬件调优**：动作可取 MLIR Transform script、RVV 微内核参数或受限 LLVM 配置；第一版只选一种。

### 6.4 文献依据

- 直接依据：TCL 证明多硬件历史数据和持续学习有价值，也明确暴露数据仍大、同厂商迁移更好、教师选择错误会负迁移。
- 硬件依据：Closer in the Gap 证明 RVV 静态成本会错，PMU 需先校准；RVV MetaSchedule 和 xDSL RVV 证明真机配置选择有实际收益。
- 动作依据：Transform Dialect 提供可检查、参数化的优化动作；RIFS 提供动态证据和安全回退的工程范式。
- 组合依据：Korch 和 MLIR Latency Hiding 说明融合边界、并行和搬运优化的收益随硬件与 workload 改变。
- 不能再声称的内容：不能声称“提出跨硬件持续学习”“首次主动采样成本模型”“首次知识蒸馏防遗忘”“首次多硬件真机调优”。
- 核心候选边界：**以实测响应而非硬件 ID 选择迁移源，并对相对变换效应进行共享—交互分解与拒绝式适配**。

### 6.5 已有工作与研究空白

现有跨硬件成本迁移常近似为：

```text
程序/调度表示 + hardware ID → 预测绝对延迟或排序
```

新方法改为：

```text
变换前后差异 ψ(program, action)
+ 实测硬件响应指纹 φ(hardware)
→ 预测相对性能效应 Δ
→ 迁移 / 拒绝 / 主动补测
```

【合理推导】“同一厂商”只是硬件相似性的粗代理。若两块板对 stride、mask、LMUL、cache working set 的响应相近，即使 ISA/厂商不同，也可能共享某类变换知识；反之，同 ISA 不同微架构也可能必须拒绝迁移。

### 6.6 核心机制

#### 1. 构建硬件响应指纹

设计 50–200 个小型 microbenchmark，覆盖：

- 标量/向量算术吞吐与依赖链延迟；
- contiguous/stride/gather/scatter 访存；
- working set 跨 L1/L2/内存边界；
- 分支、predication、mask 密度；
- RVV 的 VLEN/SEW/LMUL、`vsetvli` 和规约；
- 多线程扩展或 DMA 能力仅在硬件确实支持时加入。

指纹使用相对量而非绝对频率：

```text
φ_k(h) = log(T_pattern_k(h) / T_reference_k(h))
```

PMU 事件只在校准通过的平台内使用；跨 ISA 的公共核心是时间、吞吐和归一化曲线。

#### 2. 描述变换效应

对程序 `p` 和动作 `a`，从 Transform IR/前后 IR diff 提取：tile、布局、融合、向量化、unroll、LMUL、访存和 live-range 的变化 `ψ(p,a)`。预测相对收益：

```text
Δ(p,a,h) = log(T_base / T_after)
Δ = g_shared(ψ) + g_interact(ψ, φ(h)) + ε
```

`g_shared` 学习广泛可迁移的变换效应，`g_interact` 学习硬件响应与变换的交互，`ε` 表示测量噪声。

#### 3. 选择或拒绝教师

对目标硬件先测指纹和 20–50 个种子候选，计算每个源硬件的任务相关距离、历史校准误差和预测不确定性：

```text
score(source→target) = similarity(φ_s, φ_t)
                     - calibration_error
                     - uncertainty
```

只有 score 超阈值且目标种子上没有显著负迁移才选教师；否则使用目标域从零模型。多个教师可按变换类型路由，而不是全局选择一个教师。

#### 4. 主动补测与持续更新

优先测量“预计收益高、教师分歧大、置信区间跨零或能最大减少硬件交互不确定性”的候选。每轮更新目标 adapter/残差层，并监控旧硬件校准；无需保存或重放全部历史原始记录。

输出为三态：

1. **迁移**：教师相似且置信下界为正；
2. **目标补测**：可能有益但不确定；
3. **拒绝迁移**：种子反例或指纹距离表明风险高，退回目标搜索。

### 6.7 系统组成与数据流

```text
各硬件运行标准 microbenchmark
              ↓
校准并生成硬件响应指纹 φ(h)
              ↓
MLIR/LLVM/RVV 候选动作与前后 IR diff → ψ(p,a)
              ↓
源硬件相似度、历史误差与不确定性评估
              ↓
按变换类型选择教师 / 拒绝教师
              ↓
目标硬件少量种子测量
              ↓
共享效应 + 硬件交互残差模型
              ↓
主动选择高信息/高潜力候选
              ↓
真机编译、正确性、性能反馈
              ↓
迁移 / 补测 / 目标域回退，持续更新证据库
```

第一版建议只优化 RVV GEMM/Reduction 的 tile、unroll、LMUL 和微内核尺寸，或只优化 Linalg Transform script；不要同时覆盖 pass ordering、kernel orchestration 和函数特化。

### 6.8 小白化例子

源板 A 和目标板 B 都支持 RVV 256-bit，但 A 的 stride load 很快、B 很慢。只按 ISA/VLEN 选择教师会把“使用跨步向量加载”的策略迁到 B，导致退化。硬件响应指纹会在少量 stride microbenchmark 上显示两者差异，系统于是拒绝这类策略教师；但两块板的连续访存和矩阵乘响应相近，tile/LMUL 经验仍可迁移。拒绝是按变换类型进行的，不是把整块源硬件知识全部丢掉。

### 6.9 可检验的研究问题

1. 实测响应指纹是否比硬件 ID/静态规格更能预测跨硬件正迁移？
2. 共享—交互效应分解是否比直接混合多硬件数据具有更低目标 Regret 和更好校准？
3. 按变换类型选择教师是否优于全局选择单一教师？
4. 拒绝门控能否在保持测量样本效率的同时降低负迁移率和最坏退化？
5. 数百至数千次目标测量能否接近目标域独立大预算搜索的性能？

### 6.10 可验证假设

- H1：响应指纹距离与跨硬件变换收益排序相似度显著相关，并优于静态规格距离。
- H2：相对 TCL 式无选择持续适配或普通 fine-tune，教师路由 + 拒绝门控降低负迁移率。
- H3：相对直接预测绝对延迟，预测相对效应的共享—交互模型在未见硬件上具有更低 Regret/ECE。
- H4：主动补测比随机目标采样用更少运行达到相同目标性能。
- H5：删除拒绝机制后，平均性能可能相近，但最坏 10% 退化和错误教师使用显著增加。

### 6.11 最小可行 Demo

- **目标**：在 3 个硬件域和 20–30 个 kernel/shape 上，以数百至数千次目标测量验证选择/拒绝教师。
- **硬件域**：优先两块不同 RVV 板 + 一台 x86；若只有一块 RVV，则使用两台 x86 微架构作源域，RVV 作跨 ISA 目标，具体设备需人工确认。
- **动作空间**：复用 xDSL RVV/MLIR Transform Dialect，限定 tile、unroll、向量化、LMUL 和微内核 `mr/nr`。
- **指纹**：先做约 100 个 microbenchmark，测量运行时间和经校准的可用 PMU。
- **数据预算**：每个源域 2,000–5,000 个历史候选；目标域种子 50 个，主动追加不超过 500–1,000 个。
- **模型**：首版使用 LightGBM/小 MLP/层级回归，不以 Mamba 或 LLM 为必要条件。
- **步骤**：建指纹→生成 Transform 候选→源域测量→目标种子→教师选择/拒绝→主动补测→目标测试集评测。
- **预计工作量**：2 周测量基础设施，2 周指纹与动作提取，2 周模型/主动采样，2 周全量实验。
- **成功标准**：相同目标预算下优于 target-only/random 和无拒绝迁移；优势在未见 kernel 上成立，不靠更多测量。

### 6.12 实验设计

#### 实验平台

所有平台记录 CPU/ISA、编译器 commit、频率、核心绑定、内核、运行库和环境温度。跨平台不比较绝对时间，比较相对基线效应和排序。PMU 先以已知 microbenchmark 校准，无法对齐的事件不强行共享。

#### 数据集

- Kernel：GEMM、Conv、Reduction、Softmax、elementwise 和少量非规则访问；
- Shape：规则训练 shape 与未见 BERT/MLP shape；
- 动作：Transform script 或 xDSL RVV 参数；
- 指纹 microbenchmark 与调优 kernel 分开，避免模型直接记住测试任务；
- 按 kernel 家族和硬件留一评测，避免近重复泄漏。

#### 对比基线

- target-only：只用相同目标测量预算训练；
- source-only：直接复用源模型；
- static-nearest：按 VLEN/缓存/核心数选择最近教师；
- fine-tune：选择一个源模型后普通微调；
- multi-task/continual：TCL 思路的简化可复现版本或论文代码（若可得）；
- no-reject：使用指纹但强制选择教师；
- target-exhaustive/大预算搜索：性能上限参照；
- 完整方法：指纹、效应分解、类型路由、拒绝和主动补测。

#### 消融实验

依次删除响应指纹、效应相对化、共享—交互分解、按类型教师路由、不确定性、拒绝门控和主动采样。指纹分别使用静态规格、时间曲线、时间+PMU，衡量增量。

#### 评价指标

- 目标硬件 best-found speedup、Regret@k 和达阈值所需测量数；
- 负迁移率、最坏 10% 退化和教师拒绝 precision/recall；
- 候选排序 pairwise accuracy、Spearman、Top-k recall；
- ECE/Brier/置信区间覆盖；
- 指纹距离与收益迁移相关性；
- 训练/推理/编译/运行总时间与存储；
- 旧硬件性能保持和持续加入新硬件后的遗忘。

#### 统计要求

每个候选性能重复至少 10–20 次，按平台噪声决定；报告中位数和 bootstrap 95% 置信区间。每种主动采样方法运行多个随机种子并画学习曲线。比较方法必须使用相同目标测量次数和相同候选池。

### 6.13 与已有工作的创新边界

- 与 TCL 的区别：TCL 从大规模历史记录中主动抽样并持续蒸馏；本方法用低成本实测指纹显式选择/拒绝教师，并分解相对变换效应与硬件交互，目标数据量小两个数量级。
- 与 Learning to Optimize Tensor Programs/Ansor 的区别：旧工作已有迁移学习和不确定性搜索；本方法研究任务相关硬件响应指纹、负迁移拒绝和跨 ISA 交互分解。
- 与 RIFS 的区别：RIFS 在单 x86 上选择带守卫函数特化；本方法面向跨硬件优化动作的教师路由和低样本适配。
- 与 Korch 的区别：Korch 用单 GPU 实测延迟做 BLP；本方法可为不同硬件提供候选成本/置信度，但不把 orchestration 本身当核心。
- 与 Transform Dialect 的区别：Transform IR 是结构化动作层；创新在于谁迁移、何时拒绝和怎样用真机响应校准。
- 与类别一的区别：类别一在 Pass 级做反事实跨硬件信用；本类别提供更通用的硬件表征、教师选择和跨动作低样本迁移框架。
- 直接复用的模块：MLIR/xDSL、Transform Dialect、LightGBM/小模型、主动学习、真机 microbenchmark。
- 核心创新候选：**实测响应指纹 + 相对效应因子化 + 按类型教师路由 + 可拒绝主动适配**。

### 6.14 风险与降级方案

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 在线检索发现硬件指纹教师路由已有完整实现 | 新颖性下降 | 收窄到 RVV PMU/VLEN 指纹或变换类型级拒绝；先补近邻检索 |
| 只有两块硬件 | 教师选择证据不足 | 做 leave-one-platform-out 不足时，明确定位为二域迁移；不夸大多硬件泛化 |
| 指纹 microbenchmark 与真实 kernel 相关性低 | 无法预测迁移 | 按变换族扩展指纹；报告相关性失败并回退目标域 |
| PMU 不可比或不可靠 | 指纹不稳定 | 核心使用归一化时间/吞吐曲线；PMU 只在校准通过时增加 |
| 源数据采集仍昂贵 | 失去低样本价值 | 复用已有 xDSL/TVM 记录；严格报告总测量成本和摊销场景 |
| 动作空间过大 | 模型数据需求上升 | 首版只做一种 IR 和 4–5 个参数，不同时做 Pass/编排/特化 |
| 拒绝过于保守 | 退化为 target-only | 评价 coverage-risk 曲线，允许按变换类型部分迁移 |
| 平台软件栈差异被当成硬件差异 | 指纹解释错误 | 固定编译器/库版本并做软件栈消融；必要时把软件版本纳入域描述 |
| TCL 代码不可复现 | 强基线缺失 | 实现其核心 baseline：RDU/普通持续微调/蒸馏；明确不声称完整复现 |
| 最终性能收益小 | 主张削弱 | 转向负迁移检测/测量节省的可靠结果，或收窄到 RIFS 跨 ISA 特化 |

### 6.15 可证伪条件

以下任一结果会否定或显著削弱候选创新：

1. 静态硬件规格或随机教师与响应指纹具有相同迁移效果；
2. 指纹距离与变换收益迁移没有稳定相关性；
3. 共享—交互效应模型不比直接混合数据或普通 fine-tune 更准；
4. 拒绝门控不能降低负迁移，或因过度拒绝使成本接近 target-only；
5. 主动补测不比随机采样节省目标测量；
6. 优势只存在于已见 kernel/shape，在未见家族或第三硬件上消失；
7. 达到相同最终性能仍需要 TCL 量级的数十万目标记录；
8. 所有收益来自更大的源数据或更多总运行次数，而非指纹、分解和拒绝机制。

### 6.16 综合评分

| 维度 | 1—5分 | 评分理由 |
|---|---:|---|
| 新颖性 | 5 | 在 TCL 直接碰撞上增加实测硬件表征、效应分解和可拒绝教师路由 |
| 文献证据 | 5 | TCL、Closer、Transform Dialect、RIFS、Korch 与旧代价模型形成完整证据链 |
| 可实现性 | 4 | 受限动作空间可用轻量模型完成，主要成本是真机测量基础设施 |
| 实验可验证性 | 5 | Regret、负迁移、拒绝准确、校准和测量预算均可量化 |
| 与 RISC-V 相关性 | 5 | 可用 RVV VLEN/LMUL/predication/stride 指纹形成目标域，且不局限单板调参 |
| 与总体主线兼容性 | 5 | 可统领 Pass、规则、RVV 迁移和后端配置的跨硬件知识边界 |
| 研究风险 | 3 | 最大风险是可用硬件数量、指纹相关性和 TCL 复现难度 |

结论：当前是六类中最适合作为**唯一主线框架**的候选。它的学术问题不是“再训练一个更强代价模型”，而是：如何用低成本、可审计的硬件响应证据决定优化知识是否可迁移，并在不确定时安全拒绝。其他类别的创新可以成为它的证据生成、动作表示、验证或 RVV 后端模块。
