# 可执行证据契约驱动的 LLM 编译优化智能体

## 1. 文件夹定位

本文件夹是当前主线的独立研究材料，不使用 `09` 编号。

主线名称：**可执行证据契约驱动的硬件感知 LLM 编译优化智能体**。

主线重点是 LLM Agent 如何提出结构化编译优化、声明预期证据、接受反证式工具反馈并管理可迁移记忆。RISC-V/RVV 只作为实验平台之一。

## 3. 推荐阅读和执行顺序

1. 先读 `01_主线研究框架.md`，确认研究对象不是 RISC-V 专用后端。
2. 再读 `02_LLM智能体与证据契约材料.md`，明确 Agent 主机制和近邻边界。
3. 按 `06_预实验Demo.md` 先运行单平台 GCC 版本。
4. 运行成功后，再把 Stub Agent 替换为你的 LLM/API。
5. 最后加入其他平台；RISC-V/RVV 作为其中一个可选平台。

## 4. 重要边界

- “用了 LLM”本身不是创新；可检验的证据契约、反证反馈和记忆门控才是候选核心。
- “换到 RISC-V 测试”本身不是创新；RISC-V 只提供外部平台实验。
- 预实验中的单个 kernel 结果只能证明工具链闭环可运行，不能证明跨程序或跨平台泛化。
