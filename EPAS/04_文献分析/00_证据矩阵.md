# 六类论文组创新提炼证据矩阵

> 用途：支撑六份候选创新点文档。本文中的“研究空白”是基于当前证据集合的文献内推论，不等于完成了全领域查新。
>
> 证据范围：35 个条目基于本地 PDF 全文与重点章节阅读；06、08、15、18、21、22、25、28、29 为来源受限条目，只作为线索或边界提醒，不承担关键结论的唯一证据。

## 1. 编译阶段排序与强化学习调优

| 代表来源 | 当前文献已覆盖 | 不能重复包装为创新 |
|---|---|---|
| [AutoPhase](https://arxiv.org/abs/2003.00671) | IR 特征表示、RL 搜索 Pass 顺序、HLS 周期反馈 | “使用 RL 搜索 Pass 序列” |
| [Compiler Phase-Ordering for HLS with DRL](https://arxiv.org/abs/1901.04615) | 面向 HLS 的深度强化学习 phase ordering | “把 phase ordering 写成 MDP” |
| [CompilerGym](https://arxiv.org/abs/2109.08267) | 标准化编译器交互环境、轨迹与验证接口 | “提供 Gym 风格编译环境” |
| [MileStone](https://arxiv.org/abs/2605.23435) | 图表示、强化学习、多目标 phase ordering | “多目标奖励”本身 |
| [AlphaDev](https://www.nature.com/articles/s41586-023-06004-9) | 用真实性能和正确性反馈发现低层算法 | “将 CPU 延迟作为奖励”本身 |

**共同边界（证据）**：这组工作主要回答“如何搜索”和“如何封装环境”，但大多在单一平台或单一任务上训练与评价；跨架构的 Pass 收益究竟由共享规律还是平台残差造成，并未被系统分解。

**可研究空白（推论）**：建立同一程序、同一 Pass 动作在多平台上的配对收益，显式学习共享效应与平台残差，并仅用少量新平台样本校准残差。

**来源限制**：Booster Pass Chain（06）只有来源页/元数据，不能作为算法细节的主证据。

## 2. LLM 编译优化智能体与反馈驱动

| 代表来源 | 当前文献已覆盖 | 不能重复包装为创新 |
|---|---|---|
| [Compiler-R1](https://arxiv.org/abs/2506.15701) | SFT+GRPO、工具交互、Pass 序列调优 | “LLM+RL+工具调用” |
| [Meta Large Language Model Compiler](https://arxiv.org/abs/2407.02524) | LLM 对编译任务的生成与优化能力 | “用 LLM 做编译优化” |
| [REASONINGCOMPILER](https://arxiv.org/abs/2506.01374) | 推理/搜索驱动的编译优化 | “显式推理后再优化” |
| [ACCLAIM](https://arxiv.org/abs/2604.04238) | 源码、IR、汇编多层 Agent 协作 | “多 Agent 或多层 Agent” |
| [IntOpt](https://arxiv.org/abs/2602.18511) | 显式分离 intent formulation、compiler-analysis-grounded refinement 与 concrete transformation realization | “显式优化意图”“意图—变换分离” |
| [Compiler Generated Feedback](https://arxiv.org/abs/2403.14714) | 编译器反馈改善 LLM 代码生成 | “把编译错误反馈给 LLM” |

**共同边界（证据）**：Agent、编译反馈、多层协作和 intent 都已有相邻工作。特别是 IntOpt 已将高层优化意图与低层分析、变换显式分离，因此不能再把“让 LLM 先表达 intent”作为主创新。当前组内工作尚未系统回答：同一 intent 在不同目标架构上采用不同实现时，哪些跨层效应应保持、需要新增多少架构知识，以及如何由实测结果识别知识的迁移边界。

**可研究空白（推论）**：把 intent 升级为带平台归一化观测的跨层效应契约；在正确性与后端合法性约束下，学习保持该效应所需的最小架构增量，并将效应实现误差作为后续特化和迁移边界判断的反馈。

**来源限制**：Foundation Language Models for Compiler Optimization（08）为来源受限条目；IntOpt 在清单中重复出现（16、45），证据计数不重复计算。

**可研究空白（推论）**：构造同时携带证明证书、验证边界、多平台收益分布和置信度的规则知识库，把安全性与平台盈利性分开决策。

**来源限制**：Verified Learning（15）和 Souper GitHub（18）为来源受限条目，关键论证以 Alive/Alive2、Souper 论文、STOKE、Minotaur、LPG 全文为主。

## 4. 向量化与跨 ISA 代码迁移

| 代表来源 | 当前文献已覆盖 | 不能重复包装为创新 |
|---|---|---|
| [LLM-Vectorizer](https://doi.org/10.1145/3696443.3708929) | LLM 向量化、验证和性能评测 | “LLM 生成向量代码+验证” |
| [IntrinTrans](https://arxiv.org/abs/2510.10119) | NEON→RVV intrinsic 翻译、多 Agent 编译测试闭环 | “多 Agent 完成 NEON→RVV” |
| [VecIntrinBench](https://arxiv.org/abs/2511.18867) | 向量 intrinsic 翻译/评测基准 | “建立 intrinsic 翻译测试集” |
| [neon2rvv](https://github.com/zzh-wisdom/neon2rvv) | 人工/规则化 NEON 到 RVV 兼容层 | “API 映射表” |

**共同边界（证据）**：已有工作能直接翻译 API、用 Agent 修复和验证，但固定宽度 SIMD 与 RVV 可变向量长度之间存在语义结构差异；逐 API 映射容易把源 ISA 的宽度假设带入目标实现。

**可研究空白（推论）**：设计与 ISA 无关的向量语义中间层，先恢复 lane、mask、内存模式、归约、饱和/舍入、向量长度依赖，再面向 RVV 或其他目标 ISA 降低。

**来源限制**：neon2rvv（28）是项目页而非论文全文，只用于工程基线与边界说明。

## 5. RISC-V / RVV 编译器与真实后端

| 代表来源 | 当前文献已覆盖 | 不能重复包装为创新 |
|---|---|---|
| [Closer in the Gap](https://arxiv.org/abs/2605.10860) | 多 RVV 环境真实性能、编译器与微架构差异 | “在 RISC-V 实机跑 benchmark” |
| [Tensor Program Optimization for RVV](https://arxiv.org/abs/2507.01457) | TVM/MetaSchedule 与 RVV intrinsic 的真实性能调优 | “将 TVM 调优移植到 RVV” |
| [RISC-V Vector C Intrinsic Specification](https://github.com/riscv-non-isa/rvv-intrinsic-doc) | RVV intrinsic 语义与接口规范 | “支持 RVV intrinsic” |

**共同边界（证据）**：RVV 的 predication、stride、LMUL、VLA 语义、spill 和工具链成熟度都会造成静态判断与真实运行不一致。现有工作主要测量或搜索，较少把“预测方向与硬件结果相反”的反例作为专门学习对象。

**可研究空白（推论）**：检测收益符号翻转或大残差样本，利用性能计数器/机器码特征诊断原因，并在线校正平台条件化代价模型。

**来源限制**：本组 21、22、25、29 均为来源受限，只有 23、24 具备完整 PDF；因此该候选点最需要后续补齐 RVV autovectorization、TSVC coverage、RVCC 和 intrinsic 规范相关原文/版本信息。

## 6. 多硬件编译、效应契约与架构特化

| 代表来源 | 当前文献已覆盖 | 不能重复包装为创新 |
|---|---|---|
| [QiMeng-GEMM](https://ojs.aaai.org/index.php/AAAI/article/view/34461) | 以平台无关 meta-prompt 描述 GEMM 通用优化原语，组合平台特定自然语言 hints/代码骨架，并在目标平台搜索优化组合 | “通用 prompt + 平台 hints”“用 LLM 在目标平台搜索 GEMM” |
| [TVM](https://www.usenix.org/conference/osdi18/presentation/chen) | 多硬件张量编译、设备 RPC、学习调优 | “多硬件自动调优” |
| [Learning to Optimize Tensor Programs](https://proceedings.neurips.cc/paper/2018/hash/8b5700012be65c9da25f49408d959ca0-Abstract.html) | 学习型代价模型与迁移 | “训练 cost model 排序候选” |
| [Ithemal](https://arxiv.org/abs/1808.07412) | 基本块吞吐量预测 | “用神经网络预测性能” |
| [ProGraML](https://arxiv.org/abs/2003.10536) | 图结构程序表示 | “用 GNN 表示 IR” |
| [MLIR](https://arxiv.org/abs/2002.11054) | 多级 IR 基础设施 | “增加一个中间表示层” |
| [Ansor](https://www.usenix.org/conference/osdi20/presentation/zheng) | 搜索空间、进化搜索与学习型代价模型 | “模型引导的搜索” |

**共同边界（证据）**：性能预测、模型引导搜索和多硬件支持已有成熟工作。QiMeng-GEMM 进一步证明平台无关优化描述可以与平台 hints 组合并实例化到目标平台；其第 7 页消融还显示，简单 block tiling 对 hints 不敏感，而 thread/warp tiling、Float4 vectorization 等平台相关实现明显依赖 hints。其边界是通用描述与 hints 主要由专家预定义、研究对象限于 GEMM、实验针对已配置提示库的平台开展搜索，未把通用描述转为可测量的跨层效应契约，也未以“保持效应所需的最小架构增量”发现知识边界。单纯双层 schema、共享模型、Adapter、平台 ID、pairwise ranking 或 RISC-V 实测不能单独构成创新。

**可研究空白（推论）**：为一般编译优化定义跨层效应契约，使用平台归一化的 IR—MIR/汇编—硬件观测计算效应实现误差，在正确性和合法性约束下只学习保持该效应所需的最小架构增量，并根据实现误差、适配成本和负迁移率自动识别通用、架构敏感与架构特有知识。候选排序只作为真实性能验证器和样本节省机制。

## 7. 综合边界与写作规则

- **文献事实**：只描述当前条目中已有的方法、实验和作者明确承认的局限。
- **研究推论**：由多篇文献共同边界导出的空白，统一使用“当前文献组尚未系统解决”“可进一步研究”等措辞。
- **候选方案**：六个方案均标注“候选创新，尚需针对性查新”，不使用“首次”“首个”等断言。
- **优先验证**：创新是否成立取决于专门消融和跨平台配对实验，而不是系统模块数量。
