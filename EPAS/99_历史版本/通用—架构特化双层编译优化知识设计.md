# 通用—架构特化双层编译优化知识设计

> 状态：经用户确认的研究方向设计稿，待用户审核书面规范后实施。  
> 日期：2026-07-13  
> 研究边界：候选创新，尚需针对性查新，不声称首次。  
> 参考启发：QiMeng-GEMM（AAAI 2025）第 3–4 页的方法框架及第 7 页的平台提示消融。

## 1. 调整结论

当前主线从：

> 面向多硬件平台的共享排序知识与架构残差候选排序

调整为：

> **通用—架构特化双层知识驱动的多硬件编译自适应。**

候选排序不再是研究的唯一核心，而是目标架构特化方案的验证与选择机制。研究重点转向：

1. 什么编译优化知识可以跨架构复用；
2. 同一通用优化意图如何在不同架构上形成不同实现；
3. 如何利用少量目标平台测量修正架构特化知识；
4. 如何证明通用知识确实被保留，而不是为每个平台重新训练独立模型。

## 2. QiMeng-GEMM 提供的证据与留下的空白

QiMeng-GEMM 将 GEMM 优化知识拆成三部分：

- 平台无关描述：tiling、reordering、vectorization、layout、pipeline；
- 平台特定提示：面向 RISC-V、NVIDIA GPU 等平台的自然语言说明和代码骨架；
- 实例化与搜索：将通用 meta-prompt 和平台提示组合，再在目标硬件上搜索高性能代码。

论文第 7 页消融表明，简单 block tiling 对平台提示不敏感，但 thread tiling、warp tiling、Float4 vectorization 等架构相关实现高度依赖平台特定提示。这支持“通用优化知识与架构实现知识需要分层”的研究动机。

但 QiMeng-GEMM 仍留下四个可继续研究的空白：

1. 通用知识和平台提示主要由专家预定义，没有系统学习它们的共享边界；
2. 研究对象仅限 GEMM，尚未覆盖一般 LLVM IR 优化或代码翻译候选；
3. 实验在已配置提示库的平台上搜索，没有把完整硬件平台留出后检验未见平台适应；
4. 没有显式验证哪些知识被复用、哪些知识在新平台上被重新学习。

因此，本研究不能简单复制“通用 prompt + 平台 hints”，而应把它升级为可执行、可学习、可验证的双层编译优化知识。

## 3. 备选方案与选择

### 方案 A：共享排序器 + 架构残差

直接学习：

$$
Q(P,c,h)=Q_{shared}(P,c)+Q_{arch}(P,c,h).
$$

优点是实现简单、实验清晰；缺点是“通用”和“特化”只体现在分数分解中，没有回答具体优化知识如何转换成不同架构实现。

### 方案 B：通用模板 + 人工平台提示库

按照 QiMeng-GEMM，为每类优化定义通用模板，再为 RISC-V、x86、ARM 等平台编写提示和代码骨架。

优点是可快速实现；缺点是与 QiMeng-GEMM 接近，且对人工知识库依赖较强，未见平台仍需人工补充提示。

### 方案 C：双层结构化知识 + 架构实例化 + 排序验证（采用）

将优化知识显式拆成：

- 跨架构通用优化知识；
- 目标架构特化知识；
- 从通用知识到具体实现的实例化机制；
- 对实例化候选进行真实性能验证的排序器。

该方案保留方案 A 的可执行性，又比方案 B 更强调自动适应和知识边界验证，因此作为当前正式设计。

## 4. 核心研究问题

### 主研究问题

> **如何将跨架构可复用的优化意图、适用条件与预期效应，同目标架构的实现约束和代码生成手段分离建模，使系统能够利用少量目标硬件反馈，将通用优化知识自动实例化为适合 RISC-V、x86、ARM 等平台的具体编译策略？**

### 子问题

1. 哪些优化意图和前置条件能够跨架构共享？
2. 同一优化意图在不同 ISA、微架构和编译器后端上应如何实例化？
3. 新平台需要多少真实性能测量才能形成有效的架构特化知识？
4. 双层知识模型是否比共享单模型、独立平台模型和静态提示库更少产生负迁移？

## 5. 双层编译优化知识表示

### 5.1 通用优化知识层

一个通用优化知识单元定义为：

$$
K_g^m=(I_m,Pre_m,E_m,Slots_m,Verify_m).
$$

其中：

- \(I_m\)：优化意图，例如改善局部性、降低访存、暴露向量化、增加 ILP、降低分支开销；
- \(Pre_m\)：适用条件，例如存在规则循环、别名关系可判定、归约模式可识别；
- \(E_m\)：架构无关的预期效应，例如减少内存流量或增加可并行操作；
- \(Slots_m\)：需要由目标架构填写的实现槽位，例如向量宽度、展开因子、数据布局和具体指令形式；
- \(Verify_m\)：正确性与效果验证条件。

通用层不直接绑定某个 ISA，也不把某条固定 Pass 序列误认为普遍规律。

### 5.2 架构特化知识层

目标平台 \(h\) 的特化知识表示为：

$$
S_h=(D_h,C_h,R_h,A_h).
$$

其中：

- \(D_h\)：平台描述，包括 ISA、扩展、向量能力、寄存器、Cache 和 ABI；
- \(C_h\)：后端约束和编译器能力，例如 LLVM 后端支持程度；
- \(R_h\)：通用意图在该平台上的实现规则；
- \(A_h\)：利用少量实测数据更新的轻量平台适配参数。

示例：

| 通用意图 | RISC-V 特化 | x86 特化 | GPU 特化 |
|---|---|---|---|
| 暴露向量化 | RVV 可伸缩向量、VL 设置、RVV intrinsic | AVX2/AVX-512 固定宽度向量 | SIMT 线程映射与 warp 级实现 |
| 改善局部性 | Cache tiling、packing | 多级 Cache tiling、预取 | global/shared/local memory 多级搬运 |
| 增加并行性 | 控制展开因子和寄存器压力 | SIMD + ILP + 展开 | block/thread/warp 分层并行 |

## 6. 通用知识到架构实现的实例化

对程序 \(P\)、通用知识单元 \(K_g^m\) 和目标平台特化知识 \(S_h\)，实例化器生成候选：

$$
\mathcal C_h(P)=\bigcup_m Instantiate(P,K_g^m,S_h).
$$

候选可以是：

- LLVM Pass 宏动作或 Pass 序列；
- 编译参数组合；
- IR rewrite；
- 架构相关 intrinsic；
- LLM 生成的目标架构代码实现。

实例化器必须先检查 \(Pre_m\)，再填写 \(Slots_m\)。不满足前置条件的知识单元不能被强行应用。

第一版不要求 LLM 自由生成所有实现。可以使用结构化模板和有限候选空间验证双层知识机制，后续再引入 LLM 生成和知识抽取。

## 7. 候选排序的支撑定位

原有共享—残差排序模型保留为后端评价器：

$$
Q(P,c,h)=Q_{shared}(P,c)+Q_{arch}(P,c,h).
$$

其职责变为：

1. 对实例化器产生的多个候选排序；
2. 用少量目标平台测量校准 \(Q_{arch}\)；
3. 选择 Top-k 候选进行真实运行；
4. 将成功或失败反馈写回 \(S_h\)。

因此，排序器是闭环中的性能验证和样本节省机制，不再单独承担“编译优化知识”的全部含义。pairwise ranking、Adapter 和少样本残差本身不作为主创新。

## 8. 新平台适应流程

```text
输入一个未见硬件平台
        ↓
读取 ISA、扩展、向量与后端静态信息
        ↓
初始化架构特化知识 S_new
        ↓
选择适用的通用优化知识 K_g
        ↓
实例化若干目标平台候选
        ↓
排序器选择 Top-k 真实测量
        ↓
更新 A_new、实现规则置信度和候选偏好
        ↓
在未见程序上生成并选择特化策略
```

校准预算继续采用：

$$
K\in\{0,5,10,20,50\}.
$$

适应时冻结通用知识主体，只更新平台特化层、轻量适配参数和候选评价残差。

## 9. 最小可行范围

为控制硕士阶段工作量，第一版限定为：

- 平台：x86 + RISC-V；增强版增加 ARM；
- 程序：20–40 个 PolyBench、MiBench 或 LLVM test-suite 子程序；
- 通用意图：6–8 类；
- 候选：现有 6 个编译配置，逐步扩展为 8–12 个 Pass 宏动作；
- 目标：运行时间；正确性和代码尺寸作为约束；
- 学习方式：监督式候选排序和轻量平台适应，不使用完整 RL；
- 不进入：性能世界模型、多步 rollout、双 LLM 训练、创新 05 的 RVV 反例主线。

现有 Mini Demo 继续作为统一编译、运行和数据采集骨架，不直接作为算法创新。

## 10. 实验设计

### 10.1 核心对比

1. 固定 `-O3`；
2. 每个平台独立优化；
3. 跨平台共享排序器；
4. QiMeng 式“通用模板 + 静态平台提示”；
5. 普通平台条件模型；
6. 双层知识但不使用目标平台反馈；
7. 完整双层知识 + 少样本特化 + 排序验证。

### 10.2 消融

- 去掉通用知识层；
- 去掉架构特化知识层；
- 将结构化知识替换为纯自然语言提示；
- 不检查适用条件；
- 不更新平台特化层；
- 全模型微调替代仅更新特化层；
- 排序器随机选择候选；
- 不同校准预算和平台组合。

### 10.3 指标

- 真实运行加速比；
- Top-k Recall、Regret@k、Speedup@K；
- 正确候选生成率；
- 架构特化成功率；
- 负迁移率；
- 新平台真实评测次数；
- 通用知识复用率；
- 同一通用意图在不同平台上的实现差异。

### 10.4 关键验证

实验必须能展示：

1. 同一通用意图在 RISC-V 与 x86 上产生不同实现；
2. 不同实现都可追溯到同一个通用知识单元；
3. 新平台适应只修改特化层，不破坏通用层；
4. 在完整留出目标平台时，少量测量仍能改善未见程序；
5. 结果优于静态提示库和单纯共享排序模型。

## 11. 与 QiMeng-GEMM 的创新边界

本研究不能声称“首次提出平台无关模板与平台特定提示”。QiMeng-GEMM 已经明确使用这一结构。

候选创新边界应表述为：

> **将一般编译优化知识表示为包含优化意图、适用条件、预期效应和架构实现槽位的结构化通用知识，并通过可学习的架构特化层和少量真实性能反馈，将其自动实例化为目标平台编译策略；同时以完整平台留出实验验证通用知识的复用边界和未见架构适应能力。**

该表述是否成立，仍需检索以下相邻方向：

- architecture-independent and architecture-specific compiler knowledge；
- compiler optimization intent representation；
- hardware-aware transformation templates；
- cross-architecture compiler adaptation；
- transferable compiler optimization rules；
- few-shot target-specific code generation；
- multi-level compiler knowledge representation。

## 12. 主要风险与降级方案

### 风险一：通用知识仍由人工定义

降级方案：第一版承认通用知识 schema 由专家初始化，但用跨平台数据学习适用性、实现选择和效果置信度；后续再增加从成功轨迹自动抽取知识。

### 风险二：与 QiMeng-GEMM 过于相似

降级方案：避免以 prompt 模板为核心，突出结构化知识、一般 LLVM 编译对象、未见平台留出和可学习特化层。

### 风险三：范围扩大为通用编译器

降级方案：第一版只选 6–8 个优化意图和 8–12 个 Pass 宏动作，不修改 LLVM 后端源码。

### 风险四：无法证明知识真正分层

降级方案：保存通用知识单元标识、实例化轨迹和特化参数；使用冻结实验、层级消融和跨平台实现差异分析。

### 风险五：目标平台太少

降级方案：两平台时只声称跨平台特化；至少三类平台并执行 leave-one-platform-out 后，才声称未见架构适应。

## 13. 与代码翻译方向的接口

代码翻译作为后续扩展：

```text
源程序或源 ISA 代码
    → 识别通用优化意图与语义约束
    → 根据目标架构特化知识生成多个翻译候选
    → 正确性验证
    → 目标平台排序与真实运行
```

这使“代码翻译”和“编译器优化”共享同一套双层知识，而不是分别构建两个无关系统。
