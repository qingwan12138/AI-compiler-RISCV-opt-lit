# EPAS 研究项目文件说明

## 当前研究定位

EPAS（Effect-Preserving Architecture Specialization）研究如何让同一条可复用编译知识在不同硬件架构上保持预期后端效应，并只学习目标平台所必需的最小架构增量。

当前主创新由三个相互约束的机制组成：

1. 跨层优化效应契约；
2. 效应保持的最小架构增量特化；
3. 编译知识迁移边界发现。

## 永久技术约束

本项目在任何研究阶段都不使用世界模型，不进行虚拟 Pass 执行、状态转移预测、imagined rollout 或合成硬件反馈。所有效应判断、架构特化和迁移结论必须以真实编译、真实后端分析和真实运行测量为依据。

允许使用 LLM 进行知识抽取和有限候选生成，也允许使用监督式候选排序与主动测量选择，但预测结果不能替代真实编译和硬件验证。

## 文件夹结构

- `01_核心研究框架`：EPAS 总体框架、主创新 06 和六类创新总览，建议优先阅读。
- `02_其余五类候选创新`：创新 01–05；其中 01/02/04 为主线支撑或扩展，05 不进入当前主线。
- `03_设计与实施计划`：EPAS 设计说明和文档重构实施计划。
- `04_文献分析`：44 个文献条目的逐篇笔记与综合研究方向分析。
- `05_旧Demo参考`：此前 CrossTune-RL Mini Demo，仅作为编译运行接口参考，不代表 EPAS 方法。
- `99_历史版本`：EPAS 收敛前的通用—架构特化双层知识方案，仅用于追溯，不作为当前框架。

## 文件存放规则

从 2026-07-13 起，所有新增 EPAS 相关交付物统一放入本桌面文件夹：

- 新研究文档放入 `01_核心研究框架` 或 `03_设计与实施计划`；
- 新 Demo 放入 `06_EPAS_Demo`；
- Demo 的真实运行结果、测试报告和哈希清单保存在 Demo 自身目录；
- 旧方案只进入 `99_历史版本`；
- 工作区副本只用于开发和验证，桌面 `EPAS` 是用户查看和继续研究的统一入口。

## 当前 Demo 状态

旧 Demo 已保留，但存在人工候选排序、模拟结果、正确性验证不足和统计流程不完整等限制。新的 EPAS Demo 尚未实现，后续应建立以下真实闭环：

```text
效应契约
→ 有限候选实例化
→ 真实编译和运行
→ 后端效应观测
→ 效应保持度计算
→ 最小架构增量选择
→ 追加保存实验轨迹
```

新 Demo 不使用世界模型，且在没有 RISC-V 工具链时不伪造 RISC-V 性能数据。
