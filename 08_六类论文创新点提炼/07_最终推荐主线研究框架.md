# 最终推荐主线研究框架

## 1. 最终决策

【候选主线】**可执行证据契约驱动的硬件感知 LLM 编译优化智能体**。

英文工作名可暂定为 **Evidence-Contract Compiler Agent（ECCA）**。名称只是便于组织研究，不构成原创性声明。

一句话目标：让 LLM Agent 提出结构化编译优化候选，先声明“为什么会变快、应该出现什么证据、什么现象会推翻解释”，再由确定性编译器工具验证；硬件指纹只用于辅助迁移和拒绝，RISC-V 仅作为实验平台之一。

## 2. 单一研究问题

> 在有限的编译和性能测量预算下，LLM Agent 能否通过可执行证据契约和反证式反馈，生成可验证、可解释、可迁移的编译优化，而不是依赖偶然的 benchmark 加速？

研究对象是**LLM 与编译器工具的协作闭环**，不是单独训练一个代价模型，也不是开发一个 RISC-V 专用后端。

## 3. 核心论点与非论点

### 3.1 需要实验支持的核心论点

1. 结构化动作空间比自由文本代码修改更容易产生可编译、可复现的优化候选。
2. 可执行证据契约能减少“性能变好但解释错误”的偶然成功进入长期记忆。
3. 主动反证和失败诊断能让 Agent 的后续搜索比只看成功/失败分数更有效。
4. 加入硬件响应摘要后，Agent 在未见硬件或程序上的候选迁移负担和负迁移率下降。
5. 在相同 Agent 调用和编译测量预算下，完整闭环优于无契约、无反证和无记忆门控的版本。

### 3.2 明确不声称的内容

- 不声称 LLM 能替代编译器正确性检查、性能测量或硬件代价模型。
- 不声称对任意语言、任意 ISA 和任意程序都泛化。
- 不声称 RISC-V 是理论限定；它只是可选实验平台。
- 不把“使用 LLM”“增加 prompt”“换一个模型”单独当作创新。
- 未完成定向查新和实验前，不把本框架表述为既成原创成果。

## 4. 最小系统边界

### 4.1 推荐首版配置

| 项目 | 建议范围 |
|---|---|
| LLM 输出 | 受限 MLIR Transform 脚本、Pass 序列或编译参数，不直接生成任意项目代码 |
| Agent 工具 | IR 检查、编译报告、汇编查看、正确性测试、性能运行、差分对照 |
| 程序 | 20—30 个向量/内存密集 kernel，划分 train/validation/unseen test |
| 平台 | 2—3 个平台；可组合 x86、ARM、GPU、RISC-V/RVV，RISC-V 不必是必选平台 |
| Agent 预算 | 每任务 20、50、100 次候选编译/运行阶梯预算 |
| 记忆 | 只保存通过正确性、机制证据和重复性能门的优化经验 |
| 输出 | 候选变换、证据契约、工具证据、失败诊断、最终动作和记忆门控结果 |

### 4.2 不进入 MVP 的内容

- 任意 C/C++ 仓库级重写；
- 多个 LLM 互相辩论的复杂多智能体编排；
- 同时覆盖 Pass 排序、向量化、代码迁移和后端改造；
- 重新实现完整 LLVM/RVV 后端；
- 让硬件指纹模型取代真实性能测量。

## 5. Agent 数据流

```text
程序/IR/编译器状态
        ↓
Agent 生成结构化候选 Transform
        ↓
生成可执行证据契约
        ↓
确定性工具链执行编译、检查、测试和测量
        ↓
证据裁决器：接受 / 修订 / 拒绝
        ↓
失败诊断反馈给 Agent；通过者进入受门控记忆
```

每轮 Agent 只能从允许的动作集合中选择动作，并必须保留完整的输入、工具版本、随机种子和测量元数据。

## 6. 核心机制

### 6.1 结构化候选生成

Agent 不直接输出“优化后的代码”，而输出可解析的动作：

```json
{
  "action": "tile_and_unroll",
  "target": "function_or_loop_id",
  "parameters": {"tile": 32, "unroll": 4},
  "preconditions": ["independent_loop", "aligned_access"],
  "expected_effect": "increase_vector_utilization"
}
```

首版只允许 4—6 个经过编译器支持的动作，避免把研究问题变成无限制代码生成。

### 6.2 可执行证据契约

每个候选必须同时提交：

| 字段 | 含义 |
|---|---|
| 前提 | 该变换适用的 IR、形状、依赖和硬件条件 |
| 动作 | 要执行的 Transform/Pass/参数 |
| 预期 IR 证据 | 哪些循环、向量、内存操作应该发生变化 |
| 预期机器证据 | 汇编、指令类别或编译报告中应出现什么 |
| 性能假设 | 预期改善的瓶颈和方向 |
| 正确性条件 | 差分、数值误差、边界输入和超时规则 |
| 否定条件 | 哪种反例会推翻当前解释 |

契约不是自然语言备注，而是能被脚本解析并映射到工具检查的实验对象。

### 6.3 反证式反馈

工具链不只返回一个 reward：

- 编译失败：返回失败阶段和 IR 位置；
- 预期 IR/汇编未出现：标记机制不成立；
- 正确性失败：缩减输入并返回最小反例；
- 性能不稳定：增加重复测量或改变对照；
- 性能变好但机制不匹配：暂存为未验证候选，禁止写入长期记忆；
- 预期证据与反例冲突：要求 Agent 重写契约。

### 6.4 硬件感知反馈与选择性迁移

硬件响应指纹是辅助观测：

`φ(h) = Normalize([vector, cache, stride, branch, predication, ...])`

它用于：

1. 从历史记忆中检索相似硬件上的候选；
2. 在目标硬件上判断是否需要补测；
3. 检测可能的负迁移并触发拒绝。

它不替代 Agent，也不成为论文的唯一理论对象。没有可靠指纹时，系统应退化为目标平台实测和 target-only 搜索。

### 6.5 记忆门控

只有同时满足以下条件的记录才能成为可迁移经验：

1. 编译成功；
2. 参考实现差分通过；
3. 契约中的关键 IR/机器证据出现；
4. 多次性能测量稳定改善；
5. 在至少一个对照条件下未被反证；
6. 记录适用程序和硬件包络。

“偶然变快但解释错误”的结果可以作为失败样本保留，不能作为成功经验检索。

## 7. 研究问题与假设

### RQ1：证据契约是否提高优化候选质量？

**H1**：在相同 Agent 调用预算下，带证据契约的候选具有更高编译成功率、正确率和机制证据通过率。

### RQ2：反证反馈是否优于单一性能分数？

**H2**：加入 IR/汇编/正确性反证诊断后，Agent 达到固定性能阈值所需的候选次数更少。

### RQ3：记忆门控是否减少偶然知识迁移？

**H3**：门控记忆相对无门控记忆在未见程序上具有更低负迁移率和更高证据一致性。

### RQ4：硬件反馈是否改善跨平台迁移？

**H4**：加入硬件响应摘要后，Agent 在未见平台上的候选排序和迁移收益优于仅使用硬件 ID 或无硬件信息的版本。

### RQ5：结果是否跨平台而非只在 RISC-V 成立？

**H5**：方法在至少两个不同平台上保持正的中位收益；RISC-V/RVV 若参与实验，只作为其中一个平台进行外部有效性验证。

## 8. 基线设计

1. **编译器默认配置**：现实起点。
2. **无 Agent 的随机/贝叶斯调优**：判断 LLM 是否提供额外价值。
3. **自由文本 LLM 优化**：没有结构化动作和证据契约。
4. **结构化 Agent、无证据契约**：隔离契约贡献。
5. **结构化 Agent、只看性能分数**：隔离反证反馈贡献。
6. **结构化 Agent、无记忆门控**：隔离长期记忆污染。
7. **结构化 Agent、无硬件指纹**：隔离硬件感知反馈。
8. **target-only 高预算搜索**：性能上界和成本参照。
9. **跨平台强制迁移**：暴露硬件负迁移。

## 9. 必需消融

| 消融 | 被检验的机制 |
|---|---|
| 去掉结构化动作，改为自由文本 | 动作约束是否必要 |
| 去掉预期 IR/汇编证据 | 机制契约是否必要 |
| 去掉否定条件 | 反证式反馈是否必要 |
| 去掉正确性门 | 性能收益是否由错误程序造成 |
| 去掉记忆门控 | 偶然成功是否污染后续搜索 |
| 用单一 reward 替换多源证据 | 编译器证据是否提供额外信息 |
| 去掉硬件响应摘要 | 硬件感知是否减少负迁移 |
| 换用 RISC-V/RVV、x86、ARM 或 GPU 平台 | 方法是否依赖单一平台 |

## 10. 评价指标

- 候选编译成功率、执行正确率、超时率；
- 契约证据通过率和证据—结果一致性；
- 达到固定性能阈值所需 Agent 调用数和编译测量数；
- 几何平均加速比、相对高预算上界的 regret；
- 负迁移率、记忆命中后的成功率和拒绝率；
- 未见 kernel、输入规模和平台上的泛化；
- 输出解释与 IR/汇编/性能证据的可重放一致性。

## 11. 实验纪律

- 每个性能配置预热并重复测量，报告中位数和 bootstrap 置信区间；
- 主要比较使用相同 Agent 调用预算和相同目标测量预算；
- 成功、失败、拒绝和不确定样本都要计入统计；
- 固定模型版本、prompt 模板、编译器、运行库和系统负载；
- 未见平台不能用于反向调阈值；
- RISC-V 平台实验与 x86/ARM/GPU 实验使用同一 Agent 协议和同一证据格式。

## 12. 分阶段实施

### 阶段 A：单平台 Agent 闭环

- 选择 MLIR Transform 和 8—10 个 kernel；
- 实现结构化动作、证据契约和确定性工具裁决；
- 比较自由文本 Agent、无契约 Agent 和完整 Agent。

**继续条件**：完整 Agent 在编译成功率、正确率或证据一致性上有可测优势。

### 阶段 B：反证和记忆门控

- 加入最小反例缩减、失败诊断和记忆写入门；
- 测量偶然加速被过滤的比例；
- 在未见 kernel 上验证记忆迁移。

### 阶段 C：硬件感知跨平台实验

- 选择 2—3 个实验平台；
- 加入硬件响应摘要、迁移/补测/拒绝决策；
- RISC-V/RVV 可作为其中一个平台，但不作为唯一平台。

### 阶段 D：可选增强

只选择一个增强方向：类别三的双证书、类别四的 VLEN 压力测试或类别一的 Pass 因果信用；不同时改造 RVV 后端和 LLM Agent。

## 13. 风险、失败信号与降级路径

| 风险/失败信号 | 对主张的影响 | 降级路径 |
|---|---|---|
| Agent 只是增加编译调用，没有提高证据质量 | LLM 主线贡献不足 | 收缩为“证据契约降低无效搜索”的研究 |
| 契约字段难以自动检查 | 机制无法复现 | 先保留 IR、正确性和性能三类硬门，减少自由文本字段 |
| 反证反馈不能改变后续动作 | Agent 闭环退化为打分器 | 只保留可影响下一轮动作的诊断字段 |
| 记忆门控过于保守 | 迁移覆盖率过低 | 将记忆分为已验证、待验证和失败三层 |
| 硬件指纹与收益无相关性 | 硬件辅助模块失败 | 回退到目标平台实测，不影响 LLM Agent 主线 |
| 只有一个平台有效 | 泛化主张下降 | 将结论限定为单平台 Agent 证据闭环 |
| RISC-V 工具链不稳定 | 外部有效性受影响 | 使用 x86/ARM/GPU 完成主结果，RISC-V 仅报告可复现实验子集 |
| 已有工作覆盖完整证据契约 Agent | 新颖性下降 | 收窄到特定 Transform、跨平台拒绝或失败诊断记忆格式 |

## 14. 可证伪标准

满足任一情形时，不应继续声称主线成立：

1. 完整 Agent 与无契约 Agent 在相同预算下没有证据质量或搜索效率差异；
2. 去掉反证反馈后性能和正确性没有变化；
3. 记忆门控不能降低未见程序上的负迁移或解释不一致；
4. 加入硬件反馈后没有跨平台收益，且指纹成本超过节省的测量成本；
5. 结果只由一个模型、一个 kernel 或一个平台驱动；
6. 正确性过滤后性能优势消失。

## 15. 预期交付物

1. 一个受限动作空间的 LLM 编译优化 Agent 原型；
2. 可解析、可重放的证据契约格式和工具适配器；
3. 反证式失败诊断和三层记忆门控；
4. 同预算、跨程序、跨平台的可重放评测脚本；
5. 负迁移、拒绝和失效边界的完整报告；
6. 至少两个平台的实验结果；RISC-V/RVV 如纳入，则作为其中一个实验平台。

## 16. 与其余五类候选的关系

| 类别 | 在主线中的角色 | 是否为 MVP 必需 |
|---|---|---|
| 1 Pass 信用分配 | Agent 的细粒度因果归因器 | 否 |
| 2 反证式智能体 | 主线核心：候选、契约、反证、记忆 | **是** |
| 3 双证书规则 | 规则部署前的语义/盈利审计 | 可选 |
| 4 VLEN 反例验证 | 跨平台实验中的边界压力测试 | 可选 |
| 5 RVV 状态化后端 | 特定平台的后端动作扩展 | 否 |
| 6 指纹与效应因子化 | Agent 的硬件反馈和选择性迁移组件 | 建议加入，但不单独成主线 |

最终收敛原则是：**主论文证明 LLM Agent 如何通过可执行证据契约、反证反馈和记忆门控产生可验证优化；硬件指纹与 RISC-V 只服务于跨平台实验，不改变研究主轴。**

## 17. 投稿前必做查新

进入开题答辩或论文写作前，需定向检查以下组合是否已有高度重合工作：

- executable evidence contract + compiler optimization agent；
- falsification-driven LLM compiler optimization；
- compiler feedback memory gating；
- hardware-aware LLM autotuning；
- selective transfer/rejection for compiler agents。
