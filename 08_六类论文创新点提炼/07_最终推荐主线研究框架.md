# 最终推荐主线研究框架

## 1. 最终决策

【候选主线】**硬件响应指纹驱动的可拒绝跨硬件编译优化知识迁移**。

英文工作名可暂定为 **Fingerprint-Gated Cross-Hardware Tuning（FGCT）**。名称只是便于工程组织，不构成原创性声明。

一句话目标：用少量可复现微基准测出目标硬件的响应指纹，从多个源硬件中选择或拒绝优化经验，再用有限目标实测校准，使低预算调优尽量接近大预算 target-only 搜索，同时显式控制负迁移。

## 2. 单一研究问题

> 当新硬件只能提供数百次而非数十万次测量时，实测硬件响应指纹能否比静态规格或硬件 ID 更可靠地预测“某类编译变换是否可迁移”，并通过选择性拒绝减少负迁移？

研究对象不是“做一个万能 AI 编译器”，也不是把六类创新全部实现。核心只研究**硬件域如何表示、变换经验如何分解、迁移何时应该拒绝**。

## 3. 核心论点与非论点

### 3.1 需要实验支持的核心论点

1. 实测响应指纹与跨硬件变换收益的相关性高于静态硬件字段或简单 one-hot 硬件 ID。
2. 预测相对变换效应，比直接预测绝对运行时间更容易跨硬件共享。
3. 带拒绝选项的教师路由，在相同目标测量预算下比强制迁移产生更少负迁移。
4. 主动补测可以在较低目标预算下达到接近高预算 target-only 调优的性能。

### 3.2 明确不声称的内容

- 不声称对任意 ISA、任意编译器和任意程序都泛化。
- 不声称响应指纹完全解释微架构行为。
- 不声称取代完整硬件代价模型、穷举搜索或真实性能测量。
- 不把 LLM、强化学习、多智能体或新 IR 作为必需贡献。
- 未完成定向查新和实验前，不把本框架表述为既成原创成果。

## 4. 最小系统边界

### 4.1 推荐首版配置

| 项目 | 建议范围 |
|---|---|
| IR/动作空间 | 二选一：MLIR Transform 参数；或 RVV 微内核的 tile/unroll/SEW/LMUL/prefetch 参数 |
| 硬件域 | 2—3 个平台，至少一个真实 RISC-V/RVV；其余可为 x86、ARM 或另一 RVV 实现 |
| 程序 | 20—30 个向量/内存密集 kernel，划分 train/validation/unseen test |
| 输入 | 每个 kernel 选择多个规模、对齐和 stride，测试集包含未见组合 |
| 指纹 | 50—200 个短 microbenchmark 条目，可在几分钟至可接受时限内完成 |
| 目标测量预算 | 50、100、250、500、1000 次阶梯预算 |
| 输出 | 候选配置、预测相对收益、置信区间、教师选择/拒绝决定、回退原因 |

若只能获得两块硬件，不虚构“多源”结论：将问题降级为二域选择性迁移，并把第三域作为后续扩展。

### 4.2 不进入 MVP 的内容

- 全 LLVM Pass 序列搜索。
- 自动重写任意 C/C++ 项目。
- 从 MLIR 到机器指令的完整新后端。
- 通用语义规则生成器。
- 依赖昂贵大模型的在线闭环。

## 5. 核心机制

### 5.1 硬件响应指纹

对硬件域 `h` 执行一组固定且可版本化的 microbenchmark：

`φ(h) = Normalize([r_vec, r_stride, r_cache, r_branch, r_pred, r_reduce, ...])`

其中每个响应可由延迟、吞吐、带宽曲线或经校准的 PMU 事件组成。首版应以跨平台可比的归一化时间/吞吐为核心，PMU 只作为可选增强。

建议指纹维度覆盖：

- 不同数据类型和向量宽度的算术吞吐；
- 连续、固定 stride、随机访存及缓存容量转折；
- 分支可预测性和 predication；
- reduction、shuffle、gather/scatter；
- RVV 平台上的 VLEN/有效 `vl`、SEW、LMUL 和尾部策略响应。

### 5.2 变换效应描述

对程序 `p` 和动作 `a` 构造描述 `ψ(p,a)`，包含静态程序特征、变换类型、参数差异和必要的动态基线特征。预测目标不是绝对时间，而是：

`Δ(p,a,h) = log(T_base(p,h) / T_after(p,a,h))`

`Δ > 0` 表示变快，`Δ < 0` 表示变慢。

### 5.3 共享效应与硬件交互因子化

一个可检验的最小模型为：

`Δ(p,a,h) = g_shared(ψ(p,a)) + g_interact(ψ(p,a), φ(h)) + ε`

- `g_shared` 学习跨硬件稳定的变换规律；
- `g_interact` 学习某种硬件响应对变换效果的修正；
- `ε` 包含测量噪声和未建模因素。

实现可以从 LightGBM/小型 MLP/高斯过程开始。模型复杂度不是创新中心，必须先用简单模型证明表示和决策机制有效。

### 5.4 教师选择、拒绝与补测

对每个源硬件教师 `s` 计算：

- 指纹相似度 `sim(φ(s), φ(t))`；
- 在少量目标校准集上的误差和校准程度；
- 候选变换预测的不确定性；
- 历史负迁移率。

决策保持三态：

1. **迁移**：相似度和校准通过，且预测收益下界高于零；
2. **补测**：存在潜在收益但不确定性过高，主动选择最有信息的目标测量；
3. **拒绝**：教师不相似、校准失败或负迁移风险过高，回到 target-only。

拒绝不是异常路径，而是需要独立评价的系统输出。

## 6. 正确性与安全门

任何性能样本进入训练或比较前必须通过：

1. 编译成功；
2. 正常执行且无超时/崩溃；
3. 与参考实现的差分测试通过；
4. 浮点程序满足预先固定的误差容限；
5. 多个输入和边界条件通过；
6. 测量稳定性满足阈值，否则标记为噪声样本而非性能证据。

类别三的“语义证书”和类别四的“VLEN 参数化反例”可作为增强，但 MVP 先采用确定性的编译/执行/差分测试门，避免主线失控。

## 7. 研究问题与假设

### RQ1：响应指纹是否能预测可迁移性？

**H1**：在未见目标硬件上，响应指纹模型对变换收益排序的 Spearman 相关性和 top-k 命中率显著高于静态规格、硬件 ID 和无硬件特征模型。

### RQ2：效应因子化是否优于绝对时延迁移？

**H2**：在相同训练数据和模型容量下，预测相对效应的模型具有更低目标域排序遗憾和更好的跨硬件校准。

### RQ3：拒绝机制能否降低负迁移？

**H3**：在相同目标测量预算下，选择性迁移相对强制教师迁移显著降低负迁移率，并改善 coverage-risk 曲线。

### RQ4：低样本主动补测是否有实际价值？

**H4**：在 500 或 1000 次目标测量预算内，完整方法的最终性能优于 target-only 随机/贝叶斯调优，并接近更高预算 target-only 上界。

### RQ5：结果是否跨 kernel 和输入保持？

**H5**：在未见 kernel 与未见输入形状上，方法仍保持正的中位收益；若不成立，应明确把适用范围收缩到同族 kernel。

## 8. 基线设计

至少包含以下基线：

1. **编译器默认配置**：现实起点。
2. **高预算 target-only**：近似性能上界，同时报告测量成本。
3. **同预算 target-only random**：排除“只是多测了数据”。
4. **同预算 target-only Bayesian/active tuning**：强目标域基线。
5. **Source-only 强制迁移**：暴露负迁移。
6. **静态规格最近教师**：检验响应指纹是否必要。
7. **所有源数据联合微调**：检验教师路由是否必要。
8. **无拒绝版本**：相同模型但总是选择一个教师。
9. **TCL-like 持续迁移基线**：在代码可得性受限时复现其核心数据重用/蒸馏思路，并明确复现边界。

所有学习方法必须使用相同的目标测量预算，源数据成本和指纹采集成本单独列出。

## 9. 必需消融

| 消融 | 被检验的机制 |
|---|---|
| 去掉响应指纹，换硬件 ID | 指纹的实际贡献 |
| 响应指纹换静态规格 | 实测响应是否优于规格表 |
| 去掉 `g_interact` | 硬件交互项是否必要 |
| 改为绝对时间预测 | 相对效应因子化是否必要 |
| 去掉拒绝阈值 | 拒绝是否降低负迁移 |
| 去掉不确定性校准 | 置信决策是否可靠 |
| 随机补测替代主动补测 | 主动学习是否节省预算 |
| 去掉一类 microbenchmark | 哪些指纹维度真正有用 |
| 去掉目标校准样本 | 零样本迁移的真实边界 |

## 10. 评价指标

### 10.1 性能与搜索成本

- 最终几何平均加速比；
- 相对高预算上界的 regret；
- 达到固定性能阈值所需目标测量次数；
- 总调优墙钟时间、编译次数和能耗（可得时）；
- 指纹采集成本及其跨任务摊销点。

### 10.2 迁移质量

- 负迁移率；
- 教师选择准确率或 oracle regret；
- Spearman/Kendall 排序相关性；
- top-k 候选命中率；
- transfer gain over target-only at equal budget。

### 10.3 选择性预测

- coverage-risk 曲线；
- 拒绝率与拒绝后的 target-only 性能；
- 置信区间覆盖率；
- ECE/Brier score 或回归校准误差；
- 不同风险阈值下的性能—覆盖权衡。

### 10.4 正确性和鲁棒性

- 编译成功率、执行正确率、超时率；
- 多次测量的变异系数；
- 未见 kernel、输入规模和软件栈版本上的退化；
- RVV 场景下不同 VLEN/有效 `vl` 条件的正确性与收益。

## 11. 统计与实验纪律

- 每个配置预热后重复测量，使用中位数和 bootstrap 置信区间；重复次数由测量噪声预实验确定。
- 跨 kernel 汇总使用几何平均或配对分布，不只报告最佳案例。
- 对主要基线做配对检验并报告效应量和置信区间。
- 模型选择只使用训练/验证域；未见目标硬件测试结果不能反向调阈值。
- 预先固定超时、错误容限、异常值处理和失败样本计入方式。
- 同时报告成功案例、无收益案例和负迁移案例。
- 固定编译器、运行库、频率策略和系统负载；软件栈变化作为单独消融。

## 12. 分阶段实施

### 阶段 A：两域可行性原型

- 选定一个动作空间和 8—10 个 kernel；
- 构建 30—50 维最小响应指纹；
- 验证指纹距离与变换收益差异是否相关；
- 实现 source-only、target-only 和简单指纹路由。

**继续条件**：至少在部分变换族上出现稳定相关性，且指纹路由优于静态规格。否则先调整指纹，不进入复杂模型。

### 阶段 B：因子化与拒绝机制

- 扩展至 20—30 个 kernel；
- 实现共享项、交互项和不确定性校准；
- 产生 coverage-risk 曲线；
- 验证无拒绝版本是否出现显著负迁移。

**继续条件**：拒绝机制在同预算下可降低负迁移，且不是通过拒绝几乎所有样本获得。

### 阶段 C：低样本主动调优

- 加入阶梯目标预算；
- 比较随机、贝叶斯及主动补测；
- 加入未见 kernel/输入测试；
- 在真实 RISC-V/RVV 平台完成主结果。

### 阶段 D：可选增强

按收益选择一个增强，不同时展开：

- 类别四：VLEN 参数化压力测试；
- 类别三：盈利证书和可重放记录；
- 类别一：Pass 级反事实信用作为另一种动作效应；
- 类别五：把显式 RVV 配置状态暴露为新的调优动作。

## 13. 风险、失败信号与降级路径

| 风险/失败信号 | 对主张的影响 | 降级路径 |
|---|---|---|
| 指纹与真实变换收益无相关性 | 核心假设 H1 失败 | 按变换族设计局部指纹；若仍失败，转为“指纹失效边界与负迁移检测”研究 |
| 响应指纹采集过贵 | 低样本优势被抵消 | 做维度选择和早停；报告摊销任务数 |
| 只有两块硬件 | 多源教师选择证据不足 | 收缩为二域选择性迁移，不报告多源泛化 |
| 拒绝率接近 100% | 方法退化为 target-only | 按变换类型部分迁移；用 coverage-risk 而非单阈值评价 |
| 拒绝率很低但负迁移仍多 | 不确定性失准 | 使用保序校准/共形区间，或缩小可迁移动作空间 |
| 简单 target-only 已经最好 | 跨硬件迁移无实用价值 | 报告预算交叉点，限定到极低预算或重复任务摊销场景 |
| 软件版本主导域差异 | “硬件”解释不成立 | 把编译器/库版本纳入域描述并做分层实验 |
| RVV 工具链不稳定 | 主实验不可复现 | 先在成熟平台验证机制，再把 RVV 作为外部有效性测试；不隐瞒工具链限制 |
| TCL-like 基线难完整复现 | 近邻比较不充分 | 实现其核心持续学习基线，详细记录偏差，并在投稿前补官方代码核验 |

## 14. 可证伪标准

满足任一情形时，不应继续声称主线成立：

1. 响应指纹相对静态规格在多个目标域上没有稳定优势；
2. 相对效应因子化不优于同容量绝对时间模型；
3. 拒绝机制在匹配覆盖率后不能降低负迁移；
4. 加入指纹采集成本后，方法在目标预算上不优于 target-only；
5. 结果只由一个 kernel、一个平台或一个输入规模驱动；
6. 正确性过滤后性能优势消失；
7. 未见程序上持续为负收益且无法通过明确边界解释。

这些失败仍可形成有价值的边界性结论，但必须相应缩小论文标题和主张。

## 15. 预期交付物

1. 可版本化的跨硬件响应指纹 microbenchmark 套件；
2. 一套变换相对效应数据格式，包含程序、动作、硬件、正确性和测量元数据；
3. 因子化代价模型与教师选择/拒绝/补测策略；
4. 同预算、可重放的跨硬件调优评测脚本；
5. 负迁移、拒绝和失效边界的完整实验报告；
6. 至少一个真实 RISC-V/RVV 平台的复现配置。

## 16. 与其余五类候选的关系

| 类别 | 在主线中的角色 | 是否为 MVP 必需 |
|---|---|---|
| 1 Pass 信用分配 | 可提供更细的变换效应标签 | 否，后续扩展 |
| 2 反证式智能体 | 可生成候选并记录机制证据 | 否，避免让 LLM 成为主线依赖 |
| 3 双证书规则 | 可提供语义/盈利审计层 | 否，首版使用确定性正确性门 |
| 4 VLEN 反例验证 | 可作为 RVV 外部有效性和压力测试 | 建议加入，但不阻塞核心模型 |
| 5 RVV 状态化后端 | 可提供更有硬件意义的动作空间 | 否，工程风险较高 |
| 6 指纹与效应因子化 | 主线核心 | **是** |

最终收敛原则是：**主论文只证明一种硬件表示、一个效应模型和一个选择性迁移决策；其余模块只在能直接增强该因果链时加入。**

## 17. 投稿前必做查新

本框架来自本地总结的综合推导。进入开题答辩或论文写作前，需定向检查以下组合是否已有高度重合工作：

- hardware response fingerprint + compiler autotuning；
- selective transfer / reject option + cross-device cost model；
- few-shot hardware adaptation + transformation effect prediction；
- active measurement + negative transfer detection；
- RVV/VLEN microbenchmark fingerprint + tuning transfer。

查新后若核心三元组“响应指纹 + 效应因子化 + 可拒绝迁移”已有完整实现，应优先收缩到 RVV/VLEN 指纹、变换类型级拒绝或指纹采集预算优化，而不是维持宽泛主张。
