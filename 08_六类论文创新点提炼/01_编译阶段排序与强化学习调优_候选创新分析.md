# 类别一：编译阶段排序与强化学习调优——候选创新点分析

> 文献数量：2024–2026 年独立条目 16；旧文献边界条目 8
> 完整阅读数量：16 份新文献总结；其中 15 份为完整 13 节总结，1 份源材料受限
> 证据范围：本地逐篇阅读总结；旧文献只用于已有工作边界
> 分析日期：2026-07-16
> 证据充分程度：中高（跨硬件迁移空白明确，但直接多 ISA 反事实证据仍少）

## 1. 这一类在研究什么

结论：这类研究想自动决定编译器优化步骤的顺序。Compiler Pass（编译阶段）是一次改变程序中间表示的优化操作；LLVM IR（LLVM Intermediate Representation）是源码和机器码之间的程序表示。顺序不同会改变运行时间、代码尺寸和能耗，但组合数量巨大。强化学习（Reinforcement Learning，RL）让策略通过反复编译和测量学习顺序。它与 RISC-V 的关系在于：同一顺序在 x86、ARM 和 RISC-V 后端可能产生不同机器指令，不能只看 IR 就判断收益。

## 3. 已有工作已经解决了什么

结论：候选生成、结构化动作、在线搜索、动态硬件观测、Pass 删除证据和编译器内集成都已有代表工作，不能再把这些模块单独称为创新。

1. 【论文事实】AutoPhase、CompilerGym、MLIR RL 和 Pearl 已分别建立特征化 MDP、标准环境与结构化循环动作。
2. 【论文事实】Priority Sampling、CompilerDream、CITROEN 已从候选去重、模拟预筛和不确定性采样三个角度降低测量成本。
3. 【论文事实】DeCOS 已将硬件计数器和两个 AMD 平台纳入 RL 评测，但没有显式学习平台共享效应与目标平台残差。
4. 【论文事实】ECCO 已通过删除冗余 Pass、记录边际 cycles 与相邻 synergy 构造证据。因此，单平台 Pass 删除或交换不能再冒充创新。
5. 【论文事实】AwareCompiler、ECCO、Protean 已覆盖“知识/模型生成或预测 + 经典搜索/工具反馈”的宽泛组合。

## 4. 仍未解决的研究空白

结论：最清晰的空白不是再找一个更强搜索器，而是判断一条 Pass 证据能否跨硬件复用，并在不确定时主动拒绝迁移。

### 空白 A：跨硬件 Pass 信用没有可校准的分解

- 【论文事实】ECCO 的边际证据来自 `llvm-mca`；CITROEN 对各目标平台独立搜索；DeCOS 展示跨两块 AMD CPU 的结果，但未输出“共享效应、硬件残差、置信区间”。
- 【合理推导】同一 Pass 在源平台有效不等于它在 RISC-V 上仍有效。若系统只加入硬件 ID，模型可能记住平台，却无法回答哪部分证据可迁移。
- 这不是简单工程问题：需要可识别的干预、层级效应模型、测量噪声和主动实验共同定义迁移边界。
- 证据充分度：中高。

### 空白 B：局部收益与整程序收益缺少层级信用修正

- 【论文事实】DeCOS 报告函数级更优但整程序可能更差；Protean 主要按模块优化。
- 【合理推导】热点覆盖、调用频率、代码布局和跨模块优化会使局部奖励失真。
- 证据充分度：中。

### 空白 C：LLVM 版本变化造成的知识失效缺少系统研究

- 【论文事实】AwareCompiler/ECCO 使用 LLVM 10，CITROEN 使用 17，Protean/MLIR RL 使用 19；statistics 和 Pass 管线随版本变化。
- 【合理推导】版本漂移可能改变特征语义和序列收益，但当前语料缺少直接纵向实验。
- 证据充分度：低。当前文献证据不足，需要继续查找相关研究，不能直接声称这是创新。

## 6. 最推荐的创新点

### 6.1 创新点名称

【候选创新】**反事实置信区间驱动的跨硬件 Pass 信用分配**。

### 6.2 一句话解释

不直接相信 x86 上“某个 Pass 有用”的经验，而是用删除或交换 Pass 的小实验，估计它在不同硬件上的真实贡献和不确定性；证据稳定才迁移，不稳定就要求在 RISC-V 上补测。

### 6.3 创新点命名拆解

- **反事实（counterfactual）**：比较“保留这个 Pass”和“删除/交换这个 Pass”两个只差一个因素的版本。
- **置信区间（confidence interval）**：不是只报一个收益值，而是报告测量噪声下可能的范围。
- **跨硬件**：至少包含一个源平台和一个目标平台，而不是只改变程序输入。
- **Pass 信用分配（credit assignment）**：把整条序列的最终收益合理分给其中的关键步骤。

### 6.4 文献依据

- 正面依据：CITROEN 证明实际变换 statistics 和不确定性采样有价值；DeCOS 证明动态计数器能改善决策并暴露跨硬件差异；ECCO 证明删减 Pass、边际收益和 synergy 可构成训练证据。
- 已覆盖近邻：ECCO 已覆盖单平台删减证据；CITROEN 已覆盖单平台 GP 主动搜索；DeCOS 已覆盖硬件计数器和跨两个 AMD CPU 的结果。
- 不能再声称的内容：不能声称“提出 Pass 反事实归因”“首次使用硬件计数器”“首次主动选择测量”“首次跨硬件调优”。
- 仍缺证据：多 ISA 上 Pass 干预效应的公开数据、RISC-V 真实性能计数器稳定性、LLVM 版本变化的影响。

### 6.5 已有工作与研究空白

现有工作已经能够：

1. 用 Pass statistics、IR diff 和硬件计数器描述候选产生的变化；
2. 用删除、搜索或代理模型筛选有价值的序列。

但仍然不能：

1. 区分某个 Pass 的收益是平台共享效应还是目标硬件特有效应；
2. 给出“可以直接迁移”或“必须重新测量”的校准置信度。

因此真正的研究空白是：

> 【合理推导】在有限目标硬件测量预算下，如何以反事实干预估计 Pass 贡献的跨硬件稳定性，并让系统在证据不足时拒绝迁移。

### 6.6 核心机制

输入包括：程序及输入集、候选 Pass 序列、每步 compilation statistics、源/目标硬件描述和重复运行时间。输出包括：每个关键 Pass 的共享信用、硬件残差、置信区间，以及“迁移、拒绝、补测”三态决策。

对程序 `p`、序列中的干预 `j` 和硬件 `h`，定义：

```text
Δ(p,j,h) = log(T_without_j / T_full)
Δ(p,j,h) = μ_shared(p,j) + r_h(p,j) + ε
```

- `T_full`：完整序列运行时间；
- `T_without_j`：删除或交换第 `j` 个 Pass 后的时间；
- `μ_shared`：多个硬件共同支持的效应；
- `r_h`：硬件 `h` 的特有残差；
- `ε`：测量噪声。

数字例子：x86 上完整序列为 100 ms，删除 Pass 后为 110 ms，则 `Δ=log(1.10)≈0.095`，说明该 Pass 有帮助；RISC-V 上完整序列 120 ms，删除后 114 ms，则 `Δ=log(0.95)≈-0.051`，说明它反而有害。两个平台符号相反时，系统不能迁移“有用”标签，应把该干预列为目标平台补测对象。

新增信息是跨硬件成对干预结果；新增约束是只有置信区间不跨零且目标残差足够小时才允许迁移；反馈来自目标平台补测对后验分布的更新。本质变化发生在“从给序列打总分”转为“估计可迁移的步骤级效应并允许拒绝”。

### 6.7 系统组成与数据流

```text
输入程序与候选 Pass 序列
        ↓
逐步 statistics、IR diff 与热点特征提取
        ↓
删除/交换关键 Pass 的反事实候选生成
        ↓
源硬件重复测量 + 少量目标硬件测量
        ↓
共享效应—硬件残差层级模型与置信区间
        ↓
正确性测试、编译失败与异常值门控
        ↓
迁移 / 拒绝 / 主动补测
        ↓
更新序列排序或搜索策略
```

关键 Pass 先由 statistics 变化、序列位置和初步边际收益筛出，避免对每一步穷举。目标平台只测量“置信区间跨零、平台残差大或预计信息增益高”的干预。

### 6.8 小白化例子

原方法在 x86 上发现 `loop-unroll` 后程序变快，就把包含它的序列搬到 RISC-V。失败原因可能是 RISC-V 寄存器更紧张，展开后产生 spill（寄存器不够而写回内存）。新方法先删除 `loop-unroll` 做一组对照：若 x86 变慢而 RISC-V 变快，就把它标成“硬件特有、禁止直接迁移”，而不是继续增加训练数据让模型记住一个错误的通用规律。

### 6.9 可检验的研究问题

1. 在相同目标平台测量预算下，三态迁移门控能否降低负迁移率？
2. 分解共享效应与硬件残差后，目标平台最佳序列的 Regret@k 是否下降？
3. 主动选择的干预是否比随机删除/交换用更少测量达到同等信用排序相关性？
4. 从 x86→RISC-V 与 RISC-V→x86 两个方向是否出现不对称迁移？

### 6.10 可验证假设

- H1：与直接复用源平台信用相比，完整方法将降低目标平台负迁移率；95% 置信区间应显示方向一致且不跨零。
- H2：与随机选择干预相比，主动补测在相同测量次数下具有更低 Regret@5。
- H3：与只加入硬件 ID 的条件模型相比，共享效应—残差分解具有更好的置信区间覆盖率和校准误差。
- H4：删除迁移拒绝门控后，性能均值可能接近，但最坏情况退化和负迁移率会显著上升。

### 6.11 最小可行 Demo

- **目标**：证明 10–20 个程序上存在可重复的跨硬件 Pass 信用符号变化，并验证三态门控能减少错误迁移。
- **数据**：从 cBench/PolyBench 选择 20 个可稳定运行的 C 程序，每个程序生成 10 条长度 8–12 的候选序列；排除源材料受限论文中的推测序列。
- **平台**：一台 x86-64 Linux 主机和一块可运行 Linux/perf 的 RISC-V 开发板；具体板卡、核心、频率控制和可用 PMU 事件需要人工确认。
- **软件**：同一 LLVM 主版本、Clang/opt、`-stats-json`、Linux `perf`、测试脚本。
- **步骤**：编译基线→筛关键 Pass→每条序列生成最多 5 个删除/交换干预→两平台各重复运行→拟合层级模型→按置信区间作迁移/拒绝/补测→比较目标平台结果。
- **预计开发工作**：2 周构建序列与测量管线，1 周实现效应模型，1 周完成基线和图表；不训练大模型。
- **输出**：干预数据表、每个 Pass 的共享/残差信用、迁移决策和目标平台性能。
- **成功标准**：在不少于 5 个程序中观察到可重复的硬件特有效应；完整方法相对直接迁移降低负迁移率，且不是靠增加目标测量次数获得。

### 6.12 实验设计

#### 实验平台

固定 CPU governor、核心绑定、温度预热、编译器版本和链接参数。QEMU 只用于可执行性预筛，不能作为 RISC-V 性能结论。

#### 数据集

第一阶段 20 个 cBench/PolyBench 程序；扩展阶段加入 SPEC CPU 子集。训练/选择干预与最终测试程序分开，并记录程序输入。

#### 对比基线

- 简单基线：直接复用源平台最佳序列及其 Pass 信用。
- 强基线：目标平台独立的 CITROEN 式 GP/主动搜索，使用同等目标测量预算。
- 最近邻方法：ECCO 式单平台删除证据，加一个普通硬件条件预测头，但不做共享—残差分解和拒绝门控。

#### 消融实验

依次删除反事实干预、共享—残差分解、置信区间门控和主动补测；另以相同总测量数控制“更多数据”因素。比较只用静态特征、只用 statistics、再加入硬件计数器的增量。

#### 评价指标

- 目标平台 speedup：越大越好，回答是否真的变快；
- 负迁移率：源平台有益但目标平台退化的比例，越小越好；
- Regret@k：前 `k` 个候选与真实最优之间的差距，越小越好；
- 目标平台测量次数/总时间：越小越好，衡量样本效率；
- 信用排序 Spearman 相关：越大越好，衡量估计与真实干预排序一致性；
- 置信区间覆盖率和 Expected Calibration Error：分别衡量区间是否可信与概率是否校准。

#### 统计要求

每个二进制先 warm-up；至少重复 15 次，优先报告中位数与 bootstrap 95% 置信区间。事先定义异常值规则；对完整方法与基线使用配对检验，并报告效应量。多个程序比较时控制多重检验。

### 6.13 与已有工作的创新边界

- 与 ECCO 的区别：ECCO 用单平台/静态估计的删减证据训练解释与搜索；本方法研究同一干预的跨硬件稳定性、不确定性和拒绝决策。
- 与 CITROEN 的区别：CITROEN 在目标平台直接建 GP 选候选；本方法复用源平台干预证据，只把不确定部分送到目标平台。
- 与 DeCOS 的区别：DeCOS 将计数器作为状态并展示跨 AMD CPU；本方法输出显式共享效应、硬件残差和经过校准的迁移边界。
- 直接使用的现有模块：LLVM statistics、perf、GP/层级回归、测试门控。
- 核心创新候选：**反事实信用的跨硬件分解 + 基于不确定性的迁移拒绝/补测闭环**。
- 删除核心机制后，系统退化为单平台 Pass 归因、普通条件模型或独立平台调优，因此不是简单模块拼接。

### 6.14 风险与降级方案

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 近邻文献已做多硬件干预分解 | 新颖性下降 | 缩小到 RISC-V/RVV 特有效应或改为局部—整程序信用修正；先补检索 |
| RISC-V PMU 事件少或权限不足 | 动态解释不足 | 保留运行时间和反汇编；计数器只作可选解释，不作核心输入 |
| 真机噪声大 | 信用符号不稳定 | 增加重复、绑核/控频、分层噪声模型；不稳定样本必须输出“拒绝” |
| 干预组合太多 | 测量成本失控 | 只干预 statistics 变化最大的 3–5 个 Pass；使用信息增益主动选择 |
| 删除 Pass 导致序列非法 | 无法配对 | 记录失败为结构约束，改用相邻交换或前缀截断 |
| 正确性测试不足 | 错误代码被当成加速 | 使用现有测试、sanitizer 和差分输入；无法验证的候选不进入性能模型 |
| LLVM 版本差异 | statistics 语义漂移 | Demo 固定一个主版本；版本迁移作为后续研究而非第一版主张 |
| 结果不显著 | 主张失败 | 报告“跨硬件效应高度共享”这一否定结论，并转向降低测量成本的工程结果 |

### 6.15 可证伪条件

以下任一结果会否定或显著削弱候选创新：

1. 多数 Pass 干预在两个平台上的效应符号和排序几乎完全一致，普通源平台信用已足够；
2. 完整方法与简单硬件条件模型在负迁移率、Regret 和校准上没有显著差异；
3. 主动补测不比随机测量节省目标平台预算；
4. 所有收益来自更多测量，而非效应分解和拒绝门控；
5. 在第三个硬件或第二批程序上无法复现；
6. 拒绝迁移过于保守，导致测量成本接近从零独立调优。

### 6.16 综合评分

| 维度 | 1—5分 | 评分理由 |
|---|---:|---|
| 新颖性 | 4 | 与 ECCO/CITROEN/DeCOS 均有明确机制差异，但需补多硬件干预检索 |
| 文献证据 | 4 | 三条近邻证据互补；RISC-V 直接证据仍少 |
| 可实现性 | 4 | 第一版不需要大模型，只需 LLVM、两平台和统计模型 |
| 实验可验证性 | 5 | 负迁移、Regret、预算和校准均可直接测量 |
| 与 RISC-V 相关性 | 5 | 研究问题依赖真实后端差异，而非简单换平台 |
| 与总体主线兼容性 | 4 | 可作为跨硬件知识迁移主线，也可独立成文 |
| 研究风险 | 3 | 测量成本和近邻碰撞中等，拒绝门控提供安全降级 |

结论：当前适合作为**主创新候选**进入六类交叉比较，但尚不能在完成近期多硬件 Pass 干预检索前使用“新颖”或“首次”表述。若类别六出现更强的通用迁移机制，本方向应收窄为“Pass 级证据生成与信用分配”支撑模块。
