# 创新三：失配驱动的架构专用调优

## 1. 问题定义

当通用优化在目标架构上失败时，传统自动调优通常重新执行随机搜索、贝叶斯优化、强化学习或 LLM 候选生成。它们主要依赖最终运行时间判断候选好坏，但没有充分利用“具体哪种效应没有实现”的诊断信息。

本创新解决的问题是：

> 如何把通用知识的预期效应与目标架构真实效应之间的失配，转换成有方向的架构专用修正，从而在有限真实测量预算下减少盲目搜索？

## 2. 失配向量

定义：

$$
M(P,K,h)=E_{obs}(P,K,h)-E_{exp}(P,K,h).
$$

第一版包含：

$$
M=[m_{runtime},m_{size},m_{inst},m_{spill},m_{memory},m_{branch},m_{vector}].
$$

每个维度同时附带：

- 方向：改善、无明显变化、恶化；
- 严重程度；
- 测量置信度；
- 是否属于硬约束；
- 是否能在当前平台获得；
- 与历史失配模式的相似度。

## 3. 方法机制

### 3.1 失配诊断

系统先识别主导失配，而不是同时修改所有动作：

| 主导失配 | 可能原因 | 候选修正族 |
|---|---|---|
| spill/reload 增长 | 展开、内联、向量化增加寄存器压力 | 降低展开因子、限制内联、回退相关动作 |
| 向量效应未实现 | 循环不规范、别名、对齐、目标扩展不匹配 | 规范化循环、增加分析、调整向量相关配置 |
| 代码尺寸增长过大 | 内联、展开、循环版本化过度 | 尺寸约束动作、删除激进候选 |
| 访存恶化 | 冗余加载、局部性受损、数据布局不适合 | 内存优化宏动作、回退不利变换 |
| 分支恶化 | CFG 复杂化、布局不合适、展开副作用 | CFG 简化、布局和分支相关配置 |
| 静态效应正常但运行变慢 | 微架构瓶颈、输入变化或测量噪声 | 复测、补充硬件事件、有限替换搜索 |

### 3.2 有限候选实例化

每种失配只启用与其相关的候选修正族。例如主要问题是 spill 时，不同时搜索所有向量化、内联、布局和代码尺寸选项。

候选生成形式为：

$$
\mathcal{A}_{corr}=MapMismatchToActions(M,C_P,S_h,History).
$$

候选数量由真实测量预算约束。LLM 可以提出候选，但候选必须来自合法动作白名单，并接受编译与运行验证。

### 3.3 真实验证

对每个修正候选执行：

```text
生成候选
  -> 真实编译
  -> 正确性比较
  -> 目标合法性检查
  -> IR/汇编/二进制效应提取
  -> 预热与重复真实运行
  -> 更新失配向量
```

如果候选输出错误或目标非法，直接淘汰，并记录失败类型。

### 3.4 候选选择

候选优先级同时考虑：

- 是否修复主导失配；
- 是否改善最终运行时间；
- 是否引入新的严重副作用；
- 消耗的真实测量次数；
- 是否已有相似平台和程序证据。

最终候选必须以真实运行时间为主要评价，静态效应只用于诊断和约束。

### 3.5 停止条件

满足以下任一条件时停止：

- 达到预先设定的最低性能改善；
- 主导失配已经消除且没有新硬约束违例；
- 真实测量预算耗尽；
- 连续若干候选无改善；
- 剩余候选全部不合法或与边界冲突。

## 4. 示例：向量化没有实现

通用知识预期：

```text
意图：暴露向量化机会
动作：loop-simplify + lcssa + licm + loop-vectorize
预期：向量利用提高、运行时间改善、spill 不显著增加
```

RISC-V 实测：

```text
运行时间：几乎不变
RVV 指令：未生成
标量 load/store：未减少
spill：正常
```

主导失配是向量效应未实现，而不是寄存器压力。架构调优模块优先尝试：

- 检查目标 `-march` 是否包含所需向量扩展；
- 调整循环规范化候选；
- 检查别名与对齐条件；
- 调整向量宽度或代价相关配置；
- 若平台不具备能力，则把知识边界标记为不适用。

系统不会因为运行时间没有提升就同时搜索所有后端参数。

## 5. 与普通架构独立调优的差异

Independent-Tune 对每个平台从相同大动作空间重新搜索。CABLE 架构模块只在门控发现失配后启动，并利用失配维度缩小动作空间。

对比关系为：

```text
Independent-Tune：平台 + 程序 -> 全动作空间搜索

CABLE：通用知识 + 真实失配
       -> 相关修正族
       -> 有限候选
       -> 真实验证
```

因此，需要在相同动作空间上限和相同测量预算下比较，才能证明失配信息确实提高了调优效率。

## 6. 调优轨迹如何反哺知识

架构调优完成后保存：

- 原知识和原边界；
- 原失配向量；
- 尝试过的修正动作；
- 每个动作的真实效应；
- 成功修复或失败原因；
- 最终是否形成架构专用子知识。

成功修正不是只保存一条最佳 Pass 序列，而是形成：

```text
失配模式
  + 程序条件
  + 平台条件
  -> 有效修正动作
  -> 修正后的真实效应
```

该记录为创新二的边界分裂和子知识生成提供证据。

## 7. 实验验证

### 7.1 研究问题

- 失配信息能否缩小无效动作空间？
- 在相同预算下是否比随机搜索更快找到有效修正？
- 架构调优是否真正修复原失配，而不是以其他副作用换取偶然加速？

### 7.2 对比方法

- Random Search；
- 只按运行时间排序的搜索；
- Architecture-Only；
- Independent-Tune；
- 有门控但随机选择修正；
- 完整失配驱动架构调优。

### 7.3 固定预算

每个程序和平台设置：

$$
B\in\{10,20,50,100\}.
$$

一次真实编译、正确性验证和运行测量计为一次候选评估。所有方法使用相同动作白名单和目标参数范围。

### 7.4 指标

- `Speedup@B`；
- 最佳候选出现前的测量次数；
- 原主导失配修复率；
- 新副作用发生率；
- 非法候选比例；
- 与 Independent-Tune 的性能差距；
- 每类失配对应动作的命中率。

## 8. 消融实验

- 只输入运行时间失配；
- 去掉平台条件；
- 去掉程序条件；
- 不限制候选修正族；
- 去掉历史修正证据；
- 使用随机主导失配；
- 不把调优结果反哺知识边界。

## 9. 失败条件

以下结果会削弱本创新：

- 在相同预算下不优于 Random Search；
- 动作映射只依赖人工规则且不能从数据修正；
- 经常修复一个静态效应却使真实性能恶化；
- 失配维度与有效修正动作没有统计关联；
- 每次都退化为全动作空间搜索；
- 架构模块的额外复杂度超过性能收益。

## 10. 第一版实现建议

第一版不需要 LLM 或强化学习。可以先建立 5 至 7 类失配与有限动作族之间的规则映射，使用真实数据统计每种修正的成功率。只有当数据规模足够时，再用可解释分类器或排序模型替代部分人工映射。

整个过程不使用世界模型，不预测编译状态转移，也不进行 imagined rollout。

## 11. 创新点表述

> 提出一种失配驱动的架构专用编译调优方法，将通用知识预期效应与目标平台真实效应之间的多维偏差转换为有限修正动作族，并通过真实编译、正确性验证和硬件运行选择结果，在固定评测预算下减少无方向的架构搜索。
