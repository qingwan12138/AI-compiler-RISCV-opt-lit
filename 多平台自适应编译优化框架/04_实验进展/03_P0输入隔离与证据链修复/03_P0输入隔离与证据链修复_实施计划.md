## 1. 本轮目标与边界

修复正式驱动将不同 `input_id` 错误复用为同一 Mini 二进制及参考输出的问题，补齐可审计的工件和记录证据，并生成**新的、不可覆盖**的 PolyBench 正式 run。完成前不得进入 P2、不得测量或推断真实性能、不得以 QEMU 时间排名。

本轮先聚焦 PolyBench。TSVC 的五个边界输入和二十个固定种子，仅在 PolyBench 修复经局部验证后执行；未实际完成时必须保持 `not_run`，不能以后台执行或计划代替结果。

## 2. 已确认问题（必须逐项修复）

在 `p0-20260718-formal-001` 中，`c02_small` 至 `c05_custom` 的编译命令仍含 `-DMINI_DATASET`，且与 `c01_mini` 有相同二进制哈希。根因是：

1. 二进制路径和编译缓存键未包含 `input_id`；
2. 参考构建和候选构建只使用第一个输入；
3. 后续输入执行时复用第一个输入二进制，并回退到第一个输入的参考输出；
4. 记录缺少 `run_id`、`input_config`，stdout、stderr、IR、汇编路径为空；
5. `artifacts/` 与 `logs/` 目录未包含实际工件；
6. 四个候选使用无效 Clang 前端选项，`O3_fastmath` 在严格 FP 正确性下不一致。

旧 run、旧 manifest 和旧记录不得删除、改写或伪造修复结果。

## 3. 必做实施项

### A. 修正输入隔离与参考策略

1. 二进制、O0 参考、LLVM IR、汇编和 stdout/stderr 文件名必须包含 `program_id`、`candidate_id`（参考使用 `O0_ref`）、`target` 与稳定的 `input_id` 或配置哈希。
2. 编译缓存键必须为 `(program_id, candidate_id, target, input_id)`；参考缓存键至少为 `(program_id, target, input_id)`。
3. 每个 PolyBench `input_id` 独立编译 O0 参考及每个候选；禁止 `inputs[:1]`、`first_input`、参考回退或跨输入复用二进制。
4. `input_config` 原样保存实际宏/维度；`compile_command` 必须可证明该配置被传入。

### B. 建立可审计工件与完整记录

每条记录必须至少包含：

```text
run_id, program_id, program_family, input_id, input_config,
target_triple, compiler_version, candidate_id, pass_sequence,
compile_command, binary_hash, correctness_status, exit_code,
timeout_status, output_stream, output_hash, stdout_path, stderr_path,
ir_features_path, assembly_features_path, simulated_or_qemu_only,
diagnostic_elapsed_s, timestamp
```

- accepted 的 stdout 文件必须真实存在；失败记录必须有 stderr 和可重放命令；
- 每个成功候选二进制保存或明确索引 `.ll` / `.s` 工件；
- 路径相对 `runs/<run_id>/` 记录，不能为空；
- `coverage.csv` 必须由 JSONL 聚合，区分 `not_run`、`compile_failed`、`run_timeout`、`crashed`、`incorrect`、`accepted`。

### C. 候选池预检与 FP 语义处理

1. 创建版本化候选 manifest（不覆盖旧 manifest），对每个候选在固定小程序上进行 Clang 实际编译预检。
2. 将 `O3_nogvn`、`O3_nolicm`、`O3_nosimplifycfg`、`O3_nolooprotate` 从新严格正确性池中替换为预检通过的有效候选；提交替换映射、完整命令和预检结果。旧 run 的失败记录保留。
3. `O3_fastmath` 不得靠放宽容差进入严格 FP 池；如保留，只能归入明确排除于严格覆盖分母的“语义改变/探索性”池。
4. `correlation`、`covariance` 的所有输入、候选、目标都必须实际使用 `-DPOLYBENCH_USE_C99_PROTO -ffp-contract=off -DFMA_DISABLED=1`。

### D. 新正式 run 与分层执行

1. 新 run ID 不能是 `p0-20260718-formal-001`，目录存在时必须拒绝覆盖。
2. 先执行局部验收：`gemm` 五输入 × O0 参考与两个有效候选 × 三目标；逐项验证宏、二进制哈希、参考和输出路径正确对应。
3. 局部验收通过后，执行 6 个 PolyBench 程序 × 新严格池全部候选 × 5 真实输入 × 三目标。
4. PolyBench 通过后，执行 TSVC：先五个边界输入，后 20 个预注册固定种子；每个输入均按同输入 O0 参考比对。
5. 资源不足时停止于已完成批次，准确标记 `not_run`；不得缩小分母宣称完成。

### E. 可恢复性与不可覆盖验证

1. 对同一 run ID 不带 `--resume` 重复启动一次，保存拒绝覆盖的命令、退出码、stderr。
2. 执行一次 `--resume`，证明不会重复写记录或复用其他输入二进制；给出前后条数和哈希。
3. 任选一个非 Mini 输入组合，提交重放命令、二进制哈希、参考输出哈希和重放结果。

## 4. 禁止项

- 不删除或修改旧 run 来掩盖问题；
- 不用 Mini 二进制或参考输出代表多个 `input_id`；
- 不将空目录视为工件证据；
- 不将编译失败候选计为严格正确性覆盖；
- 不放宽 `O3_fastmath` 容差以获得 accepted；
- 不进入 P2/P3、不训练模型、不产生跨目标性能排名或加速比；
- 不因 QEMU 较慢自行删减 TSVC 固定输入集。

## 5. 验收条件

| 编号 | 验收项 | 通过标准与原始证据 |
|---:|---|---|
| C1 | 输入隔离正确 | `gemm` 五输入 × 三目标的宏、编译命令、候选/参考哈希、工件路径；不同配置不得错误共享 Mini 宏或二进制 |
| C2 | 完整记录与工件 | JSONL 必填字段非空；accepted 与失败各抽查 3 条，路径可打开 |
| C3 | 候选池可执行且语义清晰 | 新 manifest 哈希、全部预检输出、替换映射；fastmath 与严格池隔离 |
| C4 | 浮点规则可证 | correlation/covariance 全目标、全输入实际编译命令及结果 |
| C5 | PolyBench 正式覆盖 | 6 程序 × 新严格池 × 5 输入 × 3 目标，或精确声明未完成组合 |
| C6 | TSVC 输入覆盖 | 5 边界 + 20 固定输入均按同输入参考运行；未完成即未通过 |
| C7 | resume 与重放正确 | 拒绝覆盖、一次 resume、一个非 Mini 输入重放的原始日志与统计 |
| C8 | 研究边界保持 | QEMU 均标记模拟用途；无性能排名、速度提升或真实性能表述 |

只有 C1–C8 全部通过，Codex 才能判定 P0 是否完成并决定是否编写 P2 准备计划。

## 6. DeepSeek 必须反馈

1. 修复前后驱动差异：路径、缓存键、参考构建、执行循环；
2. C1 完整抽样：五输入的实际宏、命令、候选/参考哈希、输出路径与哈希；
3. C2 的工件树，以及 accepted、compile_failed、incorrect 各 3 条原始 JSONL；
4. 新旧候选 manifest 哈希、替换映射和每个候选预检输出；
5. 严格 FP 池与语义改变池的成员、分母、状态统计；
6. 新 run 的 manifest、coverage、summary、命令、时间和日志路径；
7. TSVC 每个已执行和未执行输入及原因；
8. 拒绝覆盖、resume、非 Mini 重放的完整命令、退出码、日志及记录数变化；
9. 最终状态只能为“待 Codex 审查”，不得自行宣布 P0 完成或进入 P2。
