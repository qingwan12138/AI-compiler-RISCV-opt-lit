# 面向多硬件平台的自适应编译优化框架

## 一、研究方向概述

### 1. 研究题目

中文题目：

**基于平台条件化策略与跨硬件效应建模的多平台编译优化方法**

英文题目：

**MAPO: Multi-Platform Adaptive Compiler Optimization with Hardware-Conditioned Policies**

如果第一阶段明确以 LLVM Pass 排序为研究对象，可以使用：

**MAPO-Pass: Hardware-Conditioned Compiler Phase Ordering for Multi-Platform Performance Optimization**

---

## 二、研究背景

编译器通常使用 `-O2`、`-O3` 等固定优化流水线处理不同程序和硬件平台。然而，编译优化效果同时依赖：

- 程序结构；
- Compiler Pass 的组合和顺序；
- 编译器前端与后端实现；
- 目标 ISA；
- 微架构流水线；
- 缓存与内存系统；
- 向量单元和寄存器资源。

因此，同一条 Pass 序列在 x86、ARM 和 RISC-V 等不同平台上的效果可能明显不同。例如，循环展开可能在一块处理器上增加指令级并行，却在另一块处理器上引起寄存器溢出和指令缓存压力；向量化也可能受到向量宽度、后端指令选择和内存带宽的共同影响。

现有方法通常走向两个极端：

1. **所有硬件共用一条固定策略**

   这种方法简单，但忽略平台差异，难以为每个平台获得较好的性能。

2. **每个平台分别训练和搜索**

   这种方法可以产生平台专属策略，但不同平台之间无法共享优化知识，且每增加一个平台都需要维护新的搜索器、模型和训练数据。

因此，需要一种介于两者之间的方法：

> 使用一个统一模型学习不同平台之间可共享的编译优化知识，同时根据目标硬件特征生成平台专属优化策略。

---

## 三、需要解决的核心问题

### 问题一：如何表示不同硬件平台

只使用 CPU 型号、ISA 或硬件 ID，模型可能只是记住训练平台，而没有真正理解平台对编译优化的性能响应。

需要回答：

- 两个同为 x86 的平台是否一定具有相似的优化偏好？
- ARM 和 RISC-V 是否可能在某些访存优化上比两个 x86 平台更接近？
- 哪些硬件特征真正影响循环展开、内联、向量化和代码布局？

### 问题二：如何同时学习共享知识和平台差异

部分优化具有较强的通用性，例如死代码删除和常量传播；另一些优化则高度依赖平台，例如：

- 循环展开；
- 向量化；
- 函数内联；
- 预取；
- 循环变换；
- 指令调度；
- 代码布局。

如果模型只学习共享规律，会忽略平台特性；如果完全独立建模，又无法利用跨平台共性。

### 问题三：如何确定性能收益来自哪些 Pass

一条 Pass 序列最终变快，并不代表其中所有 Pass 都有正向贡献。性能提升可能来自：

- 单个关键 Pass；
- 两个相邻 Pass 的协同；
- 前序 Pass 为后续 Pass 创造机会；
- 后端对某种 IR 结构的特殊处理；
- 与 Pass 无关的测量噪声。

因此，需要从序列级总奖励进一步分析 Pass 级贡献。

### 问题四：如何保证多个平台上的稳定收益

只优化多平台平均性能，可能导致某个平台明显退化。因此，框架不仅需要提高平均加速比，还应控制：

- 负优化程序比例；
- 最坏平台性能；
- 最坏程序性能；
- 平台间性能不均衡。

---

## 四、框架核心思想

本文提出一个平台条件化的统一编译优化框架：

$$
S_h=\pi(p,h)
$$

其中：

- $p$ 为待优化程序；
- $h$ 为目标硬件；
- $\pi$ 为统一优化策略；
- $S_h$ 为针对硬件 $h$ 生成的专属 Pass 序列。

对于相同程序，不同平台可以获得不同序列：

$$
S_{\mathrm{x86}}
\neq
S_{\mathrm{ARM}}
\neq
S_{\mathrm{RISC\text{-}V}}
$$

框架不强制寻找一条适用于所有平台的公共序列，而是通过一个共享模型生成平台专属策略。

整体流程为：

```text
多平台程序与性能数据
            ↓
程序结构特征提取
            +
硬件响应特征提取
            ↓
共享优化知识学习
            +
程序—硬件交互建模
            ↓
生成平台专属 Pass 序列
            ↓
编译与正确性检查
            ↓
目标平台真实性能测量
            ↓
反事实 Pass 信用分析
            ↓
更新共享效应与平台特有效应
```

## 五、主要创新点

### 创新点一：基于真实性能响应的平台表征

除静态硬件规格外，在每个平台运行一组标准微基准，构建硬件响应向量：

$$
\phi(h)=
[\phi_1(h),\phi_2(h),\ldots,\phi_m(h)]
$$

其中可以包含：

- 整数与浮点计算吞吐；
- 指令依赖链延迟；
- 连续访存性能；
- stride 访存性能；
- 不同工作集下的缓存响应；
- 分支预测响应；
- 循环展开响应；
- 向量化响应；
- 代码尺寸和指令缓存响应；
- 多线程扩展能力。

采用相对或归一化响应：

$$
\phi_k(h)
=
\log
\frac{T_{\mathrm{pattern},k}(h)}
     {T_{\mathrm{reference},k}(h)}
$$

这样可以降低主频和平台整体性能差异的干扰。

该方法不是仅描述“硬件是什么”，而是描述：

> 该硬件对不同程序模式和编译变换如何反应。

例如，两个平台都支持向量指令，但可能分别受计算吞吐和内存带宽限制。简单的 ISA 标签无法表达这种差异，而动态响应特征能够为优化策略提供更直接的信息。

---

### 创新点二：共享效应与平台特有效应分解

定义程序 $p$、优化动作 $a$ 在硬件 $h$ 上的相对性能收益：

$$
\Delta(p,a,h)
=
\log
\frac{T_{\mathrm{baseline}}(p,h)}
     {T_{\mathrm{optimized}}(p,a,h)}
$$

模型将其分解为：

$$
\widehat{\Delta}(p,a,h)
=
g_{\mathrm{shared}}(\psi(p,a))
+
g_{\mathrm{platform}}(\psi(p,a),\phi(h))
$$

其中：

- $\psi(p,a)$：程序与优化动作特征；
- $g_{\mathrm{shared}}$：跨平台共享效应；
- $g_{\mathrm{platform}}$：程序、动作和目标硬件之间的交互效应。

共享效应示例：

- 删除冗余计算；
- 消除死代码；
- 简化控制流；
- 常量传播。

平台特有效应示例：

- 循环展开后是否产生寄存器溢出；
- 向量化后是否真正使用高效指令；
- 内联后是否增加指令缓存压力；
- 循环交换是否改善目标平台缓存行为；
- 代码布局是否匹配平台前端取指能力。

该模型明确区分：

> 什么优化知识可以共享，以及什么优化效果需要根据目标平台重新判断。

---

### 创新点三：反事实驱动的跨平台 Pass 信用分配

对于 Pass 序列：

$$
S=[a_1,a_2,\ldots,a_n]
$$

删除第 $i$ 个 Pass：

$$
S^{-i}
=
[a_1,\ldots,a_{i-1},a_{i+1},\ldots,a_n]
$$

定义该 Pass 的边际贡献：

$$
C_i(p,h)
=
\log
\frac{T(S^{-i},p,h)}
     {T(S,p,h)}
$$

若 $C_i>0$，说明删除该 Pass 后变慢，该 Pass 对当前平台有正向贡献。

还可以交换两个相邻 Pass：

$$
S^{swap(i,i+1)}
$$

比较交换前后的性能，可以识别：

- Pass 顺序依赖；
- 前后 Pass 协同；
- 某个 Pass 是否只是为后续 Pass 创造条件。

进一步比较同一个 Pass 在多个平台上的贡献：

$$
C_i(p,h_1),\quad
C_i(p,h_2),\quad
C_i(p,h_3)
$$

从而划分为：

- 跨平台稳定正收益；
- 跨平台稳定负收益；
- 平台特定正收益；
- 不同平台收益方向相反；
- 依赖 Pass 组合才能产生收益。

已有工作已经使用 Pass 删除、边际 cycles 和 synergy 分析单平台优化证据。因此，本文不把“删除 Pass”本身作为创新，而是强调：

> 将反事实 Pass 信用扩展到多个硬件，并把它用于共享效应和平台交互效应学习。

---

### 创新点四：兼顾平均收益与性能退化的平台条件化训练目标

模型在训练时从不同程序和平台中采样：

$$
(p,h)\sim D
$$

针对目标平台生成 Pass 序列，并以相对 `-O3` 的真实性能作为奖励：

$$
R(p,h)
=
I_{\mathrm{correct}}
\log
\frac{T_{O3}(p,h)}
     {T_{\pi}(p,h)}
$$

为了避免只提高平均性能、牺牲部分平台，可以增加性能退化惩罚：

$$
R_{\mathrm{reg}}
=
\max
\left(
0,
\frac{T_{\pi}(p,h)}{T_{O3}(p,h)}-1
\right)
$$

整体目标为：

$$
R_{\mathrm{total}}
=
R_{\mathrm{avg}}
-\lambda R_{\mathrm{reg}}
+\beta R_{\mathrm{worst}}
$$

其中：

- $R_{\mathrm{avg}}$：所有平台和程序的平均收益；
- $R_{\mathrm{reg}}$：相对基线退化惩罚；
- $R_{\mathrm{worst}}$：最差平台或最差程序收益。

该目标不要求所有程序都加速，而是希望：

- 多个平台几何平均性能提升；
- 负优化比例较低；
- 最坏性能退化可控；
- 不让数据量较多的平台支配训练。

## 六、与已有文献的比较

| 工作 | 主要研究内容 | 硬件范围 | 是否建模平台差异 | 是否进行 Pass 级归因 | 与本文区别 |
|---|---|---|---|---|---|
| AutoPhase / CompilerGym | 用 RL 或标准环境搜索 Pass 序列 | 主要为单平台或固定目标 | 弱 | 否 | 建立 Pass 排序基础，但不解决统一多平台策略 |

| CITROEN | 使用实际变换 statistics、GP 和主动采样 | 各平台独立调优 | 不共享 | 不以反事实为核心 | 每个平台分别搜索，没有共享—平台效应分解 |
| DeCOS | LLM 先验、IR2Vec、硬件计数器与 RL | 两块 AMD CPU | 部分 | 否 | 使用硬件动态观测，但未形成多 ISA 统一条件化策略 |
| ECCO | Pass 删除、边际 cycles 和 synergy 分析 | 单一效应域，主要使用代理 cycles | 弱 | 是 | 已覆盖单平台 Pass 归因，本文研究跨平台 Pass 效应 |
| Compiler-R1 | SFT、GRPO 与编译器工具反馈调优 Pass | 主要评价 IR 指令数 | 否 | 否 | Agent 与 RL 已被覆盖，但没有真实性能驱动的多平台适配 |
| AwareCompiler | 知识库、SFT/RL 和 Agent 优化 IR | 主要使用 IR 代理指标 | 否 | 否 | “知识+Agent+RL”不是本文创新重点 |
| TCL | 跨硬件代价模型持续学习、教师蒸馏与 EWC | 多硬件 | 是 | 否 | 更关注代价模型迁移；本文关注平台条件化 Pass 策略和跨平台信用 |
| 本文 MAPO-Pass | 共享模型生成平台专属 Pass 序列 | x86、ARM、RISC-V 等 | 是 | 是 | 联合硬件响应、共享—平台效应分解和跨平台反事实信用 |

需要注意：

- CITROEN、DeCOS 和 ECCO 分别说明实际变换统计、动态硬件反馈和 Pass 边际证据已有价值；
- 因此，本文不能宣称“首次使用硬件计数器”“首次删除 Pass”或“首次做多硬件调优”；
- 真正应强调的是这些证据在统一多平台条件化策略中的组合方式；
- Compiler-R1、AwareCompiler、IntOpt、AutoComp 等已经覆盖 LLM Agent、强化学习、知识库和工具反馈，因此第一篇论文不应把 LLM 智能体作为核心创新，而应把 LLM 定位为可替换的候选生成器。

## 七、完整实验框架

### 1. 实验平台

优先使用三个平台：

- x86-64 平台；
- ARM 平台；
- RISC-V 平台。

条件受限时，可以使用：

- x86 平台 A；
- x86 平台 B；
- RISC-V 平台 C。

第二种组合能够同时研究：

- 同 ISA、不同微架构；
- 跨 ISA、不同微架构。

RISC-V 只是实验平台之一，不需要设计 RISC-V 专属创新。具备 RVV 时，可以在硬件响应测试中加入向量相关项目；不具备 RVV 也不影响论文主线。

所有平台需要记录并固定：

- LLVM/Clang 版本；
- 操作系统和内核版本；
- 编译参数；
- 链接参数；
- 运行库；
- CPU governor；
- 线程和核心绑定；
- 预热次数；
- 输入数据；
- 超时限制。

QEMU、gem5 等模拟器可以用于可执行性预筛，但最终性能结论应来自真实硬件。

---

### 2. Benchmark

第一阶段建议使用：

- PolyBench；
- cBench；
- LLVM test-suite 中可稳定运行的程序；
- TSVC；
- MiBench 中测试完整的程序。

数据按照程序家族划分：

- 训练集；
- 验证集；
- 测试集；
- 外部分布测试集。

不能把同一程序的不同参数或轻微修改版本分别放入训练和测试两侧。

---

### 3. Pass 动作空间

第一阶段建议选择 15–30 个稳定 Pass，例如：

- `instcombine`；
- `simplifycfg`；
- `reassociate`；
- `gvn`；
- `sccp`；
- `adce`；
- `dse`；
- `memcpyopt`；
- `licm`；
- `loop-unroll`；
- `loop-rotate`；
- `loop-vectorize`；
- `slp-vectorizer`；
- `inline`；
- `globalopt`；
- `jump-threading`。

第一版建议固定：

- Pass 集合；
- 最大序列长度；
- 编译器版本；
- 基础优化流水线；
- 程序输入。

不建议同时研究：

- 完整 LLVM Pass 空间；
- 源码重写；
- IR 局部规则生成；
- 后端指令选择；
- RVV intrinsic 参数；
- kernel orchestration。

### 4. 候选生成方法

#### 阶段一：传统搜索生成数据

使用：

- Random Search；
- Genetic Algorithm；
- Simulated Annealing；
- Beam Search。

用于建立多平台候选性能数据集。

#### 阶段二：监督式候选排序

输入：

```text
程序特征
+ 硬件特征
+ Pass 序列特征
```

输出：

```text
候选在目标平台上的性能分数或排序
```

首版模型可以使用：

- LightGBM；
- XGBoost；
- MLP；
- Learning-to-Rank 模型。

#### 阶段三：平台条件化策略

待候选排序模型验证有效后，再实现：

- 强化学习策略；
- Mixture-of-Experts；
- 平台 Adapter；
- LLM 候选生成器。

这样可以先验证研究假设，避免一开始将问题归因于大模型或 RL 训练不稳定。

### 5. 程序特征

可以提取：

- LLVM IR 指令数量；
- 指令类别直方图；
- 基本块数量；
- CFG 边数量；
- 循环数量和嵌套深度；
- 静态 trip count；

第一版不必全部使用，可以先采用静态统计特征，后续增加图表示和 IR2Vec。

### 6. 硬件特征

静态特征：

- ISA；
- 核心数；
- 缓存容量；
- 向量扩展；
- 目标 triple；
- 编译器后端；
- 主频范围。

动态响应特征：

- 标量计算吞吐；
- 浮点计算吞吐；
- 依赖链延迟；
- 连续访存带宽；
- stride 访存；
- 工作集大小曲线；
- 分支响应；
- 循环展开响应；
- 向量化响应。

PMU 事件可以作为可选特征，不要求不同 ISA 具有完全相同的事件名称。无法可靠校准的 PMU 特征应标记为缺失，而不是强行对齐。

## 八、对比基线

### 1. 编译器基线

- LLVM `-O2`；
- LLVM `-O3`；
- LLVM `-Os`；
- 各平台默认优化配置。

### 2. 搜索基线

- Random Search；
- Genetic Algorithm；
- Simulated Annealing；
- 每个平台独立搜索；
- 每个平台独立训练模型。

### 3. 多平台建模基线

#### Universal Pipeline

所有平台共用同一条 Pass 序列。

#### Universal Model

多平台数据混合训练，但模型不接收硬件信息。

#### Hardware-ID Model

输入程序特征和硬件 ID。

#### Static-Hardware Model

输入程序特征和静态硬件规格。

#### Platform Embedding

使用可学习的平台 embedding。

#### Independent Models

每个平台独立训练模型。

#### Shared + Platform Head

共享程序编码器，每个平台使用独立策略头。

#### 完整方法

硬件响应表征、共享—平台效应分解和反事实 Pass 信用。

## 九、研究问题

### RQ1：统一平台条件化模型能否提高多个平台的性能？

与 `-O3`、公共序列和普通共享模型相比，MAPO-Pass 能否在 x86、ARM、RISC-V 等平台获得更高的几何平均性能？

### RQ2：平台条件化是否优于平台独立训练？

统一模型能否在保持平台特性的同时，达到或超过多个独立模型的综合效果？

### RQ3：硬件响应表征是否有效？

动态响应表征是否优于：

- 硬件 ID；
- ISA 标签；
- 静态硬件规格；
- 普通平台 embedding？

### RQ4：不同平台是否确实需要不同 Pass 序列？

同一程序在不同平台上的最优序列是否存在稳定差异？这些差异是否对应运行时间、汇编和硬件行为变化？

### RQ5：共享—平台效应分解是否有效？

显式分解模型是否优于直接拼接程序和硬件特征？

### RQ6：反事实 Pass 信用能否提高平台适配能力？

加入 Pass 删除和交换证据后，模型是否能够：

- 更准确地预测候选排序；
- 识别平台特定负优化；
- 生成更合适的平台专属序列？

### RQ7：方法是否适用于未见程序？

在未参与训练的 benchmark 家族中，模型能否保持多平台性能提升？

### RQ8：方法是否偏向某个平台？

联合训练是否只改善数据量多或性能强的平台，而损害其他平台？

4. 去除共享主干；

需要重点证明：

## 十二、预实验设计

### 预实验一：验证不同平台的最优策略确实不同

#### 实验目的

证明“多平台适配”是一个真实问题，而不是人为构造的问题。

#### 实验配置

- 3 个硬件平台；
- 10–20 个 PolyBench/cBench 程序；
- 15–20 个 LLVM Pass；
- 每个程序生成 100–300 条相同候选序列；
- 所有候选分别在三个平台运行。

#### 分析内容

1. 同一候选在不同平台上的性能排序；
2. 各平台 Top-1、Top-5 序列的重合率；
3. 平台间候选排名 Spearman 相关性；
4. 源平台最佳序列在其他平台上的表现；
5. 公共最佳序列与平台专属最佳序列的差距。

#### 建议成功标准

以下标准用于决定是否继续，不是预设实验结论：

- 多个程序在不同平台上具有不同的最佳序列；
- 存在一批候选在不同平台上收益方向不同；
- 平台专属最佳策略整体优于公共策略；
- 候选排序不是在所有平台上完全一致。

如果三个平台的排序几乎相同，需要扩大硬件差异或将动作空间调整为更平台敏感的 Pass，例如向量化、展开、内联和循环变换。

---

### 预实验二：验证硬件响应特征是否有用

#### 实验目的

比较不同硬件表示方法。

#### 对比输入

- 程序特征；
- 程序特征 + 硬件 ID；
- 程序特征 + 静态硬件规格；
- 程序特征 + 动态响应特征；
- 程序特征 + 静态与动态特征。

#### 模型

先使用 LightGBM 或 XGBoost 排序模型。

#### 评价指标

- 候选排序 Spearman；
- Pairwise accuracy；
- Top-5 recall；
- 模型选出候选的实际加速比。

#### 成功标准

动态响应特征在至少部分平台和未见程序上优于单纯硬件 ID 或静态规格。

如果动态响应没有明显提升，需要检查：

- 微基准是否与 Pass 动作相关；
- 特征是否过多或噪声过大；
- 是否需要按计算、访存、控制流分别构造子指纹。

---

### 预实验三：统一模型与独立模型比较

#### 实验目的

判断统一平台条件化模型是否具有研究价值。

#### 对比模型

1. 所有平台共享的普通模型；
2. 每个平台独立模型；
3. 共享主干 + 平台独立头；
4. 共享主干 + 动态硬件条件化；
5. 共享效应 + 平台残差模型。

#### 预期观察

- 普通共享模型可能忽略平台差异；
- 独立模型能适配平台，但无法共享知识；
- 平台条件化模型应在综合性能上优于普通共享模型；
- 平台条件化模型应接近或超过独立模型的平均效果。

#### 论文成立的基本条件

完整方法至少需要：

- 在多个平台上优于公共策略；
- 综合性能优于普通共享模型；
- 不在某个平台上产生大面积退化；
- 相对独立模型具有可接受或更好的表现。

---

### 预实验四：Pass 反事实贡献分析

#### 实验目的

验证 Pass 在不同平台上的贡献确实存在差异。

#### 实验步骤

1. 从每个平台选出若干优良序列；
2. 对序列中的关键 Pass 逐个删除；
3. 对相邻 Pass 进行交换；
4. 在所有平台重复运行；
5. 计算 Pass 边际效应；
6. 记录 IR diff、汇编变化和运行时间。

#### 输出结果

可以形成以下图表：

- Pass × Platform 热力图；
- 各 Pass 跨平台贡献箱线图；
- Pass 贡献符号一致率；
- Pass synergy 网络；
- 平台共享效应和平台残差分布。

#### 成功标准

观察到以下至少一种现象：

- 同一个 Pass 在多个平台上贡献大小不同；
- 某个 Pass 在不同平台上贡献符号相反；
- 相同 Pass 只有在特定前后文中有效；
- 反事实信用能够提高候选排序准确率。

---

### 预实验五：小规模端到端验证

#### 实验目的

证明统一框架能够生成平台专属策略并提升性能。

#### 实验规模

- 3 个平台；
- 10 个训练程序；
- 5 个验证程序；
- 5 个独立测试程序；
- 每个平台相同候选池；
- 使用简单排序模型，不使用 RL。

#### 流程

```text
生成候选序列
      ↓
多平台编译与测量
      ↓
提取程序、硬件、Pass 特征
      ↓
训练平台条件化排序模型
      ↓
为每个平台选择 Top-k 候选
      ↓
真实性能评测
      ↓
与 -O3、公共模型和独立模型比较
```

#### 预实验目标

1. 三个平台均能生成不同的候选排序；
2. 平台条件化模型整体优于公共模型；
3. 多个平台相对 `-O3` 获得几何平均性能提升；
4. 性能退化程序比例可控；
5. 结果不是由单个极端 benchmark 主导。

## 十三、推荐实施顺序

### 第一阶段：建立可复现的多平台测量管线

完成：

- 相同源码和输入；
- 自动编译；
- 正确性检查；
- 自动计时；
- 环境记录；
- 结果数据库。

### 第二阶段：证明平台差异

完成：

- 相同候选跨平台测量；
- 排名相关性分析；
- Top-k 重合率；
- 跨平台性能迁移矩阵。

### 第三阶段：实现平台条件化排序模型

完成：

- 程序静态特征；
- 静态硬件特征；

## 十四、风险与备选方案

### 风险一：不同平台最佳序列差异不明显

可能原因：

- 硬件平台差异不足；
- Pass 动作空间过于通用；
- 程序计算规模太小；
- 后端优化覆盖了前端 Pass 差异。

解决方法：

- 增加向量化、展开、内联和循环相关 Pass；
- 增加不同 ISA 平台；
- 加入内存密集型和分支密集型程序；
- 使用不同输入规模；
- 从完整程序缩小到热点函数或 kernel。

---

### 风险二：很难稳定超过 `-O3`

`-O3` 是较强基线，盲目从零生成 Pass 序列容易破坏其优化效果。

解决方法：

- 从 `-O3` 管线进行删除；
- 在 `-O3` 基础上调整局部顺序；
- 只开放少量平台敏感 Pass；
- 搜索 `-O3` 管线的子序列或局部变体。

论文目标可以设为：

> 相对固定公共策略和普通统一模型获得稳定提升，并在多个平台上达到或超过 `-O3`。

---

### 风险三：统一模型不如独立模型

解决方法：

- 平台 Adapter；
- 平台残差头；
- Mixture-of-Experts；
- 硬件条件化门控；
- 按平台类型共享部分参数。

统一模型不应强制所有参数共享，而应采用“共享主干 + 平台交互模块”。

---

### 风险四：运行时间噪声掩盖真实收益

解决方法：

- 固定 CPU governor；
- 绑定核心；
- 预热；
- 随机化候选运行顺序；
- 重复运行；
- 使用中位数；
- 报告置信区间；
- 过滤不稳定程序；
- 优先选择运行时间足够长的输入。

---

### 风险五：LLM 或 RL 增加复杂度但没有收益

第一篇论文可以完全不依赖 LLM。使用随机搜索、遗传算法和排序模型已经可以验证核心创新。

LLM 的合理位置是后续候选生成器，而不是论文成立的必要条件。

---

## 十五、论文贡献表述

1. **提出一个统一的多平台编译优化框架。**  
   该框架以程序和目标硬件为联合条件，为不同 ISA 和微架构生成平台专属的编译优化序列，而不是让所有平台共用固定策略。

2. **提出基于真实性能响应的硬件表征方法。**  
   通过计算、缓存、访存、分支和向量等微基准描述硬件对编译变换的实际响应，避免模型仅依赖硬件 ID 和静态规格。

3. **提出共享效应与平台交互效应分解模型。**  
   将编译优化收益分解为跨平台共享规律和目标平台特有残差，使统一模型能够同时利用平台共性并保持平台差异。

4. **提出跨平台反事实 Pass 信用分析方法。**  
   通过删除和交换关键 Pass，识别不同编译阶段在各硬件平台上的正向、负向和协同效应，为平台条件化策略提供细粒度监督。

5. **在包含 RISC-V 的多个真实硬件平台上完成评测。**  
   从单平台性能、多平台综合性能、负优化比例、平台适配能力和 Pass 归因等角度验证框架的有效性。

---

## 十六、最终研究主线

本文不重点研究：

> 如何使用很少的目标硬件测量完成新平台调优。

而是研究：

> 如何通过一个统一的编译优化模型，学习多个硬件平台之间的共享优化规律和平台特有性能效应，为每个平台生成专属优化策略，并在包括 RISC-V 在内的多个真实硬件上获得稳定的整体性能提升。

第一阶段最关键的不是训练 LLM，而是用预实验证明三个事实：

1. 不同硬件确实需要不同的 Pass 策略；
2. 硬件响应特征能够帮助模型区分平台优化偏好；
3. 共享效应与平台交互效应模型优于固定公共策略和普通共享模型。

只有这三个假设成立，后续加入强化学习和 LLM 才有明确意义。
